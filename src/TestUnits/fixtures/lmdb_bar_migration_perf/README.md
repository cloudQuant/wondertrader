# R100/R32 staging：快速路径的边界与受控对照

本轮没有改变 staging 实现，也没有跳过现有前缀核验。隔离环境中的对照表明，单靠 LMDB 事务号、当前 binding 身份和文件 inode，不能检测非合作方的原位文件改写；这不排除未来在实际强制独占的受限会话中实现快速路径。

## 对照与结果

`cache_guard_test.cpp` 只操作新建的实体临时 LMDB 文件，不交易、不创建符号链接。先提交一条 staging 记录并记录源和目标事务号：

- `source-raw` / `target-raw`：关闭环境，由测试进程原位修改源值或目标 staging 值后重开。源/目标事务号仍为 4/6；当前完整前缀核验分别返回 `MissingEvidence` / `Conflict`。
- `source-live` / `target-live`：源、目标环境和同一个 binding 始终存活；前一批事务结束后，独立的 `fork` + `exec` 子进程直接改写相应隔离文件，父进程再执行一批。事务号仍为 4/6；当前完整前缀核验同样分别返回 `MissingEvidence` / `Conflict`。改写发生在两批之间，这不证明扫描期间任意非合作写入均能检测。
- `multiple-bindings`：顺序初始化两个绑定到同一目标，故意违反现有单 binding 合同；第二个 binding 可以撤销已提交前缀的证据，目标事务号从 6 增至 7，原 binding 完整核验返回 `MissingEvidence`。此对照不声称并发的多个 binding 受到支持。

上述 5 个用例普通和 ASan/UBSan 各 5/5；真实磁盘故障、并发原始文件写入、恶意伪造的证据和其他平台未验证。正常路径、受控撤销、子进程中断后恢复、目标/证据篡改、单 binding 并发的既有能力回归：普通和 ASan/UBSan 各 7/7。原 34 个 callback 相关历史用例未按通过统计；旧 callback 明确 fail-closed。原始 TSan 和 semaphore 注解版的并发撤销均退出 134，均报告 LMDB reader slot 访问竞争；不能断言为误报或称 TSan 通过。

本机单次合成规模观察，批次 1024，证据装载不计时：1 万 / 5 万 / 10 万 / 25 万条分别耗时 35 / 820 / 3375 / 22271 ms，25 万条最大 RSS 约 256 MiB，包含 LMDB 映射与页缓存。这些数据体现当前约 O(N²/B) 的重复前缀扫描，不代表真实吞吐或更大规模的资源上限。

## 快速路径候选合同，尚未实现

1. 须有实际可验证、在会话期持续生效的独占能力，覆盖源、目标和证据；明确威胁边界，阻止绕过组件的文件写入、第二 binding 和未协调的 LMDB 事务。证据来源、旧二进制阻断、源写入停排与权限隔离仍须可信外部控制面独立证明。一个布尔值、callback、普通锁约定或调用者声称独占均不构成这种能力。
2. 组件须真正拥有或可安全租借环境与 DBI 的生命周期，活跃调用期间禁止未协调的关闭、resize、替换以及与迁移冲突的事务。目前 `Bindings` 借用裸环境指针，目标句柄和 staging DBI 可被取出，互斥锁仅属于单个 binding，无法单独建立此合同。
3. 创建或重开会话时，对固定源快照、持久证据与目标已提交前缀做有界完整核验；核验后才在同一会话内缓存前缀位置及其与源、目标、证据、manifest 的关系。进程重启、崩溃恢复、租约失效或事务结果不确定后，丢弃快速资格并重新完整核验，不凭进程内标志或持久事务号跳过审计。
4. 快速批次须将受控证据读取、撤销、目标变更及批次提交纳入同一可验证串行化协议。证据写入或撤销后，已有 `C→I` 必须与证据修改原子提交，并使所有相关会话的缓存失效；异常、外部门禁丢失、源/目标/证据或版本变化均 fail-closed。完成仅意味着当时受控快照的 staging 扫描完成，不能发布。
5. 即便引入校验树或快照标识，也须证明底层数据不能绕过对应的完整性维护；没有这个约束时，仅持有摘要或文件元数据不能发现未读取部分被修改。落地后需独立覆盖首次及重启完整核验、批内和批间撤销、异常和 commit 前后崩溃、多 binding / 跨进程绕过、生命周期、篡改、规模资源，以及各目标平台的并发行为。

当前实现没有可强制的上述独占和环境所有权能力，已有 TSan 报告也未排除实际影响，因此现阶段不引入基于缓存的快速路径。
