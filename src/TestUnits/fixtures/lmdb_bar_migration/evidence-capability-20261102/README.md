# 受控证据表候选：本机验证记录

2026-11-02，macOS arm64。此为离线 staging 候选与受限测试，不是验收或发布许可。没有修改生产 AD reader/writer，也没有真实交易或符号链接。证据内容由调用者提供；组件不认证颁发者、签名或外部撤销，不阻断不合作进程，不负责停写或禁止旧二进制。这些均是仍需独立证明的外部门禁。`Bindings` 借用源和目标环境，所有者须在所有调用结束前保活且不得并发关闭 DBI、关闭或 resize 环境；每个目标必须只有一个受控 binding，所有证据更新必须经过它。

目标 LMDB 命名表持久保存受控证据，单次最多装载 4096 条并在同一事务提交或回滚。证据记录绑定完整源键与源值；内存占用不随证据表总条数线性复制，但仍受 LMDB 映射、页缓存、环境最大大小和磁盘空间约束。证据更新、撤销及 staging 提交通过同一 binding 的互斥串行化，受控更新或撤销将已有 `C` 在同一个 LMDB 写事务内降为 `I`。重启后再次调用会重新核验全部已提交前缀；`C` 只说明提交时的受控快照通过，绝非访问控制或发布授权。证据表本身没有签名或对抗恶意直接写入的完整性认证，不能证明源数据或证据来源真实。

旧 `EvidenceLookup` 重载直接返回 `EvidenceCapabilityRequired`，不调用 callback、不写入 staging。因此旧 34 例中依赖 callback 的路径**不兼容并明确 fail-closed**；这次没有把旧 34 例宣称为通过。原先的批内撤销 known-red 探针保留在 `migration_test.cpp`，它现在因 callback 根本不运行而不再能重现原始红控；旧红控结果见仓库 `docs/迭代计划/迭代03/实施跟踪/evidence/R100-R32-evidence-consistency-20261102/README.md`。受控并发测试令撤销请求在目标批次事务中途发起，验证完成后撤销导致 `C→I`，再次核验拒绝缺失证据，恢复证据后可重新核验完成。
