# SEL factory exception quarantine: focused fixture

From the repository root, run `src/TestUnits/fixtures/sel_factory_quarantine/run.sh /private/tmp/sel-factory-quarantine`. The optional environment variable `WT_SEL_BASELINE_SOURCE` supplies a saved pre-edit `SelStrategyMgr.cpp` for red controls; its source hash is recorded. The default run only tests the current implementation. Boost, fmt and spdlog include roots default to physical Homebrew Cellar paths and can be overridden by `WT_BOOST_INCLUDE`, `WT_FMT_INCLUDE`, `WT_SPDLOG_INCLUDE`. No symbolic links are created. Tests use fake dynamically loaded libraries and a stub logger sink; the real logger formatting template is enabled.

The 15 targeted cases cover throwing creator/getName, null/empty results, healthy creation, repeated scan, same-name different-module conflict across managers, same-handle reentry and concurrency, preserving two long names, and missing creator or remover exports. The SEL ABI requires both exports before invoking creator. A module lacking either export remains unregistered and its loader reference is retained because static initialization may have started work. Repeated missing-export scans continue to be ignored as before; concurrent or quarantined attempts can now return false. A local name conflict keeps its object/reference resident without preventing an independent manager from using the healthy module.

Only the manager copy in this translation unit sees the registry; the strategy ABI cannot prove vendor quiescence, cross-DSO identity, module unload/reload safety, wrapper lifetime, or arbitrary concurrent strategy-map access. Loader static initialization executes before `dlopen` returns and cannot be intercepted by this registry. Healthy plugin multiple-instance safety, the real C API/logger backend, non-macOS platforms, long directory paths in log messages, full build and regression remain unverified. Deliberate retained references are not a proof of leak freedom.
