# SEL factory exception and lifetime: focused fixture

From the repository root, run `src/TestUnits/fixtures/sel_factory_quarantine/run.sh /private/tmp/sel-factory-quarantine`. Optional `WT_SEL_BASELINE_DIR` and `WT_SEL_OWNER_BASELINE_DIR` select directories containing matching pre-change `SelStrategyMgr.cpp` and `SelStrategyMgr.h` for initial quarantine and lifetime controls, respectively. Both files must come from the same snapshot. Boost, fmt and spdlog include roots default to physical Homebrew Cellar paths and can be overridden by `WT_BOOST_INCLUDE`, `WT_FMT_INCLUDE`, `WT_SPDLOG_INCLUDE`. No symbolic links are created. Tests use fake dynamically loaded libraries and a stub logger sink; the real logger formatting template is enabled.

Focused cases cover throwing creator/getName, null/empty result rescans, healthy creation, repeated scan, same-name different-module conflict across managers, same-handle reentry and concurrency, preserving two long names and full valid long directory paths, bounded invalid-path logging, missing creator/remover exports, and wrapper lifetime. The no-preload case retains two strategies and a null wrapper beyond the manager, verifies both creation overloads and exactly-once strategy deletion, and records the factory remains resident. The `owner-final-removal` scenario is expected to fail: the current manager has no contract or mechanism establishing safe factory deletion. The SEL ABI requires both exports before invoking creator. Missing-export scans remain ignored; concurrent or quarantined attempts can return false. A local name conflict keeps its object/reference resident without preventing an independent manager from using the healthy module.

Only the manager copy in this translation unit sees the quarantine registry; the strategy ABI cannot prove vendor quiescence, cross-DSO identity, module unload/reload safety, or arbitrary concurrent strategy-map access. Loader static initialization executes before `dlopen` returns and cannot be intercepted by this registry. Healthy plugin multi-instance safety, the real C API/logger backend, non-macOS platforms, full build and regression remain unverified. Successful modules, factories and failed/conflicting instances remain resident; deliberate retention is not proof of leak freedom.
