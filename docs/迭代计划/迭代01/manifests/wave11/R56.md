## 5. 未覆盖面与原因

1. `WTSHotMgr::getCustomRawCode` 的 dt==0（WTSHotMgr.cpp:326-327）与 `getPrevCustomRawCode`
   的 dt==0（:277-278）：dt=0 会读 `TimeUtils::getCurDate()`，按 lane 约束不引入墙钟依赖。
2. `WTSHotMgr.cpp:280-281`（`m_mapCustRules` 二次判空）与 `:384`（prodMap 为空）：
   前者在 274-275 已返回，后者与 “curHotCodes 非空必对应已加载 tag” 的前置矛盾，属防御性死分支。
3. `WTSHotMgr.cpp:337-341`（以及 :291-295）切换日之前 `cit--` 落在 `begin()` 上：
   std::map 迭代器下越界（UB），已登记 BUG-R56-001，正常用例不触发。
4. `WTSLogger.cpp:104-116` 的 `checkDirs` 无 '/' 分支：无目录的文件名只能落到运行目录，
   为保证“临时文件只写系统临时目录”未构造该输入；其余 logger 行已覆盖。
5. `WTSBaseDataMgr.cpp:65-68`（析构里第二次 release `_fullpid_map`）、`:83`（`_fullpid_map`
   判空）、`:102`（`_code_map` 命中但数组为空）：构造后成员恒非空且装载必 append，不可达。
6. `WTSBaseDataMgr.cpp:608/676-679/776`：`tDate/uDate` 传 0 的挂钟分支，按约束不驱动。
7. `WTSDataFactory.cpp:203-217`（时段外 tick 的 `at(size()-1)` 空指针路径）：
   公开入口 `updateKlineData` 先做 `isInTradingTime` 校验，protected 路径不可达；
   同类缺陷已在 P12 lane 登记（BUG-P12-001）。
8. `WTSDataFactory.cpp:259-261/470-472`（`uOnlyMin==0`）与 `:309/:514`（protected 入口的
   sInfo 判空）：公开入口已提前判空/时间映射不会返回 0，属防御性分支。
9. `WTSDataFactory.cpp:175-178/406-409`（`setClosed(true)`）：bar 时间戳恒 >= 原始分钟时间，
   该 else 在当前算法下不可达。
10. `WTSDataFactory.cpp:716-721`（秒线 unix 时间戳跨日）与 `:1338-1340`（tick 提取跨日）：
    需要 `secondsToTime` 回绕到小于 action HHMMSS 的形态；现有 session 模型下
    （收市 2400 或次日 0100）未构造出确定输入。
11. `WTSDataFactory.cpp:831/955`（extract 的 time=0 回退）与 `:871`（对齐时间早于原始时间）：
    需 `timeToMinutes(0)` 后再做 `-1/-5`，会产生无符号下溢，结果不可审核，故留白。
12. `CsvHelper.cpp` 在本轮后无已知未覆盖行；`get_*` 在未调用 next_row 时的空 vector 下标
    属缺陷（BUG-R56-003），已用 DISABLED 用例锁定，不纳入正常覆盖。
