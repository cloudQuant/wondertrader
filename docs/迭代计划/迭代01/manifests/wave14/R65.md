## 3. 关键修复说明

### 3.1 R59 的 `getUndoneQty` 语义

`updateUndone` 在 `buy()` 入口就按请求量累加，委托回报到达后 `onRspOrders`
会用 `_undone_qty.clear()` 重建（`TraderAdapter.cpp:1611-1712`）。因此
`buy()` 同步返回后读到的 10.0 是产品既定语义，不是限额失效。测试同时保留了
`api2_.vols_[0] == 3.0`，证明限额截断仍然生效。

### 3.2 R60/R61 的产品缺陷与 DISABLED 占位

- `BUG-R65-001`：开仓成功 `state_msg` 为空（平仓才写 `"下单成功"`）；
- `BUG-R65-002`：持仓查询末行合约未登记时提前 `return`，整批持仓不回调。

两者均按纪律保留精确断言 + `DISABLED_` + 缺陷登记，不把缺陷固化成正确行为。

### 3.3 R61 登录用例的 `char[]` 比较

`CThostFtdcQrySettlementInfoConfirmField::BrokerID` 等字段是 `char[N]`。
`EXPECT_EQ("9999", field)` 的一侧是 `const char*`、另一侧是 `char[N]`，
gtest 的 `const char*` 重载不匹配，退化为 `operator==` 指针比较，必然失败
（日志只打印两个地址）。改用 `EXPECT_STREQ` 后按内容比较，实际值确为
`"9999"`/`"tester"`；期望文本未变。
