## 3. 留白面及原因（不硬闯既有接缝）

1. **`WtRdmDtReader::init(cfg!=NULL)` L79-166**：会无条件起 5 秒轮询清理线程、析构 join；
   本 lane 纪律禁止。因此 `_base_dir` 经 Sandbox 相对路径驱动，`loadStkAdjFactorsFromFile`
   在 Rdm 侧未走通，`cacheAdjustedStkBars` 的因子回放循环（:1508-1555）留白
   （同一循环已由 `WtDataReader` 用例 9 覆盖）。
2. **WtRdmDtReader 的 RT 容量变化重映射**（tick/queue/order/trans/min1/min5，约 60 行）：
   需要在同一进程内先映射再原地改头部 capacity；R52 只在 `WtDataReader` 侧做了该面，
   Rdm 侧本轮仍留白。
3. **WtDataWriter `CMD_CLEAR_CACHE` 分支 L2240-2390（约 150 行）**：含 `sleep_for(300s)`
   重试面，任务令明确禁止触碰。
4. **WtDataWriter `check_loop` L1616-1696（约 70 行）**：10 秒节拍 + 600 秒过期判定，
   依赖墙钟且线程不可 join，不做。
5. **WtDataWriter `resizeRTBlock` 异常/重映射失败 L336-357**：需要可控的磁盘写失败或
   map 失败（R23 BUG-006 已登记代码事实），本轮未构造。
6. **`get*Block` 的 "Mapping file failed" L710-714 / L804-808 / L899-903 / L1002-1006**：
   `BoostMappingFile::map` 对目录/空文件是抛异常而不是返回 false，无法在公开 API 下稳定制造。
7. **`dump_bars_to_file` 的 create_or_open 失败 L2126-2129 / L2203-2206**：要制造该失败需让
   合法父目录下的目标路径不可打开；目录替身会在 `create_directories` 或 `read_file_content`
   先抛异常，不能保证只命中该 else。
8. **`proc_block_data` 的 L1849-1854 / WtDataReader L81-86**：`!bCmped && !bOldVer` 已在
   函数开头 return，这两段是死代码，无法覆盖。
9. **`WtDataReader::cacheIntegratedBars` 的 HOT 包裹文件分支 L1019-1041**：被 BUG-R52-001
   的变量遮蔽阻断（异常 → catch → false），不重复冲撞。
10. **`WtDataReader` 的 `cacheIntegratedBars` 异常 catch、exright==2 的 `readKlineSlice` RT 区间
    分支与 `readKlineSliceByCount` RT 缓存分支（:1844-1876 / :2316-2372）**：前者需抛异常的
    loader；后两者受 BUG-R52-002/003（首次 memcpy +1、尾定位越界）阻断，已有 DISABLED，
    不重复冲撞。
11. **WtDataReader `readKlineSlice` 的 `&_bars[size-hisCnt]` 空 vector 取址（R1 已登记）**：
    本轮未新增崩溃用例。
