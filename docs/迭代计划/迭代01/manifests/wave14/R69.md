## 3. 留白面及原因（不硬闯既有接缝）

1. **WtPorter C API 的「引擎已配置」分支**：`cta_get_bars/cta_get_ticks`、
   `cta_enter/exit_*/cta_set_position`、`*_sub_ticks`、`cta_get_price/day_price`、
   `config_porter/run_porter` 都要求 `getRunner()._engine` 已由 `config_porter` 建立。
   `R6PorterLifecycle.init_*` 在**同一二进制、后序执行**时断言单例 `getEngine()==nullptr`
   （`r6_porter_lifecycle_test.cpp:246`），而 `_engine` 一旦配置无公开复位入口，
   因此本 lane 不能改单例状态；这些行只能靠「每用例一进程 + 单独 config」取样。
2. **`release_porter` / `WtRtRunner::release`（L1141-1155，约 15 行）**：
   末行 `WTSLogger::stop()` 置静态 `m_bStopped` 并 `spdlog::shutdown()`，会让同进程
   后续用例日志永久静音；R6 已按 BUG-R6-006 裁定留白，本 lane 不重复冲撞。
3. **WtBtPorter C API 的 mocker 非空分支（约 300 行）**：`cta_*/sel_*/hft_*` 全部从
   进程单例 `getRunner()` 取 mocker。若 r69 在单例上 `init_cta_mocker/init_sel_mocker/
   init_hft_mocker`，链接顺序为 `q06 -> r46 -> r69 -> r9_*`，
   后序 `R9Wired.MockersAreNullAndAsyncFalseBeforeInit`（r9_exp_mocker_bridge_test.cpp:358-362）
   会因槽位非空而失败；mocker 槽位没有公开复位 API，无法在用例末尾还原。
   因此 K线/tick 切片、下单/撤单、userdata/log 的 mocker 命中支整体留白，需
   「每用例一进程」或给 runner 增加 reset 接缝后再取。
4. **`run_backtest` / `release_backtest`（WtBtPorter.cpp:213-235）**：
   前者要求 `config_backtest` 成功（真实 replayer/storage），后者同第 2 条的
   `WTSLogger::stop`；已按 DISABLED 占位。
5. **`WtRtRunner::initSelStrategies`（L745-789）**：函数是 private 且全仓库无调用点；
   `config()` 在 L708-711 只按 `_is_hft` 二选一，`_is_sel` 仅用于选引擎。
   SEL 策略初始化整段不可达（BUG-R69-002），无法用公开 API 触达。
6. **`WtRtRunner::run()`（L1091-1124）与 `on_ext_parser_quote` 命中支（L1247-1251）**：
   run 的同步等待循环需信号钩子；成功 parser 分支要求先 `createExtParser`（需已配置
   engine）并把 tick 投进 `ParserAdapter::handleQuote`，会级联进引擎/数据管理器，
   属进程级路径，留给集成 lane。
7. **`WtBtRunner::run/stop` 的 `_running==true` 分支（L509-583）**：
   需真实回放器 prepare/run + 线程 join；R9 BUG-R9-007 已登记 `_running` 只在异步
   lambda 内置位的问题，本 lane 不重复。
8. **ExpHftContext 的 `on_trade`（L236-242）与「已订阅 tick」支（L181-184）**：
   `on_trade` 的基类 `do_set_position` 会取 `_engine->get_commodity_info`，本 lane 的
   堆 runner 虽有 engine，但未装载商品信息；`on_tick` 订阅支前置 `stra_sub_ticks`
   会解引用 `_engine->get_hot_mgr()`（未 `init()` 的 HftEngine 上为 NULL）。
   两者都会把用例推向未初始化成员，留白。
9. **`WtRtRunner` basefiles 的 `rules` 多标签顺序、`hot` 回填结果**：受
   `WTSHotMgr::getHotTags` 静态缓存影响，跨用例的顺序会改变第二份 config 看到的
   标签集（BUG-R69-001）；本 lane 只断言配置返回值，不把「某 hotCode 已挂到合约」
   写成跨用例断言。

## 6. 评审注意（交主控裁决）

1. **单例顺序约束**：`CoverageTests_porter` 的对象顺序为 q06 → r13 → r35 → r46 → r69 → r6；
   `CoverageTests_btporter` 为 q06 → r46 → r69 → r9_exp → r9_mocker。
   本 lane 的 porter 配置用例一律用「堆上 new、永不 delete」的 runner；btporter 的
   C API 生命周期用例只动 `init_backtest/config_backtest/stop_backtest` 这三个不建
   mocker 的导出，保证后序 r6/r9 的「单例空引擎/空 mocker」断言仍成立。
2. **`init_backtest` 的 static 门**：该函数在目标进程内只生效一次。R46 用的是
   `WtBtRunner::init` 方法层，q06/r9 都没调用 C 导出，因此 r69 的
   `InitBacktestStampsDirsOnlyOnce` 是进程内首调；若主控未来把它挪到其它用例之后，
   需同步调整哨兵断言。
3. **临时目录**：均带 `getpid()`，用例内 `remove_all`；`WtHelper::getPortifolioDir()`
   的函数内 static 会缓存首次调用时的 generate 目录（R46 已把该路径指到 tmp），
   因此即使目录被清理，重启后也只在 tmp 下重建，不写仓库。
4. **本 lane 不新增 CMake 改动**：r69_*.cpp 由既有的 `dir:q06_porter` / `dir:q06_btporter`
   GLOB 自动纳入；文件已按任务要求先以 `.cpp.tmp` 通过门禁再改名。
