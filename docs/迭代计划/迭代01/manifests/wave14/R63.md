### 3.1 R66（wtcore，6 条）

R66 的 ticker 用例通过 `armThreadedMode()`（stop -> run -> stop）让 `_thrd` 非空，
再在主线程同步喂 tick。三个 ticker 的 `on_tick` 都有同一前置分支：

```
if (_cur_pos == 0) { _cur_pos = minutes; }   // 只记录分钟位，不调用 trigger_price
```

- `WtCore/WtCtaTicker.cpp:110-114`
- `WtCore/WtHftTicker.cpp:102-106`
- `WtCore/WtSelTicker.cpp:105-109`

因此**第一笔 tick 只建立分钟位，不会写入引擎价格，也不会 set_date_time**。R66 原用例在
第一笔 tick 后断言价格/时间，属于期望放置错误；另外三条小节末用例把 HHMMSSmmm 写成了
8 位。

| # | 根因 | 修法（测试侧） | 源码依据 | 判决 |
|---:|---|---|---|---|
| 1 | 第一笔 09:01 后断言 `get_cur_price`=3500/热合约=3500，但 `_cur_pos==0` 支不触发行情 | 把价格与热合约断言移到同一分钟第二笔（90130000）之后，断言 3501/3501；首笔只保留 `min_time==900` 与 `reader.count==0` | WtCtaTicker.cpp:110-114、160-169 | PASS |
| 2 | `actiontime` 用了 8 位 `14590000`/`15000000`，被解析成 145/150 分钟，落在 900-1500 之外；`timeToMinutes` 返回 `INVALID_UINT32` 后 `minutes++` 回绕为 0，`_cur_pos` 始终为 0 | 改为 9 位 HHMMSSmmm：`145900000` / `150000000` | WtCtaTicker.cpp:92-107；WTSSessionInfo.hpp:144-189 | PASS |
| 3 | 同 #2（HFT 版本） | 同上改为 9 位 | WtHftTicker.cpp:92-107 | PASS |
| 4 | 第一笔 09:01 后断言热合约价格 3500，但 `_cur_pos==0` 支不触发 `trigger_price` | 断言移到 09:03:50（分钟闭合）之后，断言热合约 3502；其余闭合/重放断言不变 | WtSelTicker.cpp:105-109、110-159 | PASS |
| 5 | 只有一笔 09:31 tick，仅建立 `_cur_pos`，从未走 `trigger_price` 的热合约循环，价格断言必为 0 | 增加同分钟第二笔 09:31:30（481），第二笔才触发行情；断言 au2212=481、au.HOT=0、`min_time==932` | WtSelTicker.cpp:92-109、148-153 | PASS |
