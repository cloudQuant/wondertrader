## 3. 关键修复说明

### 3.1 R52 的路径层数

产品拼装（`WtDataReader.cpp:1019-1026`）没有交易所子目录：

`{hisdir}{pname}/{exchg}.{product}_{ruleTag}{suf}.dsb`

因此日线 HOT 包裹文件应为 `his/day/SHFE.rb_HOT.dsb`。旧夹具写成
`his/day/SHFE/SHFE.rb_HOT.dsb` 时探测不到文件，走不到 L1035 的
`read_file_content`，也就不会触发 BUG-R52-001 的变量遮蔽。修正文件名后
LL_ERROR 与空切片都由真实异常路径产生，不是测试伪造。注意 `bugs/R52.md`
的「输入/前置条件」仍写着旧的多层路径，缺陷机制与代码行号不变，以本文为准。

### 3.2 R56HotMgr 的两个 false 语义

- 未登记 tag：`m_mapCustRules` 无该 tag 或 `curHotCodes` 为空 → 真 false；
- 已知 tag + 未知品种：代码走 `return "";`，bool 上下文为 true，是缺陷。
  精确断言保留在 `DISABLED_UnknownProductIsNotHot`，启用后稳定显示
  `Actual: true / Expected: false`（BUG-R64-001）。

### 3.3 R56Logger 的格式化入口

`WTSLogger::debug("dbg-%d", 1)` 不会格式化：`fmtutil::format_to` 使用 fmt 语法，
`%d` 是普通字符。落盘内容因此是 `dbg-%d`，与期望 `dbg-1` 不符。
把 13 处调用改为 `{}` 后，级别过滤（root=debug/info/warn/fatal）、分类双写、
handler 回调计数 22、动态 logger、二次 init 早退等断言全部保持原样。
lane_gate 的每用例独立进程模型也避免了 `m_bInited/m_bStopped` 静态标志
在同进程内跨用例污染（同进程连跑时第二个 logger 用例会因 `stop()` 后
`spdlog::get("root")` 为空而崩，这不是产品行为，gate 不会这样跑）。

### 3.4 R54ParserGuard 的夹具所有权

真实 `WTSBaseDataMgr::getContracts()` 用 `append(cInfo, true)`（`WTSBaseDataMgr.cpp:172`），
数组释放只减引用；夹具用 `false` 却仍被 `WTSArray` 无条件 release，等于把
fixture 的最后一个引用交出去。测试在 `initExt` 前补 `retain()` 是恢复生产
所有权语义，不是掩盖适配器的 `_stopped` 守卫断言。

### 3.5 R54StraMgr 的产品 ABI 缺陷

`UftStrategyMgr::loadFactories` 把 `deleteStrategyFact` 强转成
`FuncDeleteUftStraFact`（`UftStrategyMgr.cpp:76`），而该 typedef 带 `*&`。
`~StraFactInfo` 调 `_remover(_fact)`（`UftStrategyMgr.h:140-144`）时，插件拿到的
是 `_fact` 成员的地址而不是工厂地址，`delete` 内部指针必然崩溃。该问题与测试
是否持有 `UftStrategyPtr` 无关：最小探针只 load 工厂、不创建策略也 rc=139。
按纪律不修产品，活动用例用「不析构 manager」保住 load/create 覆盖率，崩溃
复现留在 DISABLED 用例并登记 BUG-R64-002。

### 3.6 R44 二次 initExt

`initExt`（`WtDtCore/ParserAdapter.cpp:46-52`）只做覆盖赋值。用例锁定
「api1 既不 release 也不 delete」的现状，并在末尾自行 `delete api1` 防止进程级
泄漏；api2 的 release/delete 由 `ParserAdapter::release()` 完成。`run()` 在
release 后仍会 UAF 的另一条缺陷继续留在 `DISABLED_RunAfterReleaseUsesFreedApi`
（BUG-R44-004），本轮未触碰。
