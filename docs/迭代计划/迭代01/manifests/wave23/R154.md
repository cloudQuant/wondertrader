## 1. 协作与运行约束

- UDP 只 bind `127.0.0.1` / `0.0.0.0` 的临时端口，客户端只向 `127.0.0.1` 发包；配置里的组播地址只用于 `addMRecver` 的 `join_group`，`do_broadcast` 从不向组播列表发送，无外网流量。
- Shm 用例把队列落在系统临时目录的普通文件（非 System V/POSIX shm 段、不跨进程），用例结束析构 unmap、fixture 删除目录。
- 状态机用例必须让产品线程跑 2~4 轮：`run()` 内部按墙上时钟做 1 秒节流，无法注入时钟；墙钟只作为等待上限，目标状态由会话模板保证与具体 HHMM 无关。单个用例约 2~4 秒。
- 所有起线程的用例用 `MonitorGuard` / `CasterGuard` 收尾，ASSERT 早退也能 `join`，避免 joinable `std::thread` 析构触发 terminate。
- 语法门禁: `CoverageTests_dtcore.sh` 对 3 个 `.cpp` 均为 0 error。

## 3. 未覆盖行及原因

### UDPCaster.cpp

- 114-117：`start()` 的 socket 构造 catch。要触发需 bind 已占用/特权端口；触发后紧接着的 `do_receive()` 会对 NULL `m_sktSubscribe` 解引用（BUG-R5-001），用例会崩溃，不启用。
- 150-154：`do_receive` 的 `ec` 分支。socket 关闭/取消只能由产品内部触发，公开 API 无接缝。
- 195-199、210-214：回包 `async_send_to` 的 `ec` 分支；回环发送成功，无错误注入点。
- 321-322：`castData._data == NULL` 的 break。四个公开 broadcast 都在 `do_broadcast` 入口拒绝 NULL，队列里不可能出现空对象。
- 360-363：未知 `dataType` 的 break。公开包装只传 0x200/0x201/0x202/0x203 四个常量。
- 371-376、383-388：单播/组播 `send_to` 的 `ec` 日志。回环接收方常驻，发送不失败；组播发送会出网，按约束不构造。
- 379-388：`m_listRawGroup` 的组播发送循环。需要 type=2 的合法组地址并向 239.x 发送，违反“不访问外网”，留白。
- 402-416：`handle_send_broad/handle_send_multi` 是 dead code（BUG-R5-004）。
- 其余零散分支：`init` 的 broadcast/multicast 项若不是对象（`getCString` 行为未定义）不构造；端口负数/超界语义已在 R5 记录。

### StateMonitor.cpp

- 340-345：`SS_RECEIVING -> SS_CLOSED`。需要当前 `offTime` 在两轮之间跨过 close；模板若把 close 设小，首轮就不会进 RECEIVING，无法与“先进 RECEIVING 再收盘”同时确定性成立。
- 347-369：`SS_RECEIVING` 的竞价分支与 `-> PAUSED`。需要 `offTime` 在同一会话的 1 秒轮次间从区间内跨到区间外；依赖分钟边界，非确定。
- 390-397、408-423：`SS_PAUSED` 的节假日判断与 `PAUSED->RECEIVING`。首轮进入 PAUSED 的模板要求区间不覆盖当前时间，次轮同一分钟仍在区间外；反之进入 RECEIVING 后无法在同一模板内离开区间。
- 437-449：`isSessionProceeded()==true` 直接转 SS_PROCED。`DataManager` 无 writer 时恒为 false；需要可注入 writer（BUG-R44-005 同族接缝）。
- 489-501、506-510：`SS_Holiday/PROCED` 的“节假日解除后重置”。首轮进入 Holiday 的两种前提（无品种 / 全品种节假日）在次轮仍成立，无法在同一用例内翻转；PROCED 重置已由 `CLOSEPROC` 覆盖。
- 周末：`isTradingDate` 硬编码 false，非节假日序列用例 `GTEST_SKIP`；节假日保持用例周末/工作日都成立。

### UDPCaster.h / StateMonitor.h

- 头文件内联函数在多个 TU 中由链接器择一发射，覆盖率按对象归并；`isInSections` 与三个查询已由用例执行，若报告仍显示未命中属于归并口径，不是未调用。
