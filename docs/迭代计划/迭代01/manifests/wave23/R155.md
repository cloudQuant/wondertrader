## 2. 修复内容

### 2.1 `src/TestUnits/coverage/q01_wtcore3/r140_engine_fee_test.cpp`

- 新增 `initEngine()`：用 `WTSCfgLoader::load_from_content` 构造最小 cfg
  （`product.session=TRADING`、空 `fees`/`filters`），`engine.init(cfg, &bd, NULL, &hot, NULL)`
  后 `cfg->release()`，再 `attach` 保留原固定日期。
- 两条用例把 `engine.attach(&bd, &hot, NULL)` 改为 `initEngine(engine, bd, hot)`。
- 原因：`WtCtaEngine::_cfg` 只在 `init` 中赋值，`~WtCtaEngine` 无条件 `if (_cfg) _cfg->release()`；
  r73::CtaEngine 由测试直接构造、从未 init，析构读到未初始化指针 → 用例在 `[ RUN ]`
  后 SIGSEGV，日志无断言输出。该缺陷已由 BUG-R35（`WtCtaEngine` 构造漏 `_cfg=NULL`）登记，
  本 lane 按「夹具问题修夹具」处理，不重复立案。
- 期望与断言未改动（6/4/2/0、0.33、14/7/3.5、未知品种 0）。

### 2.2 `src/TestUnits/coverage/p05_datastorage2/r142_reader_ad_residual_test.cpp`

- 三条用例的 `add_future(EXR/EXS/EXT, "rb", "rb2301")` 改为
  `add_future(..., "rb2301", "rb2301")`：`CodeHelper::extractStdCode("EXR.rb2301")`

  `DISABLED_R142ReaderADKlineIncrementalAppendAndRtMiss`：修夹具后该用例暴露
  产品缺陷 BUG-R155-001，断言与期望值（[933,934,935]）原样保留，按纪律禁用待修；

## 3. 产品缺陷 BUG-R155-001（详见 `bugs/R155.md`）

`WtDataReaderAD::readKlineSlice`（`src/WtDataStorageAD/WtDataReaderAD.cpp:430-438`）
用 **引用** 缓存 `lastBar`，`update_cache_from_lmdb` 追加新 bar 后第 437 行又对同一引用赋值。
环形缓冲已满回绕时，该引用指向逻辑首条；追加 934/935 后逻辑首条变为 933，赋值把
`_bars.back()`（935）写进该槽位，933 被覆盖。实测切片 `[935,934,935]`，契约应为
`[933,934,935]`。修复方向：`lastBar` 改为按值副本，或更新后直接读
`barsList._bars.back().time`，不要保留旧元素引用。
