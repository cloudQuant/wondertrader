### 运行安全设计

- 实盘侧 `WtRtRunner` 用「堆上 `new`、故意不 `delete`」的实例：构造函数未初始化
  `_config/_engine/_feed_obj/_feeder_*`，栈实例析构会释放引擎里的野 `_cfg`（BUG-R46-001）。
  绝不能 `config()` 单例：`r6_porter_lifecycle_test.cpp` 的启用用例断言单例
  `getEngine()==nullptr`，本 lane 不破坏它。
- 回测侧 `WtBtRunner` 同样用堆实例，且只走不读 `_hft_mocker/_exec_mocker/_worker/
  _cfg/_loader_auto_trans` 的入口（这些槽位同样未初始化）；`stop()` 早退走静态零初始化的单例。
- 文件只写 `std::filesystem::temp_directory_path()` 下的
  `wt_r46_porter_gen/`、`wt_r46_btporter_out/`，每条用例末尾 `remove_all`。
- 无网络、无柜台、无真实行情、无 sleep、无墙钟断言；用例之间不共享断言状态。

## 4. 未覆盖面及原因

| 未覆盖 | 原因 |
|---|---|
| `WtRtRunner::run`（L1091-1124）、`release`（L1141-1155） | `run` 同步模式在 `while(!_to_exit) sleep(10ms)` 上阻塞；`release` 调 `WTSLogger::stop()`，会把进程级 `m_bStopped` 置位并 `spdlog::shutdown()`，污染同二进制后续用例 |
| `WtRtRunner::initSelStrategies`（L745-789） | 全仓无调用点（config 在 sel 模式下仍调 `initCtaStrategies`），属死代码 |
| `initCtaStrategies` / `initHftStrategies` 的 active 项（L726-742 / L801-836） | 需要 `WtCtaStraFact`/`WtHftStraFact` 策略模块 DLL，本机无可用插件 |
| `initExecuters` 的 `routers`（L680-682）与 `_cta_engine.loadRouterRules` | 路由规则会按合约解析，空基础数据下无有效标的可断言，留待有 basefiles fixture 的 lane |
| `WtPorter.cpp` 的 `init_porter` / `config_porter` 转发（L239-249 等） | 二者写全局单例；r6 已覆盖 `init()` 本体，config 单例会打破 r6 的 `getEngine()==nullptr` 断言 |
| `ExpHftContext::on_channel_ready/on_channel_lost/on_trade` | 三者解引用 `_trader`；`createHftContext` 在本机必然拿不到已连接 trader，属已知崩溃路径（r13 已登记同类），不重复制造 |
| `WtBtRunner::run/stop(运行中)/release` | 起回放线程并 join；`release` 是全局 `WTSLogger::stop()` |
| `WtBtRunner::initHftMocker` | 构造列表未初始化 `_hft_mocker`，堆实例首调会 `delete` 野指针（BUG-R46-001）；单例首调会打破 r9 的 `hft_mocker()==nullptr` 断言 |
| `WtBtPorter.cpp` 其余 C 入口 | 已由 q06_btporter / r9 覆盖（守卫面、feed 面、userdata/log 落盘），本 lane 不重复 |
