## 4. 覆盖要点

- WtEngine 基类：构造、时间/交易日、init（fees/riskmon/无风控）、init_outputs、
  load_datas（fund/positions/details/riskmon）、save_datas（fund/positions/riskmon JSON）、
  on_tick（待触发信号、volume==0 早退、后台任务）、append_signal/do_set_position
  完整开/平/反手、calc_fee 模板缺失、get_kline_slice 四种周期、get_cur_price 三种复权、
  get_day_price 五个 flag、get_exright_factor 规则因子、sub_tick 两个分支、
  handle_push_quote（含热合约）、on_session_end 资金结算与 funds.csv。
- WtCtaEngine：init/Release、addContext/getContext、on_init（过滤器 + 风险缩放 + 执行器提交）、
  on_schedule 无线程池/线程池两分支、handle_pos_change、on_tick 原始/后复权订阅分发、
  on_bar 分发、session 事件、notify_* 空 notifier 守卫、IExecuterStub 访问器。
- 三个 ticker：init（有效/缺失 session）、on_tick 的同步触发分支、CTA 的
  time_to_mins/is_in_trading、stop 幂等。
- WtHftEngine：init、on_tick、on_session_begin/end。
- EventNotifier：active=false、模块缺失、成功加载后 8 个 notify 入口的 JSON 生成。

## 5. 未覆盖面与原因

1. `WtCtaEngine::run()` / `WtHftEngine::run()` / `WtSelEngine::run()`（WtCtaEngine.cpp:61-114、
   WtHftEngine.cpp:69-115 等）：marker.json 写入本身可测，但随后 `ticker->run()` 会起后台线程，
   盘外分支固定 `sleep_for(10s)`，`stop()` 的 join 会把用例拖成 10s 墙钟依赖，
   不符合“不依赖墙钟/长 sleep”约束，故整体不调用。
2. 三个 ticker 的 `run()` 线程体（WtCtaTicker.cpp:171-276、WtHftTicker.cpp:157-252、
   WtSelTicker.cpp:160-239）及 `on_tick` 中 `_thrd != NULL` 的分钟闭合分支：同上，
   只能由 run() 创建线程；不做短 sleep 猜测触发。
3. `WtEngine::init_riskmon` 加载成功分支（WtEngine.cpp:1165-1184）：需要真实的
   WtRiskMonFact 插件 + 风控实现，属外部模块；本 lane 只覆盖 active=false 与模块加载失败。
4. `WtEngine::get_exright_factor` 的股票分支（WtEngine.cpp:759-761）：替身只构造期货品种，
   股票除权因子需要数据模块 reader。
5. `WtHftEngine::handle_push_order_detail/order_queue/transaction`、WtSelEngine 的
   handle_pos_change/on_minute_end 等 Level2/调度入口：不在 api-brief-R1 的 missed 清单内，
   且需要构造 WTSOrdDtlData/WTSOrdQueData/WTSTransData 数据面，留给对应 lane。
6. `WtCtaEngine::isInTrading/transTimeToMin`（WtCtaEngine.cpp:673-681）：二者解引用
   `_tm_ticker`，而 `_tm_ticker` 只能由 `run()` 创建；未 run 时调用会空指针崩溃，故不调用。
7. `WtSelEngine` 自身的 init/release/on_tick 细节（不在 R41 文件清单内）：本 lane 只把它
   当作 WtSelTicker 的宿主。
8. EventNotifier 成功路径依赖构建目录里的 `libWtMsgQue`；找不到时用例 `GTEST_SKIP`，
   对应 JSON 行段在无库环境不计入覆盖。
9. `WtEngine::load_datas` 的解析失败分支（WtEngine.cpp:487-494）：没有同日再写坏 JSON 的
   独立用例（每文件用例数上限 10），可后续补。
10. 计时相关行（TimeUtils::getDateTime/getLocalTimeNow）无法从行覆盖上剥离，用例只断言
    写入-读回值，不断言墙钟。
