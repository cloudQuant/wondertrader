## 1. 复现与根因

### 1.1 dtcore · R154UdpCasterTest（3 条 CRASH）

复跑均为 `rc=139 (SIGSEGV)`，gtest 输出停在 `[ RUN ]`。在 `r154_udp_caster_start_test.cpp`
内临时加检查点后可见：`init`、`addMRecver`、`broadcast`、`guard.stop()` 全部返回，
最后一条检查点之后、`[ OK ]` 之前崩溃。即崩溃点在 `~UDPCaster`，不在用例断言面。

根因是既有产品缺陷：`UDPCaster.h:88-96` 的成员声明顺序使 `m_ioservice`（H96）先于
`m_sktBroadcast`/`m_sktSubscribe`/`m_list*Group`（H88-95）析构；active 装配只要建过
socket，socket 析构访问已销毁的 reactor 即 SIGSEGV。R164 lane 已用系统崩溃报告取证并
登记为 **BUG-R164-001**，本 lane 不重复主张。

修复方式（测试侧）：
- `r154_test_util.h` 新增 `r154::LeakyCaster`：堆上创建 `UDPCaster`，`stop_once()` 只
  停 io_context 并 join 产品线程，**不 delete**；`case_runner` 对每条用例起独立进程，
  进程退出即回收。
- 3 条 active 用例改用 `LeakyCaster`，**全部断言原样保留**（slice/数据报长度与类型、
  CastData 引用计数、回包文本、done/计数）。
- 新增 `R154UdpCasterTest.DISABLED_DestructorAfterActiveStartCrashes` 作为缺陷触发占位，
  注释交叉引用 BUG-R164-001；不为该缺陷新开编号。

### 1.2 btcore · R151ReplayerPaths.CsvLoadReportsEveryThousandBars（CRASH）

崩溃发生在 `HisDataReplayer::prepare()`：该用例没有 `register_sink`，
`prepare()` L669 无条件调用 `_listener->handle_init()`，`_listener` 为 NULL → SIGSEGV。
产品侧缺失判空是既有缺陷 **BUG-P04-002**；但本用例是夹具漏调用 `register_sink`
（R151 其余 4 条都在 `prepare()` 前注册了 `Sink`），属夹具问题。

修复：`prepare()` 前注册 `r151::Sink`，并新增 `EXPECT_EQ(1u, sink.init_calls)` 证明
`handle_init` 确实被回调（不是用空断言换绿）。

### 1.3 btcore · R151ReplayerPaths.DailySecondaryBarsCursorCatchesUp（FAIL）

失败点 `mainSlice == NULL`。原夹具把主K线写成 0106 起、回测起点 0102，此时
`get_kline_slice` 的初始游标定位走到 `curBar.date > _cur_tdate` 的“标的尚未上市”
兜底，`_cursor=0`，L2458 按契约返回 NULL。用例误把“主K线首根晚于当前交易日”当作
可返回非空 slice 的场景。

修复（不改任何断言）：
- 主K线增加 0102 一根仅用于定位的历史 bar，实际回放首日仍是 0106；
- 次K线改为 20191231 起（仍早于主K线 0102 的数据起点）；
- `prepare()` 后主/次 slice 均非空；主K线 0106 收盘时次K线游标由 0103 推进到 0106，
  继续命中 `simTicks` 的 L1372-1378 补齐分支；
- 末尾 `count_code(kRb)>=8`、`count_code(kCu)>=8`、`done_calls==1` 原样保留并通过。
