## 5. 留白面及原因

1. **EventNotifier 的 JSON/MQ 转发（约 119 行）**：只有 `_mq_sid != 0` 才进入 asio 任务；
   `init` 成功要真实 `dlopen WtMsgQue` + `create_server`，并起 2ms 轮询线程，属本轮禁止的
   真实 MQ/长线程接缝。`tradeToJson/orderToJson` 是 private，只能由该 lambda 调用。
2. **UftStraContext 数值 `watch_param`（705-727）**：`allocate_value` 返回 nullptr 被直接
   解引用（BUG-R11-002），启用即崩。`stra_get_*` 的 `sub_*` 真分支（944/954/963/972/982）
   需要 `WtUftEngine::get_tick_slice/get_kline_slice/get_*_slice` 返回非空，而
   `WtUftEngine.cpp:179-183/209-243` 首行 `return NULL`（BUG-R123-001），公开 API 无数据注入点。
3. **UftStraContext `load_local_data` 的 mannual.yaml 成功解析分支**：需要构造合法的 details
   段并让 `BoostMappingFile::map` 成功；R78/R85 已覆盖空文件、缺 details、未知合约 continue，
   本轮补了四个块文件 map 失败的 else。其余 yaml 字段组合未再重复。
4. **WtUftTicker 216-221（跨零点）/230-235（收市 on_session_end）**：实测
   `minuteToTime` 只有在 `_cur_pos` 越过 section 长度时才返回收盘时间，此时
   `isInTradingTime(thisMin,true)` 必为 false，工作线程进入 10s 休息分支，`stop()/析构`
   的 join 会阻塞 10s；本轮不引入不可接受的挂钟等待，保留为时间轴接缝。
5. **WtUftEngine 213-243 / 592-602**：`get_kline_slice` 首行 `return NULL`（BUG-R123-001），
   `_bar_sub_map` 无公开写入点，`on_bar` 的分发循环不可达。
6. **WtUftCore ParserAdapter 90-93 / 153-161**：构建产物里没有“导出 createParser 但返回
   NULL”或“init 返回 false”的插件；现有 ParserCTP/Femas/UDP/Shm/XTP 的 init 均返回 true，
   不伪造插件。
7. **WtUftCore TraderAdapter 1864-1965**：风险时间缓存写入语句在产品里被注释
   （BUG-Q04-004），`_order_time_cache/_cancel_time_cache` 恒为空；`getRiskParams` 缺 default
   时对 `end()` 取址（BUG-Q04-005），`riskPara` 恒非空，1864/1926 不可达。
8. **WtDtServo WtDataManager 64-85**：符号缺失/装载失败后仍执行 `_reader->init`，
   启用即空指针崩溃（BUG-Q05-001/R8-002 一族）。**145-156**：`get_session_info(sid,false)`
   是 private 且所有公开调用点传 true。**184**：需要 `extractKlineData` 对非空 tick 返回 NULL，
   不可构造。
9. **WtDtServo ParserAdapter 129-138 / 192-200**：同 6，无 createParser 返回 NULL 或
   init 返回 false 的插件。
10. **头文件 inline 行（WtUftCore、WtDtServo）**：均为公开内联访问器，由上述用例间接执行；
    不再单列。
