## 1. 打法与数据来源

本轮只补「C 导出函数拿到非空切片/信号/委托」后的公开分支。既有 lane 的缺口
不是守卫（`ctx == NULL` 早已覆盖），而是**数据链路没有打通**：实盘侧只配了
`data:{}`，`WtDtMgr` 没有数据读取器；回测侧没有注册外部数据加载器。

本轮统一走产品自带公开链路，不镜像类布局：

1. 实盘：`register_ext_data_loader` 注册 `FuncLoadFnlBars`；`config` 的
   `data.store` 指定本机构建产物 `libWtDataStorage`（module=`WtDataStorage`，
   测试把 `WtHelper::setInstDir` 指到 `bin/`）。`WtDataReader` 读不到文件时回调
   `IHisDataLoader::loadFinalHisBars`，loader 内再调用公开 C API `feed_raw_bars`
   把两根合成日线写回读取器。
2. 回测：`register_ext_data_loader` 注册 fnl/tick loader；`HisDataReplayer`
   的 `cacheFinalBarsFromLoader` / `cacheRawTicksFromLoader` 分别调用
   `loadFinalHisBars` / `loadRawHisTicks`，loader 内调用 `feed_raw_bars` /
   `feed_raw_ticks`。
3. 合约代码统一用三段式 `SHFE.rb.2510`。既有 R113/R124 的 `SHFE.rb2510`
   会被 `CodeHelper` 解析成 product=`rb2510`，`getCommodity` 必然失败，
   信号/委托表因此一直为空（见 `bugs/R134.md` BUG-R134-003 的复现记录）。

## 5. 夹具与确定性说明

- 实盘侧在 `bin/TestUnits` 运行，`WtHelper::setInstDir` 取 `getInstDir()` 的父目录
  （`bin/`），`libWtDataStorage.dylib` 由此按产品默认命名加载；若测试二进制被移到
  其他目录，该路径需同步调整。
- 回测侧 `mode=none`，不创建存储引擎；`prepare()` 只做 reset/日期初始化/handle_init，
  不进入 `run()`。
- 合成 K 线两根（20240102/20240103，close 4505/4520）；合成 tick 两根
  （action_time 93000000/93001000，price 4501/4502）。日期固定，不读挂钟。
- 每个用例 `~WtRunner + placement new` 重置进程单例，loader/回调在 TearDown 清空；
  不依赖执行顺序，无跨用例共享可变状态。
