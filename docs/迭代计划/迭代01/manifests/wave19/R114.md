## 3. 注入方式（不碰生产代码）

### 3.1 CTPOptLoader：纯虚接口 stub 直接赋给全局 `pUserApi`

`r114_ctpopt_api_stub.h` 用 `R114TraderApi : public ctp_sopt::CThostFtdcTraderApi`
逐条实现 93 个纯虚函数（这是实现抽象接口，不是布局镜像），只记录
`ReqAuthenticate/ReqUserLogin/ReqQryInstrument/GetTradingDay/RegisterSpi/RegisterFront/
Subscribe*Topic/Init/Join/Release` 的调用与入参，其余返回 0。用例把 `new R114TraderApi()`
赋给生产 TU 的全局 `pUserApi`，即可在不 dlopen 厂商库的前提下驱动：

- `TraderSpi.cpp:111-178`：OnFrontConnected → ReqAuth → OnRspAuthenticate →
  ReqUserLogin → OnRspUserLogin 成功 → LoadFromJson → ReqQryInstrument；
- `TraderSpi.cpp:397-485`：增量缓存正/负路径；
- `TraderSpi.cpp:390-394、488-600`：最后一包 DumpToJson + `exit(0)`，用 gtest
  死亡测试关在子进程里执行，父进程继续断言两个 JSON 文件。

**没有进入** `CTPOptLoader.cpp:203-267`：`run()` 在必填项齐全后必然
`load_library` 厂商期权库，失败时 `g_ctpCreator` 为 NULL 仍被调用（BUG-T4-014）。
本机 `CTPOptLoader` 覆盖率目标未开 `-export_dynamic`，无法把测试可执行文件自身
当作可导出 stub 的 module；因此启用用例一律在 `:198-201` 必填项校验处返回。

### 3.2 TraderDumper：用构建目录里已有的真实交易模块

`TraderAdapter::_trader_api` 是私有字段且无 setter；但 `init()` 会按配置 dlopen 模块。
测试复用构建产物 `libTraderMocker.dylib` / `libTraderCTP.dylib`：

- **Mocker**：`init` 只建 `mocker_<id>/` 目录；用例从不 `connect()/login()`，
  因此不起撮合线程。`queryAccount/queryPositions/queryTrades/queryOrders` 只向
  未 run 的 `io_context` post，lambda 永不执行；`onLoginResult` 直接注入交易日。
- **CTP**：`init` 在 macOS 仅保存 creator 地址；`m_pUserAPI` 保持 NULL。
  `handleEvent(WTE_Connect,0)` 的 `login()` 在 `:415-421` 早退，不建线程；
  `release()` 只清空空数组。用于覆盖 `release` 的非空 `_trader_api` 分支。
- 模块目录由 `getBinDir() + "../WtPorter|WtRunner|WtUftRunner/traders/"` 探测；
  找不到时 `GTEST_SKIP`，不会回退到真实柜台。
- 不调用 mocker 的 `release()`：`TraderMocker::registerSpi(NULL)` 缺少判空
  （见 bugs/R114.md BUG-R114-001），`TraderAdapter::release()` 会传 NULL。
- 所有落盘只发生在 `mkdtemp("/tmp/r114_dumper_XXXXXX")`，TearDown 递归删除。

## 6. 未覆盖面与原因（诚实口径）

1. **`CTPOptLoader.cpp:203-267`**：越过必填项守卫后立刻 `DLLHelper::load_library`
   `soptthosttraderapi_se`（本机只有 Windows/Linux 库），随后 `get_symbol` 为 NULL
   仍调用 `g_ctpCreator(...)`（BUG-T4-014）。2026-10-28 当前 CTPOptLoader 覆盖率目标
   链接行未带 `-export_dynamic`，无法用「测试可执行文件自身作为 module + 强符号
   CreateFtdcTraderApi」绕过；`mapfiles` 解析（`:205-235`）也在这段之后，故一并未进。
2. **`TraderSpi.cpp:331-333`**：`pname` 在 `:294-295` 已按需转 UTF8，`:331-333`
   对同一变量再判一次，非 UTF8 与 UTF8 两侧都不可能让 `:333` 执行；属死代码。
3. **`TraderAdapter.cpp:116-125` `run()`**：现有 Mocker/CTP/Femas/XTP/YD 的
   `connect()` 全部会起线程或解引用空 creator；lane 约束禁止长线程/挂钟，故只覆盖
   `_trader_api==NULL` 的失败返回。`WTE_Connect` 成功事件改走 CTP 的 `login()`
   空 API 早退，已覆盖 `:141-143`。
4. **`Dumper::run(false)` 的 refresh 命中体**：本用例用空 `g_adapterMgr` 验证启停与
   join；若放入 done 适配器会让 worker 线程与用例线程竞争同一全局表，确定性变差，
   故 refresh 的命中语义放在单线程的 `TraderAdapterMgr::refresh` 用例中验证。
5. **gtest 死亡测试子进程**：`DumpToJson` 的 `exit(0)` 只能在子进程里执行；父进程
   断言文件内容与退出码。若产品将来去掉 `exit(0)`，`EXPECT_EXIT` 会失败——这是
   对 BUG-T4-015 现状的显式钉住，不是放宽。
