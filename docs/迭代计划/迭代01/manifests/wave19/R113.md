## 1. 范围与思路

R46/R69 已打通 runner 的配置/生命周期，R82 补了 WtPorter 的 C API 真实上下文与
WtRtRunner 的失败臂，R83 补了 WtBtPorter 的 mocker 非空面，R60/R103 补了
TraderMocker 的 connect/查询/报单/撤单/UDP 包。本轮只补它们**仍未触达且能从公开
API 进入**的行段：

- WtRtRunner：`basefiles.rules` 回填主力的 `!isHot -> continue`；
  `initCtaStrategies` 的 active 项（需要真实 CTA 策略工厂）。
- WtPorter：`config_porter("")` 回落到 `config.json`。
- WtBtPorter：`release_backtest` 的两级转发；`cta_get_all_position` 的非空信号枚举；
  `hft_buy/hft_sell/hft_cancel_all` 的非空 OrderIDs 拼串；`sel_get_last_entertag`
  的空 mocker 支。
- TraderMocker：`login()` 启动的公开撮合线程 + 本机 UDP tick，覆盖 `match_once`
  的报价/拆量/成交/持仓/状态主链，以及部分成交后的撤单状态消息。

只走公开 API；不使用 `#define private public`、不镜像类布局、不改宏。TraderMocker
的 `match_once` 仍是私有函数，但本轮通过公开 `login()` + 回环 UDP 驱动它，
没有直接调用私有成员。

## 3. 留白面及原因

1. **WtPorter/WtBtPorter 的非空 K线/tick/ordque/orddtl/trans 切片**
   （`WtPorter.cpp:510-531、553-567、1304-1321、1363-1380、1807-1824、1848-1865、
   1890-1904、1929-1943、1968-1982`；`WtBtPorter.cpp:440-457、478-496、1166-1183、
   1222-1239、1589-1606、1627-1644、1665-1679、1700-1714、1735-1749`）：
   需要 `WtDataStorage` reader + 真实 bar/tick/Level2 fixture；本 lane 不重建数据层，
   只取 mocker 为空的 NULL 支（既有 lane 已覆盖）。
2. **WtRtRunner/WtPorter 的 `run()` 同步等待与异步 ticker**
   （`WtRtRunner.cpp:1091-1124`、`WtPorter.cpp:277-279`）：同步模式死等退出标记，
   异步模式启动引擎 ticker 线程；按 lane 约束不进入。
3. **WtBtRunner `run/stop(运行中)`**（`WtBtRunner.cpp:509-583`）：需已配置
   replayer/storage 并起回放线程；`_running` 的置位时序另有 BUG-R9-007。
4. **`WtBtRunner::config` 的 `_inited` 守门**（`WtBtRunner.cpp:451-455`）：
   `_inited` 全仓无置 true 点（BUG-R9-001），该分支不可达。
5. **`WtRtRunner::initSelStrategies`**（`WtRtRunner.cpp:745-789`）：private 且全仓无调用点
   （BUG-R69-002），公开 API 不可达。
6. **`WtRtRunner::initHftStrategies` 的 active 项**（`WtRtRunner.cpp:816-833`）：
   需要 `libWtHftStraFact.dylib`；当前 coverage 构建只把它编进
   `CoverageTests_selfthft`，没有可加载的 HFT 工厂 dylib。CTA 侧已用
   `libWtCtaStraFact.dylib` 打通同类分支。
7. **`initExecuters` 的 `init()` 失败 return**（`WtRtRunner.cpp:958/985/1012/1039`）：
   四类执行器的 `init` 只在 `params == NULL` 时 false，而 config 数组项恒非 NULL，
   属不可达分支。
8. **WtBtPorter 的 `cta_step/hft_step` 异步支**（`WtBtPorter.cpp:899-904、1996-2001`）：
   需要 `isAsync()==true`，即先 `run_backtest(true)`；按约束不进入。
9. **TraderMocker `disconnect()`**（`TraderMocker.cpp:705-716`）：
   `disconnect` 后 `release()` 早退导致 io worker 未 join（BUG-R60-001），
   本 lane 的撮合用例统一走 `release()`，不碰该崩溃序列。
10. **TraderMocker `handle_read` 的 socket error/reconn**（`:937-948`、`:666-687`）：
    需要真实 socket 故障注入或第二次 `reconn_udp`；`_b_socket` 为私有，公开 API 不触达。
11. **TraderMocker `orderAction` 在首次成功下单前**（`:750-772`）：
    `_awaits == NULL` 直接解引用（BUG-R60-002），本 lane 先下单再撤单。
12. **`splitVolume` 的 `curVol == 0` 分支**（`:72`）：`init` 把 0 的 minqty 改成 1，
    公开配置无法稳定制造 0 步长；且该函数每次 `srand(time(NULL))`（BUG-R113-002）。

## 6. 评审注意

1. **TraderMocker 首次真正驱动 `match_once`**：公开 `login()` 会起一个 5ms 轮询的
   本地撮合线程；TearDown 的 `release()` 设置 `_terminated` 并 join，未启用
   `disconnect()`（BUG-R60-001）。UDP 只发 127.0.0.1 临时端口，等待上限 3s。
2. **拆量随机性**：`splitVolume` 每次 `srand(time(NULL))`，本 lane 的断言只校验
   总成交量/持仓/状态，不校验成交笔数与单笔数量（缺陷见 BUG-R113-002）。
3. **BUG-T6-001 被实际执行但未断言**：撮合路径会执行
   `setVolTraded(getVolTraded() - curVol)`，`Sink` 记录了该字段但测试不把它写成期望。
4. **fork 子进程**：`config_porter("")`、`release_backtest`、WtBt mocker 用例都在
   fork 子进程执行并用 `exit()` 落 profraw；父进程不触碰单例/全局 logger。
5. **单例顺序**：WtBt null-mocker 用例用公开析构 + placement new 复位单例（同 R83），
   放在 r46/r69/r83 之前（文件排序 q06 < r113 < r46 < r69 < r83 < r9），不破坏
   后序「mocker 为空」断言。
6. **CTA 工厂依赖**：`R113PorterCtaFactory` 需要构建目录里的
   `libWtCtaStraFact.dylib`；缺失时 `GTEST_SKIP` 并打印路径，不把「缺构建产物」
   伪装成产品失败。
