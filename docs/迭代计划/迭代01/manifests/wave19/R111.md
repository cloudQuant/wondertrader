## 1. 为什么本轮能补上「策略/执行器非空」整族

R92 的留白口径是「不加载真实策略 DLL」，因此 `_strategy/_exec_unit` 非空分支
（Cta 968/1023-1040/1237/1266、Uft 154-166/225/296-390/804-825、Exec 71-85/140-192/285-347）
一直不可达。本 lane 改变的是测试夹具而非产品契约：

- 插件路径由测试可执行文件位置推出（`<bin>/lib*.dylib`、`<bin>/WtUftRunner/...`），
  已确认三份构建产物与 `create*Fact` 导出符号存在；
- 只调用插件公开工厂接口，策略/执行单元均为产品自带 Demo（DualThrust / SimpleUft /
  WtMinImpactExeUnit），参数取最小合法集；
- Exec 测试把 `volunit` 置 0 且喂真实 tick，使 `WtMinImpactExeUnit::do_calc` 在
  「目标==持仓」处返回，避免未注册合约的 `_comm_info` 解引用；
- Cta/Uft 测试的 `on_bar/on_tick/on_schedule` 都走策略基类空实现或数据缺失早退，
  不产生真实委托。

## 6. 留白面及原因

1. Hft/Sel 的 `init_*_factory` 成功路径：本机构建只产出 CTA/UFT 策略工厂；
   `HftStraFact/SelStraFact` 在本机没有 dylib，无法在不改 CMake 的前提下创建真实策略。
2. `step_tick/step_calc` 与 `_cond_calc.wait()`（Cta 687/1060-1200、Hft 329-343/362-429）：
   线程/墙钟接缝，本轮按约束不进入。
3. `HftMocker::_ticks` 缓存分支（888-893）：`_ticks` 只 create/release，从不写入，
   公开路径不可达（与 R92 结论一致）。
4. Cta `add_chart_mark/set_index_value`（2157-2160、2208-2227）：仅在
   `_is_in_schedule=true`（策略 `on_schedule` 内部）可调用，DualThrust 不调用这两接口。
5. Sel `_desprice!=0`（368-369）与 Cta `do_set_position` 的 volume==qty/comm==NULL
   （1614/1618）：公开信号入口在生成信号前已做同值/品种校验，不可构造。
6. HisDataReplayer 的夜盘 offset（1174-1187）、24h session、任务日历换日等：
   R103 已按「避免时间轴回绕」留白，本轮不重复。
7. `proc_block_data` 的畸形/老版本块头（69-72/80-85/127-135）：R72 已覆盖老版本主路径，
   本轮不重复构造畸形块。
