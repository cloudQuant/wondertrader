## 3. 注入方式（不碰生产代码）

- `ParserCTP`：`init()` 在 `__APPLE__` 分支取 `CThostFtdcMdApi::CreateFtdcMdApi`
  的函数地址（ParserCTP.cpp:119-120）。测试 TU 在 `r105_ctp_api_stub.h` 里给出同名强定义，
  `init()` 因此拿到 stub。厂商静态归档中该符号位于 `ThostFtdcMdApiImpl.o`，而
  `ParserCTP.cpp.o` 对厂商库只有这一个未定义引用（`nm -u` 实测），所以归档成员不会被抽取，
  不会重复定义；stub 的 `Release/Init/RegisterSpi/SubscribeMarketData/ReqUserLogin`
  都只记计数，不触网。
- `ParserCTPMini/Femas/CTPOpt`：`init()` 在 macOS 走 `DLLHelper::load_library` + `dlsym`
  （本机无对应厂商 dylib），末尾会空函数指针调用，不能启用。测试 TU 用
  `#define private public`（仅本 TU，包含顺序已把全部依赖头预包含）把 `m_pUserAPI`
  指向各自 stub，再通过公开的 `connect/registerSpi/subscribe` 与
  `OnFrontConnected/OnRspUserLogin/OnRtnDepthMarketData` 驱动。
- `ParserCTPMini/Femas/CTPOpt` 的 `init` 配置/目录分支用**异常路径**覆盖：把
  `flowdir` 指到一个“父路径是普通文件”的系统临时目录，
  `std::filesystem::create_directories` 抛 `filesystem_error`，在触碰
  `m_funcCreator` 之前退出；临时目录在 fixture 析构时递归清理。CTP 则直接用
  stub 工厂走完 init 的正常返回路径。

## 6. 未覆盖面及原因

1. **`init` 的厂商符号/creator 尾段**
   - Mini `126-135`、Femas `118,126-134`、Opt `127-134`：本机没有 darwin 版
     `thostmduserapi` / `USTPmduserapiAF` / `soptthostmduserapi_se`；
     `get_symbol` 返回 NULL 后产品仍直接调用 `m_funcCreator`（BUG-T4-009 / T3-001），
     启用即 SIGSEGV。配置/目录/load_library 前半段已由异常路径覆盖。
   - CTP 无此缺口：`__APPLE__` 分支的静态 creator 被测试 TU 的同名定义接管。
2. **错误应答的 else 分支不可达**
   - 四个文件的 `IsErrorRspInfo` 都恒返回 `false`（CTP 426-429、Mini 410-413、
     Femas 405-408、Opt 402-405），因此 `OnRspSubMarketData` 的 else
     （CTP 356-359、Mini 340-343、Femas 336-338、Opt 332-335）和
     `OnRspUserLogin` 的“错误应答”路径永远不执行；属产品逻辑缺口，见 R105 bugs。
3. **夜盘零小时分支**
   - 外层条件要求 `actHour >= 20`，内层 `else if (actHour == 0 && curHour == 23)`
     （CTP 271-274、Mini 252-256、Femas 248-252）中 `actHour==0` 与 `actHour>=20`
     矛盾，赋值行是死代码；`actHour==23 && curHour==0` 的赋值行只有午夜运行才会命中。
4. **03:00-09:00 运行窗口**
   - 若主控在该窗口运行夜盘用例，产品按设计整笔丢弃，夜盘分支的 240-256 区间会少覆盖
     约 8 行；这是 BUG-T4-012 的挂钟依赖，不是用例不确定性。
5. **构造函数未初始化 `m_sink/m_pBaseDataMgr/m_funcCreator/m_hInst`**
   - 在 `registerSpi` 之前触发任何回调都是野指针（BUG-T4-008 等同源），
     本轮所有启用用例都先 `registerSpi` 或用 `nullptr` 显式置空，不改产品代码。
6. **`write_log` 的 `sink==NULL` 早退（四文件第 32 行）**
   - Mini/Femas/CTPOpt 的所有调用点外层都有 `if(m_sink)`，该早退分支不可达；
     CTP 的 `OnRspUserLogin`（ParserCTP.cpp:196）没有外层守卫，已由
     `R105CtpTest.null_sink_and_null_api_guards_are_silent` 覆盖。
