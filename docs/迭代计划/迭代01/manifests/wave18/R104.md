## 一、为什么能进「成功路径」

R14 / R28 把两个入口的可启用面都停在「缺文件早退」，原因是其后会起线程或进死循环。
本轮找到两个可自行终止的成功路径：

### 1. `QuoteFactory::initialize()`：`allday: true` 把状态机整段关掉

`initialize()`（`main.cpp:96~262`）的控制流是：
`load_from_file` → basefiles 五类数据 → `shmcaster`/`broadcaster`（可省略）→
`allday` 判断 → `initDataMgr(writer)` → `index` → `parsers` → `g_parsers.run()` →
`if(!bAlldayMode)` 才 `sleep(5ms)` + `g_stateMon.run()`。

配置里写 `allday: true` 时 `:257` 的 `if` 取假侧，`:259/:260` 的状态机线程不会启动；
`shmcaster`/`broadcaster` 两段不写，也就没有共享内存与 UDP 端口。此时整条 `initialize()`
在一份纯 YAML + 七个 JSON 夹具上**正常返回**，`:108~:257` 的主干全部可取样。

`writer` 段必须给（`:199` 把 `config->get("writer")` 直接交给 `DataManager::init`，
后者第一句就是 `params->getCString("module")`，缺段即空指针，见 BUG-R104-001），
本轮写法是 `writer: { module: R104NoSuchWriterModule }`：
`DataManager.cpp:79-95` 的 `load_library` 失败后原地 `return false`，不落任何存储目录。

`parsers` 段同理：`module` 取一个不可能存在的插件名，`ParserAdapter.cpp:110-121` 在
`load_library` 失败后 `return false`，不会起接收线程；适配器对象仍会被登记，
`:254 g_parsers.run()` 对它调 `run()` 时因 `_parser_api == NULL` 直接返回 `false`。

### 2. `WtRunner::Config()`：三个子初始化器的 active 体不需要真实插件

`initParsers` / `initTraders` / `initExecuters` 的 active 体此前整段未覆盖（`:440~455`、
`:563~571`、`:476~544`）。逐段核对过：插件模块加载失败时三条链都在 dlopen 处原地返回：

| 调用点 | 失败位置 | 行为 |
| --- | --- | --- |
| `initParsers():451` | `WtCore/ParserAdapter.cpp:105~121` | `load_library` 为 NULL → log → `return false`，无接收线程 |
| `initTraders():566` | `WtCore/TraderAdapter.cpp:163~178` | 同上，无连接线程 |
| `initExecuters():483/511` | `WtCore/WtLocalExecuter.cpp:75~157`、`WtDiffExecuter.cpp:84~122` | 只读 scale/clear/groups（`poolsize:0` 不建线程池）；diff 只从 `execdata/` 读一份不存在的 json |
| `initExecuters():538` | `WtCore/WtDistExecuter.cpp:47~57` | 只读 `scale` |

所以一份 `env.name=cta` + 三种执行器（local/diff/dist）的 `executers` 配置可以在 `:276`
返回 `true`，全程不连柜台、不起线程。`_cta_engine.run()`（`:585`）没有调用，因此不会碰到
`WtCtaRtTicker` 的定时器线程。

## 五、执行注意

- 两个目标都必须**串行**（`-P 1`）：`WtRunner` 的用例会往共享 cwd 写 `r104wt_*.yaml`
  夹具、往 `Logs/` 写日志、往 `portfolio/` 写 `trades.csv`；`QuoteFactory` 的 fork 子进程
  会在同一 cwd 读 `r104qf_*` 夹具。与 r6/r28 的夹具前缀不重名。
- `QuoteFactory` 子进程的计数依赖显式 `__llvm_profile_write_file()`；若后续维护时把
  `_exit(0)` 改成 `return`/`exit()`，会变成「父进程计数被覆盖」，`main.cpp` 的覆盖会凭空回落。
- 没有任何用例修改 `WTSLogger` 的全局级别去断言日志文本：本轮只断言**控制流返回**
  与**落盘文件**（`module_dir`、`portfolio/trades.csv`），避免日志格式变化把用例变脆。
