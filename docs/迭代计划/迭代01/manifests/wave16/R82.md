## 3. 留白面及原因

1. **K线/tick/委托队列切片的非空分支**（`WtPorter.cpp:511-521、553-558、
   1303-1312、1362-1371、1806-1815、1846-1856、1888-1895、1927-1934、1966-1973`，约 70 行）：
   非空 slice 需要 `WtDataStorage` reader + 真实数据 fixture；`data` 段为空时
   `WtDtMgr::_reader == NULL`，所有 `get_*_slice` 在首行返回 NULL。本轮只取 NULL 支，
   非空支留给数据存储 lane 的 fixture。
2. **`cta_get_all_position` / `sel_get_all_position` 的逐项回调**
   （`WtPorter.cpp:683-684、1259-1260`）：需要 `_pos_map` 非空，而 C API 只能
   `append_signal`（写 `_sig_map`），没有任何公开入口注入持仓。
3. **`initCtaStrategies` 的 active 策略创建**（`WtRtRunner.cpp:726-740`）与
   **`initHftStrategies` 的上下文创建**（`816-832`）：需要先 `loadFactories` 成功；
   CTA 分支还不检查 `createStrategy` 返回空（BUG-R82-002），在无工厂时会直接崩溃，
   HFT 分支虽检查 null 但需要 HFT 工厂 dylib。为避免测试依赖构建目录里的可选产物，
   本轮不加载策略工厂。
4. **`initSelStrategies`（`745-789`）**：private 且全仓库无调用点、读取的是
   `strategies.cta`，属不可达代码（BUG-R69-002），公开 API 无法触达。
5. **`run()`（`1091-1124`）**：同步模式会 `install_signal_hooks` 后死等退出标记，
   异步模式会启动各引擎的 ticker 线程；任务约束禁止启动完整实盘线程，整段留白。
   `release()` 已在用例 9 覆盖（不调用 run 时引擎的 `_tm_ticker` 为空，安全）。
6. **`config_porter("" , true)` 的空串回落支**（`WtPorter.cpp:262-263`）：
   需要把进程 CWD 切到含 `config.json` 的临时目录再切回；为避免进程级 CWD 副作用，
   只覆盖 `isFile=false` 的正常转发支。
7. **`initExecuters` 的 init 失败 return**（`WtRtRunner.cpp:958/985/1012/1039`）：
   四个执行器的 `init(cfgItem)` 只会在 `params == NULL` 时 false，而 config 数组项
   永远非 NULL，属不可达分支。

## 6. 评审注意

1. **单例顺序**：`CoverageTests_porter` 的对象顺序为 q06 → r13 → r35 → r46 → r69 →
   r6 → r82。r82 是最后一个，且用例 9（`release_porter` -> `WTSLogger::stop`）固定
   写在文件末尾；若主控未来调整文件排序，需要把 r82 保持在 r6 之后。
2. **兄弟引擎初始化**：`WtRtRunner::config` 只 init 当前 env 对应的引擎；
   `create_sel_context/create_hft_context` 却直接使用各自引擎。r82 在 SEL/HFT 用例
   前分别以 `env=sel/hft` 重新 config 一次，规避了 BUG-R82-001 的未初始化指针。
3. **HFT buy/sell 用 qty=0**：`TraderAdapter::buy/sell` 在写 `_stat_map` 之前返回，
   因此只覆盖 WtPorter 包装层，不触碰未 init 的 `TraderAdapter::_stat_map`。
4. **不加载策略工厂**：避免依赖构建目录里的 `libWtCtaStraFact.dylib` 等可选产物。
5. **临时目录**：均带 `getpid()`；用例内清理，即使 `WtHelper` 的函数内 static
   目录缓存保留旧路径，下次调用也只在系统临时目录下重建。
