## 3. 关键做法（ticker 的 run/线程路径）

三个 ticker 的 `on_tick` 只有 `_thrd != NULL` 才会进入分钟切片。`_thrd` 仅由 `run()`
创建，直接调用会进入 `sleep_for(10s)`。本 lane 用“先 stop 再 run”：

1. `ticker.stop()`：`_stopped = true`，此时 `_thrd` 为空；
2. `ticker.run()`：完成 engine 的 `on_init/on_session_begin`、创建 ticker 线程，
   线程首轮读 `while(!_stopped)` 立即退出；
3. `ticker.stop()`：`join()` 立即返回，`_thrd` 保持非空；
4. `ticker.init(&reader, "TRADING")`：补上 store 与 session，随后在主线程同步喂 tick。

全程不等待 10s/10ms 睡眠，不依赖墙钟断言；run() 内的 marker/初始化也一并执行。

## 5. 未覆盖面及原因

1. **三个 ticker 的 `run()` 线程体**（WtCtaTicker.cpp:190-276、WtHftTicker.cpp:173-252、
   WtSelTicker.cpp:176-239）：首轮即退出，只覆盖线程创建/退出；循环内的 10s/10ms
   睡眠、`_next_check_time` 自动闭合、跨日 `getNextDate` 需要真实时间推进，按纪律不做
   墙钟等待，留白。
2. **CTA ticker 的 `bEndingTDate` 支**（WtCtaTicker.cpp:129-142 的 session_end）：
   `offMin == getCloseTime(true)` 要求收盘后还有可交易分钟位，正常单日 session 中
   `minutes` 不会超过收盘位置；构造多小节会改变 `getCloseTime`，属不可达/需专用 session
   配置，留白。
3. **WtEngine/Wt*Engine 的 `run()`**（WtCtaEngine.cpp:61-114、WtHftEngine.cpp:67-114、
   WtSelEngine.cpp:339-380）：内部 `new` ticker 后立即 `ticker->run()`，无法像单测那样
   预置 `_stopped`；线程盘外分支固定 10s 睡眠，`release()` 的 join 会把用例拖成墙钟依赖。
   引擎 `run()` 的 marker.json 写入路径留给主控的进程级/集成用例。
4. **EventNotifier 私有函数 `tradeToJson/orderToJson` 的 NULL 入参支**
   （EventNotifier.cpp:234-238, 269-273）：公开 `notify` 在入队前已拦截 NULL，无法经
   公开 API 到达；不为打点加 `#define private public` 一类旁路。
5. **EventNotifier `init` 的 creator==NULL 支**（79-84）：需要“能 dlopen 但不导出
   create_server”的伪库；本 lane 不生成二进制替身，留白。
6. **EventNotifier `on_mq_log`**（32-35）：只有当 WtMsgQue 内部触发日志回调时才会被调用，
   测试无法确定性驱动。
7. **WtSelEngine::on_minute_end 的“真正触发任务”支**（WtSelEngine.cpp:329-335）：
   局部 `StdThread` 析构会 `std::terminate`（既有 DISABLED 用例已记录），本 lane 不重复
   触发；只覆盖不触发/跳过路径（r10 已覆盖大部分）。
8. **WtCtaEngine/WtHftEngine 的完整上下文交易路径**：R41 已覆盖；本 lane 按要求只打
   空上下文/空订阅分支，不重复 init/load_datas/下单主路径。
