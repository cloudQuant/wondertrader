## 4. 留白面及原因

1. **`StateMonitor::run()` 全部状态机**（`StateMonitor.cpp:145-530`，约 385 行）：切换输入只有 `TimeUtils::getCurDate()/getCurMin()` 与 `StdThread` 内 2ms 轮询，无 `checkOnce(curDate,curMin)` 接缝；按任务令不启动长线程。见 BUG-R5-002。
2. **`UDPCaster::init(active=true)`/`start`/`do_receive`/`do_broadcast`**（L70-131、145-220、288-400）：需要真实 UDP bind / `async_receive_from` / io 线程；且 `start` 在 bind 失败后仍调用 `do_receive()`（BUG-R5-001）。见 BUG-R5-001/003/008。
3. **`UDPCaster::handle_send_broad/handle_send_multi`**（L402-416）：private 且全仓库无调用点，死代码；不能用 `#define private public` 绕过。
4. **`DataManager::init` 成功段**（L78-106）与 `release` 的真实 `_remover`：只能经 `WtDataStorage` 插件取得 `_writer`；插件 init 会起 `sleep_for(10s)` 的检查线程并创建目录/缓存文件，违反「不依赖墙钟长等待」。
5. **`ShmCaster::init(active=true)` 成功段与四个 `broadcast` 写入体**（L47-64、72-172）：需要真实文件映射/共享内存；`_queue` private 且无 setter，无内存写入入口。
6. **`IndexWorkerMgr` 的 `poolsize>0`**（L136-139、182-194）：`boost::threadpool::pool` 构造即起服务线程，按任务令 poolsize 恒 0。
7. **`IndexWorkerMgr` 工厂成功段依赖构建产物**：若主控只构建 `CoverageTests_dtcore` 而未构建 `WtIndexFactory` 插件，三条用例会 SKIP，行段回到留白；建议全量构建后再度量本 lane。
