## 2. 关键发现：StateMonitor.h/DataManager.h 的 0% 是内联记账，不是未调用

`llvm-cov export` 显示 `StateMonitor::isInState/isAnyInState/isAllInState`、
`_StateInfo::isInSections`、`DataManager::add_caster`、`IndexWorkerMgr::get_*` 各只有
**一条函数记录且 count=0**；与此同时 q05/r18/r68 的调用点行有计数（例如
`q05_state_monitor_test.cpp:160-175` 每行 count=1）。这些函数在类内定义，Debug/-O0
下仍被前端内联，独立的 out-of-line 副本从未执行，profdata 因此记 0。

本轮的测法：用**成员函数指针**发起间接调用（`&StateMonitor::isInState`、
`&DataManager::add_caster` 等），阻止内联，强制调用链接器保留的副本。测试只走公开
API，未使用 `#define private public`、类布局镜像或宏改写。

## 4. 未覆盖行及原因（本轮约束下的硬留白）

### UDPCaster.cpp：剩余 65 行全部依赖真实 socket

- 114-117：`start()` 的 socket 构造 catch；占用端口可触发，但随后 `do_receive()`
  对 NULL `m_sktSubscribe` 解引用（BUG-R5-001），不能启用。
- 128：io 线程 catch 的 `m_ioservice.stop()`；只由 `run()` 内异常触发。
- 150-154：`do_receive` 的 `ec` 分支；需 socket 关闭/取消，公开 API 无接缝。
- 184-199：订阅命中且 `getCurTick != NULL` 的回包段；`DataManager::getCurTick` 在
  `_writer==NULL` 时恒 NULL，writer 无公开注入点（BUG-R44-005 同族）。
- 212-214：短包回包 `async_send_to` 的 `ec` 分支；回环成功，无错误注入点。
- 321-322：队列里 `_data==NULL` 的 break；四个公开 broadcast 都在入口拒绝 NULL。
- 360-363：未知 `dataType` 的 break；公开包装只传 0x200/0x201/0x202/0x203。
- 371-375：raw 单播 `send_to` 的 `ec` 日志；需真实广播 socket 且目标不可达。
- 379-388：`m_listRawGroup` 组播发送循环；需 join_group 成功的真实 socket 并向
  239.x 发送，违反本 lane「不启动真实 socket/不访问外网」。
- 402-416：`handle_send_broad/handle_send_multi` 无引用点，dead code（BUG-R5-004）。

### StateMonitor.cpp：剩余 29 行是 1 秒节流下的跨分钟转换

- 341-345：`RECEIVING -> CLOSED`，需两轮之间跨过 `closetime`；run 轮次固定 1 秒，
  HHMM 只在分钟边界变化，无法在同一模板内确定性构造。
- 348-369：`RECEIVING -> PAUSED` 与「超过市场收盘仍接收」子分支；`isInSections` 与
  `getCloseTime` 的区间定义互斥，同一分钟内不翻转。
- 390-398、413-423：`PAUSED` 的节假日判断与 `PAUSED -> RECEIVING/Holiday`；首轮进入
  PAUSED 的前提在次轮同一分钟内不变。
- 445-449：`isSessionProceeded()==true -> PROCED`；`DataManager` 无 writer 时恒 false，
  writer 无公开注入点（BUG-R44-005 同族）。
- 491-496：Holiday 分支的复合节假日条件右侧；R164 已驱动左侧，右侧需夜盘偏移与
  当日非交易日同时成立，属分支归并口径。

以上均需时钟注入或真实 socket/writer，本 lane 按任务约束不强行构造，也不放宽断言。
