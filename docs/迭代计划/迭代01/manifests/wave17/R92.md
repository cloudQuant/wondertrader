## 3. 关键输入设计

- **Cta 条件单**：默认 `HisDataReplayer` 构造后 `_tick_simulated=true`（`HisDataReplayer.cpp:150`），
  因此 `proc_tick` 走模拟 tick 的区间比较分支；`handle_tick(pxType=0)` 会连续调用两次
  `proc_tick`，第一遍触发条件单并 `append_signal`，第二遍由 signal 触发 `do_set_position`，
  与 R62 已验证的模式一致。
- **Sel 查询矩阵**：`kStk` 设 `TM_LongT1`，先 0→100（走平仓分支反手建仓）再 100→150
  （走 open 分支并累计冻结），跨日 `handle_session_begin` 解冻后才能归零；
  `kRb` 用 0→-100→0 覆盖空头平仓符号。
- **Uft/Hft 撮合**：`procOrder` 的对手价/对手量来自 `HisDataReplayer::get_last_tick`
  （Loader 注入的 tick），不是 `handle_tick` 参数里的 tick；因此：
  - Uft 用 `match_this_tick=true`（由 `init_uft_factory` 解析后模块加载失败留下标志）
    先排空 entrust 任务，再成交并 erase，规避 BUG-R92-001；
  - Hft 非 match 分支用「Loader askqty=1 + 委托 2 手」制造部分成交，第一笔只成交 1 手，
    订单保留，entrust 任务在 `procTask` 中安全排空；第二笔成交剩余 1 手才 erase。
- **Exec**：不加载执行器 DLL，只覆盖「模块可装载但缺 creator」与 15:00 早退。

## 6. 留白面及原因

1. **策略 DLL 回调族**：`Cta 968/1017-1040/1238/1267`、`Uft 225/296-329/340/361/365`、
   `Sel 404/461/471/477`、`Hft 311/439-483/501/530` 等 `_strategy->on_*` 行需要真实策略模块；
   按约束不加载真实策略 DLL，整族留白。
2. **hook/step 阻塞路径**：`Cta 687/1060-1087/1138-1200`、`Hft 329-343/362-368/411-429`、
   `Sel` 无 hook 相关；这些分支进入 `_cond_calc.wait()` / `while(!_resumed)`，
   属线程/墙钟接缝，不硬闯。
3. **Cta 条件单 switch 的 default**（L769/799）：`WTSCompareType` 公开枚举只有 0-4，
   无条件单 JSON 能注入 5，属不可达。
4. **Cta `dump_stradata`/`dump_chartdata` 的 `fs::create_directories`**（L215/317）：
   `handle_replay_done` 先调用 `dump_outputs` 且其已建目录，公开调用序列下目录必存在；
   只有直接私有调用才会命中。
5. **Cta 图表打点/指标写值**（L2157-2161、L2208-2227）：`add_chart_mark`/`set_index_value`
   要求 `_is_in_schedule=true`，该窗口只在 `on_schedule` 内、且需要策略 `on_schedule`
   回调才能插入调用；与第 1 项同一策略接缝。
6. **Sel `_desprice!=0` 分支**（L368-369）：`append_signal` 只在 `stra_set_position`
   中调用且固定 price=0，无公开入口注入非零目标价。
7. **Sel `do_set_position` 的 volume==qty / commInfo==NULL 早退**（L656/660）：
   公开入口在生成 signal 前已做同值/品种校验，无法构造到这两行。
8. **Sel 明细 `maxQty==0` continue**（L742）：Sel 平仓分支用 count 删除零量明细，
   公开 API 下不会留下零量明细。
9. **Cta `do_set_position` 的 volume==qty / commInfo==NULL / maxQty==0**
   （L1614/1618/1699）：同 7/8，公开 signal 路径不可构造；L1699 的零量明细在
   `count` 清理后不存在。
10. **Cta 除权代码后缀**（L1815）：需要 `CodeHelper::isExright()` 命中且 K 线切片非空，
    本轮无该代码的行情 fixture。
11. **Uft `_strategy` 空指针族**：`stra_enum_position`（L1031-1047）、
    `on_session_begin/end`（L344-390）在未装策略时必崩（BUG-R72-001 / BUG-P08-001），
    本轮不调用。
12. **Uft 昨仓可用路径**（L701-711/762-771 的 `_preavail` 成功分支）：
    公开 API 无入口把今仓滚成昨仓（`on_session_begin` 同 11），只能覆盖拒绝分支。
13. **Uft `_preavail` 平昨成功 / `stra_cancel` 的 offset=1 归还昨仓**（L431-432）：
    同 12，无昨仓来源。
14. **Uft offset2 的「非今仓」continue**（L1269）：明细 `_opentdate` 恒等于
    `get_trading_date()`（未回放时为 0），无公开入口构造昨仓明细。
15. **Hft `_ticks` 缓存分支**（L888-893）：`HftMocker` 从不向 `_ticks` 写入，
    该分支实际不可达（成员只 create/release）。
16. **Hft 零量明细 continue**（L1154）：Hft 平仓后按 count 清理零量明细，公开路径不可构造。
17. **Exec `_exec_unit` 非空路径**（L136、L140-161、L164-192、L270-274、L286-335）：
    需要 `createExecFact` 执行器 DLL；本轮按 n04 的接缝口径不加载产品 DLL，
    只覆盖 creator 缺失与 15:00 早退。
18. **`splitVolume` 的 curVol==0 continue**（Hft L68/98）：`minQty=1`，随机值恒 >=1，
    不可达。
