## 3. 关键安全边界（为什么这些成功支可以确定性运行）

1. **不加载任何插件**：`parsers`/`traders` 的 active 条目都写不存在的 `module`。
   UFT/HFT 的 `ParserAdapter::init` 在 `module.empty()` 或 `dlopen` 前返回；`TraderAdapter::init` 同样在
   `dlopen` 前返回。`WtUftRunner::initParsers/initTraders` 不检查返回值，于是覆盖到 addAdapter/count
   路径，但没有任何接收线程被启动。
2. **不碰共享内存**：配置里没有 `share_domain`，`ShareManager::_inited` 保持 false，
   `start_watching(2)` 在 `WtUftCore/ShareManager.cpp:78-81` 直接返回 false。
3. **`WtUftRunner::run()` 的退出**：先 `raise(SIGINT)`，构造时安装的回调（`WtUftRunner.cpp:40-45`）
   把 `_to_exit` 置真；`:362-365` 的 10ms 轮询不会进入。用完把 SIGINT 恢复为 `SIG_DFL`。
4. **ticker 线程可控**：`UftRtTicker`/`HftRtTicker` 只在 `run()` 成功后启动；自写 session
   `ALLDAY` 用单段 `0~2400`，任意 hhmm 都在交易时段内，线程只做 10ms 轮询；工具析构时
   `WtUftEngine`/`WtHftEngine` 的析构函数 `stop()` + `join()`，不会落进 10s 休眠。
5. **times=0/1 不构造 tick**：times=0 只走 `TestParser::run` 的头尾；times=1 且不加载合约，
   循环体在 `getContract` 返回 NULL 后立刻返回。不触发 `TestStrategy::on_tick`、不下单。
6. 每个用例 `chdir` 到 `temp_directory_path()/wt_r95_*`，产品相对路径（`generated/`、日志）
   全部落在临时目录，析构时恢复 cwd 并删除。

## 5. 未覆盖面及原因

1. **`WtUftRunner::initEvtNotifier()`（340-349）**：全文件没有任何调用点，`config()` 也不调用；
   属死代码。已登记 `bugs/R95.md` BUG-R95-001。
2. **`WtUftRunner::config()` 的 `share_domain` 分支（115-122）**：需要真实共享内存段与
   `WtShareHelper` 模块；本轮不碰。沿用 BUG-R14 的共享内存结论。
3. **`WtUftRunner::initUftStrategies()` 的「策略创建成功」段（226-248）**：需要
   `WtHelper::getCWD()/uft/` 下真实可装载的 UFT 策略工厂；`getCWD()` 是进程级静态缓存，
   无法在不污染其他用例的前提下把查找目录指向临时目录。本轮只覆盖 inactive 与
   createStrategy 返回 NULL 两条。
4. **`WtUftRunner::run()` 的成功循环（362-365）**：`_to_exit` 只能由信号翻转；本 lane 用
   `raise(SIGINT)` 让循环不进入，拿到函数其余行。真正等待 10ms 轮询需要墙钟，不取样。
5. **入口 `main()` 的非 help 分支**：三个可执行体都在 `config()/init()` 之后无条件 `run()`，
   HFT/UFT 的 `main.cpp` 末尾还有 `getchar()`；进程内调用会阻塞。`main.cpp` 单独计，
   本轮不驱动；HFT/UFT 的 `test_hft()/test_uft()` 包装已由第 2 节的 entry 用例覆盖。
6. **HFT/UFT 的 `TestParser` tick 主体与 `TestStrategy::on_tick`**：需要加载合约并让
   `times>=1`；一旦 tick 进入引擎，HFT 的策略订阅名与 ParserAdapter 生成的
   `SHFE.rb.2205` 同名，会走 `stra_buy`/下单链；UFT 的 `TraderAdapter::initExt` 把
   `_policy_mgr` 设为 NULL。为避免把未验证的下单链引入覆盖率进程，本轮只取 times=0/1
   无合约路径。
7. **`checkValid`/`strToTime`（HFT 52-83）**：文件内 `inline` 且全文件无调用点，
   TU 外也拿不到可用符号；属未使用的死函数。
8. **`WtLatencyHFT::init` 的 `isUTF8`（361-362）**：只读不用的局部变量，无分支可覆盖。
