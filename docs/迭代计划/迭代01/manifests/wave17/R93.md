## 一、范围与手法

既有 T4/T5/R60 覆盖的是 `m_pUserAPI == NULL` 的拒绝面与回调解析。本 lane 为三个适配器各写一份
**厂商 API 纯虚函数机械空实现**：

| stub | 基类 | 纯虚函数数 | 来源 |
| --- | --- | --- | --- |
| `t_TraderYD/r93_yd_api_stub.h` | `YDApi` | 56 | `src/API/yd1.108.360/ydApi.h` |
| `t_TraderFemas/r93_femas_api_stub.h` | `CUstpFtdcTraderApi` | 48 | `src/API/Femas3.02/USTPFtdcTraderApi.h` |
| `t_TraderXTP/r93_xtp_api_stub.h` | `XTP::API::TraderApi` | 70 | `src/API/XTP2.2.32.2/xtp_trader_api.h` |

stub 只记调用计数/最近一次请求并返回可控值，**不加载厂商 dylib、不建 socket、不起线程**。
YD/Femas 通过 `TraderYD`/`TraderFemas` 的派生探针写 protected `m_pUserAPI`；XTP 的数据成员
全部 private，测试 TU 按仓库先例（p03/p08/p10）在包含完所有依赖头后以
`#define private public` 暴露，仅用于注入 stub、预置线程和读取状态，未改产品代码。

落盘纪律：
- YD 的 `ydlocal/`、XTP 的 `./xtpdata/local/` 都是相对 cwd 写；用例在
  `mkdtemp` 风格的系统临时目录里 chdir，析构时恢复 cwd 并 `remove_all`。
- Femas 的 `flowdir` 配到系统临时目录，用例结束删除。
- 不启常驻线程：YD/Femas 的 `m_thrdWorker`、XTP 的 `_thrd_worker` 预置为未启动的 `std::thread` 占位（非 joinable），
  产品检查非空即跳过创建；worker 线程体保持留白，全程不创建线程。

## 五、留白面及原因

1. **真实厂商 API 创建/发送**：三个模块都只走测试内 stub；真实 dylib 加载、
   `makeYDApi`/`CreateFtdcTraderApi`/`CreateTraderApi` 与柜台网络不在本 lane（禁外网/真实柜台）。
2. **常驻线程体**：YD L690-711、Femas L203-210、XTP L696-703 以未启动的 `std::thread` 占位跳过；
   真起线程后 YD/Femas/XTP 的退出语义分别见既有缺陷与本文件 bugs。
3. **XTP `OnDisconnected` 重连 lambda**（L350-354）：内含 `sleep_for(2s)` 与 `doLogin`，
   按「不启墙钟等待」不执行；只保留既有 T5 的事件断言。
4. **Femas `triggerQuery` 的延迟分支**（L1159-1166）：`curTime - m_lastQryTime < 1000` 时
   sleep 50ms 后重投，属墙钟等待，未启用。
5. **Femas 持仓查询 append 缺失**：KNOWN BUG-T4-002，本 lane 不重复触发；只测请求侧。
6. **YD 无 `#` 的 entrustID**：产品 `extractEntrustID` 会越界读（BUG-R93-001），
   本 lane 用双 `#` 的畸形串覆盖拒绝分支，不制造崩溃。
7. **XTP 无 `_api` 时四个查询**：KNOWN BUG-T5-02，未在无 API 态调用；只在 stub 非空时测正向与失败返回。
