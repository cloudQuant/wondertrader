## 一、范围与手法

既有 lane T1/T3 只覆盖了 `m_pUserAPI == NULL` 的拒绝面。本 lane 新增两个**机械空实现**的厂商 API stub：

- `r61_ctpopt_api_stub.h`：`ctp_sopt::CThostFtdcTraderApi` 的 93 个纯虚函数逐条实现，取自
  `src/API/CTPOpt3.5.8/ThostFtdcTraderApi.h`；
- `r61_ctpmini_api_stub.h`：`CThostFtdcTraderApi` 的 49 个纯虚函数逐条实现，取自
  `src/API/CTPMini1.5.8/ThostFtdcTraderApi.h`。

stub 只做调用计数并返回可控 `stub_ret_`，**不加载厂商 dylib、不建 socket、不起线程**。
用例通过派生探针把 protected `m_pUserAPI` 指到 stub（与 t_TraderCTP 的既有做法同源），
因此可以确定性地走完登录/下单/撤单/查询的正向组装分支，而不需要真实柜台。
`connect()/disconnect()` 用例另把 `m_thrdWorker` 预置为一个立即返回的线程，
避免触发产品里永不退出的查询线程（见 bugs/R61.md BUG-R61-001/002）。

落盘纪律：`m_strFlowDir`、eid/oid 缓存、IniHelper 全部指向 `mkdtemp("/tmp/wt_r61_*")`
目录，用例析构时 `std::filesystem::remove_all` 清理；无墙钟等待、无外网、无真实柜台。

## 五、留白面及原因

1. **真实厂商 API 创建/发送**：`connect()` 仍走测试内 creator + stub；真实 dylib 加载、
   `CreateFtdcTraderApi`、柜台网络不在本 lane（禁外网/禁真实柜台）。
2. **查询 worker 线程体**（Opt L333-360、Mini L191-219）：用例预置空线程跳过创建；
   产品 `m_bStopped` 无置真路径，真起线程后 `disconnect()` 会挂死（BUG-R61-001/002）。
3. **`wrapTimeCondition`（Opt L184-202）**：产品写成 TU 内 `inline`，跨 TU 声明会链接失败，
   T1 已登记接缝诉求；本 lane 不复制产品实现。
4. **`OnRspQryTradingAccount` 的「首帧即错误且 bIsLast」**：Mini L713-719 对空 `m_ayFunds`
   调 `clear()` 必崩（T3-007），保持 DISABLED 面，不硬闯。
5. **空指针入参**（`orderInsert(NULL)`/`orderAction(NULL)` 在 ALLREADY 态）：产品直接解引用；
   本 lane 只覆盖显式带守卫的 `orderInsertOpt(NULL)`，其余不制造崩溃。
6. **`TraderCTPOpt` 的 `confirm/queryConfirm/authenticate/doLogin` 私有性**：只能经
   `OnRsp*`/`login` 间接进入；本 lane 已把可达分支走完，未改访问级别。
7. **真实柜台返回码组合**：stub 只覆盖 0 与非 0 两侧的代表值（-2/-3/-5/-7/-8/-9），
   不枚举厂商全部错误码。
