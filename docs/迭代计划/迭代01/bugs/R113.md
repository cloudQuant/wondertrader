## BUG-R113-001 TraderMocker 的 connect/login 非幂等，第二次调用对 joinable std::thread 做 reset 触发 std::terminate

- 编号: BUG-R113-001
- 状态: 待审核
- 模块/文件/行: `src/TraderMocker/TraderMocker.cpp:689-703`（`connect`，`_thrd_worker.reset(new StdThread(...))` 在 `693`）、
  `:723-743`（`login`，`_thrd_match.reset(new StdThread(...))` 在 `725`）、
  `:640-657`（`release` 在 `_terminated` 为 true 时早退）
- 相关测试: `src/TestUnits/coverage/t_TraderMocker/r113_mocker_login_retry_test.cpp`
  `R113MockerLoginRetry.DISABLED_SecondLoginOrConnectTerminates`（崩溃类，保留 DISABLED）
- 输入/前置条件:
  1. `TraderMocker api; WTSVariant* cfg = ...; api.init(cfg); api.registerSpi(&sink);`
  2. `api.connect(); api.login("", "", "");`（首次成功，`_thrd_worker`/`_thrd_match` 均 joinable）
  3. 再次 `api.login("", "", "")` 或 `api.connect()`
- 期望行为: 重复 connect/login 要么幂等返回，要么先 `join()/detach()` 旧线程再替换；
  不得因析构仍 joinable 的 `std::thread` 而终止进程。
- 实际行为: `StdThreadPtr` 是 `std::shared_ptr<std::thread>`（`src/Share/StdUtils.hpp:23-24`）。
  `_thrd_match.reset(new StdThread(...))` / `_thrd_worker.reset(...)` 在旧 `std::thread`
  仍 joinable 时销毁它，`std::thread::~thread()` 调用 `std::terminate()`。
  此外 `release()` 在 `_terminated` 已为 true 时（第 642-643 行）直接返回；
  若在 `release()` 之后再调用 `login()`，新起的 `_thrd_match` 之后没有任何路径 join，
  对象析构时同样 terminate。
- 复现步骤:
  1. 按上述前置条件 connect + login；
  2. 再调用一次 `login()`（或 `connect()`）；
  3. 进程在 `std::thread::~thread()` 处 SIGABRT（`terminate called without an active exception`）。
  4. 或将 `DISABLED_SecondLoginOrConnectTerminates` 去掉 `DISABLED_` 后运行。
- 影响范围: 交易通道断线重连、登录重试、宿主重复调用 `connect()`；仿真器在无日志、
  无错误码的情况下直接打死宿主进程。
- 严重级别: Major（进程 abort；重连路径常见）
- 备注: 修复方向：`connect/login` 开头检查 `_thrd_worker`/`_thrd_match` 是否已存在，
  存在则先 `join()`/`detach()` 并 `reset()`；`release()` 不要因 `_terminated` 跳过
  `_thrd_match` 的 join。与 BUG-R60-001（disconnect 后 release 跳过 worker 清理）
  同属线程生命周期问题，但本条是「重复 connect/login」的另一触发点。

## BUG-R113-002 TraderMocker::splitVolume 每次调用都 srand(time(NULL))，拆量不可复现且污染全局 PRNG

- 编号: BUG-R113-002
- 状态: 待审核
- 模块/文件/行: `src/TraderMocker/TraderMocker.cpp:52-80`（`splitVolume`，`srand((uint32_t)time(NULL));` 在 `63`）
- 相关测试:
  - `src/TestUnits/coverage/t_TraderMocker/r113_mocker_match_long_test.cpp`
  - `src/TestUnits/coverage/t_TraderMocker/r113_mocker_match_short_test.cpp`
  - `src/TestUnits/coverage/t_TraderMocker/r113_mocker_partial_cancel_test.cpp`
  （只断言总成交量/持仓/状态，不依赖具体拆量序列）
- 输入/前置条件: 任意一次成交量 > `minQty` 的撮合（本 lane 的开多 5 手、开空 4 手）
- 期望行为: 仿真拆量要么使用可注入的确定性 RNG，要么至少使用进程内独立 PRNG；
  同一输入、同一配置在测试/回放中应可复现。
- 实际行为: `splitVolume` 是全局函数，每次调用都以秒级 `time(NULL)` 重置 C 全局
  `rand()`。后果：
  1. 同一秒内的多次拆量得到完全相同的前缀序列；
  2. 与宿主/其它线程对 `rand()` 的使用互相污染（`srand/rand` 非线程安全）；
  3. 回测/仿真报告无法按固定种子复现单笔成交量。
- 复现步骤:
  1. 用相同配置连续两次做同一笔 10 手撮合，间隔 <1s；
  2. 记录 `onPushTrade` 的每笔 volume；
  3. 两次序列一致；间隔跨秒后序列变化；宿主其它 `rand()` 调用也会改变结果。
- 影响范围: 仿真成交明细的可复现性、并发多 TraderMocker 实例、宿主内其它使用
  `rand()` 的组件。
- 严重级别: Minor
- 备注: 修复方向：把 RNG 作为 TraderMocker 成员（`std::mt19937`），用配置项
  `seed` 初始化；`splitVolume` 改为成员函数或显式传入 RNG。该函数还有
  `curVol == 0` 的 `continue`（`:71-72`）在 `minQty == 0` 时可达，本 lane 的
  `init` 会把 0 改成 1，公开配置无法稳定触达。
