> 涉及用例见 [manifests/wave10/R46.md](../manifests/wave10/R46.md)。

## BUG-R46-001 运行器构造列表漏初始化多个指针/句柄成员，非静态实例在 init/config 前调用部分入口即读未定义值

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtPorter/WtRtRunner.cpp:55-100`（构造函数）；`src/WtBtPorter/WtBtRunner.cpp:47-89`（构造函数）
- 现象:
  - `WtRtRunner` 的初始化列表覆盖了全部 `_cb_*`，但没有 `_config`、`_engine`、`_feed_obj`、
    `_feeder_bars`、`_feeder_fcts`；`getEngine()`（`.h:324`）、`createExtParser()`（`.cpp:295-303`）、
    `get_raw_stdcode()`（`.cpp:361-366`）、`load*`（`.cpp:203-275`）都会直接读它们。
  - `WtBtRunner` 的初始化列表覆盖了 `_cta_mocker/_sel_mocker/_inited/_running/_async`，
    但没有 `_hft_mocker`、`_exec_mocker`、`_worker`、`_cfg`、`_loader_auto_trans`；
    `initHftMocker()`（`.cpp:285-297`）首句就 `if (_hft_mocker) delete _hft_mocker;`，
    `stop()`（`.cpp:550-559`）读 `_worker`，`isAutoTrans()`（`.h:122-125`）读 `_loader_auto_trans`。
  - 静态单例 `getRunner()` 因静态零初始化而"看起来正常"，把缺陷完全掩盖；任何栈/堆实例都会踩中。
- 相关测试:
  - `r6_porter_lifecycle_test.cpp` 的 `R6PorterFactories.*`、`R6PorterLifecycle.init_*`（栈上构造 `WtRtRunner`）。
  - 本 lane 的 `r46_porter_config_test.cpp` / `r46_btporter_runner_test.cpp` 全部改用
    「堆上 `new`、故意不 `delete`」的实例规避，未启用会触发 UB 的用例。
- 输入: `WtRtRunner r; r.getEngine();` 或 `WtBtRunner* r = new WtBtRunner(); r->initHftMocker("x");`
- 期望: 非静态实例的成员在构造函数里全部置空（或类内默认初始化），未 `init()/config()` 时
  返回 `nullptr`/`false`，不读取未定义值。
- 实际: 读取未初始化的栈/堆内存；可能是野指针，`delete`/`release` 时崩溃或静默破坏内存。
- 复现步骤:
  1. 在任意测试里栈构造 `WtRtRunner r;`（不调用 `config()`），退出作用域；
  2. 成员引擎 `WtCtaEngine::~WtCtaEngine` 判断 `if (_cfg)` 时读到栈垃圾，非空即 `release()` 野指针。
- 影响: 任何"非单例"用法（测试、嵌入式宿主、多实例）都可能段错误；覆盖率侧导致
  `WtRtRunner` 的 config 链与 `WtBtRunner` 的 mocker 链只能靠泄漏实例取样，无法用正常 RAII 写用例。

## BUG-R46-002 WtRtRunner::config 忽略 initEngine() 失败，env 缺失时仍返回 true 且 _engine 未赋值

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtPorter/WtRtRunner.cpp:584`（`initEngine();` 返回值未接）、`:840-842`（`env` 缺失直接 `return false`）
- 现象: `config()` 对 `initEngine()` 的 `bool` 返回值不做判断；`env` 段缺失时
  `initEngine()` 在 `_config->get("env")` 为 NULL 处提前返回 false，既不设置 `_engine`，
  也不回滚后续步骤；`config()` 继续执行 `initDataMgr()`/`initActionPolicy()`，
  在 `bspolicy` 存在时一路走到 `return true`。
- 相关测试: `r46_porter_config_test.cpp:R46PorterConfig.DISABLED_MissingEnvLeavesEngineUninitializedButConfigSucceeds`
- 输入: `config("{\"basefiles\":{},\"data\":{},\"bspolicy\":\"<存在的actions.json>\"}", false)`
- 期望: 返回 false（或至少把 `_engine` 置空并记录错误），让调用方知道运行环境没建起来。
- 实际: 返回 true；`_engine` 从未赋值，叠加 BUG-R46-001 后 `getEngine()` 读到不确定值。
  此后 `create_ext_parser`/`run_porter` 会按 BUG-R6-003 的路径崩溃。
- 复现步骤:
  1. 构造 `WtRtRunner`（堆或单例均可），`init()` 后调用上述 `config()`；
  2. 观察返回值为 true；
  3. 调用 `create_ext_parser("x")` 或 `run_porter(false)`。
- 影响: 配置漏写 `env` 属常见笔误，实盘侧表现为"配置加载成功"却在启动阶段崩溃，
  排障信息指向 `_engine` 空指针而不是缺段本身。

## BUG-R46-003 WtBtRunner::config 对 replayer / env 两段没有 NULL 守卫，缺段即空指针解引用

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件: `src/WtBtPorter/WtBtRunner.cpp:467`（`_replayer.init(_cfg->get("replayer"), ...)`，`HisDataReplayer::init` 首行即解引用 cfg）、`:469-470`（`WTSVariant* cfgEnv = _cfg->get("env"); const char* mode = cfgEnv->getCString("mocker");`）
- 现象: `config()` 只校验了 `_cfg` 是否为 NULL（`:458-462`），对两个必需子段都没有判空。
  `env` 缺失 -> `cfgEnv->getCString` 段错误；`replayer` 缺失 -> `HisDataReplayer::init`
  （`src/WtBtCore/HisDataReplayer.cpp:175`）在 `cfg->getCString("mode")` 处段错误。
  同函数对 `notifier` 段（`:465`）反而有判空，三处口径不一致。
- 相关测试:
  - `r46_btporter_runner_test.cpp:R46BtRunner.DISABLED_ConfigWithoutEnvSectionDerefsNull`
  - `r46_btporter_runner_test.cpp:R46BtRunner.DISABLED_ConfigWithoutReplayerSectionDerefsNull`
- 输入:
  - `config("{\"replayer\":{\"mode\":\"none\",\"basefiles\":{},\"path\":\"/tmp\"}}", false)`（缺 env）
  - `config("{\"env\":{\"mocker\":\"none\"}}", false)`（缺 replayer）
- 期望: 返回/记录 "config missing env/replayer" 并安全退出（`config` 返回 void，至少不崩）。
- 实际: SIGSEGV 打死宿主；`catch(...)` 抓不到，gtest 进程直接终止。
- 复现步骤:
  1. `WtBtRunner* r = new WtBtRunner();`
  2. `r->config("{\"env\":{\"mocker\":\"none\"}}", false);`
  3. 进程在 `HisDataReplayer::init` 内崩溃。
- 影响: 回测配置写错 / 使用旧版配置模板（不含 `replayer` 段）时，回测进程崩溃而非报错；
  覆盖率侧导致 `config()` 的这两条错误路径无法在进程内取样。
