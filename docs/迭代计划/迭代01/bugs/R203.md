## 观察 1：跨类型缓存守卫使委托/成交读取跳过装载（既有 BUG-R74-001 / BUG-R100-001）

- 位置:
  - `src/WtDataStorage/WtDataReader.cpp:690`（`readOrdDtlSlice` 查 `_his_ordque_map`）、
    `:847`（`readTransSlice` 同）、`:741-743`、`:898-900`
  - `src/WtDataStorage/WtRdmDtReader.cpp:701`、`:876`、`:1050`（三个 ByRange 入口同型）、
    `:913-915`、`:1087-1089`
- 现象: 只要同一 `stdCode-endTDate` 的队列读取曾在 `_his_ordque_map` 留下 key
  （包括短文件/坏文件失败后留下的空块），委托/成交入口就跳过自己的文件装载，
  直接在空的自有 map 上返回 NULL。
- 与本 lane 的关系: 用例 1/2 只提供**没有**委托/成交数据的环境，因此期望 NULL
  本身是独立正确的（缺失数据应返回 NULL），并非把“有数据却返回 NULL”断言为正确。
  该守卫是命中 743/900/915/1089 的既有实现路径；不重复立案。
- 交叉引用: `bugs/R74.md` BUG-R74-001、`bugs/R100.md` BUG-R100-001、
  `bugs/R112.md`、`bugs/R162.md`。

## 观察 6：RT 块 map 失败分支会抛未捕获异常（既有登记）

- 位置: `WtDataWriter.cpp`、`WtRdmDtReader.cpp:2019-2209`、`WtDataReader.cpp:1948-2201`、
  `WtDataReaderAD.cpp:330-334` 等调用点
- 现象: `BoostMappingFile::map` 直接 `new file_mapping`/`new mapped_region`，对目录、
  零长、无权限文件抛 `boost::interprocess::interprocess_exception`；调用点无 try/catch。
- 与本 lane 的关系: 不写必崩用例；AD 用例 6 使用 writer 生成合法 cache 文件，
  不做 r172 式布局直写（该直写用例在基线 SIGSEGV，见 `bugs/R182.md` 观察 5）。
- 交叉引用: `bugs/R182.md` 观察 5、`bugs/R193.md` 观察 2。
