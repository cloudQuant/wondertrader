# R67 缺陷记录（第十三波 · HisDataReplayer / ExecMocker / HisDataMgr 补测）

> 只记录、不修复。两条均为源码静态风险；本次运行了 R67 启用用例 14 条，均通过，
> 但两条风险用例均未被动态触发。`IBtDataLoader` 文档没有规定成功返回必须至少回调
> 一根 K 线；未知品种订阅的合法性也未在 `sub_tick` 契约中说明。

## BUG-R67-001 空 K 线集合仍读取首尾元素（loader/dsb 输入契约待澄清）

- 状态: 静态越界风险成立；loader 空结果契约未定义，具体触发范围待确认
- 严重级别: Major（空集合下标访问为未定义行为；输入契约待确认）
- 模块/文件: `src/WtBtCore/HisDataReplayer.cpp:3699-3700`（`cacheFinalBarsFromLoader` 的 loader 成功臂）；
  同类问题另见 `:3662`（autoTrans dsb 命中但解压后 `barcnt==0`）
- 相关测试: `src/TestUnits/coverage/q02_btcore3/r67_replayer_loader_gap_test.cpp`
  `R67LoaderGap.DISABLED_EmptyLoaderSuccessDerefsEmptyBars`
- 输入/前置条件（loader 分支）:
  - `HisDataReplayer::init(cfg, NULL, loader)`，`mode=csv`；
  - 自定义 `IBtDataLoader::loadFinalHisBars` 返回 true 但一次回调都不调用（携带 0 条 K 线）。
    接口注释只说返回值表示“是否成功加载数据”，没有明文规定“返回 true 必须回调且
    `count > 0`”，所以该输入是否违反 loader 契约目前不明；
  - `get_kline_slice("SSE.STK.600000", "d", 3, 1, true)`。
- 期望行为: 在读取首尾元素前验证条数；空结果应按明确的 loader 契约处理为失败/无数据，
  再由调用方尝试配置的 CSV/bin 来源。只有没有可用回退源时，`get_kline_slice` 才应返回 NULL。
- 实际行为: 源码在 `bSucc==true` 后无条件执行
  `uint64_t stime = isDay ? barsList->_bars[0].date : barsList->_bars[0].time;`
  以及 `etime = ... _bars[_count - 1] ...`。此时 `_count==0`、`_bars` 为空，
  `operator[]` 越界是 UB（libc++ 调试模式直接断言，发布模式读垃圾内存）。
  同一函数上方 dsb 分支在 `barcnt==0` 时也执行同样的 `_bars[0]` 访问。
- 测试边界: `DISABLED_EmptyLoaderSuccessDerefsEmptyBars` 函数开头有 `GTEST_SKIP()`，且
  用例默认禁用；即使以 `--gtest_also_run_disabled_tests` 启动也会先跳过，不会调用
  目标代码。本次未动态触发 UB。
- 复现步骤（静态触发条件，未执行）:
  1. 用临时目录构造 csv 模式配置并注册上述 loader；
  2. `prepare()` 后请求日线切片；
  3. 观察 UB（或 ASan 的 heap-buffer-overflow）。
- 影响范围: 若 loader 的 bool/callback 契约允许“成功但 0 条”，或缓存文件解压得到 0 根，
  对应请求会进入未定义行为路径；不能把“任何无数据 loader 都会踩中”作为已证事实。
  与 BUG-P04-004（空 csv）同属「空序列仍取首尾元素」家族，但触发面在 loader 接缝。
- 备注: 本次 14 条启用 R67 用例通过，不能覆盖两个 `DISABLED_` 边界。修复方向是 loader
  与 dsb 分支都先判零条数并避免访问首尾元素；明确接口把“无数据”表达为 false 还是
  true+count=0，并让回退行为符合该约定。

## BUG-R67-002 未订阅日线模拟 tick 未检查 commodity/session 查询结果

- 状态: 静态空指针风险成立；未知代码是否属于合法输入待确认
- 严重级别: Major（存在空指针解引用路径；输入边界待确认）
- 模块/文件: `src/WtBtCore/HisDataReplayer.cpp:1474-1482`（`simTickWithUnsubBars` 日线分支；
  空指针解引用点为 `:1478`，session 结果也未判空于 `:1482`）
- 相关测试: `src/TestUnits/coverage/p07_btcore_replayer2/r67_replayer_bars_gap_test.cpp`
  `R67CsvBars.DISABLED_UnknownCommodityUnsubBarsDerefsNullCommodity`
- 输入/前置条件:
  - csv 模式、`tick=false`；
  - 主K线为已登记品种（`SSE.STK.600000`）；
  - `sub_tick(5, "SSE.NOPE.999999")`，且 `csv/SSE.NOPE.999999_d.csv` 存在；
  - `prepare()` -> `checkUnbars()` 成功把该合约装入 `_unbars_cache`；
  - `run(false)` 进入日线主循环后调用 `simTickWithUnsubBars`。
- 期望行为: 对缺少 commodity 或 session 元数据的未订阅代码安全拒绝/跳过，并记录可诊断信息；
  不应在未验证查询结果前解引用。
- 实际行为: 代码先取
  `WTSCommodityInfo* commInfo = _bd_mgr.getCommodity(cInfo._exchg, cInfo._product);`（返回 NULL），
  随后 `if (commInfo->isStock() && cInfo.isExright())` 先解引用 `commInfo`，
  与右侧 `isExright()` 的短路顺序无关 —— 必然空指针崩溃。
- 测试边界: `DISABLED_UnknownCommodityUnsubBarsDerefsNullCommodity` 函数开头有
  `GTEST_SKIP()`，且用例默认禁用；即使显式运行禁用用例也会先跳过，不会创建 CSV、调用
  `sub_tick` 或进入回放。本次未动态触发空指针路径。
- 复现步骤（静态触发条件，未执行）:
  1. 在临时目录写入主K线日线 csv 与未知品种 `SSE.NOPE.999999_d.csv`；
  2. `init` 后注册 sink，`handle_init` 中请求主K线日线并 `sub_tick` 未知合约；
  3. `prepare()` 后 `run(false)`，崩溃点在 `simTickWithUnsubBars` 日线分支。
- 影响范围: 如果 `sub_tick` 接收未登记代码且其日线 CSV 被加载入 `_unbars_cache`，在触发
  日期时源码会解引用空 `commInfo`；即使对此处加判空，后续 `get_session_info()` 也可能
  返回 NULL，需一并验证。该边界对合法已登记合约不成立；当前接口没有明确声明未登记
  代码是合法还是调用方错误。
- 备注: 修复方向是先判 `commInfo`，再判 `get_session_info()`；未登记代码可安全跳过或让
  `prepare()`/订阅入口返回可诊断失败。对应 DISABLED 用例当前只是跳过占位，不是运行证据。
