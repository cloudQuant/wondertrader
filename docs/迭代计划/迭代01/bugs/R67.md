# R67 缺陷记录（第十三波 · HisDataReplayer / ExecMocker / HisDataMgr 补测）

> 只记录、不修复。两个条目均由公开 API 可触发的确定性输入推导得出，
> 对应用例为 `DISABLED_`，避免把整轮覆盖率度量拖入崩溃。

## BUG-R67-001

- 状态: 待审核
- 严重级别: Blocker（空 vector 下标访问，未定义行为，常见表现为段错误或读出垃圾K线）
- 模块/文件: `src/WtBtCore/HisDataReplayer.cpp:3699-3700`（`cacheFinalBarsFromLoader` 的 loader 成功臂）；
  同类问题另见 `:3662`（autoTrans dsb 命中但解压后 `barcnt==0`）
- 相关测试: `src/TestUnits/coverage/q02_btcore3/r67_replayer_loader_gap_test.cpp`
  `R67LoaderGap.DISABLED_EmptyLoaderSuccessDerefsEmptyBars`
- 输入/前置条件:
  - `HisDataReplayer::init(cfg, NULL, loader)`，`mode=csv`；
  - 自定义 `IBtDataLoader::loadFinalHisBars` **返回 true 但一次回调都不调用**（携带 0 条K线，
    属于接口允许的「成功但无数据」表达）；
  - `get_kline_slice("SSE.STK.000001", "d", 3, 1, true)`。
- 期望行为: `cacheFinalBarsFromLoader` 把「0 条」视为无数据并返回 false，`get_kline_slice` 返回 NULL；
  至少不能读取空 `std::vector`。
- 实际行为: 源码在 `bSucc==true` 后无条件执行
  `uint64_t stime = isDay ? barsList->_bars[0].date : barsList->_bars[0].time;`
  以及 `etime = ... _bars[_count - 1] ...`。此时 `_count==0`、`_bars` 为空，
  `operator[]` 越界是 UB（libc++ 调试模式直接断言，发布模式读垃圾内存）。
  同一函数上方 dsb 分支在 `barcnt==0` 时也执行同样的 `_bars[0]` 访问。
- 复现步骤:
  1. 用临时目录构造 csv 模式配置并注册上述 loader；
  2. `prepare()` 后请求日线切片；
  3. 观察 UB（或 ASan 的 heap-buffer-overflow）。
- 影响范围: 任何「loader 成功但当日/该周期无数据」的扩展数据源都会踩中；
  与 BUG-P04-004（空 csv）同属「空序列仍取首尾元素」家族，但触发面在 loader 接缝。
- 备注: 阻塞该函数 0 条数据分支的覆盖率；建议修复方向为 `_count==0` 时返回 false，
  并让 dsb 分支同样判 `barcnt==0`。

## BUG-R67-002

- 状态: 待审核
- 严重级别: Blocker（空指针解引用）
- 模块/文件: `src/WtBtCore/HisDataReplayer.cpp:1476-1479`（`simTickWithUnsubBars` 日线分支）
- 相关测试: `src/TestUnits/coverage/p07_btcore_replayer2/r67_replayer_bars_gap_test.cpp`
  `R67CsvBars.DISABLED_UnknownCommodityUnsubBarsDerefsNullCommodity`
- 输入/前置条件:
  - csv 模式、`tick=false`；
  - 主K线为已登记品种（`SSE.STK.600000`）；
  - `sub_tick(5, "SSE.NOPE.999999")`，且 `csv/SSE.NOPE.999999_d.csv` 存在；
  - `prepare()` -> `checkUnbars()` 成功把该合约装入 `_unbars_cache`；
  - `run(false)` 进入日线主循环后调用 `simTickWithUnsubBars`。
- 期望行为: 未在 commodity 底座登记品种的未订阅合约应被跳过（或至少判空后跳过模拟tick）。
- 实际行为: 代码先取
  `WTSCommodityInfo* commInfo = _bd_mgr.getCommodity(cInfo._exchg, cInfo._product);`（返回 NULL），
  随后 `if (commInfo->isStock() && cInfo.isExright())` 先解引用 `commInfo`，
  与右侧 `isExright()` 的短路顺序无关 —— 必然空指针崩溃。
- 复现步骤:
  1. 在临时目录写入主K线日线 csv 与未知品种 `SSE.NOPE.999999_d.csv`；
  2. `init` 后注册 sink，`handle_init` 中请求主K线日线并 `sub_tick` 未知合约；
  3. `prepare()` 后 `run(false)`，崩溃点在 `simTickWithUnsubBars` 日线分支。
- 影响范围: 任意「有K线文件但 commodity 未登记」的未订阅合约（拼写错误的品种、临时增加的数据源）
  都会让整轮回测崩溃；分钟分支无此解引用（不取 commInfo）。
- 备注: 阻塞 `_unbars_cache` 日线分支的异常输入覆盖；建议先判 `commInfo != NULL`。

  已由 `BUG-P07-007` 登记，本 lane 只复用其 dsb 分支，不重复。
- `HisDataMgr::init` 在模块装载失败后解引用 NULL `_reader` —— 已由 `BUG-R20-*` / `BUG-N04-002` 登记，
  本 lane 不触碰该入口。
