## BUG-R44-001 StateMonitor::initialize 重入时不清空 _map（重入契约待确认）

- 迭代02第二轮前状态（历史）: - 状态: 待验证（重入后的残留行为由源码/用例定义；是否支持同实例重配未确认）
- 状态: 已撤回（迭代02：NOT_BUG，原产品主张不成立）
- 严重级别: 中（仅同一实例重复 initialize 且应替换配置时影响）
- 模块/文件: `src/WtDtCore/StateMonitor.cpp:107`（`_map[stateInfo->_session] = stateInfo`，函数内无 `_map.clear()`）
- 相关测试: 原 `ReinitializeKeepsRemovedSessionInStateTable` 将二次成功和旧会话保留固化为期望；现改为 `DISABLED_ReinitializeSemanticsNeedContract`，不对未定义的重入语义做断言。
- 输入/前置条件: 第一次 initialize 配置 `{"SSE": {...}}`；第二次 initialize 只配置 `{"SHFE": {...}}`（同一 StateMonitor 实例，会话模板表同时含 SSE/SHFE）
- 期望行为: 待确定重复初始化是替换、合并还是拒绝；只有选择替换语义时才能要求旧 SSE 从状态表移除。
- 实际行为: 源码对新配置执行 `_map[key] = stateInfo` 而不清除旧表；此前测试观察过 SSE 残留。该观察不证明重入契约。
- 复现步骤: 历史测试先配置 SSE、再配置 SHFE 并查询 SSE；该现状式用例现已禁用，等待合同确定后重建。
- 影响范围: 只有同一对象二次 initialize 且调用者期待“替换配置”时才会保留旧会话。`WtDtRunner.cpp:192` 与 `QuoteFactory/main.cpp:193` 中查到的是启动初始化调用，未找到生产热重载/重复调用路径。不得把转历史等下游影响写成已观察事实。
- 修复方向: 先明确接口是一次性初始化还是支持 reload；若只允许一次，应在第二次调用时返回 false 并记录；若支持 reload，应解析到临时 map 后在成功时原子替换，避免失败配置清掉现有状态。用例应覆盖所选契约，不应只锁定当前残留行为。

- 输入/前置条件: 同一 ParserAdapter 先 `initExt("id", api1)`，再 `initExt("id", api2)`

- 修复方向: 明确 initExt 是否一次性；若一次性，加已初始化守卫并保证失败时所有权语义清楚；若允许替换，先停止/释放旧 API，再接管新 API。不要将重入测试的历史现状当成已确认产品合同。
