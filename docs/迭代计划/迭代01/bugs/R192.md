# R192 缺陷记录（第二十七波 · WtCore ticker / 调度残余面）

- Lane: R192
- 日期: 2026-10-28
- 生产代码: 未修改
- 说明: 本轮只读核对生产代码与公开 API，不修复生产缺陷；以下条目均待审核。

## BUG-R192-001 WtEngine::get_adjusting_flag 丢弃数据管理器返回值，复权 flag 位恒为 0

- 状态: 待审核
- 严重度: 中（后复权 tick 的量/额/持仓字段不复权，价格与量纲不一致）
- 位置: `src/WtCore/WtEngine.cpp:771-777`
- 现象:
  ```cpp
  uint32_t WtEngine::get_adjusting_flag()
  {
      if (_data_mgr)
          _data_mgr->get_adjusting_flag();   // 返回值被丢弃
      return 0;
  }
  ```
  `WtDtMgr::get_adjusting_flag()`（`WtDtMgr.cpp:263-275`）会缓存并返回
  `IDataReader::getAdjustingFlag()`，但这里没有 `return` 它，函数恒返回 0。
  因此 `WtSelEngine::on_tick` 的后复权分支中 `if (flag & 1)` / `(flag & 2)` /
  `(flag & 4)` 三个块（`WtSelEngine.cpp:189-206`）永远不执行：后复权 tick 只调整
  OHLC，`total_volume/volume`、`total_turnover/turn_over`、
  `open_interest/diff_interest/pre_interest` 全部保持原值；
  `WtHftEngine::on_tick` 更是完全没有处理这三个 flag 位。
- 复现: `r192_wtcore_ticker_residual_test.cpp` 中
  `R192SelEngine.DISABLED_HfqFlagBitsScaleVolumeTurnoverAndInterest`：
  用 `R192FlagDtMgr` 覆写 `get_adjusting_flag()=7`，HOT 规则 factor=2，
  后复权订阅 `SHFE.ag.2512`。期望量字段 /2、额字段 *2、持仓字段 /2；
  当前只有 OHLC 被乘 2，量额持仓不变（用例禁用）。
- 影响面: 所有依赖 `get_adjusting_flag()` 的引擎级复权逻辑；也是
  `WtSelEngine.cpp` 剩余 17 行不可覆盖的直接原因。
- 建议: 改为 `return _data_mgr->get_adjusting_flag();`（或先取回再返回），
  并为 flag&1/2/4 三个分支补回归用例；`WtHftEngine` 同步补齐量额持仓复权。

## BUG-R192-002 WtSelEngine::on_minute_end 用局部 StdThreadPtr 包 std::thread，任何到期任务都会 std::terminate

- 状态: 待审核
- 严重度: 高（进程级 abort，调度任务完全不可用）
- 位置: `src/WtCore/WtSelEngine.cpp:329-336`
- 现象:
  ```cpp
  StdThreadPtr thrd(new StdThread([ctx, curDate, curTime, nextTime](){ ... }));
  tInfo->_last_exe_time = now;
  ```
  `StdThread` 是 `std::thread` 的 typedef（`src/Share/StdUtils.hpp:23`），
  `StdThreadPtr` 是 `std::shared_ptr<std::thread>`。局部 `thrd` 在循环迭代结束时
  析构；`std::thread` 析构函数对 joinable 线程直接调用 `std::terminate()`，
  既没有 `join()` 也没有 `detach()`。
- 复现: 任一 TPT_Daily/Monthly/Weekly/Yearly/TPT_Minute 任务命中时间即触发；
  公开入口 `addContext` + `on_minute_end` 即可。因启用即 abort，本轮未新增
  可运行的复现用例，保留为 `DISABLED_` 记录的候选（与既有 BUG-R10 同源）。
- 影响面: `WtSelEngine.cpp` 剩余 32 行调度相关代码（265-336）在测试中不可达。
- 建议: 将线程对象存入任务表/引擎成员，或在 `new StdThread` 后立即
  `detach()`；更稳妥的是复用引擎任务线程而非每个任务起线程。

## BUG-R192-003 调度任务 id 与上下文 id 空间不一致，on_schedule 永远拿不到 ctx

- 状态: 待审核
- 严重度: 中（即使修复线程生命周期，定时任务也不会回调策略）
- 位置: `src/WtCore/WtSelEngine.cpp:402-415`、`:329-333`；
  `src/WtCore/SelStraBaseCtx.cpp:35-51`、`SelStraBaseCtx.h:202`
- 现象: `addContext` 把上下文存进 `_ctx_map[ctx->id()]`（实际 id 从 3000 起），
  但 `TaskInfo::_id = makeTaskId()`（从 1 起）是另一个自增序列；
  `on_minute_end` 触发时执行 `getContext(tInfo->_id)`，用 1/2/... 去查 3000+ 的 map，
  恒返回空 `SelContextPtr`。因此 lambda 里的 `if (ctx) ctx->on_schedule(...)`
  永远不会执行，`schedule_fires` 永远为 0。
- 复现: 设计中的 `DISABLED_` 用例：注册 TPT_Daily 任务后调用
  `on_minute_end(20250110,930)`，期望 `schedule_fires==1`；实际先触发
  BUG-R192-002 的 abort，即便绕过线程问题 `ctx` 也为空。
- 建议: `TaskInfo` 直接保存 `ctx->id()`（或让 `_tasks` 以 `_id` 为键并在
  `addContext` 时统一两套 id）；补一条定时任务回调计数用例。

## BUG-R192-004 WtCtaRtTicker::on_tick 用函数级 static 保存分钟换算，跨实例/跨 session 污染

- 状态: 待审核
- 严重度: 中（同进程多 ticker 时分钟数/收盘时间可能串用上一个实例的 session）
- 位置: `src/WtCore/WtCtaTicker.cpp:87-108`
- 现象:
  ```cpp
  static uint32_t prevMin = UINT_MAX;
  static uint32_t minutes = UINT_MAX;
  static bool isSecEnd = false;
  static uint32_t wrapMin = UINT_MAX;
  if (prevMin != curMin) { minutes = _s_info->timeToMinutes(curMin); ... }
  ```
  `prevMin/minutes/isSecEnd/wrapMin` 是函数级静态变量，被所有
  `WtCtaRtTicker` 实例共享。若两个 ticker 的 session 不同、却先后收到同一
  `curMin`（如都要处理 23:59），第二个实例会直接复用第一个实例按另一 session
  算出的 `minutes` 和 `wrapMin`，导致 `_cur_pos` 与平台时间错位。
- 触发条件: 同一进程创建两个以上 `WtCtaRtTicker`（回测/多组合、或测试套件中
  多个用例复用同一进程）且分钟序列重叠。
- 建议: 把四个变量改为 `WtCtaRtTicker` 的成员；同时修正 `_time` 的单位约定
  （on_tick 写 HHMMSSmmm，run 内 `set_date_time(_date, thisMin, 0)` 写 HHMM），
  避免跨实例状态泄漏。
