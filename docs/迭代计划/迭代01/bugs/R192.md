## 复核裁定

| 原条目 | 分类 | 裁定与修复方向 |
|---|---|---|
| BUG-R192-001 WtEngine 丢弃 adjusting flag | **真实源码缺陷；重复 BUG-P02-003** | WtEngine::get_adjusting_flag 调用 data manager 后固定 return 0。Sel 与 CTA 引擎都消费此标志；现有 R211 测试只验证 accessor 结果为 0，不能证明所有字段复权影响。HFT 当前不消费该标志，不把它列为影响路径。修复方向是返回 data manager 的值，并分别覆盖真实消费者及 flag 位语义。 |
| BUG-R192-002 Sel 调度线程局部析构时仍 joinable | **真实源码缺陷；重复 BUG-R10-004** | WtSelEngine::on_minute_end 创建局部 StdThreadPtr，离开循环作用域前没有 join/detach；StdThread 为 std::thread，其 joinable 析构会调用 std::terminate。此为标准语义和静态路径结论；本 lane 没有启用运行到到期任务的测试，不能写成动态复现。应复用受管任务线程或明确管理线程生命周期，并用实际到期回调验收。 |
| BUG-R192-003 TaskInfo id 与 context id 混用 | **源码可见的独立关联缺陷；运行效果未验证** | addContext 用 ctx->id() 存 _ctx_map，任务以 makeTaskId() 生成 TaskInfo::_id；调度时再把 TaskInfo::_id 传给 getContext。两者是不同计数器，源码未建立映射，因此普通任务不能保证取回所属 ctx；不可称“恒空”，因数值偶然碰撞并未排除。R192 计划的禁用用例会先被线程问题中断，未证明回调次数。修复方向是 TaskInfo 保存 ctx->id()，或在任务对象上保存 context 引用；再用多个 context/任务验证对应回调。 |
| BUG-R192-004 CTA ticker 函数级 static 分钟缓存 | **真实共享状态风险；动态影响证据不足** | prevMin/minutes/isSecEnd/wrapMin 是 WtCtaTicker.cpp::on_tick 的函数静态变量，所有实例共用；使用不同 session 的多个实例若遇到相同 curMin，后来的实例可能复用前一实例换算值；并发访问这些可变静态量也缺同步。保存的 R211 CTA ticker 用例为 CRASH，不能当作此问题的动态证明。修复方向是改成每实例成员并添加两个不同 session ticker 的测试。 |
| 原文附加的 _time 单位不一致说明 | **撤回，非缺陷** | on_tick 保存 actiontime 的 HHMMSSmmm；run 的 _time = thisMin * 100000 还原同一单位；传给 engine 的 set_date_time 参数则是引擎接口使用的 HHMM 分钟值。这是有意转换，不作为此条修复项。 |
