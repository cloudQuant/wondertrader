## BUG-R91-001 checkOrderDetails / checkOrderQueues 缺数据时写错缓存，污染 trans 缓存

- 编号: BUG-R91-001
- 状态: 待审核
- 模块/文件/行:
  - `src/WtBtCore/HisDataReplayer.cpp:2729-2739`（`checkOrderDetails` 的 `!hasData` 分支，
    实际写入 `_trans_cache[stdCode]`）
  - `src/WtBtCore/HisDataReplayer.cpp:2771-2781`（`checkOrderQueues` 同样写入 `_trans_cache`）
  - 受影响读取：`HisDataReplayer.cpp:2786-2825`（`checkTransactions`）、`2643-2688`
    （`get_transaction_slice`）
- 相关测试: `src/TestUnits/coverage/q02_btcore3/r91_replayer_bin_hft_test.cpp`
  `R91BinHft_DISABLED_OrderDetailCacheMissPoisonsTransactionCache`
- 输入/前置条件:
  1. `mode=bin`，`prepare()` 后当前交易日 20200102；
  2. 临时存储中只有 `his/trans/SSE/20200102/000003.dsb`（两条成交 20.1/20.2），
     没有 `his/orders/SSE/20200102/000003.dsb`；
  3. `get_order_detail_slice("SSE.STK.000003", 2, 202001020933)` 先执行（返回 NULL）。
- 期望行为: 缺少委托明细只应把 `_orddtl_cache` 标记为当日空；随后
  `get_transaction_slice("SSE.STK.000003", 2, 202001020932)` 应从磁盘装载并返回两条成交
  （20.1/20.2）。
- 实际行为: `checkOrderDetails` 在无数据分支执行
  `auto& dataList = _trans_cache[stdCode]; dataList._items.resize(0); ... _date = uDate; _count = 0;`
  把**成交缓存**伪造成「当日已装载的空列表」。`checkTransactions` 看到 `_date == uDate`
  后直接返回 true，不再调用 `cacheRawTransFromBin`；`get_transaction_slice` 在空 vector 上
  继续按 `_cursor = UINT_MAX` 计算，返回 NULL（`items.data()` 为空）或越界切片，
  磁盘上的两条成交永远不可见。`checkOrderQueues` 是同一份复制粘贴错误，缺 queue 时
  同样会踩坏 trans 缓存。
- 复现步骤:
  1. 按上述夹具在覆盖率构建中启用 `DISABLED_` 用例；
  2. 先取 order detail（NULL），再取 transaction；
  3. `ASSERT_NE(nullptr, slice)` / `ASSERT_EQ(2u, slice->size())` 失败（实际 NULL）。
- 严重级别: Major（公开 API 在「Level2 某一类数据缺失」的常见场景下静默丢失另一类数据；
  若空 vector 的 `data()` 非空则退化为越界读）
- 备注: 修复方向是把两处 `_trans_cache` 分别改为 `_orddtl_cache` / `_ordque_cache`。
  本 lane 不修，仅归档。

## BUG-R91-002 bin K线装载失败后留下未初始化 `_period` 的空 BarsList

- 编号: BUG-R91-002
- 状态: 待审核
- 模块/文件/行:
  - `src/WtBtCore/HisDataReplayer.cpp:4497-4500`（进入 `cacheRawBarsFromBin` 即
    `_bars_cache[key].reset(new BarsList)`）
  - `src/WtBtCore/HisDataReplayer.cpp:4560-4567`（loader/HisDtMgr 都失败且 buffer 为空时
    直接 `return false`，空 BarsList 留在缓存里）
  - `src/WtBtCore/HisDataReplayer.h:321`（`_BarsList` 构造函数未初始化 `_period`）
  - 触发点：`HisDataReplayer.cpp:684-711`（`run()` 自动挑选主K线时读取每个缓存项的 `_period`）
- 相关测试: 无启用用例。该分支读取的是未初始化标量（UB），无法写成确定性断言；
  由 `R91BinBars_MissingBinBarsYieldNullSlice` 的只读审阅路径发现（该用例本身不调用 `run()`，
  以免触发 UB）。
- 输入/前置条件:
  1. `mode=bin`，`prepare()`；
  2. `get_kline_slice("SSE.STK.600000", "d", 3, 1, false)`，但存储中没有
     `his/day/SSE/600000.dsb`（返回 NULL，同时 `_bars_cache` 多出一个空 `BarsList`）；
  3. 不显式请求任何有效主K线，直接 `run(false)`。
- 期望行为: 装载失败不应留下可被 `run()` 选中的半成品缓存；至少 `_period` 应有确定值，
  或失败时把该 key 从 `_bars_cache` 中移除。
- 实际行为: 空 `BarsList` 的 `_period` 是未初始化枚举。`run()` 在 `_main_key.empty()`
  时遍历 `_bars_cache` 并执行 `if (barsList->_period < minPeriod)`，读到不确定值：
  可能把该空缓存选成主K线，随后 `run_by_bars` 用空 `_code` 取 session/切片，
  进入空指针或空 vector 的未定义路径；也可能只是静默选错主K线。
- 复现步骤:
  1. 临时 bin 存储留空；
  2. `init` + `prepare` + 一次失败的 `get_kline_slice`；
  3. `run(false)`；在 ASan/UBSan 或 libc++ 调试模式下观察未初始化读/空 vector 访问。
- 严重级别: Major（公开 API 的普通「无数据」路径即可把进程带入 UB；影响自动主K线选择）
- 备注: 修复方向是失败时 `_bars_cache.erase(key)`，并在 `_BarsList` 构造函数中初始化
  `_period(KP_DAY)`。本 lane 不修，仅归档。

## BUG-R91-003 get_order_detail/queue/transaction_slice 在 etime 不早于最后一笔时越界读

- 编号: BUG-R91-003
- 状态: 待审核
- 模块/文件/行:
  - `src/WtBtCore/HisDataReplayer.cpp:2578-2592`（`get_order_detail_slice`）
  - `src/WtBtCore/HisDataReplayer.cpp:2626-2640`（`get_order_queue_slice`）
  - `src/WtBtCore/HisDataReplayer.cpp:2674-2688`（`get_transaction_slice`）
- 相关测试: 无启用用例。越界读的结果依赖堆内存布局，不能写成确定性断言；
  ASan 下可用下述输入稳定报 heap-buffer-overflow。
- 输入/前置条件:
  1. 当日 orders/queue/trans 缓存各有 3 条（931/932/933）；
  2. `prepare()` 后 `_cur_date/_cur_time` 为 20200102 09:30；
  3. 调用 `get_order_detail_slice(code, 3, 202001021500)`（etime 晚于全部数据），
     queue/trans 同理。
- 期望行为: lower_bound 落在 `end()` 时应把 `eIdx` 夹到 `size()-1`，返回最后 3 条。
- 实际行为: `std::lower_bound` 返回 `end()` 时 `idx == size`，代码写
  `_cursor = idx + 1`（= size+1），随后 `eIdx = _cursor - 1`（= size），
  `sIdx = eIdx + 1 - count`。以 size=3、count=3 为例：sIdx=1、realCnt=3，
  最终 `create(code, items.data() + 1, 3)` 读取 items[1]/[2]/[3]，最后一条越过
  vector 末尾（size=3 时合法下标只到 2）。count=2 时读 items[2]/[3]，同样越界。
- 复现步骤:
  1. 写 3 条 orddtl（或 ordque/trans）到临时 bin 存储；
  2. `prepare()` 后调用 `get_order_detail_slice(code, 3, 202001021500)`；
  3. 在 ASan 构建中读取 `slice->at(2)`，报 heap-buffer-overflow。
- 严重级别: Major（公开切片 API 的默认 `etime=0` 在收盘后/缓存尾部同样会走到 end()，
  越界读可能返回垃圾数据或崩溃）
- 备注: tick 切片使用 `eIdx = _cursor - 2`（L2534）避开了这个问题；三处 Level2
  切片可参照修正。本 lane 的切片用例刻意把 etime 放在最后一笔之前，避免触发。
  本 lane 不修，仅归档。
