## BUG-R42-001 WtSelEngine 构造未初始化 `_tm_ticker`，析构/release() 读取未初始化指针

- 状态: 待审核（源码确认未初始化读取；禁用用例未运行）
- 严重级别: Major
- 模块/文件: `src/WtCore/WtSelEngine.cpp:33-37`（构造函数初始化列表只有 `_terminated`、`_cfg`）、`:45-56`（`release()` 中 `if (_tm_ticker)` 后 `_tm_ticker->stop()` / `delete`）；成员声明 `src/WtCore/WtSelEngine.h:94`（`WtSelRtTicker* _tm_ticker;` 无默认值）
- 相关测试: `src/TestUnits/coverage/p02_wtcore_engines2/r42_sel_ctx_test.cpp::DISABLED_DestroyWithoutInitReadsUninitializedTicker`（默认禁用）；该 lane 的 SEL 夹具因此故意不 delete 引擎实例
- 输入/前置条件: `new WtSelEngine()` 后不调用 `init()`，直接 `delete`
- 期望行为: `_tm_ticker` 初值为 `nullptr`；`release()` 判定为空后直接返回，`delete` 安全
- 实际行为: `if (_tm_ticker)` 读取未初始化值；若为随机非空，`stop()` 在野指针上做虚调用，随后 `delete` 野指针 —— 未定义行为（崩溃或内存破坏）
- 触发步骤: `new WtSelEngine()` 后不调用 `init()` 并析构会读取未初始化成员；这是源码级 UB 判断，本次未运行。ASan 通常不检测未初始化值，不能把 ASan/MallocScribble 描述为稳定复现证据；如需动态确认，应使用 MemorySanitizer 或受控初始化/poison 检查。
- 影响范围: 任何合法的构造后直接析构路径（例如 init 失败后的清理）均可能遇到未定义行为；仓库内具体是否有该失败清理路径尚未追到，不把选择器启动失败写成已观察现象。
- 备注: HFT 版本（`WtHftEngine::WtHftEngine`）显式把 `_tm_ticker` 置 NULL，Sel 版本漏了。建议构造函数补 `_tm_ticker(NULL)`。

## BUG-R42-002 HftStraBaseCtx 未初始化 `_ud_modified`；`_trader` 依赖绑定且部分接口无守卫

- 状态: 待审核（`_ud_modified` 为源码确认的未初始化读取；`_trader` 在未绑定后调用时有风险）
- 严重级别: Major（上下文被注册但 trader 未绑定时，策略若调用无守卫交易接口会触发 UB）
- 模块/文件: `src/WtCore/HftStraBaseCtx.cpp:41-48`（构造函数初始化列表只含 `_engine/_slippage/_data_agent/_context_id`）；成员声明 `HftStraBaseCtx.h:673`（`TraderAdapter* _trader;`）、`:686`（`bool _ud_modified;`）均无默认值
- 相关测试: `src/TestUnits/coverage/p02_wtcore_engines2/r42_hft_ctx_test.cpp::UserDataFlushedByCallbacksAndReloaded`（每次回调前先调用 `stra_save_user_data`，所以不会覆盖初始未修改状态）；`LogsSubscriptionsMetadataAndSessionEnd`。本次未运行。
- 输入/前置条件: 两个独立边界：①构造后未调用 `stra_save_user_data` 就收到 `on_tick/on_bar/on_order/on_channel_*`，读取未初始化 `_ud_modified`；②`setTrader` 未执行却调用 `stra_cancel/stra_enter_long/stra_exit_long` 等无判空接口。`WtRunner.cpp:346-358` 找不到 trader 时只记日志，仍把上下文加入引擎；该策略随后是否调用交易 API 取决于策略行为。
- 期望行为: `_trader == nullptr`、`_ud_modified == false`；未绑定 trader 时所有交易 API 都应以明确失败值返回或按已声明契约拒绝上下文注册。
- 实际行为: 1) `_ud_modified` 在构造、`on_init()`/`load_userdata()` 中均未赋初值；例如 `on_tick` 在 :143-149 直接读取，只有 `stra_save_user_data` 在 :720-723 才置 true。2) `_trader` 未在构造中初始化；`stra_cancel`（:188 起）及 enter/exit 系列（:325-414）直接解引用。`WtRunner` 的未绑定分支仍会加入上下文，因此若策略继续调用这些接口就有未定义行为；正常绑定路径会先调用 `setTrader`。
- 触发步骤: ①构造并 `on_init()`，不调用 `stra_save_user_data`，直接调用基类 `on_tick(code, nullptr)`；②单独验证未绑定交易接口前，先准备有效 fake engine，再调用 `stra_enter_long`/`stra_cancel`。原 R42 回调测试不是①的证据，因为它在 `on_tick` 前已将 `_ud_modified` 设为 true。两条均未在本次运行；ASan 不保证捕获未初始化读取。
- 影响范围: 任一 HFT 基类回调在用户数据未被修改时都读 `_ud_modified`；未绑定 trader 的上下文仍会被 Runner 注册，调用无守卫交易接口时可触发 UB。未验证用户数据在某次运行中实际被错误覆盖/丢失，也未确认仓内策略存在缺失 trader 配置。
- 修复方向: 构造函数或成员默认初始化 `_trader(nullptr)`、`_ud_modified(false)`；所有交易 API 对空 trader 一致返回失败，并由 Runner 明确选择未绑定时拒绝注册还是允许只读策略。
