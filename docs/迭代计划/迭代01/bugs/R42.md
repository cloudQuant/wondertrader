## BUG-R42-001 WtSelEngine 构造未初始化 `_tm_ticker`，析构/release() 读取未初始化指针

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtCore/WtSelEngine.cpp:33-37`（构造函数初始化列表只有 `_terminated`、`_cfg`）、`:45-56`（`release()` 中 `if (_tm_ticker)` 后 `_tm_ticker->stop()` / `delete`）；成员声明 `src/WtCore/WtSelEngine.h:94`（`WtSelRtTicker* _tm_ticker;` 无默认值）
- 相关测试: `src/TestUnits/coverage/p02_wtcore_engines2/r42_sel_ctx_test.cpp::DISABLED_DestroyWithoutInitReadsUninitializedTicker`（默认禁用）；该 lane 的 SEL 夹具因此故意不 delete 引擎实例
- 输入/前置条件: `new WtSelEngine()` 后不调用 `init()`，直接 `delete`
- 期望行为: `_tm_ticker` 初值为 `nullptr`；`release()` 判定为空后直接返回，`delete` 安全
- 实际行为: `if (_tm_ticker)` 读取未初始化值；若为随机非空，`stop()` 在野指针上做虚调用，随后 `delete` 野指针 —— 未定义行为（崩溃或内存破坏）
- 复现步骤: 1) `WtSelEngine* e = new WtSelEngine();` 2) `delete e;`（不调用 init）；在 ASan/MallocScribble 下可稳定暴露
- 影响范围: 选择器进程启动失败、配置解析异常退出、测试/工具中短暂构造 WtSelEngine 的场景；与是否连柜台无关
- 备注: HFT 版本（`WtHftEngine::WtHftEngine`）显式把 `_tm_ticker` 置 NULL，Sel 版本漏了。建议构造函数补 `_tm_ticker(NULL)`。

## BUG-R42-002 HftStraBaseCtx 构造后 `_trader` 与 `_ud_modified` 未初始化

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtCore/HftStraBaseCtx.cpp:41-48`（构造函数初始化列表只含 `_engine/_slippage/_data_agent/_context_id`）；成员声明 `HftStraBaseCtx.h:673`（`TraderAdapter* _trader;`）、`:686`（`bool _ud_modified;`）均无默认值
- 相关测试: `src/TestUnits/coverage/p02_wtcore_engines2/r42_hft_ctx_test.cpp::UserDataFlushedByCallbacksAndReloaded`（构造 + 回调路径）；`r42_hft_ctx_test.cpp::LogsSubscriptionsMetadataAndSessionEnd`
- 输入/前置条件: 未调用 `setTrader()`，直接构造 `HftStraBaseCtx`；随后调用 `on_tick/on_bar/on_order/on_channel_*` 或任何 `stra_buy/sell/enter/exit`
- 期望行为: `_trader == nullptr`、`_ud_modified == false`；未注入 trader 时下单接口返回空并不解引用
- 实际行为: 1) 各回调 `if (_ud_modified)` 读取未初始化 bool，可能在本轮无需落盘时触发 `save_userdata()`，也可能漏存；2) `stra_enter_long/stra_exit_long`（`HftStraBaseCtx.cpp:325-414`）无判空直接 `_trader->openLong/closeLong`，未注入 trader 时在随机指针上做虚调用
- 复现步骤: 1) 构造 `HftStraBaseCtx ctx(&engine, "x", false, 0);` 2) 不调 `setTrader` 3) 调 `ctx.on_tick(code, NULL)` 或 `ctx.stra_enter_long(code, 0, 1, "t")`；在 ASan/MallocScribble 下可稳定暴露
- 影响范围: 引擎装配顺序错误、纯回测/研究模式复用 HftStraBaseCtx、单元测试直接构造；`_ud_modified` 的随机读还会造成用户数据非预期落盘或丢失
- 备注: 建议构造函数补 `_trader(NULL)`、`_ud_modified(false)`，或成员就地初始化；下单接口补 `_trader` 判空（与 `stra_buy/stra_sell` 中已有的 `_trader &&` 风格保持一致）。

## BUG-R42-003 ParserAdapter::run 在 release 之后对已释放的 `_parser_api` 做虚调用（UAF，WtCore 版）

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件: `src/WtCore/ParserAdapter.cpp:214-235`（`release()` 中 `delete _parser_api` 后不置空；`run()` 只判 `== NULL` 后调 `connect()`）
- 相关测试: `src/TestUnits/coverage/p02_wtcore_engines2/r42_parser_adapter_test.cpp::InitExtHandlesApiStates`、`HandleQuoteConvertsMonthlyCodeAndFiltersInvalid`（均覆盖 release 生命周期；未启用 `run-after-release`，避免 UAF）
- 输入/前置条件: `initExt` 成功注入 api -> `release()` 成功 -> 再调用 `run()`
- 期望行为: `release()` 后将 `_parser_api`/`_remover` 置空并置 `_stopped`；`run()` 识别 `_stopped` 或空指针返回 false
- 实际行为: `_stopped` 只被 handle* 系列检查，`run()` 不检查；`_parser_api` 为悬垂指针，`connect()` 在已释放内存上分派虚函数 -> use-after-free
- 复现步骤: 1) `initExt("x", new FakeApi, stub, bdm)`；2) `release()`；3) `run()`；在 ASan 下报 heap-use-after-free
- 影响范围: 上层 stop/start、异常重连、配置热重载后误调 run 即触发；与 WtDtCore 同名问题（BUG-R44-004）同构，本次是 WtCore 实现
- 备注: 建议 `release()` 末尾 `_parser_api = nullptr; _remover = nullptr;`，`run()` 增加 `if (_stopped || _parser_api == NULL) return false;`。
