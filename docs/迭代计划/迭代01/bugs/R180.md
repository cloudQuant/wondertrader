## 复核：WtTWapExeUnit::do_calc 非配对释放行情引用（既有 BUG-R7-015）

- 状态: 已合并（主编号 BUG-R7-015；本条确认的源码所有权问题与主项同源，动态后果仍按主项证据边界处理）
- 严重度: 沿用 `BUG-R7-015`；对象池复用/进程崩溃的动态后果未由本 lane 证明
- 位置: `src/WtExeFact/WtTWapExeUnit.cpp:713-767`（`WTSTickData* curTick = _last_tick;`
- 现象: `on_tick` 替换 `_last_tick` 时释放旧成员引用，再对新 tick `retain()`；而
  `do_calc` 只复制裸指针到 `curTick`，发单臂末尾却额外 `release()`，没有对应的
  `retain()`。这会消耗该执行单元持有的引用，成员指针仍保留原值；若对象随后归还对象池，
  后续替换/析构可能重复释放。此源码模式已在 `bugs/R7_exefact.md` BUG-R7-015 记录。
- 动态证据边界: R180 manifest 明确本轮未运行测试二进制；本文件中的
  `DISABLED_R180Exec_TwapSecondTickReleasesDanglingLastTick` 也不足以复现所述时序。
  `_target_pos` 初始为 0，`handle_init` 时尚无 tick；首个 tick 在默认零仓位下不进入
  发单型 `do_calc`。用例仅喂两个 tick，第二个 tick 即使进入 `do_calc`，后面也没有第三个
  tick 去触发 `on_tick` 对已少一份引用对象的再次释放。用例尾部是无条件 `FAIL()`，因此
  不能写成“启用即崩溃”或将其视为动态复现。
- 测试结论: 该 `DISABLED_` 用例是无效复现夹具；保留的输入/断言不能证明运行时崩溃。
  若后续补回归，应先按真实持有方生命周期复核引用计数，并让发单成功后的行情对象失去
  外部引用，再由后续回调触达旧成员；本 lane 未运行此路径。
- 本轮规避: `r180_btcore_mockers2_test.cpp` 的 schedule/callback 用例刻意不调用
  `handle_init`，使 `_channel_ready=false`，`do_calc` 在 552 行提前返回，
  不会走到 767 行的 `release()`；`handle_init` 用例则在 `_last_tick` 仍为空时调用。
- 修复方向: 与 `BUG-R7-015` 一致，删除无配对的 `curTick->release()`；若实现需要局部强引用，
  应在安全持有 `_last_tick` 的条件下先 `retain()` 并只释放这份局部引用，不能释放成员所有权后
  继续保留悬垂成员指针。回归覆盖成功发单后下一次行情/析构的引用生命周期。
- 交叉引用: `bugs/R7_exefact.md` BUG-R7-015（主记录）；R180 manifest 的
  “第二个 tick 即崩溃”应随本复核更正，但该 manifest 不在本次可修改范围内。
