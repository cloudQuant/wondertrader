## BUG-R190-001 ExecMocker 加载真实 libWtExeFact 后进程 SIGSEGV，94 行成功路径不可安全覆盖（状态：待审核）

- 编号: BUG-R190-001
- 状态: 待审核
- 严重级别: Major（阻塞 `ExecMocker` 全部成功路径的公开面覆盖）
- 模块/文件/行:
  - `src/WtBtCore/ExecMocker.cpp:71-85`（工厂装载成功 + `createExeUnit/init`）
  - `src/WtBtCore/ExecMocker.cpp:140-161`（`handle_init`）
  - `src/WtBtCore/ExecMocker.cpp:168-192`（`handle_schedule`）
  - `src/WtBtCore/ExecMocker.cpp:270-274、286-335`（`cancel(stdCode)` 回调与 `_exec_unit` 转发的 entrust/order/trade）
- 现象:
  - 只要 `ExecMocker::init` 越过 `module` 装载与 `createExecFact` 解析、真正创建
    `IExecuterFact/_exec_unit`，测试进程即在 `CoverageTests_btcore` 内
    `CRASH(rc=139,sig=11)`；per-test 日志停在 `[ RUN ]`，没有 gtest 的 `[ OK ]`。
  - 同一崩溃族既覆盖合法单元名（`WtTWapExeUnit`/`WtMinImpactExeUnit`），也覆盖
    「工厂成功、cfg 无 executer」的 `R121ExecMocker.FactoryWithoutExecuter`，
    因此不能归因于单一 `executer.name` 拼写。
  - 作为对照，`CoverageTests_wtcore` 内 `R120DiffTest` 加载**同一份**
    `build_x64/Debug/bin/libWtExeFact.dylib` 并创建单元是通过的；差异在宿主
    执行体（btcov）与插件/`ExecMocker` 的组合，根因尚未定位到具体函数。
- 输入/前置条件:
  - `module` 指向本机构建产物 `libWtExeFact.dylib`（`nm -gU` 确认导出
    `_createExecFact`/`_deleteExecFact`）；
  - `executer.name` 为工厂真实注册的 `WtTWapExeUnit`、`WtMinImpactExeUnit`，
    或 cfg 中不带 `executer`；
  - 调用 `ExecMocker::init(cfg)`，随后在作用域结束析构，或调用任一 `_exec_unit`
    非空回调。
- 期望:
  - `init` 成功返回后，析构与 `handle_init/handle_schedule/handle_entrust/
    handle_order/handle_trade` 不应崩溃；若插件 ABI/生命周期不兼容，应在
    `init` 内记录错误并返回 false。
- 实际:
  - 进程在 `[ RUN ]` 之后直接 SIGSEGV，per-test profraw 为空被丢弃，导致
    `ExecMocker.cpp` 的 94 行即使被用例文本覆盖也拿不到计数器。
- 证据:
  - `build-cov/coverage/CoverageTests_btcore.results` 中以下判决均为
    `CRASH(rc=139,sig=11)`：
    `R111ExecMocker.EntrustOrderTradeAndReplayDump`、
    `R111ExecMocker.InitWithRealExecuterAndInitSchedule`、
    `R111ExecMocker.ScheduleNegativeAndPositiveVolumeModes`、
    `R121ExecMocker.FactoryWithoutExecuter`、
    `R180LoaderFixture.R180Exec_InitRealExecuterAndHandleInit` 等 4 条、
    `R20ExecMocker.BuyAfterTickAccumulatesUndone` 等 tick 后下单族。
  - `build-cov/coverage/CoverageTests_btcore.R121ExecMocker_FactoryWithoutExecuter.log`
    与 `...R180LoaderFixture_R180Exec_InitRealExecuterAndHandleInit.log` 均停在
    `[ RUN ]` 后，无断言失败输出。
  - 基线 `llvm-cov show` 显示 `ExecMocker.cpp` 的 71-85、140-161、168-192、
    270-274、286-335 全部为 0，与上述空 profraw 相互印证。
- 与既有缺陷的关系:
  - 未知单元名返回 NULL 后直接解引用已登记为 **BUG-R121-002**；
  - 策略工厂空指针族已登记为 **BUG-R111-001**；
  - `_exec_unit/_last_tick` 空指针族另见 **BUG-N04-001** 与 R20 的
    `DISABLED_ExecUnitNullDerefFamily`。
  - 本条不重复上述「未知名称」空指针；登记的是**合法配置仍崩溃**的未定位段。
- 测试处理:
  - 本轮不新增 ExecMocker 启用用例，也不新增会直接 SIGSEGV 的 `DISABLED_`
    复现（根因未定位，禁用用例无法提供可复核断言，且与 R111/R121/R180 证据重复）。
  - 待主控在 btcov 下复跑并用 lldb 抓栈顶后，再决定归入 ABI、插件生命周期
    还是 `ExecMocker` 析构顺序问题。
