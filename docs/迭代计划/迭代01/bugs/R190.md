## BUG-R190-001 的证据与边界

- 生产侧调用链：ExecMocker.cpp:74 把导出符号转成 FuncDeleteExeFact；ExecMocker.h:296 在 _fact 非空时调用 remover。
- 插件侧 ABI：src/WtExeFact/WtExeFact.cpp:42 按值接收 IExecuterFact*；类型定义却要求指针引用。Uft/CTA 工厂存在同类签名问题，见 BUG-R64-002 / BUG-R191-001；此处是执行器工厂的独立 typedef 与导出点。
- 后续本机观察：独立运行 `R111ExecMocker.InitWithRealExecuterAndInitSchedule` 仍 signal 11，输出止于 `[ RUN ]`。现有 R111 fixture 没有按正常 runner 顺序先注册 sink 再 prepare，手动调度的事件时间也与回放区间不一致；这些是独立的测试前提差异。没有崩溃栈，不能断言 ABI 或夹具任一项是本次崩溃的实际原因，也不能据此证明初始化成功。
- 既有 CoverageTests_btcore.results 包含 R111/R121/R180/R20 多条 CRASH，相关单测日志有的只显示 [ RUN ]，有的完成测试主体后进程退出失败。日志没有栈，因此只能作为动态失败证据，不能据此断言共同崩溃点或函数路径。
- 修复方向：令执行器 remover typedef 与插件导出完全同型，并在析构侧校验 remover；修复后用栈对象验证成功初始化、回调和作用域析构。不要以故意泄漏 mocker 作为最终析构验收。
