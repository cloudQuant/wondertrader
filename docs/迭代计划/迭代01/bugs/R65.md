## BUG-R65-002 TraderCTPOpt 持仓查询末行合约未登记时提前返回，跳过末帧聚合回调

- 状态: 本机替身测试复现跨批持仓污染；完整快照错误通知合同与真实柜台待验证
- 严重级别: 中（未知合约位于末帧时跳过收尾并污染后续查询；生产影响待验证）
- 模块/文件: `src/TraderCTPOpt/TraderCTPOpt.cpp:1164-1313`
  （`OnRspQryInvestorPosition`；提前返回在 `:1177-1179`，收尾聚合在 `:1289-1312`）
- 相关测试: `src/TestUnits/coverage/t_TraderCTPOpt/r61_traderctpopt_api_test.cpp` 的
  `R61_TraderCTPOpt.position_query_unknown_last_row_does_not_pollute_next_batch`，
  及 `position_query_covers_open_cover_combo_and_negative` 已知末帧对照。
- 输入/前置条件: 先推送一条已登记合约 `rb2610` 的非末帧持仓，再推送一条
  `InstrumentID="ghost"`（基础库查不到）的 `bIsLast=true` 帧
- 期望行为: 对无法解析的持仓明确报告不完整或失败，并结束本次查询、清理本批状态；
  不得把部分结果静默当成完整快照，也不得将其混入后续查询。具体错误通知及重试合同待确定。
- 静态行为: `contract == NULL` 时 `return`（`:1178-1179`），连 `bIsLast` 的
  `onRspPosition`、`m_mapPosition->release()` 都跳过；因此该末帧不会交付已经聚合的
  `rb2610`，map 也不会在该分支清理；函数开头的 `m_bInQuery = false` 则已执行，不能说所有状态推进都被跳过。
- 复现步骤（本地替身）:
  1. 用只登记 `rb2610` 的假 `IBaseDataMgr` 装配 `TraderCTPOpt` 并注册 sink；
  2. `OnRspQryInvestorPosition(rb2610 持仓, nullptr, 1, false)`；
  3. `OnRspQryInvestorPosition(ghost 持仓, nullptr, 1, true)`；首批两帧使用同一 request ID；
  4. 清空测试观察后发起 ID 为 2 的第二批，末帧为已登记的 `ag2610`，应仅包含本批合约。
- 本机结果: 重建 `CoverageTests_t_TraderCTPOpt` 后运行 `R61_TraderCTPOpt.position_query_*`，已知末帧控制 PASS；跨批隔离回归 FAIL，第二批期望合约集合 `{ag2610}`，实际为 `{ag2610, rb2610}`。XML 观察属性显示首批持仓回调次数为 0；这只是现状观察，并非期望永远不回调。真实 CTP 期权运行 NOT_RUN。
- 影响范围: 末行未知合约时不会向 sink 交付本批已聚合持仓。上层位置快照因此不会被
  本次查询更新，可能保留旧值或初始值；不能据此断言必然变为空仓。`TraderAdapter`
  在 `AS_LOGINED` 状态依赖 `onRspPosition` 进入 `AS_POSITION_QRYED` 并发起订单查询，
  此次缺失回调会绕过这一适配器状态推进；该影响由源码支持，本次没有运行真实 adapter 链路。
- 修正方向: 将行处理和末帧收尾分开；未知合约应标记查询不完整并走明确错误/重试路径，确保回调或错误通知、状态清理和持仓快照提交策略一致。不要简单将部分结果当完整成功回报；覆盖未知合约非末帧/末帧、空结果、连续查询和错误回报。
