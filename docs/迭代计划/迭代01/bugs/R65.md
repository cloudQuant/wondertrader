## BUG-R65-001 TraderMocker 开仓成功不写 `state_msg`，与平仓/HftMocker 语义不一致

- 状态: 待审核
- 严重级别: 低（状态文案缺失，不影响撮合与持仓）
- 模块/文件: `src/TraderMocker/TraderMocker.cpp:211-216`（开仓分支只置 `bPass=true`）、
  `:263-264`（只有平仓冻结分支写 `msg = "下单成功"`）、`:281`（`setStateMsg(msg.c_str())`）
- 相关测试: `src/TestUnits/coverage/t_TraderMocker/r60_tradermocker_async_test.cpp` 的
  `R60MockerTest.DISABLED_open_order_success_state_message`（原红用例
  `insert_open_order_dispatches_and_persists_positions_file` 的精确断言已移入该占位用例）
- 输入/前置条件: `init` + `connect` 后，用 `WDT_LONG/WOT_OPEN`、价格 7000、数量 2
  对 `ag2512` 下单，等待 `onPushOrder`
- 期望行为: 开仓与平仓一样给出 `state_msg = "下单成功"`；`HftMocker` 对开/平仓
  都写该文案（`src/WtBtCore/HftMocker.cpp:630/833`），同一仿真器族语义应一致
- 实际行为: 开仓分支在 `:211-216` 直接 `bPass=true; break`，`msg` 保持空串，
  `WTSOrderInfo::setStateMsg("")`；只有走到平仓冻结分支才在 `:263-264` 赋值
- 复现步骤:
  1. `TraderMocker api; api.init(cfg); api.connect();`
  2. 构造 `WTSEntrust`（开仓、限价、数量 2）并 `orderInsert`；
  3. 在 `onPushOrder` 中读 `WTSOrderInfo::getStateMsg()`，得到 `""`；
  4. 换一笔可平仓的委托，同一字段得到 `"下单成功"`
- 影响范围: 依赖 `state_msg` 做 UI 展示、日志对账或策略状态判断的宿主会把开仓成功
  显示为空状态；与 HftMocker 行为不一致，回测/仿真结果文案不可比
- 修正方向（仅供评审）: 开仓分支同样置 `msg = "下单成功"`，或把赋值提到
  `if(bPass)` 内统一执行

## BUG-R65-002 TraderCTPOpt 持仓查询末行合约未登记时提前返回，整批持仓丢失

- 状态: 待审核
- 严重级别: 高（查询结果静默丢失，持仓/可用量全部失真）
- 模块/文件: `src/TraderCTPOpt/TraderCTPOpt.cpp:1164-1313`
  （`OnRspQryInvestorPosition`；提前返回在 `:1177-1179`，收尾聚合在 `:1289-1312`）
- 相关测试: `src/TestUnits/coverage/t_TraderCTPOpt/r61_traderctpopt_api_test.cpp` 的
  `R61_TraderCTPOpt.DISABLED_position_query_last_row_unknown_still_flushes`
  （原红用例 `position_query_covers_open_cover_combo_and_negative` 的末行场景已移入）
- 输入/前置条件: 先推送一条已登记合约 `rb2610` 的非末帧持仓，再推送一条
  `InstrumentID="ghost"`（基础库查不到）的 `bIsLast=true` 帧
- 期望行为: 未知合约行可以跳过建仓，但函数尾部的 `bIsLast` 分支仍应执行：
  聚合 `m_mapPosition` 并通过 `onRspPosition` 回调，最后释放 map
- 实际行为: `contract == NULL` 时 `return`（`:1178-1179`），连 `bIsLast` 的
  `onRspPosition`、`m_mapPosition->release()` 都跳过；本场景回调的持仓数为 0，
  已聚合的 `rb2610` 从未交付，map 也泄漏到下一次查询
- 复现步骤:
  1. 用只登记 `rb2610` 的假 `IBaseDataMgr` 装配 `TraderCTPOpt` 并注册 sink；
  2. `OnRspQryInvestorPosition(rb2610 持仓, nullptr, 1, false)`；
  3. `OnRspQryInvestorPosition(ghost 持仓, nullptr, 2, true)`；
  4. `sink.positions` 为空（期望 1 条 `rb2610`）
- 影响范围: CTP 查询结果末行若来自已下市/未登记合约，整批持仓（含正常合约）全部
  丢失；上层 `getPosition/enumPosition`、平仓可用量与风控在查询后处于空仓状态
- 修正方向（仅供评审）: 把 `contract == NULL` 的 `return` 改为 `continue` 语义
  （跳过本行），或在 `return` 前补执行 `bIsLast` 的聚合/回调/清理

## 测试侧修正（不计产品缺陷）

以下按根因列出 8 项，涉及 7 条目标用例；均已按产品源码修正，未改产品：

1. `R59Buy.open_caps_quantity_by_remaining_long_and_total_limits`：
   `buy()` 先 `updateUndone(stdCode, qty)` 再按限额拆单，`getUndoneQty` 语义是
   「本次请求量」而非「截断后下单量」；期望 3.0 → 10.0（`vols_[0]` 仍断言 3.0）。
2. `R61_TraderCTPOpt.user_login_success_loads_ini_and_confirms_settlement`（回调时序）：
   `onLoginResult(true)` 延后到结算确认完成（`TraderCTPOpt.cpp:965/995`），
   登录应答后应为 0 条、确认完成后 1 条。
3. 同上（字符串比较）：`EXPECT_EQ("9999", char_array)` 混型退化为指针比较，
   改为 `EXPECT_STREQ`，期望文本不变。
4. `R62CtaMockerGap.SessionBeginUnfreezesAndEnumerationMergesSignals`：
   默认 `TM_Both` 不产生 T+1 冻结，夹具显式改 `TM_LongT1`。
5. `R62HftMockerGap.StockT1LifecycleWithTickProfitAndDump`：
   同上 `TM_LongT1`；浮盈 19.999999999999929/11.999999999999957 为 IEEE-754
   累积误差，改用 `EXPECT_NEAR(..., 1e-9)`。
6. `R62HftMockerGap.SubscriptionsSlicesAndUserDataDump` /
   `R62SelMockerGap.BarsLoadDailySliceAndSeedPrice`：
   `prepare()` 已把回放游标设到 `20200102 09:30`，`stra_get_date/time` 返回游标
   （`HisDataReplayer.cpp:662-664`、`HftMocker.cpp:947-955`、`SelMocker.cpp:903-911`），
   原期望 0u 是误解；改为 20200102/930。
7. `R62SelMockerGap.ScheduleAutoExitsUnsignalledPosition`：
   同 4，夹具显式改 `TM_LongT1`。
