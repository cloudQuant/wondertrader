# BUG-R52-001

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件: `src/WtDataStorage/WtDataReader.cpp`（`cacheIntegratedBars` L1019-1041、`cacheHisBarsFromFile` L1593-1608；抛点 `src/Share/StdUtils.hpp` L57-63）
- 相关测试: `src/TestUnits/coverage/q03_storage3/r52_reader_hot_adj_test.cpp` → `R52ReaderTest.R52HotWrappedFileReadAbortsIntegratedBars`
- 输入/前置条件: 配置里 `path` 指向一个含 `his/day/<exchg>/<exchg>.<product>_HOT.dsb` 的数据目录（即主力连续的「包裹文件」存在），通过 `readKlineSlice("SHFE.rb.HOT", KP_DAY, ...)` 读取；`HotMgr::splitCustomSections` 能正常返回切段。
- 期望行为: 先读入包裹文件得到 `hotAy` 与 `lastHotTime`，再按切段续接分月合约，最后把 `hotAy` 拼到尾部（这是 `cacheIntegratedBars` L1048-1058、L1250-1265 的设计意图）。
- 实际行为: L1019 声明了外层 `std::string filename`，但 L1021-1029 的 `for (const std::string& hisdir : _his_dir)` 循环体内又声明了一个同名局部变量 `std::string filename = fmtutil::format(...)`（L1023），存在性判断用的是内层变量、真正读取用的 L1035 `filename.c_str()` 仍是**外层空串**。`StdFile::read_file_content("")` 在 `StdUtils.hpp` L60-63 直接 `throw std::runtime_error("File does not exist")`；异常一路冒泡到 `cacheHisBarsFromFile` 的 `catch (const std::exception& ex)`（L1599-1602），只打一条 `缓存...连续...数据异常` 的 LL_ERROR 后 `return false`。结果：`_bars_cache` 里留下空条目，`readKlineSlice` 返回 `size()==0` 的切片（L1895-1905 的 `hisCnt != 0` 守卫兜住空 vector），切段函数一次都没被调用。
- 复现步骤: 已用沙箱数据构造上述输入并断言：`slice != NULL && slice->size() == 0 && get_block_counts() == 0`，`LL_ERROR >= 1`，`splitCustomSections` 调用次数为 0；第二次同 key 请求直接命中空缓存，仍返回空切片。
- 影响范围: 只要某品种的 HOT 包裹 `.dsb` 存在，`cacheIntegratedBars` 的**全部**历史 K 线装配（日线/分钟线、切段、复权、hotAy）都无法执行，策略侧看到的是「该主力连续合约没有任何历史数据」；且错误信息只有底层异常文本，不会指出是路径被遮蔽。`WtDataReader` 是目前实盘/回放读历史的主要入口，严重级别按 Blocker 登记。
- 备注: 修复方向：删除 L1023 的内层声明（改为 `filename = ...`），或把存在性判断与读取统一到同一个变量；同时建议 `cacheHisBarsFromFile` 的 catch 在返回 false 前清掉 `_bars_cache[key]` 的空条目，避免第二次请求静默命中空缓存。

# BUG-R52-002

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`（`readKlineSliceByRange` L1945-1965；`readKlineSliceByCount` L2352-2370）
- 相关测试: `src/TestUnits/coverage/r23_storage4/r52_rdm_hot_adj_test.cpp` → `R52RdmTest.DISABLED_R52ExrightRealtimeRangeBeyondTailOverrunsVector`
- 输入/前置条件: `cInfo._exright == 2`（代码如 `SSE.STK.600000+` 或 `SHFE.rb.HOT+`），当日 RT 分钟块存在，且请求的 `etime` 晚于块内最后一根 bar（例如块内只到 09:31，`etime=15:00`）。
- 期望行为: `idx` 应被夹在 `[0, _rt_bars.size()-1]`，`rtCnt` 不超过实际缓存条数；无重叠时返回块内全部数据。
- 实际行为: 该分支的 `std::lower_bound(_rt_bars.begin(), _rt_bars.end(), eBar, ...)` 用的是**全闭区间** `end()` 而不是 `end()-1`，目标时间晚于全部数据时返回 `end()` → `idx == size`；紧接着 L1952 `WTSBarStruct* pBar = &barsList._rt_bars[idx]` 越界读，L1963-1964 `rtCnt = idx + 1` 得到 `size+1`，再 `appendBlock(rtHead, rtCnt)` 多读一条记录。ByCount 分支 L2358-2369 同型（`idx` 可等于 size，`rtCnt=idx+1`）。非复权分支（L1872-1905）用的是 `_bars + (_size - 1)`，没有这个问题。
- 复现步骤: 构造 `rt/min1/SSE/600000.dmb` 两条 bar（09:30/09:31），调用 `readKlineSliceByRange("SSE.STK.600000+", KP_Minute1, 202401010000, 202401101500)`；`idx` 走到 2（size=2），随后越界读/多挂一条。用例已写成 `DISABLED_`，`--gtest_also_run_disabled_tests` 可复现。
- 影响范围: 后复权合约在盘中/回放里按「当前时间」取历史分钟线时（etime 通常晚于块内最后一根），会读到 vector 尾后内存并把脏数据追加进切片；轻则返回 `size+1` 条含垃圾的 bar，重则 ASan/调试构建直接崩溃。与 BUG-R52-003 同段，但这条不依赖首次拷贝。
- 备注: 修复方向：三处 `lower_bound` 都改成 `end() - 1` 并把结果夹紧；或在取 `idx` 后统一 `idx = min(idx, size ? size-1 : 0)`。

# BUG-R52-003

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`（`readKlineSliceByRange` 的 exright==2 分支 L1922-1942，`memcpy` 在 L1930）
- 相关测试: `src/TestUnits/coverage/r23_storage4/r52_rdm_hot_adj_test.cpp` → `R52RdmTest.DISABLED_R52ExrightRealtimeRangeBeyondTailOverrunsVector`
- 输入/前置条件: 后复权代码（`_exright == 2`）首次通过 `readKlineSliceByRange` 读取当日 RT 分钟块（`barsList._rt_bars` 尚为空，`oldSize == 0`）。
- 期望行为: 首次拷贝应把 RT 块的 `newSize` 条记录完整复制到刚 `resize(newSize)` 的 `_rt_bars` 中。
- 实际行为: L1930 `memcpy(&barsList._rt_bars[idx], &kPair->_block->_bars[idx], sizeof(WTSBarStruct) * (newSize - oldSize + 1));`。首次调用时 `idx = oldSize = 0`，长度算成 `newSize + 1`，而目标 vector 只有 `newSize` 个元素 → **堆缓冲区越界写一条 WTSBarStruct**（约 100 字节），同时源端也从 RT 块读一条 `_size` 之外的数据（块容量足够时是零填充，未必立刻崩）。ByCount 分支 L2337 写的是 `newSize - idx`，没有这个 +1。
- 复现步骤: 构造当日 `rt/min1/SSE/600000.dmb`（2 条），调用 `readKlineSliceByRange("SSE.STK.600000+", KP_Minute1, 202401010000, 202401100931)`。首次进入该分支即 `resize(2)` 后 memcpy 3 条；用例中已收进 `DISABLED_`（同时会触发 BUG-R52-002 的尾越界）。ASan/MSan 或开启 libc++ 容器检查时必报 heap-buffer-overflow。
- 影响范围: 任何后复权股票/连续合约第一次按区间取当日分钟线都会写坏堆；小对象池/后续分配可能被踩，表现为随机崩溃或静默数据污染。因触发条件比 BUG-R52-002 更宽（只要首次调用，不看 etime），按 Blocker 登记。
- 备注: 修复方向：长度改为 `newSize - idx`（与 ByCount 分支一致），或首次 `oldSize==0` 时不加 1。该缺陷也解释了为什么 r52 只把 ByRange 的 exright RT 分支留成 DISABLED_，改用 ByCount 分支做启用覆盖。
