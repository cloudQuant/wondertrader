- 严重级别: Blocker

- 相关测试: `src/TestUnits/coverage/q03_storage3/r52_reader_hot_adj_test.cpp` → `R52ReaderTest.R52HotWrappedFileReadReturnsIntegratedBars`

- 实际行为: L1019 声明了外层 `std::string filename`，但 L1021-1029 的 `for (const std::string& hisdir : _his_dir)` 循环体内又声明了一个同名局部变量 `std::string filename = fmtutil::format(...)`（L1023），存在性判断用的是内层变量、真正读取用的 L1035 `filename.c_str()` 仍是**外层空串**。`StdFile::read_file_content("")` 在 `StdUtils.hpp` L60-63 直接 `throw std::runtime_error("File does not exist")`；异常一路冒泡到 `cacheHisBarsFromFile` 的 `catch (const std::exception& ex)`（L1599-1602），只打一条 `缓存...连续...数据异常` 的 LL_ERROR 后 `return false`。结果：`_bars_cache` 里留下空条目，`readKlineSlice` 返回 `size()==0` 的切片（L1895-1905 的 `hisCnt != 0` 守卫兜住空 vector），切段函数一次都没被调用。
- 复现步骤: 构建 `CoverageTests` 后设置 `LLVM_PROFILE_FILE=/tmp/wt-review-r52-%p.profraw`，运行 `CoverageTests --gtest_filter=R52ReaderTest.R52HotWrappedFileReadReturnsIntegratedBars --gtest_color=no`。修正后的用例期望首读和缓存重读均返回两根 fixture K 线，实际均为 0，错误日志为 1、切段调用为 0，退出码 1。这是返回数据缺失的测试证据，不是进程 abort 复现。
- 影响范围: 只要某品种的 HOT 包裹 `.dsb` 存在，`cacheIntegratedBars` 的**全部**历史 K 线装配（日线/分钟线、切段、复权、hotAy）都无法执行，策略侧看到的是「该主力连续合约没有任何历史数据」；且错误信息只有底层异常文本，不会指出是路径被遮蔽。`WtDataReader` 是目前实盘/回放读历史的主要入口，严重级别按 Blocker 登记。
- 备注: 修复方向：删除 L1023 的内层声明（改为 `filename = ...`），或把存在性判断与读取统一到同一个变量；同时建议 `cacheHisBarsFromFile` 的 catch 在返回 false 前清掉 `_bars_cache[key]` 的空条目，避免第二次请求静默命中空缓存。
- 复核判定（2026-10-29）: 产品缺陷，源码中的变量遮蔽与空路径读取和测试观测一致。旧用例曾以空切片为预期而 PASS；现已改成正确返回数据的回归断言，当前 FAIL。R182/R193 对同一 `cacheIntegratedBars` 遮蔽问题的描述是重复观察，不是另一个根因或新候选。

# BUG-R52-002

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`（`readKlineSliceByRange` L1945-1965；`readKlineSliceByCount` L2352-2370）
- 相关测试: `src/TestUnits/coverage/r23_storage4/r52_rdm_hot_adj_test.cpp` → `R52RdmTest.DISABLED_R52ExrightRealtimeRangeBeyondTailOverrunsVector`
- 输入/前置条件: `cInfo._exright == 2`（代码如 `SSE.STK.600000+` 或 `SHFE.rb.HOT+`），当日 RT 分钟块存在，且请求的 `etime` 晚于块内最后一根 bar（例如块内只到 09:31，`etime=15:00`）。
- 期望行为: 不论边界位置为何都不能解引用 `end()`/`begin()` 外的元素，也不能返回超过实际缓存条数的数据；`etime` 晚于末条时应按接口契约包含末条，无重叠时返回值需服从已确认的区间语义。
- 实际行为: `std::lower_bound(begin, end, eBar, ...)` 使用的是正确的半开范围 `[begin,end)`。当非空 `_rt_bars` 的所有元素都早于 `eBar` 时，结果为 `end()`、`idx == size`；随后 L1952（ByRange）/L2359（ByCount）无守卫地访问 `_rt_bars[idx]`，越过 vector 的有效元素范围并触发未定义行为。若 ByRange 路径继续执行，当前测试的起始时间早于首条，L1964 会按 `idx+1` 计算数量；ByCount 虽用 `min(idx+1,count)`，仍可能在 `count>size` 时得到超出缓存长度的数量。这里的问题是未处理 `end()`，不是传给 `lower_bound` 的 end 迭代器错误。非复权分支使用原始块，代码路径不同。
- 复现步骤: `DISABLED_R52ExrightRealtimeRangeBeyondTailOverrunsVector` 同时经过 BUG-R52-002 与 003 的路径，但无断言。本轮用 `MallocGuardEdges=1 MallocScribble=1` 启用运行后退出码 0、用例通过；没有 ASan/容器边界检测，也没有观察到失败，因此不能称为动态复现。建议单独先用 ByCount 正确拷贝 RT 数据，再请求 `etime` 晚于末条以隔离 002，并在边界检查构建中断言只返回实际存在的数据。
- 影响范围: 后复权合约按晚于 RT 末条的 etime 查询时会进入无效 vector 下标路径，具体返回值或进程表现因未定义行为而不确定。本轮没有观测到数据污染或崩溃。与 BUG-R52-003 处于同一调用段，但本项是定位迭代器边界，003 是首次 memcpy 长度错误，两者是不同缺陷；共用测试不能互相证明。
- 复核（2026-10-29）: `std::lower_bound` 的第二个迭代器本来就是半开区间的 `end()`；把它改为 `end()-1` 会把最后一根排除，空 vector 时还会产生非法迭代器。
- 复核判定（2026-10-29）: 静态源码确认的边界缺陷；动态复现未建立。保留正确的 `[begin,end)` 搜索范围，修复方向是先处理空 vector，再明确 `it==begin()`、`it==end()`、命中及中间位置各自的业务语义；禁止无条件 `end()-1` 或夹紧。
- 备注: 修复方向：保留 `[begin,end)` 查找，先处理空 vector，再按查询边界语义显式处理结果为 `end()`、`begin()`、恰好命中以及中间位置，计算块范围前验证数量不超过实际长度。ByRange 与 ByCount 均需覆盖空、单条、尾前、恰好尾部、尾后及跨日期场景；不应靠无条件夹紧掩盖无重叠情况。

# BUG-R52-003

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`（`readKlineSliceByRange` 的 exright==2 分支 L1922-1942，`memcpy` 在 L1930）
- 相关测试: `src/TestUnits/coverage/r23_storage4/r52_rdm_hot_adj_test.cpp` → `R52RdmTest.DISABLED_R52ExrightRealtimeRangeBeyondTailOverrunsVector`
- 输入/前置条件: 后复权代码（`_exright == 2`）首次通过 `readKlineSliceByRange` 读取当日 RT 分钟块（`barsList._rt_bars` 尚为空，`oldSize == 0`）。
- 期望行为: 首次拷贝应把 RT 块的 `newSize` 条记录完整复制到刚 `resize(newSize)` 的 `_rt_bars` 中。
- 实际行为: L1930 `memcpy(&barsList._rt_bars[idx], &kPair->_block->_bars[idx], sizeof(WTSBarStruct) * (newSize - oldSize + 1));`。首次调用时 `idx = oldSize = 0`，拷贝长度为 `newSize + 1`，而 vector 仅有 `newSize` 个有效元素，故目标写入越过 vector 的有效元素范围并构成未定义行为；是否同时越过分配器容量、是否被 ASan 检出取决于实现，本轮未验证。测试 fixture 的 RT 块 capacity 为 8、size 为 2，因此多读的源元素在块容量内但超出逻辑 `_size`。ByCount 分支 L2337 的长度是 `newSize - idx`，无这个 `+1`。
- 复现步骤: 现有 `DISABLED_` 组合用例的 etime 是 15:00，同时触发首次拷贝与尾定位，但无断言。本轮运行该 beyond-tail 用例后通过；没有运行 ASan/MSan 或 libc++ 容器检查，不能称已动态检出越界。隔离 003 的最小用例可首次 ByRange 查询并将 etime 设为最后一条 09:31（使 lower_bound 命中末条而不走 `end()`），再在 ASan/容器边界检查下运行；预期 `memcpy` 长度修为 `newSize - idx`，断言只复制实际 RT 条数。
- 影响范围: 后复权代码首次通过 ByRange 装载非空 RT 块时会执行越过 vector 有效元素数的写入；是否踩出分配器容量及运行时后果未验证。触发条件不依赖 etime，但范围仅证明到源码分支，严重级别仍需结合实际容器/构建配置和业务影响评估。
- 备注: 修复方向：长度改为 `newSize - idx`（与 ByCount 分支一致），或首次 `oldSize==0` 时不加 1。该缺陷也解释了为什么 r52 只把 ByRange 的 exright RT 分支留成 DISABLED_，改用 ByCount 分支做启用覆盖。
- 复核判定（2026-10-29）: 静态源码确认的越界写缺陷，动态检测未建立。最小产品修复是将拷贝长度改为 `newSize - idx`；应把当前组合用例拆成可分别归因的 ByRange 首次拷贝测试和 RT 尾边界测试，再由 ASan/容器边界检查验证。
