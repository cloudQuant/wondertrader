## BUG-R161-001 dsb 块解压失败后仍按原始长度 memcpy：块尾不足一个结构体时越界写

- 状态: 待审核
- 严重级别: High（内存破坏，可致崩溃/静默数据污染）
- 模块/文件/行:
  - `src/WtBtCore/HisDataReplayer.cpp:3495-3499`（tick 路径：`proc_block_data` 返回值被忽略，
    `tickcnt = content.size()/sizeof(WTSTickStruct)` 向下取整，`memcpy(..., content.size())`）
  - `src/WtBtCore/HisDataReplayer.cpp:3793-3803`（bar 路径：同型问题，
    `barcnt = content.size()/sizeof(WTSBarStruct)` 后 `memcpy(..., content.size())`）
  - 根因在 `src/WtBtCore/HisDataReplayer.cpp:57-72`：`proc_block_data` 在
    `content.size() != sizeof(BlockHeaderV2) + _size` 时打印错误并 `return false`
- 相关测试: `r161_btcore_edges_test.cpp::R161ReplayFixture.DISABLED_MalformedTickBlockTailBeyondLastItem`
- 输入/前置条件:
  1. csv 回放模式（`mode=csv`），tick=true；
  2. 在 `<base>/bin/ticks/<stdCode>_tick_<date>.dsb` 放一个长度
     `>= sizeof(HisTickBlockV2)`、但**不是** `sizeof(WTSTickStruct)` 整数倍的文件；
  3. 块头 `_version=BLOCK_VERSION_CMP_V2`、`_type=BT_HIS_Ticks`，且 `_size` 与文件长度不一致；
  4. 调 `get_tick_slice(stdCode, 10)`（首次会进 `cacheRawTicksFromCSV`）。
- 期望行为: 块长度校验失败时直接拒绝该 dsb（返回空/报错），不读取半截内容；或至少
  只拷贝 `tickcnt * sizeof(WTSTickStruct)` 字节。
- 实际行为: 对压缩 V2 头和 `_size` 不匹配的文件，`proc_block_data` 会打印长度错误并
  返回 false，但两个调用点都忽略返回值。tick 路径按 `content.size()/sizeof(Tick)`
  向下取整 resize，随后复制完整 `content.size()`；若总文件长度含结构体余数，复制长度
  大于 vector 的元素存储长度，构成越界写/未定义行为。bar 路径存在相同的长度计算与
  完整拷贝模式。文件长度为结构体整数倍时仍会继续把未解压的块头/坏内容当数据缓存，
  但那本身不证明越界。
- 复现步骤: 1) 按上述条件写一个 `sizeof(WTSTickStruct)+3` 字节的 dsb；2) csv 模式 init+prepare；
  3) 调 `get_tick_slice`；4) 在 ASan/GuardMalloc 下应报 heap-buffer-overflow（无 ASan 时可能
  静默改写相邻堆块，后续表现为随机崩溃/数据错乱）。
- 证据:
  - 代码静态可证：`proc_block_data` false 分支（L64-72）只记录并返回；调用点 L3495、
    L3793 都未检查返回值，随后按原始文件长度分配/复制。
  - `MalformedTickBlockSizeMismatch` 的结构体整数倍输入现存 rc 为 PASS，但用例只断言
    `get_tick_slice` 返回 NULL；它没有直接断言错误返回已传播，不能作为拒绝逻辑正确的证据。
  - `MalformedBarBlockSizeMismatch` 同样使用结构体整数倍长度；现存 rc 为
    `FAIL(rc=1)`，日志显示 `get_kline_slice` 返回非空切片。该结果支持“坏 bar 内容未被
    拒绝”，不证明越界，因为该输入的长度可被整除。
  - `DISABLED_MalformedTickBlockTailBeyondLastItem` 构造 `sizeof(WTSTickStruct)+3`，是
    触发长度差异的占位输入；本轮未执行，故没有动态 OOB/ASan 结论。当前没有对应的
    bar 尾部余数动态用例。
- 影响范围: 仅当回放读取到长度达到 V2 头部、压缩 `_size` 与文件长度不符，且返回后的
  原始长度对记录结构体有余数时，才满足本条越界条件。损坏/截断文件是可能输入，但本轮
  没有统计其出现频率，也没有确认所有版本不匹配文件都会走这条分支。
- 备注: 建议 `if (!proc_block_data(...)) return false;`，并在成功解码后校验 payload 长度
  能被记录结构体大小整除，再分配/复制；bar 同理。将 malformed bar 测试的失败保持为
  产品拒绝行为的验收断言，并为 tick/bar 尾余数分别增加 sanitizer 或等效边界检查；修复
  后再启用当前 `DISABLED_` 复现用例。
