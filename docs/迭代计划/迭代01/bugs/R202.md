## BUG-R202-001 ticker 的 24h 午夜位置未归一为 00:00：minuteToTime(1440) 返回 2400

- 状态: 待审核
- 严重度: 待定（24h 位置 1440 的标签与跨日条件不一致；日志/分钟线等业务影响需有效时间输入复核）
- 位置: `src/WtCore/WtSelTicker.cpp:199-205`、`src/WtCore/WtHftTicker.cpp:194-200`、
  `src/WtCore/WtCtaTicker.cpp:213-219`
- 现象:
  三个 ticker 的 `run()` 都用 `thisMin = _s_info->minuteToTime(_cur_pos)`，再用
  `if (thisMin == 0)` 判断跨日。但 24h 时段 `addTradingSection(0,0)` 生成的
  `TradingSection` 是 `(0, 2400)`，`minuteToTime(1440)` 走“到达本段收盘”分支：
  `stopMin = 2400/100*60 + 2400%100 = 1440`，`offset==0` 时返回
  `stopMin/60*100 + stopMin%60 = 2400`。因此在该午夜位置 **`thisMin` 为 2400 而非 0**。
  同时，非 24h 时段的最后一分钟是 section end，位置不会超过 1439；24h 时段
  位置 1440 映射为 2400，因此 `thisMin == 0` 的自动跨日条件不成立。若运行到后续
  `set_date_time`，收到的是 2400。原 R192 测试用 `235960000`（秒字段 60）立即驱动
  此位置；应以有效的 `23:59:59.xxx` 行情复核，避免把非规范输入当作正常行情证据。
- 复现: `r202_wtcore_public_surface_test.cpp` 中
  `R202SelTicker.DISABLED_MidnightRolloverNeedsMinuteToTimeWrapToZero`：
  24h 时段期望 `minuteToTime(1440)==0`，实际 2400。
  保存的 R192 Sel/HFT 日志在断言处报告 `last_time=2400`、日期未推进；二者使用
  `235960000`，秒字段为 60。CTA 日志只到 `[ RUN ]` 且结果表为 CRASH，不是相同的
  动态断言失败。本次未重跑这些日志。影响限定为源码给出的 24h 边界不匹配；后续行情、
  分钟线和 session 统计是否漏产，需用有效时间值和引擎回归继续确认。
- 影响面: 三种 ticker 的自动闭合路径在 24h 位置 1440 无法通过 `thisMin == 0`
  归一午夜标签；具体业务影响待有效行情回归确认。覆盖率 profile 的 0 计数不单独证明
 这些源码行不可达。
- 建议: 统一分钟标签的归一化，例如 `minuteToTime(1440)` 返回 0，或在 ticker
  中把 `thisMin == 0 || thisMin == 2400` 都当作跨日；补一条 24h 午夜换日回归用例。

## BUG-R202-002 24h 时段收盘比较值不一致：2359 与 2400 不相等

- 状态: 待审核
- 严重度: 待定（24h 收盘比较条件静态不匹配；下游影响尚无端到端动态证据）
- 位置: `src/WtSelTicker.cpp:130-134`、`src/WtHftTicker.cpp:127-131`、
  `src/WtCtaTicker.cpp:129-142`、`:221-234`
- 现象:
  对 24h 段（编码为 0–2400），数据驱动闭合位置 1439 时，
  `thisMin = minuteToTime(1439) = 2359`，
  `offMin = offsetTime(2359, true) = 2359`；而 24h 时段的
  `getCloseTime(true)` 在 `WTSSessionInfo.hpp` 里对 0 点做了修正，返回 2400
  （`if (ret == 0 && bOffseted) ret = 2400`）。
  因此 `offMin == getCloseTime(true)`（Sel/HFT/CTA 数据闭合分支）恒为
  `2359 == 2400` → false。
  `run()` 自动闭合分支 `thisMin=2400` 时，`offMin=offsetTime(2400,true)=0`，
  `offMin >= getCloseTime(true)` 又变成 `0 >= 2400` → false。
  因而源码所示 24h 的数据闭合和自动闭合比较都不匹配收盘值。当前没有运行有效的
  24h `on_session_end` 端到端断言，不能把下游影响写成已动态确认。
- 复现: `r202_wtcore_public_surface_test.cpp` 中
  `R202HftTicker.DISABLED_LastMinuteIn24hSessionNeverMatchesCloseTime` 直接比较得到
  2359 vs 2400；此禁用值级用例没有启动 ticker，也没有断言 `on_session_end`。
- 影响面: 若 ticker 到达上述 24h 比较路径，回调条件不成立；结算、风控换日、统计落盘
  等影响需要端到端证据。有限时段的通用分支并非整体不可覆盖：保存的 Sel
  `RunEndsSessionAtLastMinute` 用例在 0–2359 session 下 PASS；CTA 对应日志只到
  `[ RUN ]`，结果为 CRASH，不能记为 PASS；HFT 无对应保存日志。所有保存证据均未在
  本次重跑。
- 建议: 收盘对齐值统一到同一口径（如用 `offsetTime(getCloseTime(false), true)`
  或把 2400 归一为 2359/0），并补 24h 最后一分钟 session_end 用例。

## BUG-R202-003 TraderAdapter::isTradeEnabled 头文件标 inline、定义只在 .cpp，跨 TU 调用可见性不满足

- 状态: 待审核
- 严重度: 低（跨 TU 编译/链接可见性问题；具体结果依赖构建设置）
- 位置: 公开函数 `src/WtCore/TraderAdapter.h:368`；定义在
  `src/WtCore/TraderAdapter.cpp:598-607`
- 现象:
  `isTradeEnabled` 在类内声明为 `inline`，定义只出现在 `TraderAdapter.cpp`。其他 TU
  调用时看不到定义，Clang 可报告 `-Wundefined-inline`；禁用测试保留原调用，并不
  证明关告警后成功链接或返回特定值。`getContract`、`getCommodify` 声明在 `private`
  区，不计为外部公开接口问题。
- 复现/证据: `r202_wtcore_public_surface_test.cpp` 的
  `DISABLED_PublicTradeSwitchNeedsExternallyVisibleDefinition` 有调用断言但未执行；
  本条与 R215 主编号合并记录所述的编译/符号可见性风险一致，不新增动态调用结论。
- 影响面: 跨 TU 直接调用这个公开接口的编译/链接可用性受影响；不扩展到 private
  helper，也不据此声称整个 TraderAdapter 查询面不可用。
- 建议: 去掉 `isTradeEnabled` 声明中的 `inline`（保留 .cpp 定义），或把定义移回头文件；
  该问题按 BUG-R202-003 主编号与 BUG-R215-003、R211、Q04/N01/N03 关联项归并。
