## BUG-R202-001 ticker 的 00:00 跨日分支不可达：minuteToTime(1440) 返回 2400 而非 0

- 状态: 待审核
- 严重度: 中（午夜不自动换日，00:00 分钟线缺失，日志出现非法的 2400 时间标签）
- 位置: `src/WtCore/WtSelTicker.cpp:199-205`、`src/WtCore/WtHftTicker.cpp:194-200`、
  `src/WtCore/WtCtaTicker.cpp:213-219`
- 现象:
  三个 ticker 的 `run()` 都用 `thisMin = _s_info->minuteToTime(_cur_pos)`，再用
  `if (thisMin == 0)` 判断跨日。但 24h 时段 `addTradingSection(0,0)` 生成的
  `TradingSection` 是 `(0, 2400)`，`minuteToTime(1440)` 走“到达本段收盘”分支：
  `stopMin = 2400/100*60 + 2400%100 = 1440`，`offset==0` 时返回
  `stopMin/60*100 + stopMin%60 = 2400`。因此 **`thisMin` 永远不可能是 0**。
  同时，非 24h 时段的最后一分钟是 section end，`on_tick` 里的
  `timeToMinutes` 在 2359 饱和到 1439，`_cur_pos` 也不可能超过 1439；
  24h 时段的 23:59:60 行情才会把 `_cur_pos` 推到 1440。
  结果：`run()` 只会打印 `Minute bar <date>.2400 closed automatically`，
  `_date` 不 +1，`engine.set_date_time` 收到 2400。
- 复现: `r202_wtcore_public_surface_test.cpp` 中
  `R202SelTicker.DISABLED_MidnightRolloverNeedsMinuteToTimeWrapToZero`：
  24h 时段期望 `minuteToTime(1440)==0`，实际 2400。
  R192 的三条 `RunRollsDateAtMidnight` 用例即因此失败（`last_time=2400`、
  `engine.get_date()` 仍为行情日、`get_min_time()==2400`）。
- 影响面: `run()` 自动闭合跨日、`WtSelTicker.cpp:200-205`、
  `WtHftTicker.cpp:195-200`、`WtCtaTicker.cpp:214-219` 共 15 行不可覆盖；
  所有 24h 交易日（期货夜盘/数字货币）午夜换日依赖下一笔行情或次日首笔行情，
  00:00 分钟线不会产出，午夜 session 统计缺失。
- 建议: 统一分钟标签的归一化，例如 `minuteToTime(1440)` 返回 0，或在 ticker
  中把 `thisMin == 0 || thisMin == 2400` 都当作跨日；补一条 24h 午夜换日回归用例。

## BUG-R202-002 24h 时段最后一分钟的 on_session_end 永不触发：2359 与 2400 比较不相等

- 状态: 待审核
- 严重度: 中（24h 引擎午夜收盘钩子/结算动作不执行）
- 位置: `src/WtSelTicker.cpp:130-134`、`src/WtHftTicker.cpp:127-131`、
  `src/WtCtaTicker.cpp:129-142`、`:221-234`
- 现象:
  数据驱动闭合最后一分钟时，`thisMin = minuteToTime(1439) = 2359`，
  `offMin = offsetTime(2359, true) = 2359`；而 24h 时段的
  `getCloseTime(true)` 在 `WTSSessionInfo.hpp` 里对 0 点做了修正，返回 2400
  （`if (ret == 0 && bOffseted) ret = 2400`）。
  因此 `offMin == getCloseTime(true)`（Sel/HFT/CTA 数据闭合分支）恒为
  `2359 == 2400` → false。
  `run()` 自动闭合分支 `thisMin=2400` 时，`offMin=offsetTime(2400,true)=0`，
  `offMin >= getCloseTime(true)` 又变成 `0 >= 2400` → false。
  两条路径都不可能调用 `on_session_end()`。
- 复现: `r202_wtcore_public_surface_test.cpp` 中
  `R202HftTicker.DISABLED_LastMinuteIn24hSessionNeverMatchesCloseTime`：
  期望 `offsetTime(2359,true)==getCloseTime(true)`，实际 2359 vs 2400。
- 影响面: 24h 时段引擎在午夜不会收到 `on_session_end`；依赖该回调的结算、
  风控换日、统计落盘全部缺失。同时使 Sel/HFT/CTA 的 8 行收盘分支不可覆盖。
- 建议: 收盘对齐值统一到同一口径（如用 `offsetTime(getCloseTime(false), true)`
  或把 2400 归一为 2359/0），并补 24h 最后一分钟 session_end 用例。

## BUG-R202-003 TraderAdapter 公开查询函数头文件标 inline、定义只在 .cpp，跨 TU 调用触发 -Wundefined-inline

- 状态: 待审核
- 严重度: 低（当前链接可用，但违反 inline 函数的 ODR 要求，测试侧必须关告警才能编译）
- 位置: `src/WtCore/TraderAdapter.h:226-227,368`；定义在
  `src/WtCore/TraderAdapter.cpp:532,538,598`
- 现象:
  `getContract`、`getCommodify`、`isTradeEnabled` 在类内声明为 `inline`，
  但定义只出现在 `TraderAdapter.cpp`。任何其他 TU（包括覆盖率测试）调用这些
  函数时，编译器只看到 inline 声明、看不到定义，在 `-Wall -Werror` 下报
  `inline function ... is not defined [-Wundefined-inline]`。本轮用例只能对
  `isTradeEnabled` 做文件级 `#pragma clang diagnostic ignored` 才能通过语法门禁。
  另外 `getCommodify` 声明在 private 区，公开面无法调用，其 4 行只能留在
  未覆盖清单里。
- 复现: 在任意测试 TU 里直接调用 `adapter.isTradeEnabled("SHFE.ag.2512")`，
  不关告警即编译失败；关掉后行为正常（返回 true）。
- 影响面: 跨 TU 使用 TraderAdapter 公开查询面的调用方都需要额外抑制告警；
  inline 语义与实现位置不一致，属于潜在 ODR 违规。
- 建议: 去掉声明中的 `inline`（保留 .cpp 定义），或把定义移回头文件；
  若 `getCommodify` 确实是调试接口，建议改为 private 并移出覆盖率目标。
