## 观察 1：WtDataWriter 的释放/巡检/清理异常路径继续不可安全驱动

- 位置: `WtDataWriter.cpp:181-184`（`release()` join）、`:1627-1694`（`check_loop`）、
  `:2360-2387`（`remove_all` 异常后 300s sleep）
- 复核证据: 本轮 `llvm-cov show` 中这些行仍为 0；`check_loop` 每轮先睡 10s，
  过期阈值 600s；清理重试路径最多 5 次、每次 300s。
- 判定: 属线程/长睡眠面，不是公开 API 行为缺陷；按纪律留白。
- 交叉引用: `bugs/p10_storage_writer.md` BUG-P10-005、`bugs/R182.md` 观察 2。

## 观察 2：RT 块 map 失败分支会抛未捕获异常，无法用公开 API 断言 NULL

- 位置: `WtDataWriter.cpp:348-351/710-714/804-808/899-903/1002-1006/1387-1391`；
  `WtRdmDtReader.cpp:2019-2209`；`WtDataReader.cpp:1948-2201`
- 现象: `BoostMappingFile::map` 直接 `new file_mapping` / `new mapped_region`，
  对目录、零长文件、无权限文件会抛 `boost::interprocess::interprocess_exception`；
  上述调用点没有 try/catch，测试进程会直接 FAIL/CRASH。
- 判定: 需要产品侧把 `map` 改成返回 false 或各调用点补 catch 才可测；本 lane 不写
  必崩用例，也不放宽断言。R193 只覆盖 map 成功的 RT 块路径。
- 交叉引用: `bugs/R182.md` 观察 5（AD RT 缓存同型崩溃面）。

## 观察 3：WtDataWriterAD `_async_task` 仍未初始化（既有 BUG-R162-001）

  `release()` join 与 `resizeRTBlock` 失败面全部留白，不依赖未初始化残值碰运气。
- 交叉引用: `bugs/R162.md` BUG-R162-001、`bugs/p05_datastorage2.md` BUG-P05-005。

## 观察 4：AD 读端 LMDB 缓存命中分支仍不可达（既有 BUG-P05-003）

## 观察 5：WtRdmDtReader 的 5 分钟巡检释放仍不可覆盖

- 位置: `WtRdmDtReader.cpp:94-163`（70 行）
- 现象: 线程每 5s 醒来一次，只在 `now > last_time + 300000` 时释放 block；
  任何公开读取都会把 `last_time` 刷新为当前毫秒，测试无法在不等待 5 分钟、
  不直改私有字段的前提下命中。
- 判定: 线程/长等待面；本轮不写 300s 级等待用例。
- 交叉引用: `bugs/R182.md` 观察 2。

## 观察 6：WtDataReader HOT 包裹文件分支仍被变量遮蔽阻断（既有 BUG-R52-001）

  HOT 包裹文件；`:1037-1057` 继续留白。
- 交叉引用: `bugs/R52.md` BUG-R52-001、`bugs/R182.md` 观察 1。
