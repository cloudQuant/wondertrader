## 逐项复核

### 观察 1：WtDataWriter 后台巡检与清理长等待

- 位置：WtDataWriter.cpp:1627-1694 的 check_loop、:2360-2387 的 remove_all；release 还会 join 工作线程。
- 分类：测试覆盖约束，不足以构成产品缺陷。
- 证据边界：巡检启动后每轮先 sleep 10s，过期阈值为 600s；remove_all 异常重试路径会 sleep 300s、至多 5 次。未等待这些时间不能推出产品行为异常；profile 行为 0 仅说明保存的用例未进入该路径。
- 处理建议：用可注入时钟/等待策略做确定性测试；无需把长等待登记为产品 bug。
- 交叉引用：BUG-P10-005、R182 观察 2。

### 观察 2：BoostMappingFile::map 的 false-return 契约与异常

- 位置：Share/BoostMappingFile.hpp 的 map；相关调用点包括 WtDataWriter.cpp 和 WtRdmDtReader.cpp。
- 分类：源码级接口契约问题；R193 没有动态验证；与 R203 观察 6 / R68-002 同类重复。
- 证据：map 的注释声明失败返回 false，调用代码也使用 if (!map(...)) 分支；但 new boost::interprocess::file_mapping / mapped_region 在无效、零长度或权限不足等场景可能抛 interprocess_exception，new 表达式不会以 NULL 表示构造失败。若调用点没有本地或外层 catch，异常不会进入布尔失败分支。并非所有储存调用链都已逐一证明未捕获，故只确认 helper 契约与部分无 catch 调用点的风险，不概括为全仓统一 CRASH。
- 处理建议：在 helper 捕获并清理部分资源后返回 false，或正式改为抛异常并让每个公开入口明确捕获；给不存在、零长度、目录/权限错误路径添加异常断言。R193 不新增编号。

### 观察 3：WtDataWriterAD::_async_task 未初始化

- 位置：WtDataWriterAD.h:245；读取点 WtDataWriterAD.cpp:375。
- 分类：真实源码缺陷，重复 BUG-R162-001。
- 证据边界：构造函数与 init 没有为该 bool 赋值，pushTask 会读取它。profile 未覆盖只说明当前用例没有进入读取点；不能推断对象分配后取值为 false。
- 处理建议：构造时初始化并明确异步模式配置语义，保留 R162 主编号。

### 观察 4：AD 读端 tick LMDB 缓存查询键与写入键不一致

- 位置：WtDataReaderAD.cpp:597-620；WtRdmDtReaderAD.cpp:相应 get_t_db 实现。
- 分类：源码问题，重复 BUG-P05-003。
- 证据：查找键是 exchg.code，插入 map 的键却是 exchg；同实例后续相同查询不可能按复合 key 命中。已保存 coverage 的未命中是代码路径结果，不证明实际磁盘 I/O 成本或性能影响。
- 处理建议：统一 cache key（建议统一复合 exchange/code），并对同一 key 重复查询验证只创建一次数据库对象；保留 P05-003 主编号。

### 观察 5：WtRdmDtReader 5 分钟释放巡检

- 位置：WtRdmDtReader.cpp:94-163。
- 分类：长等待/线程覆盖限制，无新增产品缺陷证据。
- 证据边界：巡检 5s 一次，过期判断依赖 last_time 超过 300000ms；正常读取刷新 last_time。没有等 5 分钟或注入时钟的测试，不能把 0 覆盖写成删除逻辑错误。
- 处理建议：为 sweeper 注入时钟或周期控制后验证资源回收；交叉引用 R182 观察 2。

### 观察 6：WtDataReader HOT 包裹文件变量遮蔽

- 位置：WtDataReader.cpp:1019-1057。
- 分类：真实源码问题，重复 BUG-R52-001。
- 证据：循环内重声明 filename，后续包裹文件读操作使用被遮蔽作用域的变量；周围异常处理把 std::exception 转成 false。R193 用例没有创建 HOT 包裹文件，不能声称本 lane 动态复现。
- 处理建议：修正变量作用域/文件路径并用有效 HOT 包裹 fixture 验证；保留 R52-001 主编号。
