发现者：lane R100。所有条目均**未修改产品代码**，只记录。`DISABLED_` 表示默认不运行，不代表缺陷已动态复现；本轮裁定见文末。

## BUG-R100-001

- 状态: 待审核
- 严重级别: 条件 Major（同一 reader 同时缓存日线/分钟线且日线先迭代时漏回调）
- 模块/文件: `src/WtDataStorageAD/WtDataReaderAD.cpp`
  - `onMinuteEnd` 的 `endBarTime` 在循环外初始化：L503
  - 分钟段使用它：L515 `if(lastBarTime < endBarTime)`
  - 日线段把它改写成自然日：L528-531 `endBarTime = uDate;`
- 相关测试: 无混合周期启用复现。`_bars_cache` 是 `wt_hashmap`（`ankerl::unordered_dense::map`），key 为 `stdCode#period`，可同时保存同合约的日线与分钟线；其迭代顺序未由接口保证，不能简单表述为每次随机。
  现有 `r100_reader_ad_test.cpp` 的 onMinuteEnd 用例分别覆盖分钟缓存和日线缓存，日线部分先 reset reader；没有覆盖二者同处一个 map 的顺序敏感场景。
- 输入/前置条件:
  - 同一个 `WtDataReaderAD` 先读过日线 `readKlineSlice(..., KP_DAY, ...)`，再读分钟线，
    使 `_bars_cache` 中同时存在 `KP_DAY` 与 `KP_MINUTE1/5` 的 `BarsList`；
  - 调用 `onMinuteEnd(uDate, uTime, endTDate)`。
- 期望行为: 每个 `BarsList` 的分钟右界独立为 `(uDate-19900000)*10000+uTime`，
  日线的自然日右界不得影响分钟段。
- 实际行为: `endBarTime` 是循环外共享变量；当 `endTDate != 0` 且日线条目先被迭代，L531 把它改成 `YYYYMMDD`
  （如 20230103），随后分钟条目在 L515 比较 `lastBarTime(约 3.3e9) < 20230103` 恒为 false，
  于是 L517-525 的 RT 缓存补线与 `_sink->on_bar` 全部跳过；反之分钟先迭代则正常。
  结果依赖哈希迭代顺序，表现为偶发的分钟 bar 漏回调。
- 复现条件（尚未动态复现）:
  1. 同一 reader 读 `KP_DAY` 与 `KP_MINUTE1` 两个周期，确保两者都进入 `_bars_cache`；
  2. 准备 `cache_m1.dmb`，其中该合约未闭合 bar 晚于 LMDB 末条、早于 `uTime`；
  3. 调 `onMinuteEnd` 并传入非零 `endTDate`；当日线条目在本次 map 遍历中先于分钟条目时，分钟段不会追加/回调。
- 影响范围: 同时订阅日线与分钟线的回放/实盘场景；分钟末的最后一根 K 线可能延迟或丢失。
- 备注: 修复方向：分钟分支用独立的 `minuteEndBarTime`，日线分支用独立的自然日边界；不要在 map 遍历中跨周期复用 `endBarTime`。测试需同时缓存同一合约的 KP_DAY 与 KP_MINUTE1/5，并确保日线先被遍历。

## BUG-R100-002

- 状态: 待审核
- 严重级别: Major（可触发越界读写/崩溃）
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`
  - `readOrdQueSliceByRange` 历史段：L756-760
  - `readOrdDtlSliceByRange` 历史段：L931-935
  - `readTransSliceByRange` 历史段：L1105-1109
  - 三处都是 `if (pItem->action_date > eTick.action_date || pItem->action_time >= eTick.action_time) { pItem--; eIdx--; }`
    且没有 `if (eIdx == 0) break;`
- 相关测试: `src/TestUnits/coverage/q03_storage3/r100_rdm_crossday_test.cpp` →
  `R100RdmCrossDayTest.DISABLED_R100RdmHisHftBeforeFirstUnderflows`
- 输入/前置条件:
  - 历史文件 `his/queue/SSE/20240109/610199.dsb` 只有一条记录，`action_time=09:30`；
  - `curTDate=20240110`，请求 `readOrdQueSliceByRange("SSE.STK.610199",
    20240109090000000, 20240109091500000)`（截止 09:15 早于块内首条）。
- 期望行为: 目标时间早于块内首条时应返回空切片/NULL，不得在块首之前取址；
  应与 tick 历史段 L498-505 一样先判 `eIdx == 0` 再回退。
- 实际行为:
  1. `std::lower_bound(begin, begin + (tcnt - 1), eTick, ...)` 返回 `begin`；
  2. `pItem->action_time >= eTick.action_time` 为真，执行 `pItem--`（begin 之前，UB）与
     `eIdx--`（`std::size_t` 由 0 回绕为 `SIZE_MAX`）；
  3. 同交易日分支继续用 `begin + eIdx` 形成 `lower_bound` 区间，迭代器范围已无效；后续索引与 slice count 都进入未定义行为。具体 count 可能受无符号回绕影响，不保证固定为巨大值（dtl/trans 同型）。
- 影响范围: 任何「请求截止时间早于当日首笔」的历史逐笔回放；dtl/trans 的同一行段同样受影响。
- 备注: 与 BUG-R70-001（RT isToday 分支）属于同一类右界回退缺少零索引保护，但分支与代码行不同：本项是历史文件分支，R70 是 RT 分支，不是重复条目。修复方向：在 queue/detail/trans 三处回退前检查 `eIdx==0`，按对应接口返回空结果/NULL；仅加 `pItem != begin` 保护而仍使用回绕的 `eIdx` 不够。

## 本轮独立复核裁定（2026-10-29）

| 编号 | 裁定与证据边界 | 最小修复方向 |
|---|---|---|
| BUG-R100-001 | **顺序敏感的条件产品缺陷候选，未动态复现。** 源码在循环外初始化 `endBarTime`，分钟段用分钟编码比较，日线段会改写为自然日；同一 `_bars_cache` 可按 `stdCode#period` 同时存放日线与分钟线，map 为 `ankerl::unordered_dense::map`，迭代次序未由接口保证。成立前提还包括 `endTDate != 0`，且日线项在本次迭代中先于分钟项。现有 R100 AD 测试 minute-only 用例 PASS，日线用例在另一 reader 实例；没有混合周期测试。 | 按周期使用互不共享的边界变量；增加同一 reader、同一合约同时缓存 KP_DAY 与 KP_MINUTE1/5 的回归，确保日线先被遍历并断言分钟 RT bar 被追加且回调。 |
| BUG-R100-002 | **历史 HFT 分支的边界 UB 已由源码条件确认，动态未复现；与 R70 同族但不是重复。** 一条记录且请求截止早于首条时 lower_bound 返回 begin，随后的 `pItem--` 越界且 `eIdx` 下溢；后续行为不确定。queue 用例 DISABLED；detail/trans 只有同形源码路径，未单独测试。R70-001 覆盖 RT isToday 分支，代码位置不同。 | 三种 slice 在回退前统一处理 `eIdx==0`，按对应接口返回合法空结果/NULL；为 queue/detail/trans 分别加历史段边界测试，断言零条结果且不访问首元素之前地址。 |
