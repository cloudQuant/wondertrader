## BUG-R165-001 UDPCaster 成员析构顺序错误（复核确认 BUG-R164-001，同一缺陷）

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件/行: `src/WtDtCore/UDPCaster.h:88-96`（socket/组播容器声明在 `m_ioservice` 之前）、`src/WtDtCore/UDPCaster.cpp:58-60`（析构体为空）
- 相关测试: `r154_udp_caster_start_test.cpp::R154UdpCasterTest.DISABLED_DestructorAfterActiveStartCrashes`；同文件 3 条 active 用例在本缺陷下曾全部 CRASH
- 输入/前置条件: `UDPCaster caster; caster.init({"active":true,"sport":0}, nullptr, nullptr); caster.stop();` 后对象离开作用域
- 期望行为: 析构安全：socket 在 `io_context` 存活时 close/reset，或 `stop()` 主动 reset socket 后再销毁 `io_context`
- 实际行为: 按成员声明逆序析构，`m_ioservice`（H96）先于 `m_sktSubscribe`（H89）/`m_sktBroadcast`（H88）/`m_list*Group`（H93-95）销毁；随后 socket 析构访问已析构的 reactor，SIGSEGV。是否调用 `stop()` 不影响
- 复现步骤: 1) active=true、sport=0 构造并 init；2) stop()；3) 作用域结束；4) 崩在 `~UDPCaster` 销毁订阅 socket
- 证据:
  - 本 lane 在 3 条 R154 用例内加检查点复跑：`init`/`addMRecver`/`broadcast`/`stop()` 均返回并打印“after guard stop”，随后进程 `rc=139`，`[ OK ]` 未输出，崩溃点确定为 `~UDPCaster`；
  - R164 lane 已用系统崩溃报告取证同一栈：`~UDPCaster -> shared_ptr<basic_datagram_socket>::~shared_ptr -> kqueue_reactor::deregister_descriptor`（BUG-R164-001）；本条只复核 R154 侧可复现性，不重复主张
- 影响范围: 所有 active UDP 广播器在正常退出、配置重载、异常释放时都会崩溃；崩溃发生在关停阶段
- 备注: 建议把 `m_ioservice` 移到所有 socket/组播容器之前声明，或在 `stop()` 中先 `m_sktBroadcast.reset(); m_sktSubscribe.reset(); m_list*Group.clear();` 再停 `m_ioservice`；修复后本 lane 可删除 `LeakyCaster` 绕过并启用 `DISABLED_DestructorAfterActiveStartCrashes`

## 测试夹具修正（非产品缺陷）

### R151 `CsvLoadReportsEveryThousandBars` 崩溃：夹具漏 `register_sink`

- 现象: `prepare()` 内 `rc=139`，gtest 停在 `[ RUN ]`
- 根因: 用例未注册 `IDataSink`；`HisDataReplayer::prepare()` L669 无条件调用 `_listener->handle_init()`，`_listener == NULL`。产品侧缺判空是既有 **BUG-P04-002**；本用例是夹具违反了“回放前先 `register_sink`”的使用约定（同文件其余 4 条均已注册）
- 修复: `prepare()` 前 `_rp.register_sink(&sink, "r151_csv_load")`，并新增 `EXPECT_EQ(1u, sink.init_calls)` 验证回调确实发生
- 结果: PASS，1001 行分钟 CSV 装载、`his/min1` 创建与非空切片断言均保留

### R151 `DailySecondaryBarsCursorCatchesUp` 失败：夹具误用 `get_kline_slice` 契约

- 现象: `mainSlice == NULL`（原第 125 行 `ASSERT_NE(nullptr, mainSlice)`）
- 根因: 夹具主K线自 0106 起、回测起点 0102；首根 bar 晚于 `_cur_tdate` 时
  `get_kline_slice` 走“标的尚未上市”兜底把 `_cursor` 置 0，L2458 按契约返回 NULL。
  用例却要求该调用返回非空 slice，属夹具场景设计错误，不是产品回归
- 修复: 主K线增加 0102 一根仅用于定位的历史 bar（实际回放首日仍是 0106），次K线改为
  20191231 起；主/次 slice 均非空，次K线游标在 0106 收盘时由 0103 推进到 0106，
  继续覆盖 `simTicks` L1372-1378；原有计数与 `done_calls` 断言未改动
- 结果: PASS
