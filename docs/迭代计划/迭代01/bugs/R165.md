## 重复复核（原 BUG-R165-001）：UDPCaster 成员析构顺序错误

- 状态: 已合并（主编号 BUG-R164-001）
- 分类: 与 BUG-R164-001 相同源码位置、相同生命周期问题，不重复立案或计数。
- 模块/文件/行: `src/WtDtCore/UDPCaster.h:88-96`（socket/组播容器声明在 `m_ioservice` 之前）、`src/WtDtCore/UDPCaster.cpp:58-60`（析构体为空）
- 相关测试: `r154_udp_caster_start_test.cpp::R154UdpCasterTest.DISABLED_DestructorAfterActiveStartCrashes`；R154 三条 active 用例通过 `LeakyCaster` 绕开真实析构
- 输入/前置条件: `UDPCaster caster; caster.init({"active":true,"sport":0}, nullptr, nullptr); caster.stop();` 后对象离开作用域
- 期望行为: 析构安全：socket 在 `io_context` 存活时 close/reset，或 `stop()` 主动 reset socket 后再销毁 `io_context`
- 实际行为: 按成员声明逆序析构，`m_ioservice`（H96）先于 `m_sktSubscribe`（H89）/`m_sktBroadcast`（H88）/`m_list*Group`（H93-95）销毁，存在关联 socket 晚于 service 销毁的生命周期错误。是否表现为 SIGSEGV 取决于运行时状态与平台，不能由声明顺序推出“必崩”；调用 `stop()` 当前不 reset socket。
- 复现步骤: 1) active=true、sport=0 构造并 init；2) stop()；3) 作用域结束；4) 使用 sanitizer 或可读取的系统崩溃报告检查析构期间是否访问失效 service。当前禁用用例未运行。
- 证据:
  - R164 旧文曾引用系统崩溃报告，但其路径当前不可读取，因此无法复核旧栈。
  - 现存 R154 `.rc` 是 `LeakyCaster` 运行结果，不能证明真实析构路径；本轮未执行
    `DISABLED_DestructorAfterActiveStartCrashes`，没有新的动态崩溃证据。
- 影响范围: 与 BUG-R164-001 一致：active 路径保留关联 socket 时有生命周期风险；不据此
  断言所有实例都会在正常退出时崩溃。
- 修复方向: 以 BUG-R164-001 的建议为准，保证 service 在 socket 及其所有持有容器销毁后
  才析构，并用真实 `UDPCaster` 析构用例验证。该条仅作为 R164 的测试侧交叉复核，不另计。

## 测试夹具修正（非产品缺陷）

### R151 `CsvLoadReportsEveryThousandBars` 崩溃：夹具漏 `register_sink`

- 现象: 原夹具的历史记录为 `prepare()` 内 `rc=139`，gtest 停在 `[ RUN ]`；当前用例已注册 sink。
- 根因: 用例未注册 `IDataSink`；`HisDataReplayer::prepare()` L669 无条件调用 `_listener->handle_init()`，`_listener == NULL`。产品侧缺判空是既有 **BUG-P04-002**；本用例是夹具违反了“回放前先 `register_sink`”的使用约定（同文件其余 4 条均已注册）
- 修复: `prepare()` 前 `_rp.register_sink(&sink, "r151_csv_load")`，并新增 `EXPECT_EQ(1u, sink.init_calls)` 验证回调确实发生
- 证据: 当前用例源码包含上述注册与断言；现有 `.rc` 记录 PASS（本轮未重跑）。这验证当前
  夹具能通过已走过的 setup，不代表已修复产品侧的 P04-002 空 listener 防护。

### R151 `DailySecondaryBarsCursorCatchesUp` 失败：夹具误用 `get_kline_slice` 契约

- 现象: 原夹具历史记录为 `mainSlice == NULL`（原第 125 行 `ASSERT_NE(nullptr, mainSlice)`）；当前定位数据已调整。
- 根因: 夹具主K线自 0106 起、回测起点 0102；首根 bar 晚于 `_cur_tdate` 时
  `get_kline_slice` 走“标的尚未上市”兜底把 `_cursor` 置 0，L2458 按契约返回 NULL。
  用例却要求该调用返回非空 slice，属夹具场景设计错误，不是产品回归
- 修复: 主K线增加 0102 一根仅用于定位的历史 bar（实际回放首日仍是 0106），次K线改为
  20191231 起；主/次 slice 均非空，次K线游标在 0106 收盘时由 0103 推进到 0106，
  继续覆盖 `simTicks` L1372-1378；原有计数与 `done_calls` 断言未改动
- 证据: 当前夹具含用于定位的历史 bar，现有 `.rc` 记录 PASS（本轮未重跑）；本条确认修正
  后的测试输入与 `get_kline_slice` 当前契约相容，不构成产品回归证据。
