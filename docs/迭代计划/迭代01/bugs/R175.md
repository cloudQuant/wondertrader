## BUG-R175-001 TraderMocker::registerSpi 对 NULL 解引用，TraderAdapter::release 必崩

- 状态: 待审核
- 严重级别: Blocker（关停路径必 SIGSEGV）
- 模块/文件/行:
  - `src/TraderMocker/TraderMocker.cpp:659-664`（`registerSpi`）
  - 调用点 `src/WtCore/TraderAdapter.cpp:423`（`release()`）
  - 同型调用点 `src/WtUftCore/TraderAdapter.cpp:227`
- 证据: `R160TraderTest.R160InitLoadsTraderModuleAndParsesNodeConfig` 在
  `adapter.release()` 处 `EXC_BAD_ACCESS`；lldb 栈顶
  `TraderMocker::registerSpi(this=..., listener=0x0) at TraderMocker.cpp:663`，
  下一行 `_bd_mgr = listener->getBaseDataMgr();`。既有
  `R110TraderInit.LoadsTraderModuleAndCreatesApi` 同样在 `trader.release()` 崩溃。
- 输入/前置条件: 任意 `TraderAdapter` 通过 `init()` 装载 `libTraderMocker`，
  随后调用 `release()`（无论是否先 `run()`）。
- 期望行为: `registerSpi(NULL)` 是解绑的合法用法；实现应判空（只清 `_listener`），
  或 `TraderAdapter::release()` 先判断监听器是否已注册。
- 实际行为: `registerSpi` 无条件写 `_listener` 后立刻 `listener->getBaseDataMgr()`；
  `release()` 传 NULL 即空指针解引用。所有使用 TraderMocker 的运行器在正常退出、
  配置重载或异常释放时都会崩在关停阶段。
- 复现步骤: 1) 临时 `traders/libTraderMocker.dylib` + 配置
  `{"module":"TraderMocker","mockerid":...,"span":...}`；2) `adapter.init(...)` 返回 true；
  3) `adapter.release()`；4) SIGSEGV，栈顶 TraderMocker.cpp:663。
- 影响范围: WtCore/WtUftCore 两条 TraderAdapter 的 release 路径；R110/R160 等
  Mocker 装配用例实际不可安全清理。
- 建议: `registerSpi` 增加 `if (listener == NULL) { _listener = NULL; return; }`，
  或在两处 `release()` 中按已注册状态跳过解绑。
- 用例关系: `r160_trader_adapter_test.cpp` 的 active 用例已移除 release 清理调用
  （init 断言全部保留）；`DISABLED_R160ReleaseAfterInitCrashesInMockerRegisterSpi`
  保留原触发路径，修复后可直接启用。

## BUG-R175-002 RDM 历史逐笔 V2 装载写已释放的块头指针，小块记录破坏堆

- 状态: 待审核
- 严重级别: Blocker（读真实 `.dsb` 可堆损坏/SIGSEGV）
- 模块/文件/行: `src/WtDataStorage/WtRdmDtReader.cpp`
  - 委托队列 `:731-733`（`_buffer.resize(sizeof(HisOrdQueBlock)); append(buf);` 后写 `tBlockV2->_version`）
  - 委托明细 `:906-908`
  - 逐笔成交 `:1080-1082`
- 证据: `R162ReaderEdgeTest.R162RdmReaderHisTransBlocksWithMixedActionDates` 在
  `readOrdDtlSliceByRange` 期间停在 `libsystem_malloc.dylib mfm_alloc`
  （`EXC_BAD_ACCESS`，地址为被写坏的链表指针）；同一输入下崩溃点随分配器复用位置漂移到
  dtl/trans 调用。lldb 逐调用确认：queue 调用返回后堆已损坏。
- 输入/前置条件: 生产同格式历史文件（`BlockHeaderV2` + `BLOCK_VERSION_CMP_V2` +
  zstd payload），块内 2 条记录。以 `make_ordque/make_orddtl/make_trans` 计算：
  原始 576/208/224B，zstd 压缩后约 183/91/100B。
- 期望行为: 解压重排头后正常返回切片；V2 头部版本号改写不得触碰已释放内存。
- 实际行为: `tBlockV2` 在 `resize()`/`append()` 之前取得。`resize(12)` 保留旧容量，
  `append(buf)` 因 `12 + raw > 20 + comp` 触发重分配并释放旧块；随后
  `tBlockV2->_version = BLOCK_VERSION_RAW` 写入已释放块。记录数少的文件落在
  tiny allocator，写坏 free-list 元数据，下一次 `malloc` 崩溃；记录多时也可能静默
  破坏后续分配。
- 复现步骤: 1) 写入上述 2 条记录的 CMP_V2 `.dsb`；2) `reader.init(NULL, sink)`；
  3) `readOrdQueSliceByRange(...)`（或 dtl/trans）；4) 进程在后续分配中 SIGSEGV。
- 影响范围: 所有通过 `read*SliceByRange` 读取历史逐笔数据的进程；收盘转储后首次
  查询小合约/小单日文件最危险。
- 建议: 在 `resize` 前保存 `uint16_t version = tBlockV2->_version;`，`append` 后写
  `((BlockHeader*)buffer.data())->_version = version`；或先 `resize`/`append` 再重新
  取 `tBlockV2` 指针（不要跨重分配持有）。
- 用例关系: active 用例保留原三条切片断言，改为把已解压块挂入 reader 缓存以驱动
  `lower_bound` 的跨 `action_date` 臂；`DISABLED_R162RdmReaderHisTransBlocksWithMixedActionDatesFromFile`
  保留生产格式文件的崩溃路径，修复后应启用并删除缓存注入。

## BUG-R175-003 WtUftCore::TraderAdapter::initExt 不判空 api，NULL 守卫调用即崩

- 状态: 待审核
- 严重级别: Major（公开 API 契约违背；调用方按 WtCore 同型接口传入 NULL 即崩溃）
- 模块/文件/行: `src/WtUftCore/TraderAdapter.cpp:90-100`（`:98 api->init(NULL)`）
- 证据: `R163UftTrader.InitGuardsAndRiskTotalLimits` 的
  `guard.initExt("r163", nullptr, ...)` 处 `EXC_BAD_ACCESS (address=0x0)`；lldb 栈顶
  `TraderAdapter::initExt(... api=0x0) at TraderAdapter.cpp:98`。
- 输入/前置条件: 任意 `ITraderApi* == NULL` 的 `initExt` 调用。
- 期望行为: 与 WtCore 同名接口一致，`api == NULL` 直接返回 false
  （`WtCore/TraderAdapter.cpp:209-212` 已有该守卫）。
- 实际行为: 无判空，直接 `api->init(NULL)`。
- 影响范围: UFT 交易通道的装配代码在配置缺失/工厂返回空时崩溃，而不是走失败分支。
- 建议: 在 `initExt` 首行补 `if (api == NULL) return false;`。
- 用例关系: active 用例保留 `init(nullptr)` 守卫断言并移除会崩的 `initExt(nullptr)`；
  `DISABLED_InitExtWithNullApiCrashesInsteadOfReturningFalse` 保留原断言，修复后启用。
