## BUG-R175-001 TraderMocker::registerSpi 不接受适配器 release 传入的 NULL

- 状态: 待审核
- 分类: WtCore/WtUftCore 适配器的解绑调用与 TraderMocker 实现不兼容；接口头文件未明确
  `registerSpi(NULL)` 的空值契约。历史动态栈支持该具体组合曾发生崩溃，但当前 active 用例
  已移除 release 调用，本次没有动态重跑。
- 严重级别: 仅限使用该 TraderMocker 且执行该 release 路径的条件风险；不据此推断所有
  Trader API 或所有运行器关停都会崩溃。
- 模块/文件/行:
  - `src/TraderMocker/TraderMocker.cpp:659-664`（`registerSpi`）
  - 调用点 `src/WtCore/TraderAdapter.cpp:423`（`release()`）
  - 同型调用点 `src/WtUftCore/TraderAdapter.cpp:227`
- 历史证据: `R160TraderTest.R160InitLoadsTraderModuleAndParsesNodeConfig` 曾在
  `adapter.release()` 处 `EXC_BAD_ACCESS`；lldb 栈顶
  `TraderMocker::registerSpi(this=..., listener=0x0) at TraderMocker.cpp:663`，
  下一行 `_bd_mgr = listener->getBaseDataMgr();`。既有
  `R110TraderInit.LoadsTraderModuleAndCreatesApi` 也有 release 崩溃记录。当前 active
  用例不再调用 release，保留的 disabled reproducer 未运行。
- 输入/前置条件: 任意 `TraderAdapter` 通过 `init()` 装载 `libTraderMocker`，
  随后调用 `release()`（无论是否先 `run()`）。
- 期望行为: 适配器的 release 若用 `registerSpi(NULL)` 解绑，TraderMocker 应与该调用约定
  一致；应由接口契约明确 NULL 是否代表解绑，再决定实现判空或适配器只在已注册时解绑。
- 实际行为: `registerSpi` 无条件写 `_listener` 后立刻
  `listener->getBaseDataMgr()`；适配器执行该解绑调用时会空指针解引用。影响限定于此
  TraderMocker 与适配器的组合及对应路径。
- 历史复现步骤: 1) 临时 `traders/libTraderMocker.dylib` + 配置
  `{"module":"TraderMocker","mockerid":...,"span":...}`；2) `adapter.init(...)` 返回 true；
  3) `adapter.release()`；4) SIGSEGV，栈顶 TraderMocker.cpp:663。
- 影响范围: WtCore/WtUftCore 的适配器源码均有传 NULL 的 release 调用；当前测试绕过了
  清理路径，是否影响其他 Trader 插件取决于各自 `registerSpi` 对 NULL 的实现。
- 建议: `registerSpi` 增加 `if (listener == NULL) { _listener = NULL; return; }`，
  或在两处 `release()` 中按已注册状态跳过解绑。
- 用例关系: `r160_trader_adapter_test.cpp` 的 active 用例已移除 release 清理调用
  （init 断言保留）；`DISABLED_R160ReleaseAfterInitCrashesInMockerRegisterSpi` 未运行。
  明确 NULL 解绑契约并修复后，应启用该路径验证。

## BUG-R175-002 RDM 历史逐笔 V2 装载可能跨字符串重分配写失效块头指针

- 状态: 待审核
- 分类: 源码显示存在跨 `std::string` resize/append 保存块头指针的风险；只有发生重分配时
  指针才失效。当前 active 缓存注入用例不经过该装载路径，历史崩溃记录不能证明所有
  V2 文件或所有读操作都会崩溃。
- 严重级别: 潜在内存安全问题；确切触发输入与运行时后果待生产格式文件用例验证。
- 模块/文件/行: `src/WtDataStorage/WtRdmDtReader.cpp`
  - 委托队列 `:731-733`（`_buffer.resize(sizeof(HisOrdQueBlock)); append(buf);` 后写 `tBlockV2->_version`）
  - 委托明细 `:906-908`
  - 逐笔成交 `:1080-1082`
- 证据: 源码在 `resize()/append()` 前取得指向字符串存储的 `tBlockV2`，随后继续通过该
  指针写版本字段；若追加导致字符串重分配，该指针将失效。此前存在 lldb 崩溃记录，但本
  次当前 active `R162RdmReaderHisTransBlocksWithMixedActionDates` 通过缓存直接注入未压缩
  块，绕过 CMP_V2 文件装载；生产格式文件路径对应的 DISABLED 用例未运行。因此本次没有
  对该装载风险的动态复现。
- 输入/前置条件: 生产同格式历史文件（`BlockHeaderV2` + `BLOCK_VERSION_CMP_V2` +
  zstd payload）；是否触发取决于相应缓冲区容量与追加后长度，需用实际文件/受控夹具验证。
- 期望行为: 解压重排头后正常返回切片；V2 头部版本号改写不得触碰已释放内存。
- 实际行为: `tBlockV2` 在 `resize()`/`append()` 之前取得；若其中操作使字符串存储地址
  改变，随后写 `tBlockV2->_version` 即使用失效指针。具体文件是否重分配，以及失效写入后
  是否崩溃或破坏其他状态，不能仅由静态代码确定。
- 复现步骤: 写入受控 CMP_V2 `.dsb`，记录缓冲区追加前后地址/容量，再调用相应
  `read*SliceByRange` 并检查结果；只有确认发生重分配后才能判断失效写入及其运行时后果。
- 影响范围: 可能受影响的是会进入该 V2 装载分支且追加期间发生重分配的读取；触发范围及
  后果仍需动态证据。
- 建议: 完成 `resize`/`append` 后重新从当前缓冲区取得头部指针，再把版本字段设为
  `BLOCK_VERSION_RAW`；不要跨可能重分配的字符串操作持有 `tBlockV2`。
- 用例关系: active 用例把未压缩块注入 reader 缓存，只验证缓存路径与跨
  `action_date` 比较，不验证 V2 解压/重排。生产格式文件用例仍为 DISABLED 且未运行；应在
  修正生产代码后启用它，并保留文件路径断言。
