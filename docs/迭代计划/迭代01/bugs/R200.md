# R200 疑似缺陷登记（状态：待审核，未修改源码）

Lane: R200（第二十八波），靶子 `ExecMocker.cpp` / `HisDataReplayer.cpp`。
以下问题由基线 `llvm-cov`、既有 per-test 判决与源码对读确认，**未对 `src/**` 做任何修改**。
行号以当前 HEAD 为准。

## 独立复核裁定（2026-10-29）

- BUG-R200-001 是 BUG-R190-001 的重复证据，当前没有新增栈帧或根因证据；保存的 `CRASH(rc=139,sig=11)` 只证明对应测试进程异常退出。
- `FactoryWithoutExecuter` 的保存日志实际到达 `E8 end`，然后缺少 gtest 收尾；该用例没有执行单元，也没有调用 `handle_init` 或非 15:00 的 `handle_schedule`。因此原文“只要真正创建执行单元即崩溃”及“日志停在 `[ RUN ]`”不适用于这条记录，不能据此把退出归到 `_exec_unit` 回调或初始化。
- 真实执行单元用例的日志停在 `[ RUN ]`，没有栈；R120 在另一个宿主成功不构成根因隔离。当前不能断言所有有效工厂成功路径崩溃，也不能把 94 行 0 计数解释为这些源码行都未执行：崩溃进程没有可合并的 per-test profraw，计数缺失不等同于控制流不可达。
- 源码另有独立风险：构造函数未初始化 `_exec_unit`，无 `executer` 配置时 `init` 不赋值，而 `handle_init`/非早退 `handle_schedule` 等路径无条件解引用。R121 用例未走这些调用；这是静态发现的未初始化指针风险，不能作为本次进程退出的已证实原因，应与 BUG-N04-001/相关空指针登记一起核查。
- 修复/验证方向：保留为待定位的重复现象；先分别隔离插件装载、执行单元创建、回调、局部对象析构，并为异常退出抓取 lldb 栈。另对无 `executer` 状态显式初始化指针并定义哪些回调允许调用，再用对应契约测试验收。

## BUG-R200-001 ExecMocker 真实插件测试进程异常退出（状态：待审核；与 R190 重复）

- 编号: BUG-R200-001
- 状态: 已合并（异常退出观察并入 BUG-R190-001；崩溃原因仍未知，不能归因于 ABI）
- 严重级别: 未定（保存证据仅支持特定测试进程 rc=139，受影响调用面尚未定位）
- 模块/文件/行:
  - `src/WtBtCore/ExecMocker.cpp:71-85`（工厂装载成功 + `createExeUnit/init`）
  - `src/WtBtCore/ExecMocker.cpp:140-161`（`handle_init`）
  - `src/WtBtCore/ExecMocker.cpp:168-192`（`handle_schedule`）
  - `src/WtBtCore/ExecMocker.cpp:270-274、286-335`（`cancel(stdCode)` 回调与
    `_exec_unit` 转发的 entrust/order/trade）
- 现象:
  - 已保存的 `CoverageTests_btcore` 判决将多条 ExecMocker 用例标为
    `CRASH(rc=139,sig=11)`；这表示用例所在进程异常退出，不定位退出时的函数。
    真实执行单元用例的 per-test 日志停在 `[ RUN ]`，没有断言或栈信息。
  - 同一崩溃族既覆盖合法单元名（`WtTWapExeUnit`/`WtMinImpactExeUnit`），也覆盖
    「工厂成功、cfg 无 executer」的 `R121ExecMocker.FactoryWithoutExecuter`；
    后者的保存日志依次记录到 `E8 end`，而用例源码没有创建执行单元，也未调用
    `handle_init` 或非 15:00 的 `handle_schedule`。它不支持“创建单元后才崩溃”这一
    共同条件，也不能说明退出发生在 `init`。
  - 作为对照，`CoverageTests_wtcore` 内 `R120DiffTest` 加载**同一份**
    `build_x64/Debug/bin/libWtExeFact.dylib` 并创建单元是通过的；差异在宿主
    执行体（btcov）与插件/`ExecMocker` 的组合，根因尚未定位到具体函数。
- 输入/前置条件:
  - `module` 指向本机构建产物 `libWtExeFact.dylib`（`nm -gU` 确认导出
    `_createExecFact`/`_deleteExecFact`）；
  - `executer.name` 为工厂真实注册的 `WtTWapExeUnit`、`WtMinImpactExeUnit`，
    或 cfg 中不带 `executer`；
  - 现有用例各自配置不同：包括有执行单元的路径、无执行单元的 R121 路径，及
    回调/析构路径；保存证据没有隔离出共同触发条件。
- 期望:
  - `init` 成功返回后，析构与 `handle_init/handle_schedule/handle_entrust/
    handle_order/handle_trade` 不应崩溃；若插件 ABI/生命周期不兼容，应在
    `init` 内记录错误并返回 false。
- 实际:
  - 保存判决为 rc=139；R121 日志到达用例主体末尾标记后未输出 gtest 收尾，其他真实
    执行单元日志则在 `[ RUN ]` 后中断。没有新鲜复跑或栈证据可确定具体退出阶段。
- 证据:
  - `build-cov/coverage/CoverageTests_btcore.results` 中以下判决均为
    `CRASH(rc=139,sig=11)`：
    `R111ExecMocker.EntrustOrderTradeAndReplayDump`、
    `R111ExecMocker.InitWithRealExecuterAndInitSchedule`、
    `R111ExecMocker.ScheduleNegativeAndPositiveVolumeModes`、
    `R121ExecMocker.FactoryWithoutExecuter`、
    `R180LoaderFixture.R180Exec_InitRealExecuterAndHandleInit` 等 4 条、
    `R20ExecMocker.BuyAfterTickAccumulatesUndone` 等 tick 后下单族。
  - `CoverageTests_btcore.results` 的既有 CRASH 判决及
    `CoverageTests_btcore.R121ExecMocker_FactoryWithoutExecuter.log`（含 `E1` 至 `E8`）；
    `R180Exec_InitRealExecuterAndHandleInit.log` 停在 `[ RUN ]`。
  - 基线 `llvm-cov show` 中目标行计数为 0，但崩溃测试的 per-test profraw 未进入合并
    profile；该 0 只能说明当前 profile 没有有效计数，不能单独证明源码路径没有执行。
- 与既有缺陷的关系:
  - 本波复核确认与 **BUG-R190-001** 为重复现象记录；本波没有新栈帧或独立根因证据，
    应合并到主条目，不把本条计作新增产品缺陷。
  - 未知单元名返回 NULL 后直接解引用已登记为 **BUG-R121-002**；
  - 策略工厂空指针族已登记为 **BUG-R111-001**；
  - `_exec_unit/_last_tick` 指针风险另见 **BUG-N04-001** 与 R20 的
    `DISABLED_ExecUnitNullDerefFamily`。
- 测试处理:
  - 本轮不新增 ExecMocker 启用用例，也不新增会直接 SIGSEGV 的 `DISABLED_`
    复现（根因未定位，禁用用例无法提供可复核断言，且与 R111/R121/R180 证据重复）。
  - 待主控在 btcov 下复跑并用 lldb 抓栈顶后，再决定归入 ABI、插件生命周期、
    用例清理/对象析构还是其他问题；不得从现有日志推断“94 行成功路径”整体受阻。
