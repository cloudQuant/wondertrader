## 观察 1：StateMonitor.h/DataManager.h 的内联函数在 profdata 中恒为 0

- 位置: `StateMonitor.h:169-222`、`StateMonitor.h:70-81`、`DataManager.h:79-84`、
  `IndexWorkerMgr.h:65-66`
- 现象: q05/r18/r68 的调用点已有计数（调用行 count=1），但此前检查的 `llvm-cov export` 里
  `StateMonitor::isInState/isAnyInState/isAllInState`、`_StateInfo::isInSections`、
  `DataManager::add_caster` 各只有一条函数记录且 count=0。说明这些类内定义的小函数
  可能受内联及覆盖率归并方式影响；仅凭一条 count=0 的函数记录不能确认独立
  out-of-line 副本从未执行。
- 判定: 当前没有产品行为缺陷证据。R174 用例通过成员函数指针调用相关查询，现存用例日志
  记录通过；但本次没有对应的合并后 profdata 复核，故不能声称该调用已强制计入独立
  out-of-line 副本。覆盖率结论需在合并 R174 profdata 后按函数记录/hash 对照验证。
- 交叉引用: R18 清单第 6 条、R164 清单第 2 节均已提到同类归并口径。

## 观察 2：空表上的 isAllInState 为 vacuously true

- 位置: `StateMonitor.h:189-203`
- 现象: `_map` 为空时循环不执行，`isAllInState(任意状态)` 返回 true（包括
  `SS_HOLIDAY`）。`StateMonitor::run()` 的
  `isAllInState(SS_PROCING) && !isAllInState(SS_Holiday)` 在空表下为
  `true && !true == false`，因此不会误触发 `transHisData("CMD_CLEAR_CACHE")`。
- 判定: 语义上「所有会话都满足」对空集成立，且当前唯一调用点的组合条件已屏蔽；
  不登记为缺陷。R174 用例锁死该边界，防止后续改动把空表行为改成异常。
