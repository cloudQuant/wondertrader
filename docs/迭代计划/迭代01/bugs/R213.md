## BUG-R213-001 测试目标 `-isystem src` 导致生产头 inline 函数无覆盖映射

- 状态: 待审核
- 严重级别: Major（度量缺陷，不影响产品运行）
- 模块/文件: `src/TestUnits/coverage/CMakeLists.txt`（`WT_COV_INCS` 中
  `-isystem /Users/.../src`）；受影响样本 `src/WtDtCore/StateMonitor.h:70-81、169-222`
- 相关测试: `src/TestUnits/coverage/q05_dtsrv/r204_dtcore_test.cpp` →
  `R204StateMonitor.QueryPredicatesOnOriginalStates`（rc = PASS）；
  `src/TestUnits/coverage/q05_dtsrv/r213_dtcore_test.cpp` →
  `R213StateMonitor.HeaderQueriesAndSectionPredicates`
- 输入/前置条件: 测试 TU 通过 `<WtDtCore/StateMonitor.h>` 引入头文件并调用
  `isInState` / `isAnyInState` / `isAllInState`
- 期望行为: 被调用并执行的 inline 函数应在 `llvm-cov show` 中计入覆盖
- 实际行为: clang 把经 `-isystem` 命中的头当作系统头，测试 TU 不为其中的
  inline 函数生成覆盖映射；R204 用例 PASS，但三个查询函数仍全为 0。最小
  clang 实验复现：同一头经 `-isystem` 包含时 `llvm-cov show` 无该文件映射，
  改为从测试文件相对路径包含后计数正常
- 复现步骤: 对比 `llvm-cov show ... src/WtDtCore/StateMonitor.h` 与
  `r204_dtcore_test.cpp` 的 PASS 记录；把同一头以
  `#include "../../../WtDtCore/StateMonitor.h"` 置于测试文件首行后重测
- 影响范围: 所有只经系统包含路径进入、且实现写在头文件里的 inline 代码
  （`StateMonitor.h` 的 49 行是当前最大一块）；这些行会被长期误记为未覆盖，
  扭曲模块归因
- 备注: 本 lane 未改 CMake，只在 `r213_dtcore_test.cpp` 内用相对包含规避；
  根治方案是由 CMake 把 `src` 从 `-isystem` 改为 `-I`，或在覆盖率目标上补
  `-fno-system-header-prefix` 一类口径（需主控评估对 boost 头版本钉扎的影响）
