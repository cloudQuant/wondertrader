## 复核裁定（2026-10-29）

- ParserAdapter 两个 guard 用例不是 PASS：落盘日志中
  R213DtParserAdapter.GuardsBeforeAnyModuleIsLoaded 与
  R213UftParserAdapter.GuardsBeforeModuleLoad 均因第二次 init 后 id 实际变为
  r213_second / r213_uft_second 而 FAIL。源码先写 _id，再检查 _cfg；首次用非空空配置
  会先 retain 配置，即使因 module 为空返回 false，第二次 init 会在 _cfg 检查处返回，
  但已更新 id。当前测试注释中“_cfg 已占用所以 id 不变”与实现顺序相反；尚未找到失败
  init 必须回滚 id 的接口契约。应修测试期望或先明确原子重入/保留旧 id 契约，再决定是否
  需要生产修复；本任务不改测试或实现。
- BUG-Q05-005 的配置泄漏是源码可证路径；长 sid 越界须满足输入长度至少 16 且允许作为
  session key。当前短 ID 用例既不触发也不否定该条件性风险；与 Q05-005 为重复记录。
- BUG-R194-001 在当前源文件是明确的 NULL stub，但源码注释称当前未实现。尚无 UFT
  切片承诺可将 stub 判成接口违约；保留为实现/产品契约待确认项，不把 R213 对 NULL 的
  断言写成缺陷复现。
- 本文记录的是截至 2026-10-29 可见的已有落盘结果；没有在本轮重跑。R213 StateMonitor
