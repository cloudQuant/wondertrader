## 新增缺陷

### BUG-R214-001 WtRtRunner::initSelStrategies 无任何调用点，SEL 策略配置永不生效

- 位置: `src/WtPorter/WtRtRunner.cpp:745-789`（定义）、`:706-711`（唯一分派处）
- 现象: `initEngine` 末尾只按 `_is_hft` 调用 `initCtaStrategies()` 或
  `initHftStrategies()`；`initSelStrategies()` 在整个仓库中没有调用点。
  `grep -rn "initSelStrategies" src/` 只命中声明与定义两处。
- 影响: `config` 里 `strategies.sel` 数组永远不会被读取；SEL 环境实际走
  `initCtaStrategies`（读 `strategies.cta`），即 SEL 策略不会被创建/调度。
  该函数 44 行也因此是进程内不可达的死代码。
- 建议: 在 `_is_hft == false` 且环境为 SEL 时调用 `initSelStrategies()`，
  或删除该函数并明确 SEL 由何路径装载。
- 状态: 待审核

### BUG-R214-002 WtBtPorter::config_backtest 的 static inited 永不为 true

- 位置: `src/WtBtPorter/WtBtPorter.cpp:174-185`
- 现象: 函数体只有 `if (inited) return;`，`inited` 声明为 `static bool inited = false;`
  后从未赋值为 true（对比同文件 `init_backtest` 有 `inited = true;`）。
- 影响: 注释承诺“只执行一次、重复调用忽略”实际不成立；重复调用会再次
  `getRunner().config(...)`，重放器/模拟器/日志被重复初始化。`return;`（第 179 行）
  为不可达行。
- 建议: 在 `config` 成功后补 `inited = true;`。
- 状态: 待审核

### BUG-R214-003 WtBtRunner::_inited 从未置 true，config 的“已初始化”守卫是死分支

- 位置: `src/WtBtPorter/WtBtRunner.cpp:449-455`（守卫）、`:437-447`（init 未赋值）、
  `src/WtBtPorter/WtBtRunner.h:642`
- 现象: `_inited` 只在构造函数初始化列表置 false，`init()`/`config()` 均未写 true。
- 影响: `config()` 开头的 `if(_inited)` 分支永不执行（452-455 死代码），重复
  config 不会被拒绝；与 `WtPorter` 侧 `init_porter` 的进程级门（L138-147）
  语义不一致。
- 建议: 在 `init()` 或首次 `config()` 成功后置 `_inited = true`。
- 状态: 待审核

### BUG-R214-004 TraderMocker::disconnect 不重置 _thrd_match，且先 disconnect 后 release 会漏停 io worker

- 位置: `src/TraderMocker/TraderMocker.cpp:705-720`、`:640-657`
- 现象: `disconnect()` 只置 `_terminated` 并 join `_thrd_match`，不 reset 该指针；
  `isConnected()` 在断开后仍返回 true。更严重的是 `release()` 首行
  `if (_terminated) return;` 会直接跳过 `_io_service.stop()` 与
  `_thrd_worker->join()`；若调用方先 `disconnect()` 再 `release()`（或析构），
  io worker 线程仍在运行并持有 `this`，对象销毁后形成 use-after-free。
- 影响: 公开生命周期 API 的组合不安全；本 lane 的 disconnect 用例因此只敢在
  未 `connect()`（无 io worker）的实例上驱动，`reconn_udp` 的 socket 关闭分支
  （669-673）也只能留给有真实 UDP 生命周期的场景。
- 建议: `disconnect()` 中 `_thrd_match.reset()`，并把 worker 的停止/join 独立于
  `_terminated` 守卫（例如 release 始终执行 io 清理，重复调用用单独标志）。
- 状态: 待审核
