## 观察 1：头文件内联函数在 profdata 中仍恒为 0

- 位置: `StateMonitor.h:70-81/169-222`、`DataManager.h:79-84`、`IndexWorkerMgr.h:26-35/62-63`、
  `TraderAdapter.h:66-71/94-96/110/137`、`WtBtRunner.h:123-596`、`WtUftEngine.h:71-73`、
  `ShmCaster.h:57/83`
- 现象: R174 已对 `StateMonitor::isInState/isAnyInState/isAllInState`、`_StateInfo::isInSections`、
  `DataManager::add_caster` 使用成员函数指针发起间接调用，用例 PASS，但最新 profdata 仍记 0。
  R183 又新增 `UftStraWrapper`/`ShmCaster` 值类型的直接执行，预计同样受该口径影响。
- 判定: 属覆盖率记账/内联归并现象，不是产品行为缺陷。测试只走公开 API，未改宏、未镜像布局；
  若合并后仍为 0，应按 `llvm-cov export` 的函数记录 hash 复核。
- 交叉引用: `bugs/R174.md` 观察 1、R18/R164 清单同类条目。

## 观察 2：`WtBtRunner::_inited` 与 `config_backtest` 的 `static inited` 都不置 true

- 位置: `WtBtRunner.cpp:451-455`；`WtBtPorter.cpp:156-185`
- 复核证据: 最新基线 452/179 仍为 0；全文件没有 `_inited = true`，`config_backtest` 内也没有
  `inited = true`。第二次 config 会重复 `initEvtNotifier`、`_replayer.init` 并重建 mocker。
- 判定: 守卫不可达，重复初始化有资源泄漏/旧 mocker 悬空风险。
- 本 lane 处理: 不写「第二次不重建」的 active 用例（必红），也不写「会重建」固化缺陷；
  留白并在清单第 5 节标注。
- 交叉引用: `BUG-R173-004` / `BUG-R134-001` / `BUG-R134-002`。

## 观察 3：UFT 切片接口首行返回 NULL，订阅分支死代码

- 位置: `WtUftEngine.cpp:179-243`；`UftStraContext.cpp:944/954/963/972/982`
- 复核证据: `get_tick_slice/get_kline_slice` 第一行无条件 `return NULL`，后续
  `_bar_sub_map` 写入、周期换算、`_data_mgr->get_kline_slice` 全部不可达；上层
  `if (ret) _engine->sub_tick(...)` 永不进入。
- 判定: 公开 API 永远拿不到 K 线/Tick 切片，`on_bar`（592-602）也因订阅表无写入点而不可达。
- 本 lane 处理: `R183UftEngine` 只断言 NULL 返回路径安全，不写「期望非空」的 active 用例。
- 交叉引用: `BUG-R173-001` / `BUG-P06-005` / `BUG-R123-001`。

## 观察 4：`TraderAdapter` 频率风控窗口写入点被注释

- 位置: `TraderAdapter.cpp:1864-1965`；写入点 364/444/724/996/1025/1054/1083
- 复核证据: `checkCancelLimits/checkOrderLimits` 的时间窗 `lower_bound/erase/封禁` 分支
  在基线为 0；所有 `emplace_back(now)` 均被注释，缓存恒空，`cnt >= boundary` 永不成立。
- 判定: 「N 秒内最多 N 次报单/撤单」的风控整体失效，只剩总量限制与排除队列。
- 本 lane 处理: 公开 API 无法写入缓存，不写伪造私有成员的用例。
- 交叉引用: `BUG-Q04-004` / `BUG-R173-002`。

## 观察 5：`DataManager` 缺 writer 符号后解引用 NULL；`ParserAdapter` 无 writer 时索引分支不可达

- 位置: `DataManager.cpp:83-98`；`WtDtCore/ParserAdapter.cpp:307-309`
- 复核证据: dlopen 成功但 `createWriter/deleteWriter` 任一缺失时只记录日志，随后仍执行
  `_writer->init(...)`；`ParserAdapter::handleQuote` 先要求 `_dt_mgr->writeTick(...)` 为真，
  而 `DataManager::writeTick` 在 `_writer==NULL` 时返回 false，故 `_idx_fact->handle_quote`
  不可达。
- 本 lane 处理: 不构造缺符号的 writer 模块（会崩），也不伪造 writer 注入；
  `R183DtIndexWorkerMgr` 只测工厂目录的缺符号跳过路径。
- 交叉引用: `BUG-R18-002`、`BUG-R18-003`、`BUG-R44-005`。

## 观察 6：`IndexWorkerMgr` 构造不初始化 `_hot_mgr/_bd_mgr/_data_mgr`

- 位置: `IndexWorkerMgr.cpp:27-34`；`IndexWorkerMgr.h:62-63`
- 复核证据: 构造函数为空；`get_hot_mgr/get_bd_mgr` 在 `init` 之前返回未初始化值。

- 交叉引用: `BUG-R44-007`。
