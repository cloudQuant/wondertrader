## BUG-R45-001 ParserAdapter::release 重复调用风险（未发现正常生产路径会调用两次）
- 迭代02第二轮前状态（历史）: - 状态: 待审核
- 状态: 已撤回（迭代02：TEST，原产品主张不成立）
- 严重级别: 条件性生命周期风险；重复 release 契约未明确
- 模块/文件: WtDtServo / `src/WtDtServo/ParserAdapter.cpp:205-217`
- 相关测试: `r45_parseradapter_test.cpp::DISABLED_ReleaseTwiceDoubleDeletesApi`（归档未运行；不据此声称动态 double free）
- 输入: `ParserAdapter pa(&bd, nullptr); pa.initExt("x", new FakeParserApi()); pa.release(); pa.release();`
- 期望: 若 API 生命周期契约要求 `release()` 幂等，第二次调用应安全返回；否则应明确禁止重复调用并在接口层可诊断。
- 实际: `release()` 只置 `_stopped = true`，随后无条件 `_parser_api->release()`；`_remover` 为空时再 `delete _parser_api`。对象既未置空也无 `_released` 标记，第二次调用在已释放内存上取虚表并再次 delete。
- 定向测试设置（原 DISABLED 用例未运行）: 1) 用 fake API 建适配器；2) 连续两次 `release()`；3) 按契约断言安全 no-op 或明确拒绝。只有诊断构建实际报告后才记录 UAF/double-free 运行结果。
- 复核: 源码显示 `_parser_api` 在无 remover 时被 delete 后未置空；若调用者重复调用 `release()`，存在 UAF/double-delete 风险。但 `ParserAdapterMgr::release` 只调用一次后清表，未发现标准 runner 退出流程会重复释放；公开契约也未确认 `release` 必须幂等。应作为条件性 API 防御项，不宣称正常退出崩溃。若契约要求幂等，置空指针/加 released 状态，并以独立进程或 fake API 断言第二次调用安全且 release 只执行一次。

## BUG-R45-002 ParserAdapter::initExt 无「已初始化」守卫，重复调用泄漏前一个 api 并留下失配的 spi 绑定
- 迭代02第二轮前状态（历史）: - 状态: 待审核
- 状态: 已撤回（迭代02：TEST，原产品主张不成立）
- 严重级别: Minor
- 模块/文件: WtDtServo / `src/WtDtServo/ParserAdapter.cpp:44-50`
- 相关测试: `r45_parseradapter_test.cpp::SecondInitExtReplacesApiWithoutReleasingFirst`（源文件中启用；本复核未运行）
- 输入: 同一个适配器连续 `initExt("first", api1)`、`initExt("second", api2)`，随后 `run()`、`release()`。
- 期望: 第二次 `initExt` 应拒绝（与 `init()` 的 `_cfg != NULL` 守卫一致），或先 `release()` 旧 api 再替换。
- 实际（源码推导）: `initExt` 直接 `_parser_api = api; _id = id;`，第二次有效调用会丢失旧指针；按 `release()` 的所有权处理，旧 api 不再可被释放。测试断言描述了期望观察，但本复核未运行，故不是本机动态计数证据。
- 定向断言（源码测试未运行）: 同用例，检查 `first` 的 release/delete 次数、`second->connect_calls`、`first->connect_calls` 与 `id()`；测试文件当前断言不能当成本机已观察结果。
- 复核与修复方向: 源码确认同一适配器重复 `initExt` 会覆盖旧指针；但未发现生产调用链重复调用，不能扩大成热重载/线程/连接泄漏已发生。明确 API 生命周期：拒绝重复初始化，或先按所有权释放旧 api 再替换；启用测试应检查旧实例 release/delete 次数、新实例注册和 `id()`，并在本机运行后再报告动态结果。
