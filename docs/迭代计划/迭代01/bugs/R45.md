## BUG-R45-001 ParserAdapter::release 非幂等，二次调用在已释放对象上再做虚调用并 delete
- 状态: 待审核
- 严重级别: Minor
- 模块/文件: WtDtServo / `src/WtDtServo/ParserAdapter.cpp:205-217`
- 相关测试: `r45_parseradapter_test.cpp::DISABLED_ReleaseTwiceDoubleDeletesApi`（启用即 double free，禁止在 CI 打开）
- 输入: `ParserAdapter pa(&bd, nullptr); pa.initExt("x", new FakeParserApi()); pa.release(); pa.release();`
- 期望: 第二次 `release()` 是 no-op（`_stopped` 已为 true，`_parser_api` 应判空或被置空）。
- 实际: `release()` 只置 `_stopped = true`，随后无条件 `_parser_api->release()`；`_remover` 为空时再 `delete _parser_api`。对象既未置空也无 `_released` 标记，第二次调用在已释放内存上取虚表并再次 delete。
- 复现步骤: 1) 用 r45 的 fake api 建适配器；2) 连续两次 `release()`；3) 进程在第二次虚调用/析构处崩溃（ASAN 报 heap-use-after-free / double-free）。
- 影响: 任何「析构路径重复释放」的宿主（如退出时先手动 release 再依赖管理器清理）都会把正常退出变成崩溃；当前 `WtDtRunner` 析构为空实现，所以主链路暂时只泄漏不崩溃，属潜伏缺陷。

## BUG-R45-002 ParserAdapter::initExt 无「已初始化」守卫，重复调用泄漏前一个 api 并留下失配的 spi 绑定
- 状态: 待审核
- 严重级别: Minor
- 模块/文件: WtDtServo / `src/WtDtServo/ParserAdapter.cpp:44-50`
- 相关测试: `r45_parseradapter_test.cpp::SecondInitExtReplacesApiWithoutReleasingFirst`（启用，锁定现状）
- 输入: 同一个适配器连续 `initExt("first", api1)`、`initExt("second", api2)`，随后 `run()`、`release()`。
- 期望: 第二次 `initExt` 应拒绝（与 `init()` 的 `_cfg != NULL` 守卫一致），或先 `release()` 旧 api 再替换。
- 实际: `initExt` 直接 `_parser_api = api; _id = id;`，api1 既没有 `release()` 也没有 `delete`（静态计数：`s_release_calls == 0`），其 `registerSpi(this)` 绑定也仍指向同一个适配器；`id()` 被悄悄改成 "second"。
- 复现步骤: 同用例；断言 `first->release_calls == 0`、`second->connect_calls == 1`、`first->connect_calls == 0` 全部成立。
- 影响: 热重载/重复装配场景下解析器实例与线程/连接泄漏；日志按 `id()` 对齐时会把旧实例的日志算到新 id 上。初始化路径 `init()` 有守卫而 `initExt()` 没有，行为不一致。

## BUG-R45-003 WtRdmDtReaderAD 空库区间读对空 vector 取下标，数据服务在「空数据目录」上必崩
- 状态: 待审核
- 严重级别: Blocker
- 模块/文件: WtDataStorageAD / `src/WtDataStorageAD/WtRdmDtReaderAD.cpp:216-249`（tick）、`:353-388`（K 线）；由 `src/WtDtServo/WtDataManager.cpp:116`（`get_tick_slices_by_range`）与 `:203`（`get_kline_slice_by_range` 的 times==1 分支）直接触发
- 相关测试: `r45_runnerextra_test.cpp::DISABLED_EmptyStoreSinglePeriodRangeReadSegfaults`（启用即段错误，禁止在 CI 打开）
- 输入: `data.store` 指向一个全新的空目录（无任何 LMDB 数据），初始化成功后调用 `runner.get_bars_by_range("CFFEX.IC.2204", "m5", 202401020930, 202401021500)`（"m5" → realTimes==1 → 基础周期区间读）。
- 期望: 空库/空区间返回 `NULL`（与 `readKlineSliceByCount`、`readTickSliceByDate` 的 TODO 形态一致），至少不能越界。
- 实际: `barsList._bars` 为空时仍执行 `&barsList._bars[0]`（空 vector 的 `operator[]` 是 UB），并把 `&v[0] + (size()-1)`（size 为 0 时即 `v[0] - 1`）当上界传给 `std::lower_bound`，随后解引用 `pBar->date/time`。tick 侧 `tickList._ticks` 同构（`:216-249`）。实测在全新空目录上必崩（SIGSEGV），不是返回空切片。
- 复现步骤: 1) `WtHelper::set_module_dir(<bin>/ )`，`store.module=WtDataStorageAD`、`store.path=<空临时目录>/`；2) `WtDataManager::init` 成功；3) 调用 `get_kline_slice_by_range(code, KP_Minute1, 1, stime, etime)`（或 runner 的 "m5" 形态）；4) 段错误。
- 影响: 新装/换数据盘后的第一次区间查询即打挂整个数据服务进程；`WtDtServo` 的 C 导出 `get_bars_by_range`/`get_bars_by_date`（"m1"/"m5"）在生产上走同一条链。r45 lane 因此只能覆盖「按数量 / 按日期 Tick / 秒线」等空库安全形态，`get_tick_slices_by_range` 与 times==1 的区间读整块留白。
- 建议: 在两处 `lower_bound` 前加 `if (list.empty()) return NULL;`；并对 `eIdx < sIdx` 的 `cnt` 做下溢保护。
