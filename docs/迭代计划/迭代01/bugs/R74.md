## BUG-R74-001

- 状态: 待审核
- 严重级别: Major（顺序相关的假空数据，文件存在也返回 NULL）
- 模块/文件: `src/WtDataStorage/WtDataReader.cpp`
  - `readOrdDtlSlice` L690：`auto it = _his_ordque_map.find(key);`
    —— 装载却写进 `_his_orddtl_map`（L713、L741）
  - `readTransSlice` L847：同样查 `_his_ordque_map`
    —— 装载写进 `_his_trans_map`（L870、L898）
- 相关测试: `src/TestUnits/coverage/q03_storage3/r74_reader_residual2_test.cpp` →
  `R74ReaderResidualTest.DISABLED_R74ReaderQueueCacheHidesSameDayDetailAndTrans`
- 输入/前置条件:
  - `his/queue/SSE/20240108/600000.dsb`、`his/orders/SSE/20240108/600000.dsb`、
    `his/trans/SSE/20240108/600000.dsb` 三份文件都存在且合法；
  - `WtDataReader::init(cfg, sink, NULL)`；
  - 先调 `readOrdQueSlice("SSE.STK.600000", 5, 20240108150000000)`，再调
    `readOrdDtlSlice(...)` / `readTransSlice(...)`（同 code 同交易日）。
- 期望行为: 三类逐笔各自独立缓存；queue 的缓存命中不得影响同日 dtl/trans 的首次装载，
  两个调用都应返回包含 1 条记录的切片。
- 实际行为:
  1. queue 首读把 key `SSE.STK.600000-20240108` 放进 `_his_ordque_map`；
  2. dtl/trans 首读在 L690 / L847 查到同一个 key，于是**跳过文件装载**；
  3. 后续取的是 `_his_orddtl_map[key]` / `_his_trans_map[key]` 的默认空条目，
     `tBlkPair._block == NULL`（L741-743 / L898-900）→ 直接 `return NULL`，
     即使 `.dsb` 文件存在。
  - 附带问题：dtl/trans 自己的缓存 map 永远不会被查询，重复读取同一交易日会反复读盘/解压。
- 复现步骤:
  1. 用 `q03_storage3_fixture.h` 的 `make_block(CMP_V2)` 写三份同交易日文件；
  2. `WtDataReader` 注入单目录 cfg；
  3. 依次调用上述三个公开虚函数。
  用例已写成 `DISABLED_`，`--gtest_also_run_disabled_tests` 可复现（dtl/trans 断言失败）。
- 影响范围: 任何“先读委托队列、再读同日逐笔委托/成交”的回放或策略预热流程；结果取决于
  调用顺序，且错误静默（无日志）。
- 备注: 与 `bugs/R1_wtdatastorage.md` 第 2 条（`WtRdmDtReader.cpp` 的 L876/L1051 同型问题）
  是同一类缺陷在 `WtDataReader.cpp` 的复制，R1 只登记了 Rdm 侧；修复时建议两文件一起改，
  把 L690 / L847 换成各自的 `_his_orddtl_map` / `_his_trans_map`。
