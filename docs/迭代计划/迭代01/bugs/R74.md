## BUG-R74-001

- 状态: 已合并（迭代02：主编号 BUG-R132-002）
- 严重级别: Major（顺序相关的假空数据，文件存在也返回 NULL）
- 模块/文件: `src/WtDataStorage/WtDataReader.cpp`
  - `readOrdDtlSlice` L690：`auto it = _his_ordque_map.find(key);`
    —— 装载却写进 `_his_orddtl_map`（L713、L741）
  - `readTransSlice` L847：同样查 `_his_ordque_map`
    —— 装载写进 `_his_trans_map`（L870、L898）
- 相关测试: `src/TestUnits/coverage/q03_storage3/r74_reader_residual2_test.cpp` →
  `R74ReaderResidualTest.DISABLED_R74ReaderQueueCacheHidesSameDayDetailAndTrans`。该用例形状与源码触发条件一致，但本轮运行进程以 SIGTRAP 终止，没有 gtest 断言摘要，因此不把它记为成功的动态复现。
- 输入/前置条件:
  - `his/queue/SSE/20240108/600000.dsb`、`his/orders/SSE/20240108/600000.dsb`、
    `his/trans/SSE/20240108/600000.dsb` 三份文件都存在且合法；
  - `WtDataReader::init(cfg, sink, NULL)`；
  - 先调 `readOrdQueSlice("SSE.STK.600000", 5, 20240108150000000)`，再调
    `readOrdDtlSlice(...)` / `readTransSlice(...)`（同 code 同交易日）。
- 期望行为: 三类逐笔各自独立缓存；queue 的缓存命中不得影响同日 dtl/trans 的首次装载，
  两个调用都应返回包含 1 条记录的切片。
- 实际行为:
  1. queue 首读把 key `SSE.STK.600000-20240108` 放进 `_his_ordque_map`；
  2. dtl/trans 首读在 L690 / L847 查到同一个 key，于是**跳过文件装载**；
  3. 后续取的是 `_his_orddtl_map[key]` / `_his_trans_map[key]` 的默认空条目，
     `tBlkPair._block == NULL`（L741-743 / L898-900）→ 直接 `return NULL`，
     即使 `.dsb` 文件存在。
  - 附带问题：dtl/trans 自己的缓存 map 永远不会被查询，重复读取同一交易日会反复读盘/解压。
- 复现步骤（静态路径）:
  1. 用 `q03_storage3_fixture.h` 的 `make_block(CMP_V2)` 写三份同交易日文件；
  2. `WtDataReader` 注入单目录 cfg；
  3. queue 首读后，dtl/trans 在同一 `stdCode-endTDate` key 上错误命中 `_his_ordque_map`，跳过各自装载；
  4. 随后分别查询 `_his_orddtl_map` / `_his_trans_map` 的新默认条目，`_block` 初值为 NULL，返回 NULL。
- 影响范围: 任何“先读委托队列、再读同日逐笔委托/成交”的回放或策略预热流程；结果取决于
  调用顺序，且错误静默（无日志）。
- 备注: 与 `bugs/R1_wtdatastorage.md` 第 2 条（`WtRdmDtReader.cpp` 的 L876/L1051 同型问题）
  是同一类缺陷在 `WtDataReader.cpp` 的复制，R1 只登记了 Rdm 侧；修复时建议两文件一起改，
  把 L690 / L847 换成各自的 `_his_orddtl_map` / `_his_trans_map`。


- 迭代02复核: DUPLICATE。与 BUG-R132-002 的实现路径、误查 _his_ordque_map 的两处代码、空 block 结果完全相同；只是重复登记来源和复现 fixture 不同。

## 2026-10-29 复核与测试记录

- 源码逐项确认：`readOrdDtlSlice` 在 L690、`readTransSlice` 在 L847 都查 `_his_ordque_map`；对应读盘和后续取值分别使用 `_his_orddtl_map`、`_his_trans_map`。键由同一格式 `stdCode-endTDate` 构造，因此同日 queue 缓存可跳过另外两类数据的首次加载。修复方向是分别查正确的 detail/trans map，并保留独立缓存。
- 测试前提更新：R112 旧缺文件用例没有创建 detail/trans 文件，不能验证跨类型独立性，相关断言已移除；新建了三类文件均存在、先读 queue 的独立正确契约回归。首次执行 signal 9，原因未知，受控资源上限诊断未进入进程；该新用例现暂时 DISABLED，动态结论未建立，不能将 signal 9 归因于 map 错查或潜在的缓冲区旧指针问题。
- R1 的同类错误落在另一个 reader 类和源文件，属于复制模式相同、实现位置不同，不按同一条重复记录撤销；建议修复时一并检查两个实现。
- `CoverageTests --gtest_filter='R74ReaderResidualTest.*'` 的一次整组运行在最后一项以退出码 133（SIGTRAP）结束；前三项输出 PASS。随后单独运行 `R74ReaderKlineRtBackoffAndMinuteEnd` 为 PASS。启用路径没有完整的一次整组通过记录。
- `--gtest_also_run_disabled_tests --gtest_filter='R74ReaderResidualTest.DISABLED_R74ReaderQueueCacheHidesSameDayDetailAndTrans'` 也以退出码 133 结束，未得到断言摘要/栈信息；因此本项目前的确认来自源码数据流，不宣称该禁用用例已动态证明预期的 NULL 返回。测试环境信号原因待诊断。
