## 逐项证据边界

### UFT 切片桩

- WtUftEngine.cpp:179-183 与 :209-243 显式提前返回，且实现注释称当前为空；:221 的 _bar_sub_map 插入不可达，on_bar 只读该 map。
- r194_uftcore_test 的 NULL 断言验证的是当前 stub 行为，不代表用户接口目标就是 NULL，也不能用于宣称数据访问功能正确。
- 处理：沿用既有 UFT 切片缺口编号；由接口 owner 确认支持状态后再验收。

### 回放时间格式

- WtBtPorter 文档写秒级 14 位，HisDataReplayer::prepare 却按 12 位 date/time 拆分；这是可静态确认的公开契约冲突。
- R194 原 bars 用例允许零返回；现已修正本地 loader、12 位截止时间、条数和字段断言，CTA/SEL/HFT 各 5 根及回调在单独进程中通过。动态库加载报缺少空模块路径的诊断，此测试只覆盖本地回调数据，不证明生产插件加载。
- 这三项是 12 位对照，不能据此证明 14 位接口合同正确。旧 R134 日志里关于“loader 已回调 3 根 bar”的描述不保留为本缺陷证据，除非能以独立日志/断言证明来源。

### WtBtRunner 配置守卫

- WtBtRunner 构造 _inited=false；config 的守卫存在但全仓无 true 写入。WtBtPorter.cpp 的 config_backtest 另有未赋值 static。
- 两处可证明的是注释/守卫不匹配，不是已经发生的泄漏或回测输出错误。重复 config 的安全性和资源释放方式仍需可观察测试确认。

### TraderAdapter 风控

- 时间窗缓存写入点在 TraderAdapter.cpp 中被注释，checkOrderLimits/checkCancelLimits 定义仍存在。
- 正常撤单与 openLong/openShort/closeLong/closeShort 等委托入口对这些检查的调用也被注释。因此这份审计仅能说显式调用检查函数时，窗口数据没有有效写入来源；不能从配置存在、代码分支或覆盖率空白推导出生产订单已绕过一项本来启用的风控政策。
- 与 Q04-004 / R173-002 同一根因，不重复登记。
