## BUG-R194-001 WtUftEngine 的 K 线/Tick 切片入口无条件返回 NULL，订阅表与 on_bar 永久失效

- 状态: 待审核
- 严重度: 中（公开 API 与文档语义不符；引擎侧的 K 线回调整条链路不可达）
- 位置:
  - `src/WtUftCore/WtUftEngine.cpp:179-183`（`get_tick_slice` 先 `return NULL`，随后
    `return _data_mgr->get_tick_slice(...)` 为死代码）；
  - `src/WtUftCore/WtUftEngine.cpp:209-243`（`get_kline_slice` 先 `return NULL`，
    其后 213-243 的合约查询、`_bar_sub_map[key]` 插入、周期换算与真正的
    `_data_mgr->get_kline_slice` 全部不可达）；
  - `src/WtUftCore/WtUftEngine.cpp:584-603`（`on_bar` 只读 `_bar_sub_map`，
    而全仓唯一写入点 221 行位于上述死代码内）。
- 现象:
  - `WtUftEngine::get_kline_slice/get_tick_slice` 对任何参数都返回 nullptr，
    `UftStraContext::stra_get_bars/stra_get_ticks` 的 `if (ret) sub_*` 分支
    （`UftStraContext.cpp:943-944/953-954`）与 `on_bar` 的策略回调循环
    （`WtUftEngine.cpp:592-602`）永远不执行。
  - 全量报告中 `WtUftEngine.cpp` 的 34 行缺口（182、213-243、592-602）
    与 `UftStraContext.cpp` 的 5 行（944/954/963/972/982）属于同一条链。
- 证据:
  - `llvm-cov show CoverageTests_uftcore ... src/WtUftCore/WtUftEngine.cpp`：
    179-183/209-243 的 `return NULL` 命中，后续行 count 恒 0；
  - `r194_uftcore_test.cpp` 的 `R194UftEngine.SliceEntriesAreNullStubsAndOnBarIsInert`
    以公开 API 实测五个切片入口全部 NULL，`on_bar` 空订阅不崩。
- 期望:
  - 若这是临时桩，应在头文件/文档标注 “not implemented” 并移除不可达代码；
    若要恢复功能，删除两处提前 return，使 `_bar_sub_map` 与 `_data_mgr` 路径生效。
- 测试处理:
  - 本轮只锁定“当前返回 NULL”的桩行为，不对失效链路写启用断言；
    重采样/订阅死代码不进入覆盖目标。

## BUG-R194-002 `set_time_range` 文档要求 14 位时间，回放器按 12 位解析，区间被解析成非法日期

- 状态: 待审核
- 严重度: 高（公开 C API 按文档传参即让回测区间错位，回放可能直接空跑）
- 位置:
  - `src/WtBtPorter/WtBtPorter.cpp:187-195`（注释与导出声明均写
    `stime/etime 格式为 YYYYMMDDHHmmss`，即 14 位）；
  - `src/WtBtPorter/WtBtRunner.cpp:590-595`（原样转发给 `_replayer.set_time_range`）；
  - `src/WtBtCore/HisDataReplayer.h:782-786`（只保存原值）；
  - `src/WtBtCore/HisDataReplayer.cpp:661-662`（`_cur_date=_begin_time/10000`、
    `_cur_time=_begin_time%10000`，按 12 位 `YYYYMMDDHHMM` 解析）。
- 现象:
  - 传 `20240103000000`（14 位）时得到 `_cur_date=2024010300`、`_cur_time=0`，
    `calcTradingDate` 与 `offsetTime` 全部落在非法日期上；传 12 位
    `202401030000` 才是 2024-01-03 00:00。
  - 既有 `q06_btporter/r134_btporter_bars_test.cpp` 的三个 FAIL（`cnt=0`，
    日志 `r134_btporter_bars_test.cpp:208 Failure`）正是该原因：配置里写了
    `stime:20240103000000`，loader 已回调 3 根 bar，但切片定位返回 NULL。
- 证据:
  - `build-cov/coverage/CoverageTests_btporter.R134BtPorterBars_CtaGetBarsReturnsLoadedBlocks.log`；
  - 仓库内能跑通 loader 的夹具（`p03_btcore_mockers2/r72_common.h:304-331`、
    `r180_btcore_mockers2_test.cpp:211-228`）一律使用 12 位
    `202001020930`/`202001021500`。
- 期望:
  - 二选一：把 `WtBtPorter::set_time_range` 的文档改成 `YYYYMMDDHHMM`；
    或在 `WtBtRunner::set_time_range`/`HisDataReplayer::prepare` 统一做
    12/14 位归一化（≥1e13 时先 `/100`）。
- 测试处理:
  - 本轮 `r194_btporter_test.cpp` 改用 12 位区间，bars 用例才具备命中
    非空切片分支的可能；未修改 r134 既有用例。

## BUG-R194-003 `WtBtRunner::_inited` 只写 false，`config` 的重复初始化守卫是死代码

- 状态: 待审核
- 严重度: 低（防御代码失效；重复 `config` 会重建 replayer/mocker，潜在泄漏）
- 位置:
  - `src/WtBtPorter/WtBtRunner.cpp:85`（构造初始化 `_inited(false)`）；
  - `src/WtBtPorter/WtBtRunner.cpp:449-455`（`config` 开头 `if(_inited) return;`）；
  - `src/WtBtPorter/WtBtRunner.h:642`（成员声明）。
- 现象:
  - 全仓没有 `_inited = true` 的写入点（`grep -n "_inited" src/WtBtPorter` 仅
    上述三处），因此 `WtBtRunner.cpp:452-455` 的早退永远不执行；日志
    “WtBtEngine has already been inited” 不可达。
- 期望:
  - 在 `config` 成功末尾置 `_inited = true`，或在 `init` 成功后置位；
    同时明确 `config` 二次调用的语义（拒绝或先 `release`）。
- 测试处理:
  - 本轮不构造二次 `config`（会重建 mocker/replayer，且无公开可观察结果），
    仅在 manifest 记录该 4 行不可达。

## BUG-R194-005 TraderAdapter 的下单/撤单频率缓存插入全被注释，时间窗风控静默失效

- 状态: 待审核
- 严重度: 高（配置了 `order_times_boundary/cancel_times_boundary` 也不生效）
- 位置:
  - 插入点（均为注释）：`src/WtUftCore/TraderAdapter.cpp:340`（下单）、
    `392`（撤单）、`420`（推送回报撤单）；

- 期望:

    可注入时钟/可测边界；同时补一条“窗口内超限即加入排除队列”的用例。
- 测试处理:
