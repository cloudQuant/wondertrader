## BUG-R134-001 `config_backtest` 的一次性门永不生效

- 编号: BUG-R134-001
- 模块/文件/行: `src/WtBtPorter/WtBtPorter.cpp` L174-185（`static bool inited` L176、判断 L178、早退 L179）
- 测试用例: `R124BtPorterConfig.SecondConfigBacktestCallIsNoOp`（既有）；R134 覆盖复核
- 输入: 连续两次 `config_backtest("{ r124 not a json document", false)`
- 期望: 第一次调用后 `inited = true`，第二次在 L179 直接返回
- 实际: 函数体内没有任何 `inited = true` 赋值；L179 在基线报告中执行次数为 0，第二次仍转发 `getRunner().config()`。`WtBtRunner::config` 自身也没有生效的重复守卫（见 BUG-R134-002），因此配置会被重复加载、replayer 重复 init
- 复现步骤:
  1. 以覆盖率构建打开 `src/WtBtPorter/WtBtPorter.cpp` 的 L179；

  3. `llvm-cov show` 中 L179 仍为 0，测试仅因两次调用都不抛异常而“通过”
- 严重级别: 中（`WtBtRunner::_inited` 修复前，重复 config 会重建 mocker/replayer）

## BUG-R134-003 SEL 策略初始化是死代码，且键名写错

- 编号: BUG-R134-003
- 模块/文件/行: `src/WtPorter/WtRtRunner.cpp` L709-711（config 末尾只调用 `initCtaStrategies`/`initHftStrategies`）、L745-789（`initSelStrategies`）、L751（读取 `"cta"`）
- 测试用例: `R134PorterBars.SelGetBarsReturnsLoadedBlocks`（env=sel 配置成功但不会走到 SEL 策略创建）；基线覆盖 L746-789 全 0
- 输入: `{"env":{"name":"sel"},"strategies":{"sel":[{"active":true,"id":"s1","name":"X"}]}}`
- 期望: env=sel 时调用 `initSelStrategies`，读取 `strategies.sel` 并创建 `SelStraContext`
- 实际: ① `initSelStrategies` 在整份 `WtRtRunner.cpp` 中没有任何调用点，L746-789 在基线报告中执行次数为 0；② 即便被调用，L751 读的是 `cfg->get("cta")` 而不是 `"sel"`。因此 SEL 策略永远无法通过配置文件创建；非 HFT 环境还会统一走 `initCtaStrategies`，在 SEL 引擎下创建 CTA 上下文
- 复现步骤:
  1. 以 env=sel、strategies.sel 给出一条策略配置；
  2. `config` 返回 true 但 `getSelContext` 表为空；
  3. `llvm-cov show src/WtPorter/WtRtRunner.cpp` 中 L745-789 全 0
- 严重级别: 高（SEL 实盘策略配置整体失效，且可能把 CTA 策略错误挂到 SEL 环境）

## BUG-R134-004 实盘 `registerExtDataLoader` 静默丢弃 tickLoader

- 编号: BUG-R134-004
- 模块/文件/行: `src/WtPorter/WtRtRunner.h` L242-247；导出入口 `src/WtPorter/WtPorter.cpp` L96-104
- 测试用例: `R134PorterBars.*`（只注册 fnl/raw loader；tick 参数传入 NULL）；实盘 `*_get_ticks` 无法通过该入口注入数据（manifest 4.1）
- 输入: `register_ext_data_loader(fnl, raw, fct, tickLoader)`，其中 `tickLoader` 非空
- 期望: tickLoader 被保存，`WtDtMgr`/`WtDataReader` 需要 tick 数据时可回调
- 实际: 形参写作 `FuncLoadRawTicks /*tickLoader*/ = NULL`，函数体只赋值 `_ext_fnl_bar_loader/_ext_raw_bar_loader/_ext_adj_fct_loader`，tickLoader 被直接丢弃；`WtRtRunner` 也没有 `_ext_tick_loader` 成员。调用方无法感知，实盘 `cta_get_ticks/sel_get_ticks/hft_get_ticks` 只能依赖 `.dmb` 实时文件
- 复现步骤:
  1. 以非空 tickLoader 调用 `register_ext_data_loader`；
  2. 创建实盘上下文后调用 `cta_get_ticks`；
  3. tickLoader 一次都不会被调用（可加计数器验证）
- 严重级别: 中（公开 C API 参数被静默忽略，实盘 tick 外部数据源不可用）
