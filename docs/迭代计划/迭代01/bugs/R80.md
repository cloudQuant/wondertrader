## BUG-R80-001 日频任务把 preTDate 当作当日 endTDate，已订阅日线不闭盘

- 编号: BUG-R80-001
- 状态: 待审核
- 模块/文件/行: `src/WtBtCore/HisDataReplayer.cpp:1060-1082`（重点是 1075-1082）
  与 `src/WtBtCore/HisDataReplayer.cpp:772-889`（`run_by_bars` 的日线口径）
- 测试用例: `src/TestUnits/coverage/q02_btcore3/r80_replayer_task_bars_test.cpp`
  `R80TaskBars.DISABLED_DailyTaskClosesCurrentDayBars`
- 输入:
  1. 日线 CSV 两根：`20200102`、`20200103`（`SSE.STK.000001`）；
  2. `init(mode=csv, stime=202001020930, etime=202001031500, tick=false)`；
  3. `get_kline_slice("SSE.STK.000001","d",10,1,true)`；
  4. `register_task(1, 0, 1500, "d", "CHINA", "SD0930")`；
  5. `prepare()` + `run(false)`。
- 期望: 与 `run_by_bars` 一致，日频任务在 15:00 触发时把当前游标指向的日线
  （`20200103`）闭盘一次，`handle_bar_close` 至少 1 次。
- 实际: `endtime = getNextMinute(1500,-1) = 1459`，`bEndSession =
  offsetTime(1459,true) >= getCloseTime(true)` 对 SD0930 为
  `1459 >= 1500 == false`；于是 L1077/L1079 传给 `simTicks`/`onMinuteEnd`
  的是 `preTDate`（上一交易日）而不是当前交易日。日线臂只认
  `nextBar.date == endTDate` / `<= endTDate`，当前日线永远不匹配，
  `handle_bar_close` 为 0 次。
- 复现步骤:
  1. 在覆盖率构建中启用上述 `DISABLED_` 用例；
  2. 运行 `CoverageTests_btcore --gtest_filter=R80TaskBars.DISABLED_DailyTaskClosesCurrentDayBars`；
  3. 断言 `sink.bars.size() == 1 && bars[0].date == 20200103` 失败（实际 0 次）。
- 严重级别: 中（调度型回测若同时订阅日线，日线信号/指标永不推进；分钟任务不受影响，
  因为分钟臂按 `barTime <= nowTime` 匹配）
- 备注: `run_by_bars` 在 `isDay` 时明确使用 `nextTDate`（L883/L886/L889），
  两条回放路径口径不一致。修复方向是任务分支在 `isDay` 或
  `curTime >= 收盘前一分钟` 时改用 `_cur_tdate`；是否属于有意设计
  （T-1 日线）需产品口径确认，故仅登记不修。
