  与 `src/WtBtCore/HisDataReplayer.cpp:772-889`（`run_by_bars` 的日线口径）
- 测试用例: `src/TestUnits/coverage/q02_btcore3/r80_replayer_task_bars_test.cpp`
  `R80TaskBars.DISABLED_DailyTaskClosesCurrentDayBars`
- 输入:
  1. 日线 CSV 两根：`20200102`、`20200103`（`SSE.STK.000001`）；
  2. `init(mode=csv, stime=202001020930, etime=202001031500, tick=false)`；
  3. `get_kline_slice("SSE.STK.000001","d",10,1,true)`；
  4. `register_task(1, 0, 1500, "d", "CHINA", "SD0930")`；
  5. `prepare()` + `run(false)`。
- 条件期望: **仅在产品语义要求任务触发时闭合当日日线时成立**：15:00 触发时把当前游标指向的日线
  （`20200103`）闭盘一次，`handle_bar_close` 至少 1 次。该要求目前未从任务 API/注释中找到明确约定。
- 源码推演（非运行结果）: `endtime = getNextMinute(1500,-1) = 1459`，`bEndSession =
  offsetTime(1459,true) >= getCloseTime(true)` 对 SD0930 为
  `1459 >= 1500 == false`；于是 L1077/L1079 传给 `simTicks`/`onMinuteEnd`
  的是 `preTDate`（上一交易日）而不是当前交易日。日线臂只认
  `nextBar.date <= endTDate`，因此此输入下尚未到达的 `20200103` 不会闭盘。此结论来自静态控制流，未实际运行该禁用用例。
- 证据界限: 对应断言仍为 `DISABLED_`，本次没有运行测试；断言失败和闭盘次数为 0 均不是本次动态证据。分钟臂按 `barTime <= nowTime` 匹配，是不同周期的实现差异，不代表所有日频任务都“永不推进”。
- 严重级别: 待口径确认（若要求当日闭盘，则影响订阅日线的调度型回测；否则现行为可能是有意的 T-1 语义）
- 备注: `run_by_bars` 在 `isDay` 时明确使用 `nextTDate`（L883/L886/L889），两条路径口径不一致。先确认 T-1/当日语义，再决定是否在任务分支使用 `_cur_tdate`；不能仅为覆盖率一致而更改闭盘日期。
