## BUG-R59-001 净头寸模式平仓量超过今仓时持仓被扣成负数

- 状态: 待审核（净方向分支静态缺陷确认；DISABLED 用例未运行）
- 严重级别: Major（进入该 net 分支时会污染多头今仓并影响后续持仓/平开判断）
- 产品文件: `src/WtCore/TraderAdapter.cpp:2263-2269`（卖出分支）、`:2287-2293`（买入分支）
- 相关测试: `R59Misc.DISABLED_net_mode_sell_more_than_long_new_corrupts_position`
- 输入: 净头寸模式（`WTSTradeInfo::setNetDirection(false)`），持仓为多头今仓 2 手、昨仓 0，
  推送一笔成交量 5 的净卖出成交。
- 期望: 先平掉多头今仓 2 手，剩余 3 手开空；多头持仓为 0，空头持仓为 3。
- 实际: `pItem.l_newvol -= left` 把 2 手今仓减去 5，得到 -3；`left` 再减 `maxVol`(2) 后
  剩余 3 手转空。多头持仓读数为 -3（负数），空头逻辑仓位为 3（当前 `getPosition(...,flag=2)` 以负值 -3 表示），总净持仓仍为 0，但多头侧分桶读数被污染。
- 复现:
  1. 用 `initExt + run + onLoginResult(true)` 装配通道；
  2. `onRspPosition` 写入 `makePos(ct_, WDT_LONG, 0, 0, 2, 2)`；
  3. 构造 `WTSTradeInfo`，`setNetDirection(false)`、volume=5，调用 `onPushTrade`；
  4. `getPosition("SHFE.ag.2512", false, 1)` 返回 -3，而不是 0。
- 影响: 若成交回报进入 `isNet()` 分支且平仓量大于今仓，代码将产生负今仓；买入侧的 `pItem.s_newvol -= left` 同构。仓内搜索到的 `setNetDirection` 用法集中在测试及 `TestTrader` 示例，未发现当前生产柜台适配器设置该字段的调用点；因此这是公开 net 分支的实现错误，但本次不能据此断言现有实盘适配器已触发。
- 修正方向（仅供评审）: 两处分支均应从今仓扣实际平仓量 `maxVol`（`pItem.l_newvol -= maxVol; pItem.s_newvol -= maxVol;`），并启用边界用例验证剩余量转入反向仓位。

## BUG-R59-002 WtDiffExecuter 过期目标清理用标准代码查基础数据，旧目标清不掉

- 状态: 产品缺陷（错误查询参数及严格基础库清理结果均已本机复现）
- 严重级别: 条件性 Major（需基础数据只按原始码/交易所查询且相应 diff 执行单可创建）
- 产品文件: `src/WtCore/WtDiffExecuter.cpp:606-608`（`set_position` 清理循环），
  对照同文件 `:160-162`（`load_data` 先用 `CodeHelper::extractStdCode` 再按原始代码查）
- 相关测试: `src/TestUnits/coverage/p11_wtcore_traderadapter/r59_exec_autoclear_test.cpp` 的 `R59Exec.diff_stale_target_uses_raw_code_lookup_and_clears_with_real_unit` 和 `R59Exec.diff_stale_target_clears_with_raw_code_only_contract_lookup`。
- 输入: 执行器数据文件含 `{"code":"SHFE.ag.2512","target":10.0}`；基础数据库按
  `(原始代码, 交易所)` 建键（`IBaseDataMgr::getContract(code, exchg)` 的既有用法）；
  随后调用 `set_position({})` 把该合约移出目标集合。
- 期望: 清理循环找到合约，把 `_target_pos` 归零，`save_data` 写出 `"target": 0`。
- 实际: 清理循环调用 `_bd_mgr->getContract("SHFE.ag.2512")`（标准代码、交易所为空），
  在真实基础库中查不到（库里键是 `ag2512|SHFE`），走 `cInfo == NULL -> continue`，
  `_target_pos` 保持 10，`save_data` 仍写出旧目标 10。
- 复现:
  1. 用按原始代码建键的 `IBaseDataMgr` 替身（p11fix::FakeBaseDataMgr）装配 `WtDiffExecuter`；
  2. 在 `WtHelper::getExecDataDir()` 写入上述 targets JSON；
  3. `init()` 成功装载该目标；调用 `set_position({})`；
  4. 读取同名 JSON，`targets[0].target` 仍为 10。
- 测试边界: 旧测试未加载插件导致 `getUnit` 为空，无法隔离查询问题。修正后临时加载真实 `WtExeFact` 并确认执行单可创建；双格式替身确认清理调用为 `SHFE.ag.2512|`，而加载使用 `ag2512|SHFE`。另以只接受原始码与交易所的严格替身重跑，正确查询及旧目标应清零两项断言均 FAIL；本机持久化文件中未出现 `"target": 0`。该结果限定于本地 fixture，未验证外部基础数据服务。
- 影响: 有有效 diff 执行单时，若标准码单参查询落空，清理循环会在变更 `_target_pos` 前 `continue`，从而保留旧目标；`on_channel_ready` 可能继续读取旧目标/差量。测试要先提供有效执行单，才能验证该结果。
- 修正方向（仅供评审）: 清理循环按 `load_data` 的约定解析 `stdCode` 后使用原始码与交易所查询，或统一 IBaseDataMgr 参数契约。修正后的测试使用真实执行单、无行情时不发单，并覆盖严格查询及目标持久化。本轮未修改生产代码。

## 其它观察（不作为缺陷登记）

- `TraderAdapter::initExt` 在 `api->init()` 返回 false 时已经写入 `_trader_api`，
  因此若调用方忽略失败继续调用 `run()`，仍可能注册/连接该通道。原 `init_ext_guards_and_run_without_api` 将这种失败后成功运行当预期，现已移除该断言；失败后的调用是否合法需生命周期合同确认，当前作为观察项而非独立已确认缺陷。
