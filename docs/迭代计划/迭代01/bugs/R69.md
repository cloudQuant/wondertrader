## BUG-R69-001 WTSHotMgr::getHotTags 用函数内 static 缓存标签集，后装载的自定义规则被永久遮蔽

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WTSTools/WTSHotMgr.cpp:148-159`；消费点 `src/WtPorter/WtRtRunner.cpp:562-580`
- 现象: `getHotTags()` 内部是
  `static std::vector<std::string> ayTags; if (ayTags.empty()) { for (auto& v : m_mapCustCodes) ... }`。
  该 vector 是**进程级**的，只在为空时重填，且重填源是「当次调用所属的 WTSHotMgr 实例」：
  - 第一次调用把 A 实例的标签集冻进 static；
  - 之后 B 实例 `loadCustomRules()` 新增的标签不会进入 static，`getHotTags()` 仍返回 A 的集合；
  - 若 A 的 map 为空，则 static 保持空，下一次调用又会从 B 重填——结果依赖「谁先调」。
  `WtRtRunner::config()` 每次都用这个返回值做主力代码回填（`:562-580`），因此进程内
  第二次 `config()`（或多 runner 宿主、配置热重载）新增的 hot/second/custom 规则
  不会给合约挂上对应 hotCode。
- 相关测试: `r69_porter_runner_config_test.cpp:R69PorterRunnerConfig.DISABLED_HotTagsStaticCacheHidesRulesLoadedLater`
  （先 `loadCustomRules("R69FIRST")` 并查询一次，再装载 `R69LATE`，断言 tags 中应出现
  `R69LATE`；当前必失败，故 DISABLED）
- 输入:
  ```
  WTSHotMgr hot;
  hot.loadCustomRules("R69FIRST", "hot.json");
  hot.getHotTags();                     // 冻结 {R69FIRST}
  hot.loadCustomRules("R69LATE", "hot.json");
  hot.getHotTags();                     // 期望含 R69LATE
  ```
- 期望: 每次调用返回当前 `m_mapCustCodes` 的标签集合，或在 `loadCustomRules()` 后使缓存失效。
- 实际: 只返回 `{R69FIRST}`；`R69LATE` 永不出现。
- 复现步骤:
  1. 用任意 `WTSHotMgr` 实例先装载一个标签并调用一次 `getHotTags()`；
  2. 再装载第二个标签；
  3. 再调用 `getHotTags()`，观察第二个标签缺失。
- 影响: 实盘/回测进程内多次 `config()`（热重载、多 runner 测试、同进程回测多策略）时，
  后加载的主力/次主力/自定义规则全部失效；同一份配置在不同调用顺序下得到不同的
  hotCode 表，属不可复现的状态污染。
- 备注: 修复方向是把缓存改为实例成员，或在 `WTSHotMgr::loadCustomRules` 里清空
  （并注意 static 跨实例共享本身的语义问题）。

## BUG-R69-002 WtRtRunner::initSelStrategies 全仓库无调用点，SEL 模式永远按 CTA 策略表初始化

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtPorter/WtRtRunner.cpp:745-789`（`initSelStrategies` 定义）、
  `:708-711`（`config()` 只按 `_is_hft` 二选一）、`:851-853`（`_is_sel` 仅用于选引擎）
- 现象:
  - `grep -rn initSelStrategies src` 只有声明（`WtRtRunner.h:682`）与定义（`.cpp:745`），
    没有任何调用点；
  - `config()` 末尾是 `if (!_is_hft) initCtaStrategies(); else initHftStrategies();`，
    即使 `env.name=="sel"` 使 `_is_sel=true`，也仍然调用 `initCtaStrategies()`，
    读取 `strategies.cta` 数组；
  - `initSelStrategies()` 自己读的也是 `strategies.cta`（L751-753），即两份实现都
    没有消费 `strategies.sel`。
- 相关测试: 无启用用例可证伪（函数 private、无公开的 sel 上下文枚举器；
  `R69PorterRunnerConfig` 只从外部断言 `config()` 返回值与引擎类型）。
- 输入: `env.name="sel"`、`strategies":{"sel":[{"active":true,"id":"s1","name":"n1"}]}`，
  其余段按 R46 最小配置。
- 期望: `_is_sel` 时调用 `initSelStrategies()` 并读取 `strategies.sel`，把
  `SelStraContext` 加入 `_sel_engine`。
- 实际: 走 `initCtaStrategies()`；`strategies.cta` 缺失时直接 return false，
  `_sel_engine` 内没有任何策略上下文。SEL 模式静默加载 0 个策略。
- 复现步骤:
  1. 以 `env.name="sel"` 的配置调用 `WtRtRunner::config()`；
  2. 返回 true；
  3. 观察 `_sel_engine` 没有策略上下文（公开 API 下只能通过后续 `run()` 无策略回调间接确认）。
- 影响: 实盘 SEL 多因子策略无法启动；`initSelStrategies` 的 45 行在覆盖率上永久为 0，
  属不可达代码而非未测代码。
- 备注: 修复方向是把 `config()` 改为三分支
  （`_is_hft` / `_is_sel` / CTA），并让 `initSelStrategies` 读取 `strategies.sel`；
  同时补一个可观察的 sel 上下文枚举接缝，便于测试。

## BUG-R69-003 WtRtRunner::config 忽略 initDataMgr() 失败，缺 data 段仍返回 true

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtPorter/WtRtRunner.cpp:587`（`initDataMgr();` 返回值未接）、
  `:884-896`（`data` 段缺失时 return false）
- 现象: `config()` 在 `initEngine()` 之后无条件调用 `initDataMgr()`，不判断返回值。
  `data` 段缺失时 `initDataMgr()` 在 `_config->get("data")` 为 NULL 处早退，
  `_data_mgr` 未初始化，但 `_engine` 已持有 `&_data_mgr`（`initEngine()` 的
  `WtEngine::init` 把指针存进 `_data_mgr`）。`config()` 继续跑
  `initActionPolicy()/initParsers()/initTraders()/initCtaStrategies()`，最终 `return true`。
- 相关测试: `r69_porter_runner_config_test.cpp:R69PorterRunnerConfig.MissingExecuterFileAndDataSectionStillReturnTrue`
  （同一份配置同时覆盖 executers 文件缺失与 data 段缺失；用例断言实际返回 true，
  并在注释里标明这是缺陷路径，不是期望语义）
- 输入:
  ```
  {"basefiles":{}, "env":{"name":"cta"},
   "bspolicy":"<存在的 actions.json>",
   "executers":"<不存在的文件>"}
  ```
- 期望: `config()` 返回 false（或回滚 `_engine`），让调用方知道数据管理器没建起来。
- 实际: 返回 true；后续 `run()`/任何经 `_data_mgr` 的路径会在未初始化的
  `WtDtMgr` 上取 reader/hot/交易日数据。
- 复现步骤:
  1. `new WtRtRunner()` 并 `init()`；
  2. 以缺 `data` 段、其余合法的配置调用 `config()`；
  3. 观察返回 true，而 `_data_mgr` 从未 `init()`。
- 影响: 配置漏写 `data` 属常见笔误；实盘表现为「配置加载成功」，
  启动后在数据/调度路径崩溃或返回空数据，排障信息指向数据管理器而不是缺段本身。
- 备注: 与 BUG-R46-002（忽略 `initEngine()` 失败）同属「config 不校验子步骤返回值」，
  但落在不同子步骤，修复可一并处理。
