## 新增候选项（静态行为与契约分别复核）

### BUG-R211-001 WtEngine::init 丢弃 init_riskmon 结果（active 风控失败策略待契约确认）

- 位置: `src/WtCore/WtEngine.cpp:304-308`（`init_riskmon(cfgRisk);` 返回值未用）、
  `src/WtCore/WtEngine.cpp:1165-1171`（入口符号缺失时仅记日志并返回 false）
- 源码事实: `WtEngine::init` 调用 `init_riskmon` 后未检查其返回值；active 模块
  装载或工厂入口失败时，`init_riskmon` 返回 false 并记录错误日志。
- 契约边界: 当前未找到 active 风控加载失败是否必须拒绝引擎初始化的公开契约；本条
  暂为配置安全候选，不据此声称已实证交易在无风控状态下运行。
- 测试证据: 见下方复核裁定。现有同名测试的 PASS 不证明合法 dylib 的缺导出分支。
- 建议: 明确 active 风控失败时 init 的契约，再按契约检查返回值并暴露状态或拒绝启动；
  补测试确保精确 loader path 成功加载后才进入缺 createRiskMonFact 分支。
- 状态: 待审核

## 复核裁定（2026-10-29；若与本文件其他复核措辞冲突，以本节为准）

- BUG-R211-001：源码可确认 WtEngine::init 忽略 init_riskmon 的 bool 结果，且 active
  模块装载/工厂失败会返回 false；但目前没有找到“active 风控模块失败必须使引擎 init
  失败”或等价 fail-closed 的公开契约，故将其保留为配置安全候选/契约缺口，不写成已证实
  的“实盘裸奔”。测试 R211Engine.IncompatibleRiskMonModuleIsRejected 虽在已有日志中
  PASS，却没有到达工厂符号检查：测试第 180 行把无尾分隔符的 binDir 设为 instDir，
  生产按 getInstDir()+module 拼路径，日志实际尝试
  build_x64/Debug/binlibWtExeFact.dylib，落在 dlopen 失败分支。测试仅检查源文件存在和
  adjusting flag 为 0，均不证明模块已成功 dlopen 或进入缺导出分支。修复方向：先定义
  active 风控装载失败的引擎契约；测试 instDir 应用以斜杠结尾的路径，并针对实际拼出的
  loader 路径确认库已加载、缺 createRiskMonFact 后走到预期分支，再断言引擎状态。
- BUG-R192-001 的测试 R211SelEngine.DataMgrAdjustingFlagIsDroppedByEngine 有已有 PASS
  日志：只证明 stub 返回 7 时本用例中的引擎 getter 返回 0；源代码丢弃值的静态结论也相符。
  该项是既有 BUG-R192-001 的复核，不新增计数。
- BUG-R192-002/003 是既有线程析构与 task/context id 空间问题。对应 R211 用例名称含
  DISABLED_，不会执行；目前只能作为源码静态复核，不能写成该测试动态“固化”了 abort
  或 schedule 不回调。
- BUG-R192-004 的函数级 static 是源码事实，但 R211CtaTicker.LastMinuteOfFiniteSessionIsNotClosedByData
  的落盘记录为 CRASH(rc=139)，不是断言通过；用例也只构造一个 ticker，不能证明跨实例
  状态污染。要验证 static 影响，需用两个独立会话/实例做隔离顺序测试。该项应保留在
  BUG-R192-004 交叉复核，不作为本 lane 动态结论。
- BUG-R31-001：现有 NonPluginDirectoryLoadsNothing PASS 只验证 libWtShareHelper 这类
  无策略工厂的库被跳过；它不验证 WtSelStraFact 产品库。SelStrategyMgr 请求
  createMfStrategyFact、仓库 SEL 工厂导出 createSelStrategyFact 是源码/符号层证据，
  因而仍是 BUG-R31-001 的静态重复复核，修复时统一插件 ABI 名称并增加真实 SEL 工厂装载验收。
- BUG-R31-002：CTA 工厂被 HFT 接口类型解释是条件性源码风险；对应测试 DISABLED_，
  本轮没有运行，也没有动态 SIGSEGV 证据。它与 BUG-R31-002 重复登记；仅在 CTA 插件可能
  进入 HFT 工厂目录的配置契约成立时，才据此界定实际影响。
- BUG-R202-002：有限时段最后一分钟逻辑仍可按源码与 R202 主记录复核，但 R211 对应用例
  crash，不能称其动态观察到 session end 未触发；保留 R202 的 canonical 记录，不把失败
  日志当成通过。
- BUG-R202-003 的表述需收窄：getContract/getCommodify 位于 private 区，不能称为公开查询 API；
  目前唯一明确的 public inline 声明是 isTradeEnabled。其定义仅在 .cpp，存在跨 TU 可见性/
  链接风险，但本 lane 没有编译运行相应调用的结果，不能断言本轮已证明链接失败或 11 行
  公开面不可达。修复/验收方向是让声明与定义可见性一致，并用独立 TU 编译链接确认。

## 既有缺陷复核（本 lane 命中，仍成立）

- 状态: 已合并（主编号 BUG-R192-001）

### BUG-R192-002/003（复核）WtSelEngine 到期任务 abort 与 id 空间不一致

- 位置: `src/WtCore/WtSelEngine.cpp:329-336`、`:402-415`
- 复核: 局部 `StdThreadPtr` 包 joinable `std::thread`，析构路径静态上会触发
  `std::terminate()`；即便修复线程生命周期，`TaskInfo::_id` 从 1 起而
  `SelStraBaseCtx::id()` 从 3000 起，`getContext(tInfo->_id)` 恒空。
  对应 DISABLED_ 测试未执行，以上不是动态复现。
- 覆盖后果: `WtSelEngine.cpp` 剩余 45 个零计数行（含 265-336 调度面）不可测。
- 状态: 已合并（主编号 BUG-R192-002、BUG-R192-003）

### BUG-R31-001（复核）SelStrategyMgr 查找的工厂入口符号在全仓无出处

- 位置: `src/WtCore/SelStrategyMgr.cpp:61、75`

  该项是 BUG-R31-001 的重复静态复核。
- 状态: 已合并（主编号 BUG-R31-001）

### BUG-R31-002（复核）HftStrategyMgr 跨插件同名符号类型双关
