## BUG-R142-001

- 状态: 待审核
- 严重级别: Major（堆悬垂写，UB；实测旁证 rc=139）
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`
  - `readOrdQueSliceByRange` 历史 CMP_V2 解压后重建缓冲区：L728-735（版本号回写 L733）
  - `readOrdDtlSliceByRange` 同型：L903-910（L908）
  - `readTransSliceByRange` 同型：L1077-1084（L1082）
- 与 BUG-R132-001 的关系: 同一根因、同一写法，但位于另一个读取器与另外三行；
  R132 的修复只覆盖 `WtDataReader.cpp`，Rdm 侧修复时需一并处理。
- 相关测试: 无新增启用复现。旁证来自既有用例
  `src/TestUnits/coverage/q03_storage3/r112_rdm_crossday_guards_test.cpp` 的两条用例：
  `build-cov/coverage/rc/CoverageTests/R112RdmResidualTest_R112RdmHftRangeCrossDateComparators.rc`
  与 `..._R112RdmMissingAndShortFileGuards.rc` 均为 `CRASH(rc=139,sig=11)`。
  R142 的三条历史逐笔成功路径用例改用「不可压缩载荷」，绕开该分支。
- 输入/前置条件:
  - 历史队列文件 `his/queue/<exchg>/<date>/<code>.dsb` 为 CMP_V2；
  - 载荷是高度可压缩的规则化 `WTSOrdQueStruct`（q03/r112 的 `make_ordque` 即如此）：
    压缩长度明显小于解压后的记录长度；
  - 调用 `readOrdQueSliceByRange`（detail/trans 同型，文件分别为 `his/orders`、`his/trans`）。
- 期望行为: 解压后按头部+记录重建缓存，返回切片，进程不崩溃。
- 实际行为:
  1. L728/L903/L1077 `uncompress_data` 得到约 N 字节记录；
  2. L731/L906/L1080 `_buffer.resize(sizeof(HisXxxBlock))` 把 string 缩到 12 字节，
     但保留原有小 capacity（≈压缩长度）；
  3. 紧接着 `append(buf)` 需要扩容 → `_buffer` 重新分配，`tBlockV2` 悬垂；
  4. L733/L908/L1082 再向旧缓冲区写 `_version`，属于未定义行为；堆被破坏后
     常在后续 `release()`/析构或下一次分配时段错误（R112 已实测 SIGSEGV）。
- 修复方向（仅供参考）: 先 `resize(头部 + 解压长度)`，再 `memcpy` 解压数据；
  或 `append` 之后重新取 `tBlockV2 = (HisXxxBlockV2*)_buffer.data()` 再写版本号。
