## BUG-R142-001

- 状态: 待审核
- 严重级别: 待定（若 `append` 使 `_buffer` 重分配，旧头指针会失效并发生未定义行为；影响级别尚无隔离复现支撑）
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`
  - `readOrdQueSliceByRange` 历史 CMP_V2 解压后重建缓冲区：L728-735（版本号回写 L733）
  - `readOrdDtlSliceByRange` 同型：L903-910（L908）
  - `readTransSliceByRange` 同型：L1077-1084（L1082）
- 与 BUG-R132-001 的关系: 同一根因、同一写法，但位于另一个读取器与另外三行；
  R132 的修复只覆盖 `WtDataReader.cpp`，Rdm 侧修复时需一并处理。
- 相关测试: 无新增启用复现。既有用例
  `src/TestUnits/coverage/q03_storage3/r112_rdm_crossday_guards_test.cpp` 的两条用例：
  `build-cov/coverage/rc/CoverageTests/R112RdmResidualTest_R112RdmHftRangeCrossDateComparators.rc`
  与 `..._R112RdmMissingAndShortFileGuards.rc` 均记录 `CRASH(rc=139,sig=11)`；对应日志只到
  `[ RUN ]`，没有崩溃栈，且测试包含多条历史/RT 路径，不能证明故障发生在本条的版本回写。
  R142 的三条历史逐笔用例使用伪随机载荷，让压缩后文件长度不小于原始记录长度；按该夹具构造，
  `_buffer` 有足够的既有容量，不会覆盖「append 重分配」这一条件。R142 清单记录的只是语法门禁，
  未运行这些新用例。
- 输入/前置条件:
  - 历史队列文件 `his/queue/<exchg>/<date>/<code>.dsb` 为 CMP_V2；
  - `_buffer` 由历史文件读入，容量小于 `sizeof(HisXxxBlock) + 解压数据长度`；
    高度可压缩载荷可能满足此条件，但仅凭压缩长度小于原始长度不能断定 `capacity()` 不足；
  - 调用 `readOrdQueSliceByRange`（detail/trans 同型，文件分别为 `his/orders`、`his/trans`）。
- 期望行为: 解压后按头部+记录重建缓存，返回切片，进程不崩溃。
- 静态风险链（条件性）:
  1. L728/L903/L1077 解压得到原始记录；
  2. L731/L906/L1080 缩短 `_buffer`，其 `capacity()` 仍取决于历史文件装载时形成的实际容量；
  3. 若 `capacity() < sizeof(HisXxxBlock) + buf.size()`，随后 `append(buf)` 会重分配，旧的
     `tBlockV2` 指针失效；
  4. L733/L908/L1082 仍经旧指针写 `_version`，构成未定义行为。现有 R112 `rc=139` 只能作为
     同一测试进程发生崩溃的记录，不能作为上述因果链已动态验证的证据。
- 修复方向（仅供参考）: 不跨 `_buffer` 的修改保存头指针；在完成 `resize/append` 后重新从
  `_buffer.data()` 取得头指针再写版本号，或用局部头部副本组装最终缓冲区。
- 独立验收要求: 用可控压缩载荷和精确容量分别覆盖 queue/detail/trans，记录追加前后
  `capacity()`/数据地址，并在能检测失效访问的构建中验证；单独重跑 R112 只可补充症状，不能替代隔离复现。
