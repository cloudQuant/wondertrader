# 缺陷记录规范（迭代 01）

> 本迭代只记录缺陷，不修改生产代码；修复必须等评审通过后单独提交。

## 规则

1. 每个工作流只写自己的文件：`docs/迭代计划/迭代01/bugs/<工作流>.md`；不要修改其他人的 bug 文件。
2. 发现疑似缺陷时，保留测试代码，不要为了变绿而放宽断言；在清单中标记 `待审核`。
3. 禁止修改 `src/**` 的生产代码、头文件或构建脚本。
4. 若缺陷导致测试无法通过，可将测试命名为 `DISABLED_<原测试名>` 或在清单中说明阻塞；不得删除测试。
5. 修复流程：评审确认 → 单独开 bugfix 提交 → 回归本迭代测试；测试提交与修复提交分离。

## 记录模板

```markdown
## BUG-<WSxx>-<NNN>

- 状态: 待审核
- 严重级别: Blocker / Major / Minor
- 模块/文件:
- 相关测试:
- 输入/前置条件:
- 期望行为:
- 实际行为:
- 复现步骤:
- 影响范围:
- 备注（是否阻塞覆盖率目标 / 建议的修复方向，不实施）:
```

## 严重级别

- **Blocker**：导致崩溃、数据错误、资金/订单风险，或使目标模块无法达到 100%。
- **Major**：边界/错误路径行为与契约不符，但主流程可运行。
- **Minor**：日志、提示、非关键边界问题。
