## BUG-R201-001 UftMocker::on_session_begin 只解冻多头，空头 T+1 冻结永不释放

- 状态: 待审核
- 严重度: 高（空头 T+1 持仓跨日后仍显示可用 0，无法平昨；相关公开分支永久不可达）
- 位置:
  - `src/WtBtCore/UftMocker.cpp:343-359`（`on_session_begin`）；
  - 关键行 `src/WtBtCore/UftMocker.cpp:349`：
    `PosItem& pInfo = (PosItem&)it.second;`
  - `it.second` 的实际类型是 `PosInfo`（`_long` + `_short` 两个 `PosItem`），
    强转为 `PosItem&` 后只别名到第一个成员 `_long`。
- 现象:
  - 空头 T+1 开仓走 `update_position` offset=0：`_short._newvol += qty`，
    因 `commInfo->isT1()` 为真不增加 `_newavail`，即 `frozen()==qty`；
  - `handle_session_begin(nextTDate)` 只对 `_long` 执行
    `_prevol += _newvol; _preavail = _prevol; _newvol = _newavail = 0;`；
  - `_short` 的 `_newvol` / `_newavail` 原样保留，`valid()` 仍为 0，
    `stra_get_position(code, true, 2)` 返回 0，`stra_exit_short(..., false)`
    在 `valid < qty` 处直接报错返回 0；空头只能走平今（offset=2），平昨路径失效。
- 证据:
  - 源码强转如上，`PosInfo` 的成员顺序见 `src/WtBtCore/UftMocker.h:334-337`；
  - `build-cov/coverage/CoverageTests_btcore.R191MockerFixture_R191UftMocker_CoverTodayPreavailExitCancelBranches.log`：
    R191 用例在“开空 50 + `handle_session_begin(20200104)`”后断言
    `stra_get_position(kStk, true, 2) == 50`，实际得到 0，测试于该 `ASSERT` 中止；
  - 最新 `llvm-cov` 中 `509-512`（`stra_buy` 空头昨仓）、`771-772`
    （`stra_exit_short` 扣减昨仓）仍为 0 次，与上述路径不可达一致。
- 复现步骤:
  1. `WTSCommodityInfo* comm = replayer.get_commodity_info(code)`，
     `comm->setTradingMode(TM_LongT1)`；
  2. 构造 `UftMocker` 并 `init_uft_factory` 加载 `libWtUftStraFact`（`on_session_begin`
     会无条件解引用 `_strategy`，无插件会崩，见 BUG-R121-001）；
  3. `on_trade(1, code, false, 0, 50, price)` 开空 50；
  4. `handle_session_begin(nextTDate)`；
  5. 读 `stra_get_position(code, true, 2)`，期望 50，实际 0。
  对应占位用例：`r201_mocker_residual_test.cpp` 的
  `DISABLED_R201UftMocker_ShortFrozenIsNotReleasedOnSessionBegin`。
- 期望:
  - `on_session_begin` 应分别解冻 `PosInfo::_long` 与 `PosInfo::_short`，
    例如提取 `releaseFrozen(PosItem&)` 并对两腿各调用一次；
  - 修复后空头 T+1 跨日 `valid()` 应等于持仓量，`stra_exit_short(..., false)`
    可正常平昨。
- 测试处理:
  - 缺陷用 `DISABLED_` 占位，启用即失败，不进用例集；
  - 本轮 Uft 昨仓覆盖改走“同日 `CM_OpenCover` 扣 `_newavail` → 切回
    `CM_CoverToday` → 撤单还原 `_preavail`”的公开路径，不依赖会话解冻，
    断言未放宽。
- 建议:
  - 同时检查 `on_session_end` 的 `PosInfo` 遍历是否也有同类布局误用；
  - 修复后启用占位用例，并补 `509-512`、`771-772` 的跨日路径。

## BUG-R201-002 Uft 短仓会话明细写入 positions.csv 时方向标成 LONG

- 状态: 待审核
- 严重度: 低（仅落盘标签错误，不影响撮合与资金）
- 位置: `src/WtBtCore/UftMocker.cpp:383-384`
- 现象:
  - 短仓分支的格式化串仍为 `"{},{},LONG,{},{:.2f},{:.2f}\n"`，
    因此 `positions.csv` 中 `_short.volume()!=0` 的行也标为 `LONG`；
  - 同一合约多空双持仓时会写出两行 `LONG`，下游按方向汇总会把空头算进多头。
- 证据:
  - 源码第 381 行（多仓）与第 384 行（空仓）的格式串均为 `LONG`；
  - 本轮用例 `R201UftMocker_PluginEnumMismatchAndShortSessionLog` 构造
    “多 100 + 空 5”并调用 `handle_session_end`，覆盖到第 384 行，
    `positions.csv` 落盘成功；断言只检查文件存在，不把错误标签固化进期望值。
- 复现步骤:
  1. 构造 `UftMocker` 并加载 `libWtUftStraFact`；
  2. `on_trade` 开多 100、开空 5；
  3. `handle_session_end(tdate)`；
  4. 查看输出目录 `positions.csv`，空头行方向为 `LONG`。
- 期望:
  - 第 384 行格式串改为 `SHORT`，与多仓行区分。
- 测试处理:
  - 不新增失败断言（避免把缺陷行为写成期望）；缺陷单独立案，修复后可补
    `positions.csv` 内容断言。
