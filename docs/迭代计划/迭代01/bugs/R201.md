## BUG-R201-001 UftMocker 的短仓 T+1 状态可能无法跨日解冻（与 BUG-P08-002 重复）

- 状态: 已合并（主编号 BUG-P08-002；本条为相同短仓 T+1 根因的复核记录）
- 严重度: 待审核（公开 UftMocker 开空入口未执行 `canShort()` 校验；跨日行为需从该入口补端到端验证）
- 位置:
  - `src/WtBtCore/UftMocker.cpp:343-359`（`on_session_begin`）；
  - 关键行 `src/WtBtCore/UftMocker.cpp:349`：
    `PosItem& pInfo = (PosItem&)it.second;`
  - `it.second` 的实际类型是 `PosInfo`（`_long` + `_short` 两个 `PosItem`），
    强转为 `PosItem&` 后只别名到第一个成员 `_long`。
- 现象:
  - 源码把 `PosInfo` 引用为 `PosItem&`，只处理首成员 `_long`；如果 `_short` 带有冻结量，
    这段循环不会把它转成昨仓可用。
  - `TM_LongT1` 在 `WTSTypes.h` 中定义为“做多 T+1”，`canShort()` 仅在 `TM_Both` 返回真；
    但 `UftMocker::stra_enter_short()`（`:638-676`）只校验品种存在和数量，没有检查
    `canShort()`。随后 `procOrder()` 可以把成交交给 `on_trade()`，而 `update_position()`
    对多空共用 `commInfo->isT1()` 冻结规则（`:1155-1190`）。这构成 UftMocker 自身入口
    与商品能力标志之间的实现不一致；当前测试没有验证完整撮合路径。
- 证据:
  - 源码强转如上，`PosInfo` 成员顺序见 `src/WtBtCore/UftMocker.h:334-337`；
  - R191 的保存日志确有短仓跨日断言失败；但 R191 和 R201 用例均在 `TM_LongT1` 下直接
    通过 `on_trade(..., false, ...)` 注入空头成交，未证明策略下单与撮合路径。另一方面，
    `stra_enter_short()` 未拒绝 `canShort()==false`，所以该状态并非被 UftMocker 入口显式挡住；
    当前应视作有静态可达性依据、仍需端到端验证的产品问题。
- 复现步骤:
  1. 当前占位将 `WTSCommodityInfo` 设为 `TM_LongT1`；
  2. 构造 `UftMocker` 并 `init_uft_factory` 加载 `libWtUftStraFact`（`on_session_begin`
     会无条件解引用 `_strategy`，无插件会崩，见 BUG-R121-001）；
  3. 直接调用 sink 回调 `on_trade(1, code, false, 0, 50, price)` 注入空头成交；该步骤绕过了
     `stra_enter_short` 和撮合，故仅复现持仓结转，不是端到端下单证据；源码显示正式入口未检查 `canShort`；
  4. `handle_session_begin(nextTDate)`；
  5. 读 `stra_get_position(code, true, 2)`，期望 50，实际 0。此复现说明短腿结转遗漏；
     正式入口到成交的可达性仍需补测。
  对应占位用例：`r201_mocker_residual_test.cpp` 的
  `DISABLED_R201UftMocker_ShortFrozenIsNotReleasedOnSessionBegin`。
- 期望:
  - 按现有 `canShort()` 契约，`TM_LongT1` 下应拒绝空头开仓；若产品选择保留当前
    UftMocker 对该入口的接受行为，则必须定义短腿 T+1 语义，并使 `on_session_begin`
    正确结转两腿。修复前先确定这一接口契约。
- 测试处理:
  - `DISABLED_` 占位启用会按当前实现得到 0，但其直接 sink 注入没有验证策略开仓/成交路径；
    补用 `stra_enter_short` + tick 撮合端到端测试，并按定下来的 `canShort`/T+1 契约断言拒绝或解冻；
  - 本轮 Uft 昨仓覆盖改走“同日 `CM_OpenCover` 扣 `_newavail` → 切回
    `CM_CoverToday` → 撤单还原 `_preavail`”的公开路径，不依赖会话解冻，
    断言未放宽。
- 建议:
  - 优先统一 UftMocker 的开空 `canShort()` 校验与商品契约；若允许双腿 T+1，再将
    `on_session_begin` 改为分别结转两腿，并补端到端平昨断言；同时核查 `on_session_end`。

## BUG-R201-002 Uft 短仓会话明细写入 positions.csv 时方向标成 LONG

- 状态: 待审核
- 严重度: 低（仅落盘标签错误，不影响撮合与资金）
- 位置: `src/WtBtCore/UftMocker.cpp:383-384`
- 现象:
  - 短仓分支的格式化串仍为 `"{},{},LONG,{},{:.2f},{:.2f}\n"`，
    因此 `positions.csv` 中 `_short.volume()!=0` 的行也标为 `LONG`；
  - 同一合约多空双持仓时会写出两行 `LONG`，下游按方向汇总会把空头算进多头。
- 证据:
  - 源码第 381 行（多仓）与第 384 行（空仓）的格式串均为 `LONG`；
  - 本轮用例 `R201UftMocker_PluginEnumMismatchAndShortSessionLog` 构造
    “多 100 + 空 5”并调用 `handle_session_end`；保存结果为 PASS，源码路径会写出该行，
    但断言只检查文件存在，没有读取/校验 `SHORT`，因此 PASS 不是标签正确的动态断言。
- 复现步骤:
  1. 构造 `UftMocker` 并加载 `libWtUftStraFact`；
  2. `on_trade` 开多 100、开空 5；
  3. `handle_session_end(tdate)`；
  4. 查看输出目录 `positions.csv`，空头行方向为 `LONG`。
- 期望:
  - 第 384 行格式串改为 `SHORT`，与多仓行区分。
- 测试处理:
  - 不新增失败断言（避免把缺陷行为写成期望）；缺陷单独立案，修复后可补
    `positions.csv` 内容断言。
