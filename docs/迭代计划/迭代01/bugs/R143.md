## BUG-R143-001 订单通知只 retain 不 release，每笔回报泄漏一个引用

- 编号: BUG-R143-001
- 模块/文件: `src/WtUftCore/EventNotifier.cpp:214-227`
  （`ordInfo->retain()` 在 L221；lambda 内 L226 发布后没有对应 `release()`）
- 相关测试: `R143UftNotifier.postsOrderJsonWithStateAndVolumeFields`
  （`src/TestUnits/coverage/q04_uftcore3/r143_uftcore_notifier_test.cpp`）
- 输入/前置条件: `EventNotifier` 以 `inproc://` 成功 init；传入一个 `WTSOrderInfo*`
  （创建时 retainCount=1）调用 `notify(trader, localid, stdCode, ordInfo)`
- 期望行为: 与成交通知 `notify(..., WTSTradeInfo*)` 对称（L204 retain、L210 release）：
  worker 执行 `orderToJson` 并发布后释放该引用，调用方持有的对象最终可回收
- 实际行为: L221 `ordInfo->retain()` 后，lambda 只在 L226 调 `_publisher`，
  **没有 `ordInfo->release()`**。用例中 notify 后计数为 2，worker 执行完仍为 2；
  每推送一笔订单即永久泄漏一个 `WTSOrderInfo` 引用，高频通道下持续增长
- 复现步骤:
  1. 准备可加载的 `libWtMsgQue.dylib`，`WTSVariant` 设 `active=true`、
     `url=inproc://...`，`EventNotifier::init` 返回 true；
  2. `WTSOrderInfo* ord = WTSOrderInfo::create();` 此时 `retainCount()==1`；
  3. `notifier.notify("uft1", 1, "SHFE.ag2406", ord);`，等待 50ms；
  4. 观察 `ord->retainCount()` 仍为 2（预期为 1）；
  5. 析构 notifier（会 join worker）后计数仍为 2，只能由用例补释放
- 严重级别: 高（长期运行的内存/对象池泄漏，且订单推送是主路径）
- 状态: 待审核

## BUG-R143-002 `create_server` 失败被吞掉，init 仍报成功且错误回调是空函数

- 编号: BUG-R143-002
- 模块/文件: `src/WtUftCore/EventNotifier.cpp:32-35`（`on_mq_log` 空实现）、
  `:94-111`（`_mq_sid = _creator(...)` 后不检查 0，直接打 initialized 日志并建 worker，
  最后 `return true`）
- 相关测试: 静态核对 + `R143UftNotifier.*`（init 成功分支的正常对照）；
  无直接失败断言可写——`_mq_sid` 是 private，失败时五个 notify 入口都静默返回
- 输入/前置条件: `active=true`，`url` 是一个 MQ 后端拒绝绑定的地址
  （例如已被占用/非法的 nanomsg URL），但 `WtMsgQue` 模块本身可加载
- 期望行为: `_creator` 返回 0（`MQManager::create_server` 在 socket/bind 失败时返回 0）
  时，`init` 应返回 false（或至少打 error 日志并不启动 worker），让上层感知通知不可用
- 实际行为: `_mq_sid` 被赋为 0 后仍打印
  `"EventNotifier initialized with channel ..."` 并创建 asio worker、`return true`；
  之后 `notify_log/notify_event/notify(...)` 的第一行 `if (_mq_sid == 0) return;`
  把全部消息静默丢弃。MQ 模块内部通过 `FuncLogCallback` 上报的 bind/setsockopt 错误
  又被本文件的 `on_mq_log` 空实现吞掉（L32-35），现场没有任何错误日志
- 复现步骤:
  1. 用两个 `EventNotifier` 绑定同一个 `inproc://r143_same`（或传非法 URL）；
  2. 两次 `init` 都返回 true；
  3. 第二个实例的 `notify_*` 一条都发不出，日志里只有 “initialized”，没有失败信息；
  4. 若在 `on_mq_log` 打断点，可看到 MQ 后端返回的 binding failed 消息被直接丢弃
- 严重级别: 中（通知通道整体静默失效且不可观测；不影响交易主链路）
- 状态: 待审核
