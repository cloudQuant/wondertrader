- 契约对照: 14 位 `YYYYMMDDHHMMSS` 符合公开注释 `src/WtBtPorter/WtBtPorter.h:129-132`、
  `src/WtBtPorter/WtBtRunner.h:469-475`、`src/WtBtCore/HisDataReplayer.h:777-786`；不能把
  该输入直接标成测试错误。现有解析路径在 `src/WtBtCore/HisDataReplayer.cpp:661-664,744-746`

  `p04_replayer_config_prepare_test.cpp:109-110`。公开注释与当前解析及项目用法之间的
  冲突属于既有 BUG-P04-011，格式应由该条目的 API owner 裁定。
- 动态证据: 三个 gtest filter 独立运行均观察到 `cnt=0`、回调次数为 0。CTA 单案隔离 profile

  bars”，不证明把配置改为 12 位后用例必然通过；SEL/HFT 的单案失败结果相同，但没有对
  两案分别生成 profile。
- 夹具备注: `make_cfg` 未提供策略 `module`，运行时出现空 `dlopen` 诊断，属于需清理的夹具

- 分类与修复方向: 三案共享同一个时间格式前提，不是三项独立的 Porter 回调缺陷。建议增加
  一条按当前 12 位解析行为配置的独立 bars happy-path（例如 `202401030000` 到
  `202401040000`），保留非空切片、两根 bars、一次 callback 的断言；另外保留独立的 14 位
  契约验证，依 BUG-P04-011 最终决策验证其接受并正确解析，或验证经明确文档化的拒绝行为。
  本复核未运行 12 位变体，不能宣称该 happy-path 已修复或通过；保留现有原断言，不放宽为 0，
  不因 14 位输入符合公开文档而将当前用例定为测试错误。
