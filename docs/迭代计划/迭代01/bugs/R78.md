## BUG-R78-001 — WtUftCore ParserAdapter 成功 init 后永不释放 `_cfg`，缺符号失败也不 free DllHandle

- 文件: `src/WtUftCore/ParserAdapter.cpp`
- 位置: `init()` L54-55（`_cfg = cfg; _cfg->retain();`）、`~ParserAdapter()` L38-40（空实现）、`release()` L228-240（只释放/删除 `_parser_api`）、缺符号分支 L81-86。
- 输入/前置条件: 走 `ParserAdapter::init(...)` 成功加载任意 parser 插件（本 lane 用 `libParserUDP.dylib`）；或插件可 `dlopen` 但不导出 `createParser`。
- 期望行为: `release()`/析构时对 `_cfg` 做一次 `release()`；`createParser` 取不到时 `DLLHelper::free_library(hInst)` 后再返回 false。
- 实际行为: `_cfg->retain()` 后没有任何配对的 `release()`，每个适配器泄漏一份配置对象；缺 `createParser` 的失败路径直接 `return false`，已打开的 `DllHandle` 不释放。
- 复现步骤: `ParserAdapter pa; pa.init("id", cfg, stub, bd);`（插件成功）→ `pa.release();` → 引用计数不回退；或把 module 指向无 `createParser` 的 dylib，init 返回 false 且库句柄泄漏。
- 影响: 长跑/反复初始化场景的常驻内存增长；与 `BUG-R8-006` 是 WtDtServo 同名类的同源问题，但 WtUftCore 这一份此前未登记。
- 分级: C
- 状态: 待审核

## BUG-R78-002 — UftStraContext::load_local_data 全程不释放 mannual.yaml 的 WTSVariant

- 文件: `src/WtUftCore/UftStraContext.cpp`
- 位置: L1052 `WTSVariant* manual = WTSCfgLoader::load_from_file(mannualfile);`；L1053-1057（解析失败 break）、L1059-1061（无 `details` break）、L1090-1112（导入循环）之后均无 `manual->release()`。
- 输入/前置条件: 策略输出目录存在非空 `mannual.yaml`（无论解析成功、解析失败还是缺少 `details`），且当日首次 `on_channel_ready` 触发 `load_local_data()`。
- 期望行为: 三个出口（解析失败、缺 `details`、导入完成）都应 `manual->release()`。
- 实际行为: `manual` 对象只 `retain` 不释放；本 lane 的两个用例分别命中「空文件返回 NULL」和「无 details」两支，后一支每次启动泄漏一份 YAML 配置对象；正常导入路径同样泄漏。
- 复现步骤: 在 `WtHelper::getOutputDir()/<strategy>/mannual.yaml` 写入 `foo: bar`，调用 `UftStraContext::on_channel_ready(20240315)`，文件被改名但 `manual` 未释放（可用 LeakSanitizer/引用计数观测）。
- 影响: 每个策略每个交易日最多一次的小对象泄漏；不改变交易结果。
- 分级: C
- 状态: 待审核
