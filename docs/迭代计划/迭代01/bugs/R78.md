## BUG-R78-001 — WtUftCore ParserAdapter `_cfg` 引用泄漏与缺符号失败路径未释放 DllHandle

- 文件: `src/WtUftCore/ParserAdapter.cpp`
- 位置: `init()` L54-55（`_cfg = cfg; _cfg->retain();`）、`~ParserAdapter()` L38-40（空实现）、`release()` L228-240（只释放/删除 `_parser_api`）、缺符号分支 L81-86。
- 输入/前置条件: `_cfg` 子项：调用 `init(...)` 后结束 adapter 生命周期；缺符号子项：插件可被 `dlopen`，但不导出 `createParser`。
- 期望行为: `release()`/析构时对 `_cfg` 做一次 `release()`；`createParser` 取不到时 `DLLHelper::free_library(hInst)` 后再返回 false。
- 实际行为: `_cfg->retain()` 后没有任何配对的 `release()`，每个适配器泄漏一份配置对象；缺 `createParser` 的失败路径直接 `return false`，已打开的 `DllHandle` 不释放。
- 复核状态: 部分合并，分别记录证据边界。
  - `_cfg` retain 无配对 release：**状态: 已合并（与 BUG-N03-008 同根因，按一个缺陷计数）**。`BUG-N03-008` 补充 init 早退触发路径；R78 保留为主记录。
  - 缺 `createParser` 时未关闭 `hInst`：**状态: 源码确认（失败插件未运行验证）**。`DLLHelper::load_library` 返回裸句柄；此分支没有保存或释放它。测试只运行了有效 ParserUDP 插件的成功链，没有覆盖 ParserAdapter 的缺符号分支。
- 复现步骤（静态）：成功 init 后 `release()` 只处理 `_parser_api`，不释放 `_cfg`；缺符号分支获取非空 `hInst` 后查找失败并直接返回。尚未通过引用计数替身、泄漏检测或缺符号测试观察运行结果。
- 影响: `_cfg` 引用会使配置对象至少多存活一份；缺符号尝试会遗留已加载库的句柄。长期/反复失败加载的资源增长是源码推断，未做运行内存测量。WtDtServo 的 `BUG-R8-006` 是另一模块的同型问题，不与本项重复计数。
- 分级: C
- 修复方向: 统一 `_cfg` 所有权并在 release/析构配对释放、置空；无 `createParser` 时释放 `hInst`；通过引用计数对象和缺入口插件验证失败及成功清理。

## BUG-R78-002 — UftStraContext::load_local_data 全程不释放 mannual.yaml 的 WTSVariant

- 文件: `src/WtUftCore/UftStraContext.cpp`
- 位置: L1052 `WTSVariant* manual = WTSCfgLoader::load_from_file(mannualfile);`；L1053-1057（返回 NULL 时退出，不存在可释放对象）、L1059-1061（有对象但无 `details` 时退出）、L1090-1112（成功导入路径）之后均无 `manual->release()`。
- 输入/前置条件: 策略输出目录存在可解析且返回非 NULL 的 `mannual.yaml`，内容缺少 `details` 或包含有效 `details`，并触发 `load_local_data()`。空文件/解析失败而 loader 返回 NULL 的分支不构成这项对象泄漏。
- 期望行为: loader 返回非 NULL 后，无论缺少 `details` 还是完成导入，都应释放 `manual`；解析失败并返回 NULL 时没有对象需要释放。
- 实际行为: `WTSObject` 初始引用计数为 1，loader 返回非 NULL 对象后本函数没有 retain/release 的配对，也没有其他释放点。有效 YAML 缺少 `details` 时 `break`，有 `details` 时处理完同样不释放 `manual`；返回 NULL 的解析失败分支没有对象可泄漏。
- 复现步骤（静态）：用合法 YAML `foo: bar` 调用 `on_channel_ready`，会创建非 NULL `manual`、命中无 `details` 分支并继续改名文件；源码没有释放该对象。测试没有用 refcount/析构替身或 LeakSanitizer 观测释放。
- 影响: 每次返回非 NULL 并进入该路径都会遗留一份 WTSVariant 引用；累计次数/内存规模取决于调用频度，未运行测量。业务结果用例通过不证明资源已回收。
- 分级: C
- 状态: 源码确认（运行测试覆盖业务分支但未测释放）
- 修复方向: 用带 `WTSVariant::release` deleter 的 RAII 持有 `manual`，或保证所有非 NULL 出口都 release；以引用计数/析构替身和有效 YAML 缺 `details`、含 `details` 两路验证。
