## BUG-R123-001

- 编号: BUG-R123-001
- 模块/文件: `src/WtUftCore/WtUftEngine.cpp:209-243`
- 测试用例: `R123UftEngine.DISABLED_get_kline_slice_never_reaches_subscription`
  （`src/TestUnits/coverage/q04_uftcore3/r123_uft_ticker_engine_test.cpp`）
- 输入: `engine.init(nullptr, &bd, &dtMgr, nullptr)`，`bd` 注册 `SHFE.ag`/`ag2406`；
  `engine.get_kline_slice(1, "SHFE.ag2406", "m", 10, 1, 0)`
- 期望: 返回非空 `WTSKlineSlice`，并把 `(stdCode, period, times)` 与 sid 登记进 `_bar_sub_map`
- 实际: 函数首行 `return NULL;`（L211），L213-243 的品种解析、订阅登记、周期换算、
  `_data_mgr->get_kline_slice` 全部不可达；`UftStraContext::stra_get_bars` 永远拿不到 K 线
- 复现步骤:
  1. 用假 `IBaseDataMgr` 注册一个合约并初始化 `WtUftEngine`；
  2. 调 `get_kline_slice(...)`；
  3. 观察返回值恒为 NULL；随后任何 `engine.on_bar(...)` 都因 `_bar_sub_map` 为空而不分发。
- 严重级别: Major（UFT 策略 K 线取数/订阅公开 API 整体不可用）
- 状态: 待审核

## BUG-R123-002

- 编号: BUG-R123-002
- 模块/文件: `src/WtUftCore/WtUftDtMgr.cpp:34-37, 48-52, 88-100`
- 测试用例: `R123UftDtMgr.null_tick_does_not_create_cache` /
  `R123UftDtMgr.realtime_tick_roundtrip_and_release`（`r123_uft_dtmgr_test.cpp`）；
  另由静态阅读 `.cpp` 确认
- 输入: 构造 `WtUftDtMgr`，调用 `handle_push_quote` / `grab_last_tick` / 五类切片查询后析构
- 期望: `_bars_cache` / `_ticks_cache` 要么在初始化时创建，要么相关成员和分支删除；
  `handle_push_quote` 在 `_ticks_cache != NULL` 时应把 tick 追加进历史缓存
- 实际: 两个成员在构造函数置 NULL 后**从未被赋值**；因此析构的
  `if (_bars_cache) release`（L48-49）与 `if (_ticks_cache) release`（L51-52）恒不执行，
  `handle_push_quote` 的 L88-100 整段（历史 tick 追加）也是不可达死代码
- 复现步骤:
  1. 对任意 tick 调 `handle_push_quote`；
  2. 在调试器中观察 `_bars_cache`/`_ticks_cache` 始终为 NULL；
  3. 析构不会进入上述两个 if。
- 严重级别: Minor（死代码/覆盖率留白，不影响当前实时 tick 转发）
- 状态: 待审核

## BUG-R123-003

- 编号: BUG-R123-003
- 模块/文件: `src/WtDtServo/WtDataManager.cpp:39-47, 76-78, 531-534, 549-551`
- 测试用例: `R123DtServoRemainingTest.ticks_default_end_and_update_bars_code_mismatch`
  （先 `subscribe_bar` 建立 `_rt_bars`，随后析构 `WtDataManager`）
- 输入: `WtDataManager dm; dm.init(cfg, &runner); dm.subscribe_bar("CFFEX.IC.2204", KP_Minute1, 1);`
  离开作用域
- 期望: 析构释放 `_rt_bars`，并通过 `_remover` 删除 `initStore` 创建的 `_reader`
- 实际: 析构只遍历释放 `_bars_cache`；`_rt_bars`（`RtBarMap::create()`）与
  `_reader`/`_remover` 均未释放，reader 的 5s 巡检线程也不会停止，形成进程内泄漏。
  产品里 `WtDataManager` 通常与进程同寿，故列为 Minor。
- 复现步骤:
  1. 构造 WtDataManager 并 `init`（真实 store）后 `subscribe_bar`；
  2. 析构后在泄漏检测器（valgrind/ASan LSan）中观察 `_rt_bars` 与 reader 对象仍可达/未释放；
  3. 多次创建/销毁会线性增长。
- 严重级别: Minor（资源泄漏，长时间多实例场景可累积）
- 状态: 待审核
