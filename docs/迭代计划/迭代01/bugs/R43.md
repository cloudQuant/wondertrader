## BUG-R43-001

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtBtCore/SelMocker.cpp:305-307`（`SelMocker::handle_replay_done`）
- 相关测试: `src/TestUnits/coverage/n04_btcore_mockers/r43_sel_mocker_dump_test.cpp`
  - `R43SelMockerDumpTest.DISABLED_replayDoneWithoutScheduleDividesByZero`（归档，未启用）
  - 启用的 `scheduleThenReplayDoneWritesAllArtifacts` / `sessionAndTickFeedDumpRows` 均先调度一次以绕开
- 输入/前置条件: `SelMocker mocker(&replayer, "r43_sel_div0"); mocker.handle_replay_done();`
  即一次 `handle_schedule` / `on_schedule` 都没执行过（`_emit_times == 0`）。
- 期望行为: 回放结束时即使从未触发过调度，也应正常打印“调度 0 次”并落盘（`CtaMocker::handle_replay_done`
  就是这样用 `if(_emit_times > 0)` 分两支处理的）。
- 实际行为: L305-307 无条件执行
  `WTSLogger::log_dyn(..., _emit_times, _total_calc_time, _total_calc_time / _emit_times)`，
  当 `_emit_times == 0` 时是无符号整数除零（C++ 未定义行为）：x86-64 上 `div` 直接触发 SIGFPE
  终止整个进程；arm64 上 `UDIV` 对 0 除返回 0，看起来“没事”，但同一份代码在不同平台/优化下
  结果不同，属于必须消除的 UB。同一仓库 `CtaMocker.cpp:665` 有正确的判空写法，可对照。
- 复现步骤:
  1. 构造任意 `HisDataReplayer`（甚至不 `init`，因为该路径不读回放器）；
  2. `SelMocker sel(&replayer, "r43_sel_div0");`
  3. 直接调用 `sel.handle_replay_done();`
  4. 进程在进入 `dump_outputs()` 之前崩溃。
- 影响范围: 选股回测在“没有任何调度事件就结束”的异常/空数据场景下会整体崩溃，落盘文件（trades/closes/
  signals/positions/ud_*.json）全部丢失；因为崩溃发生在 gtest 进程内，也会连带吞掉同一可执行体后续用例的
  覆盖率计数。修复方向（不实施）：与 `CtaMocker` 对齐，`_emit_times > 0` 时才计算平均值。

## BUG-R43-002

- 状态: 待审核
- 严重级别: Major（未定义行为；当前仅影响私有委托账本，未观察到撮合结果错误）
- 模块/文件: `src/WtBtCore/MatchEngine.cpp:250-260`（`MatchEngine::update_lob`）
- 相关测试: `src/TestUnits/coverage/n04_btcore_mockers/r43_match_engine_flow_test.cpp`
  - `R43MatchEngineFlowTest.DISABLED_oneSidedBookDereferencesEnd`（归档，未启用）
- 输入/前置条件: 喂入**只有一侧盘口**的 tick（例如 `bid_prices[0]=10.0`、`bid_qty[0]=500`，
  而 `ask_prices/ask_qty` 全为 0），再喂一笔同构 tick。
- 期望行为: 单侧盘口时 `lower_bound` 结果需要判 `end()`；买卖价之间没有可清理区间时直接跳过。
- 实际行为: 代码为
  `auto sit = curBook._items.lower_bound(curBook._bid_px); if (sit->first == curBook._bid_px) sit++;`
  `auto eit = curBook._items.lower_bound(curBook._ask_px); if (sit->first <= eit->first) ...`。
  当账本里只有一个价位（买单侧）时，`sit++` 之后 `sit == end()`，下一行 `sit->first`
  解引用 `std::map` 的 end 节点，属未定义行为（可能读到垃圾值、也可能直接崩溃）。
  另外 L242-247 在买盘价位上写入的是 `curTick->askqty(i)`（卖盘量），盘口买量数据本身也是错的。
- 复现步骤:
  1. 新建 `MatchEngine` 并 `regisSink` 任意 `IMatchSink`；
  2. `handle_tick(code, tick)`，tick 只填 `bid_prices[0]/bid_qty[0]`，卖盘两数组保持 0；
  3. 观察 L253-260：`sit` 已指向 `end()` 仍被解引用（用 ASan/UBSan 构建可直接报
     `invalid iterator`/`null pointer`）。
- 影响范围: 回测撮合引擎的限价委托账本在“涨跌停单边报价/停牌恢复首笔”等只有一侧盘口的行情下进入未定义行为；
  账本目前只用于内部记录，撮合价量取的是 tick 字段，所以暂未观测到成交价错误，但一旦后续用 `_items`
  做深度撮合或撤单率估算，错误会直接放大。修复方向（不实施）：`sit`/`eit` 均判 `end()` 后再比较，
  买盘价位写入 `bid_qty(i)`。
