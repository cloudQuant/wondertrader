## BUG-R125-001 `WtStraDtSel::on_schedule` 在单个标的缺 K 线时提前退出

- 状态：待审核（当前代码控制流确定；跨标的预期需由策略要求与多标的测试确认）
- 候选严重级别：Major（若各配置标的应独立处理，单个缺数据会漏掉本次剩余标的信号）
- 代码位置：`src/WtSelStraFact/WtStraDtSel.cpp:121-150`。
- 源码行为：`on_schedule()` 遍历 `_codes`；非交易时段对当前代码 `continue`，但 `stra_get_bars()` 返回 NULL 或空切片时分别 `return` 整个函数。因此遇到此类数据状态后，本次调用中位于其后的代码不会被查询/计算；下一次 schedule 调用仍会重新进入循环，不能描述为后续调用也永远不处理。
- 契约边界：策略配置的 `_codes` 是 `std::unordered_set`，`on_init()` 会为集合内所有代码订阅 Tick；但 `ISelStraCtx::stra_get_bars()` 的接口注释仅说明返回切片指针，未规定空结果时是跳过该代码还是停止整次策略调度。代码在缺 K 线处留有日志注释、且非交易时段采用逐代码跳过，使“对每个代码独立处理、缺数据跳过当前代码”成为合理修复方向，但仍需产品/策略语义确认。
- 测试边界：`src/TestUnits/coverage/r125_selfthft/r125_sel_test.cpp` 的 `ScheduleEarlyReturns` 配置只有一个代码；它验证了 NULL/空切片分支不发仓位请求，没有第二个标的可证明后续遍历被跳过。当前 R125 测试因此没有动态复现多标的漏选；本次单代码用例通过也不能证明多标的行为正确。
- 迭代顺序：`unordered_set` 迭代次序未承诺，不应写成运行时“随机漏选”。缺数据代码之前/之后的具体标的随容器迭代次序及实现而定。
- 修复方向：若产品要求每个标的独立处理，将 NULL 分支改为 `continue`；空切片先 `release()` 再 `continue`。补一个双标的回归：先访问的代码返回 NULL 或空切片，随后代码返回可触发突破的 K 线；用实际调用顺序/调用计数验证后者仍被处理，不假定 unordered_set 的固定顺序。

## BUG-R125-002 UFT/HFT Demo 的 `_last_tick` 没有写入点
- 状态: 已撤回（未使用成员与不可达析构释放分支不是运行期功能缺陷）

- 审核裁定：不是运行期功能缺陷；属于未使用成员/覆盖率清理观察，不登记为产品 bug。
- 代码位置：`src/WtUftStraFact/WtUftStraDemo.cpp:31,48-49` 与 `src/WtHftStraFact/WtHftStraDemo.cpp:29,47-48`。
- 源码事实：两处 `_last_tick` 都在构造时设为 NULL；在各自文件中没有任何赋值。Tick 回调或 `do_calc` 获取的是局部变量，不会把引用存进该成员，所以析构的 `if (_last_tick)` 分支在当前实现中不可达。
- 证据边界：`R125UftDemo.InitTickEntryAndOrderExpiry` 和 `R125HftDemo.InitCalcEntryAndOrderExpiry` 会构造/析构 Demo，但只覆盖空成员状态；这不能证明成员本应有缓存功能。原记录关于“目标模块唯一剩余行”的覆盖率结论未由本次独立覆盖报告确认，不保留该说法。
- 修复方向：若策略不需要最后 Tick 缓存，后续清理可删掉成员、构造初始化和析构释放分支；若确需缓存，则先定义回调写入与 retain/release 所有权，再按该契约测试。不要仅为命中析构分支而添加私有测试钩子。
