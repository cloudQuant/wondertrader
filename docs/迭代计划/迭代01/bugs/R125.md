# lane R125 疑似缺陷记录（策略工厂 / 策略实现）

## BUG-R125-001

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtSelStraFact/WtStraDtSel.cpp` L139-143、L146-150（`WtStraDtSel::on_schedule`）
- 相关测试: `src/TestUnits/coverage/r125_selfthft/r125_sel_test.cpp`
  `TEST(R125SelStrategy, ScheduleEarlyReturns)`（覆盖两条 `return` 本身；多代码漏选效果由同一行引出）
- 输入/前置条件: `codes` 配置两个及以上标的；`on_schedule` 遍历到第一个标的时
  `stra_get_bars` 返回 NULL（L139）或空 K 线（L146）
- 期望行为: 跳过当前标的（`continue`），继续处理 `_codes` 中剩余标的
- 实际行为: 直接 `return` 退出整个 `on_schedule`，剩余标的当次及后续在该函数内全部不再处理
- 复现步骤:
  1. `init` 配置 `codes="SHFE.au.2005,SHFE.ag.2005"`；
  2. 让 fake/真实上下文对第一个代码返回 NULL 或 `size()==0` 的 K 线，第二个代码返回可突破 K 线；
  3. 调 `on_schedule(ctx, 20240102, 1000)`；
  4. 观察第二个代码从未调用 `stra_get_bars`，也不会产生 `stra_set_position`。
  `_codes` 是 `std::unordered_set`，遍历顺序不定，表现为“随机漏选”。
- 影响范围: 多标的选股策略只要有一个标的缺历史数据，其余标的当日信号全部丢失；
  与同函数 L129-130 非交易时段用 `continue` 的语义也不一致
- 备注: 修复方向：两处 `return` 改为 `continue`（空 K 线仍需先 `release()`）。
  本 lane 按纪律不修改生产代码。

## BUG-R125-002

- 状态: 待审核
- 严重级别: Minor（死代码/覆盖率阻塞）
- 模块/文件:
  - `src/WtUftStraFact/WtUftStraDemo.cpp` L31（构造置 NULL）、L48-49（析构 `_last_tick->release()`）
  - `src/WtHftStraFact/WtHftStraDemo.cpp` L29（构造置 NULL）、L47-48（同上）
- 相关测试: `TEST(R125UftDemo, InitTickEntryAndOrderExpiry)`、
  `TEST(R125HftDemo, InitCalcEntryAndOrderExpiry)`（两个 Demo 均在用例栈上构造/析构）
- 输入/前置条件: 任意 Demo 生命周期（init → on_init → on_tick/do_calc → 析构）
- 期望行为: 若成员用于缓存最后一笔 Tick，应在回调中赋值并在析构释放；
  若不需要缓存，应删除成员与释放分支
- 实际行为: `_last_tick` 除构造函数置 NULL 外全文件无任何赋值（`grep _last_tick` 仅命中
  构造函数、析构判断与 do_calc/on_tick 里的局部变量），析构中的
  `_last_tick->release()` 永远不执行；两行因此无法被任何公开 API 覆盖
- 复现步骤: 构造任一 Demo、调用全部公开回调后析构；在 L48/L47 的 `if` 处观察恒为 NULL
- 影响范围: 两行永久未覆盖（目标模块唯一剩余行）；无运行期功能影响
- 备注: 与既有 `bugs/n06_strategies_mq_share.md` BUG-WSN06-002（两个 Demo 的 `init`
  不判 cfg==NULL）是不同问题。修复方向二选一：在 on_tick/do_calc 中 retain 最后 tick，
  或删除死成员及析构分支。
