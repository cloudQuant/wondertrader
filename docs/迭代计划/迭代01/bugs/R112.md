## BUG-R112-001

- 状态: 待审核
- 严重级别: Major（可触发越界读/崩溃）
- 模块/文件: `src/WtDataStorage/WtRdmDtReader.cpp`
  - `readKlineSliceByRange` 当日 RT 段：L1868-1884
    （`std::lower_bound(_bars, _bars + (_size - 1), ...)` 在 L1873；回退 `pBar--/idx--` 在 L1882-1883）
  - `readKlineSliceByCount` 当日 RT 段：L2291-2307（同型 L2296/L2305-2306）
- 相关测试: 无启用复现（源码走查发现）。`WtDataReader::readKlineSlice` 在
  `src/WtDataStorage/WtDataReader.cpp:1809` 有 `kPair->_block->_size>0` 守卫，Rdm 侧没有，
  两处行为不一致，可直接对照。
- 输入/前置条件:
  - 当日 RT K 线块 `rt/min1/SSE/600000.dmb`（或 min5）存在，但头部 `_size == 0`
    （writer 刚建块、当日还没有任何 bar；`getRTKilneBlock` 只检查文件存在与映射成功）；
  - `cInfo._exright != 2`（普通合约/股票）；
  - 调 `readKlineSliceByRange("SSE.STK.600000", KP_Minute1, 202401100900, 202401101000)`
    或 `readKlineSliceByCount("SSE.STK.600000", KP_Minute1, 5, 202401101000)`。
- 期望行为: RT 块为空时应跳过实时段（或返回空切片），不得对 `_size - 1` 求值；
  与 `WtDataReader.cpp:1809` 的 `_size>0` 守卫一致。
- 实际行为:
  1. `_size` 是 `uint32_t`，`_size - 1` 回绕为 `0xFFFFFFFF`；
  2. `std::lower_bound(begin, begin + 0xFFFFFFFF, eBar, ...)` 的区间远远越过映射区，
     读比较器时即可能 SIGSEGV；
  3. 即使侥幸返回，L1879 `idx = pBar - _bars` 也会得到巨大值，随后
     `pBar->time/date`、`idx + 1`、`appendBlock` 全部越界。
  - `readKlineSliceByCount` 同型；若 `pBar` 指到块首之外，L1880/L2303 的 `pBar--`
    还会继续前移，属于同一根因。
- 影响范围: 盘中首次订阅某合约、writer 已建 RT 块但尚未写入第一条 bar 时，
  任何 `readKlineSliceByRange/ByCount` 实时读取都可能崩溃；回放预热、策略启动探测
  （先建块后补数据）是常见触发场景。
- 备注: 修复方向：在两处 `getRTKilneBlock` 后加
  `if (kPair == NULL || kPair->_block == NULL || kPair->_block->_size == 0) { ... }`，
  与 `WtDataReader::readKlineSlice` 的守卫保持一致。`.h` 中该 helper 的可见性无需调整。
