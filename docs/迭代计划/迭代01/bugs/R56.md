## BUG-R56-001 · 切换日之前查询主力时在 begin() 上执行 cit--（迭代器下越界）

- 状态: 待审核
- 严重级别: Major（该输入下发生迭代器 UB；本次未观察崩溃或读坏内存）
- 位置: `src/WTSTools/WTSHotMgr.cpp:337-341`（`getCustomRawCode`），
  同样形态见 `:291-295`（`getPrevCustomRawCode`）
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_hotmgr_test.cpp`
  → `R56HotMgr.DISABLED_RawCodeBeforeFirstSwitchDate`
- 输入: 换月规则首条日期为 20240102；调用
  `getRawCode("SHFE", "rb", 20240101)` 或 `getPrevRawCode("SHFE", "rb", 20240101)`
- 期望: 先明确首条规则日期之前的返回语义；无论返回空串还是首条合约，都不得对 `begin()` 自减
- 实际: `cit = dtMap->lower_bound(dt)` 已指向 `begin()`；随后
  `if (dt < cit->first) cit--;` 对 `begin()` 执行自减。C++ 标准规定
  `std::map::begin()` 自减是未定义行为；`getPrevCustomRawCode` 之后虽有
  `cit == dtMap->begin()` 判断，但越界自减已经发生
- 复现: 静态路径明确：`lower_bound` 指向首元素且 `dt < first` 时执行 `cit--`；`getPrevCustomRawCode` 的 begin 检查在自减之后，不能阻止 UB。DISABLED 用例提供最小夹具但本次未运行，故不主张已有动态崩溃证据。
- 影响: 回测起始日早于 hots.json 最早换月日时，查询主力/上一主力可能崩溃或读到脏迭代器；
  正常用例因此不驱动该输入（DISABLED_ 保留复现）

## BUG-R56-003 · next_row 未成功时 get_* 对空 _current_cells 取下标

- 状态: 待契约确认（越界风险只在无当前行时调用 getter 的条件下存在）
- 严重级别: 条件性边界安全问题；合法调用序列是否必须先成功 `next_row()` 尚未明确
- 位置: `src/WTSTools/CsvHelper.cpp:161-170`（`check_cell`），
  触发点 `:117-123`（`get_string`）及其余 `get_int32/get_uint32/get_int64/get_uint64/get_double`
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_csv_test.cpp` → `R56Csv.DISABLED_GetValueBeforeFirstRow`（禁用，未运行）
- 输入: `CsvReader reader; reader.load_from_file(有表头文件); reader.get_string("a");`
  （未调用 `next_row()`，或上一次 `next_row()` 已返回 false）
- 期望: 先明确 getter 是否要求 `next_row()` 成功；若支持无当前行查询，则返回 `""`/0 或显式报错，不能越界
- 实际: `check_cell(col)` 只用 `_fields_map.size()` 判上界，列号合法就直接
  `_current_cells[col]`；此时 `_current_cells` 为空 vector，`operator[]` 越界，
  随后对非法 `std::string` 调 `c_str()`，属未定义行为
- 复现: 源码表明 `_current_cells[col]` 在空 vector 上可能越界；禁用用例未运行，本次没有 ASAN/崩溃证据。文件只有表头时，首个 `next_row()` 返回 false 后也没有当前行。
- 影响与修复方向: 若“先成功 next_row，再读当前行”是既定前置条件，则该测试输入违反调用顺序，应改为契约/健壮性用例；若 API 承诺无当前行时 getter 返回默认值，则 `check_cell` 还应校验 `_current_cells.size()`，并覆盖首行前、EOF 后两种状态。头文件目前未明确该前置条件，结论为契约待定而非已证实的有效调用崩溃。

## BUG-R56-004 · loadHots 在配置文件缺失时仍返回 true 并置 initialized

- 状态: 证据不足（hot 文件是否必需、`isInitialized()` 的语义均未在接口中明确）
- 严重级别: 暂不定级；当前活动用例将缺失文件视为成功初始化的空规则管理器
- 位置: `src/WTSTools/WTSHotMgr.cpp:117-122`
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_hotmgr_test.cpp`
  → `R56HotMgr.MissingFilesKeepManagerEmpty`
- 输入: `loadHots("/tmp/不存在/hots.json")`
- 期望: 需先确定 hot 规则文件是必需还是可选；必需时装载失败应返回失败且不报 initialized，可选时应明确 `true` 表示管理器可按空规则工作。
- 实际: `loadHots` 丢弃 `loadCustomRules` 的 false 并置 `m_bInitialized=true`；随后 `getHotTags()` 为空、查询返回默认值。此行为有源码和活动用例支持，但本身尚不能判断违约。
- 复现: 活动用例 `R56HotMgr.MissingFilesKeepManagerEmpty` 断言 `loadHots(missing)==true`、`isInitialized()==true` 且 tags 为空；这是对现状的实测断言，不是“返回 false”才正确的证据。
- 影响与修复方向: 若缺失 hot 文件是允许的可选配置，现状可能是有意的空规则退化；若必需，则需让实现与该用例一起改为失败并报告加载原因。先补充接口/配置契约，再裁定是否保留为缺陷。
