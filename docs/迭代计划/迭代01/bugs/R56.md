## BUG-R56-001 · 切换日之前查询主力时在 begin() 上执行 cit--（迭代器下越界）

- 状态: 待审核
- 严重级别: Major（UB，可能崩溃/读坏内存）
- 位置: `src/WTSTools/WTSHotMgr.cpp:337-341`（`getCustomRawCode`），
  同样形态见 `:291-295`（`getPrevCustomRawCode`）
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_hotmgr_test.cpp`
  → `R56HotMgr.DISABLED_RawCodeBeforeFirstSwitchDate`
- 输入: 换月规则首条日期为 20240102；调用
  `getRawCode("SHFE", "rb", 20240101)` 或 `getPrevRawCode("SHFE", "rb", 20240101)`
- 期望: 返回空串（或首条规则对应的合约），不得对迭代器做越界操作
- 实际: `cit = dtMap->lower_bound(dt)` 已指向 `begin()`；随后
  `if (dt < cit->first) cit--;` 对 `begin()` 执行自减。C++ 标准规定
  `std::map::begin()` 自减是未定义行为；`getPrevCustomRawCode` 之后虽有
  `cit == dtMap->begin()` 判断，但越界自减已经发生
- 复现: 用 `dist/common/hots.json` 同形规则（首条 20190102）查询 20180101 前后即可触发；
  本 lane 用 20240102 首条 + 20240101 查询的最小夹具
- 影响: 回测起始日早于 hots.json 最早换月日时，查询主力/上一主力可能崩溃或读到脏迭代器；
  正常用例因此不驱动该输入（DISABLED_ 保留复现）

## BUG-R56-002 · log_by_cat_prefix 丢弃 format/args，日志正文只剩分类前缀

- 状态: 待审核
- 严重级别: Minor（日志内容丢失，静默）
- 位置: `src/WTSTools/WTSLogger.h:335-347`（实现体 `:341-346`）
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_logger_test.cpp`
  → `R56Logger.DISABLED_LogByCatPrefixKeepsFormattedPayload`
- 输入: 初始化 root 日志到临时文件后调用
  `WTSLogger::log_by_cat_prefix("r56cat", LL_INFO, "payload-%d", 42)`
- 期望: 落盘内容包含 `[r56cat]` 且包含格式化正文 `payload-42`
- 实际: 函数只写入 `'[' + catName + ']'`，形参 `format`/`args` 完全未使用，
  落盘内容只有 `[r56cat]`；对比 `log_dyn_prefix`（:384-397）会把正文格式化到
  前缀之后，两个“前缀”入口行为不一致
- 复现: 启用上述 DISABLED 用例即可看到 `payload-42` 缺失；正常用例
  `InitSuccessWritesAllLevelsAndCategories` 只断言 `[r56warn]` 存在，不锁定正文
- 影响: 使用该入口的分类日志正文全部丢失，排障时只能看到分类名；
  调用方不会收到任何错误提示

## BUG-R56-003 · next_row 未成功时 get_* 对空 _current_cells 取下标

- 状态: 待审核
- 严重级别: Major（越界读/崩溃）
- 位置: `src/WTSTools/CsvHelper.cpp:161-170`（`check_cell`），
  触发点 `:117-123`（`get_string`）及其余 `get_int32/get_uint32/get_int64/get_uint64/get_double`
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_csv_test.cpp`
  → `R56Csv.DISABLED_GetValueBeforeFirstRow`
- 输入: `CsvReader reader; reader.load_from_file(有表头文件); reader.get_string("a");`
  （未调用 `next_row()`，或上一次 `next_row()` 已返回 false）
- 期望: 返回 `""`/0（与列不存在时的既有约定一致），或明确报错
- 实际: `check_cell(col)` 只用 `_fields_map.size()` 判上界，列号合法就直接
  `_current_cells[col]`；此时 `_current_cells` 为空 vector，`operator[]` 越界，
  随后对非法 `std::string` 调 `c_str()`，属未定义行为
- 复现: 启用 DISABLED 用例；在 ASAN 下会报 heap-buffer-overflow/SEGV
- 影响: 调用方漏调 `next_row()` 或读到文件尾后继续取值会崩溃；
  文件只有表头时同样触发

## BUG-R56-004 · loadHots 在配置文件缺失时仍返回 true 并置 initialized

- 状态: 待审核
- 严重级别: Minor（错误被吞，调用方无法感知装载失败）
- 位置: `src/WTSTools/WTSHotMgr.cpp:117-122`
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_hotmgr_test.cpp`
  → `R56HotMgr.MissingFilesKeepManagerEmpty`
- 输入: `loadHots("/tmp/不存在/hots.json")`
- 期望: `loadCustomRules` 返回 false 时 `loadHots` 返回 false，且不置
  `m_bInitialized = true`
- 实际: `loadHots` 无条件 `m_bInitialized = true; return true;`，即使
  `loadCustomRules` 因文件不存在返回 false；随后 `getHotTags()` 为空、
  所有查询回落默认值，但 `isInitialized()` 为 true
- 复现: 正常用例已锁定当前行为（`EXPECT_TRUE(loadHots(missing))`），
  若产品修复为返回 false，需要同步更新该断言
- 影响: 上层用 `isInitialized()`/返回值判断热力规则是否可用时会误判；
  实盘/回测可能在无换月规则的状态下静默运行
