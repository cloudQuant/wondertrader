## BUG-R70-001

- 状态: 待审核
- 严重级别: Major（可触发未定义行为/崩溃）
- 模块/文件:
  - `src/WtDataStorage/WtRdmDtReader.cpp`
    - `readOrdQueSliceByRange` isToday 分支 L660-674，回绕后的 `eIdx` 在 L685 继续用于 `lower_bound`
    - `readOrdDtlSliceByRange` isToday 分支 L835-849，L860 继续使用
    - `readTransSliceByRange` isToday 分支 L1009-1023，L1034 继续使用
  - 同型观察（未单独造崩溃用例）：`src/WtDataStorage/WtDataReader.cpp` `readTickSlice` his 分支
    L437-449 的 `pTick--; eIdx--;` 也没有 `eIdx == 0` 守卫（`eIdx` 为 `uint32_t`，回绕后
    `cnt = min(eIdx + 1, count)` 得 0，`sIdx` 归 0，不崩但指针先越界）。
- 相关测试: `src/TestUnits/coverage/q03_storage3/r70_rdm_residual_test.cpp` →
  `R70RdmResidualTest.DISABLED_R70RdmTodayHftRangeBeforeFirstItemUnderflows`
- 输入/前置条件:
  - 当日 RT 委托队列块 `rt/queue/SSE/600000.dmb` 有 4 条（09:30/09:31/09:32/09:33）；
  - `endTDate == curTDate`（isToday 为真）；
  - 请求 `readOrdQueSliceByRange("SSE.STK.600000", 20240110090000000, 20240110090000000)`
    （etime 早于块内首条 09:30）。
- 期望行为: 目标时间早于 RT 块首条时应返回空切片/NULL，且不得对块首之前取址；
  `eIdx` 保持 0（与 his 分支 L499-505、L756-760 的 `if (eIdx == 0) break;` 一致）。
- 实际行为:
  1. `std::lower_bound(begin, begin + (_size - 1), eTick, ...)` 返回 `begin`；
  2. `pItem->action_time > eTick.action_time` 为真，进入 `pItem--; eIdx--;`；
     `pItem` 退到数组前一个元素（未定义行为），`eIdx`（`std::size_t`）由 0 回绕为 `SIZE_MAX`；
  3. 同交易日分支继续 `std::lower_bound(begin, begin + eIdx, sTick, ...)`，此时
     `begin + SIZE_MAX == begin - 1`，区间 `first > last`，违反 `lower_bound` 前置条件；
     典型结果是崩溃/死循环，最乐观也是未定义值。
  - 跨交易日分支虽然因为 `eIdx + 1` 回绕成 0 而使 `WTSOrdQueSlice::create` 返回 NULL，
    但 `pItem--` 的越界取址已经发生。
  - 委托明细、逐笔成交两条链是同型复制，触发条件完全一致。
- 复现步骤:
  1. 用 `q03_storage3_fixture.h` 的 `make_rt_block<WTSOrdQueStruct>(BT_RT_OrdQueue, ...)`
     写 4 条 09:30~09:33 的 RT 队列块；
  2. `WtRdmDtReader::init(NULL, sink)`，宿主 `calcTradingDate` 返回 20240110；
  3. 调 `readOrdQueSliceByRange("SSE.STK.600000", 20240110090000000ull, 20240110090000000ull)`。
  用例已写成 `DISABLED_`；`--gtest_also_run_disabled_tests` 可复现（预期 SIGSEGV 或断言）。
- 影响范围: 任何按「开盘前/首笔之前」的时间窗口查询当日逐笔队列/明细/成交的调用
  （回放预热、集合竞价时段、跨日窗口起点早于首条）都会踩到；三个公开虚函数
  `readOrdQueSliceByRange` / `readOrdDtlSliceByRange` / `readTransSliceByRange` 全部受影响。
- 备注: 修复方向：三处都补 `if (eIdx == 0) { /* 返回空/NULL */ }`，或把回退条件改成
  `pItem != begin && (...)`；建议与 BUG-R23-005 的边界语义一起评审，避免只修一条链。
