## 复核裁定

| 原记录 | 分类 | 裁定与修复方向 |
|---|---|---|
| BUG-R191-001 插件工厂加载后 Mocker 析构 SIGSEGV | **真实 ABI 缺陷，重复 BUG-R64-002** | Uft/Cta 的 FuncDelete typedef 使用 IUftStrategyFact*& / ICtaStrategyFact*&（Includes/UftStrategyDefs.h:207、CtaStrategyDefs.h:130），而插件导出 deleteStrategyFact 按值接收指针（WtUftStraFact.cpp:43、WtCtaStraFact.cpp:49）。Mocker 将符号转型后在 _StraFactInfo 析构调用 _remover(_fact)，类型不匹配构成未定义行为。R191 新增了 Mocker 析构 callsite，但与 BUG-R64-002 同一 ABI 根因，应合并复核，不作为新的根因编号。修复方向是统一 typedef 与导出签名，并对 remover 缺失作安全处理。 |
| R191UftMocker_CoverTodayPreavailExitCancelBranches 的 short 昨仓断言 | **测试前提不符合商品模式；动态结果不足以证明 short T+1 产品缺陷** | 失败在 r191_mocker_residual_test.cpp:157。夹具把商品设为 TM_LongT1，随后直接调用 on_trade(..., isLong=false, ...) 注入 short fill，并期望会话开始后 short 可用量为 50。TM_LongT1 明确表示做多 T+1；WTSCommodityInfo::canShort() 对此返回 false（Includes/WTSContractInfo.hpp:44-45，l03_commodity_info_test 也覆盖）。因此这条人工注入不能证明该商品模式应支持 short 或 short T+1。保留此前合法的多头 T+1、昨仓平仓和撤单恢复断言；删除这段无效 short rollover 期望。若要覆盖合法 short，当使用 TM_Both 时走公开开仓/成交/平仓路径，并只断言该模式支持的行为。 |
| UftMocker 开空入口与商品模式的差异 | **独立静态接口缺口；重复 BUG-P08-002 / BUG-R201-001，端到端证据不足** | UftMocker::stra_enter_short（UftMocker.cpp:638 起）只校验商品和数量，没有检查 canShort；stra_sell 的剩余量转开空路径亦进入该接口。与之对照，CtaMocker/HftMocker 的相关开空入口有 canShort 检查，商品 API 也明确暴露此能力判断。应按现有模式契约在 TM_LongT1 下拒绝开空，或先由接口 owner 明确支持 short T+1 并扩充模式模型。补测试时直接调用公开开空入口并检查不产生订单；跨日 short 结转需另以合法端到端路径验证。R191 现有直接 on_trade 注入没有做此验证。 |

## BUG-R191-001 证据边界

- 状态: 已合并（迭代02：主编号 BUG-R64-002）

- 现有 R121 日志在离开作用域前打印了探针标记，随后进程 CRASH；这是析构阶段失败的动态迹象，但日志本身没有调用栈。源码签名不匹配提供明确静态原因，不再把模块卸载顺序、插件重复释放列为根因猜测。
- _StraFactInfo 析构无条件在 _fact 非空时调用 _remover；当前该对象析构没有调用 free_library。若插件可能缺少 deleteStrategyFact，应另以公开 ABI 失败策略处理，不用 NULL 指针猜测解释本次签名不匹配。
- 直接调用插件 creator/remover 的对照测试 PASS，只说明按插件真实签名直接调用可用，不能否定通过错误 typedef 调用时的 UB。
- R191 启用用例通过 new 保留 Mocker、避免析构；该做法利于记录其他路径的覆盖结果，却绕过了析构验收。修复后应恢复作用域析构用例。


- 迭代02复核: DUPLICATE。按值插件删除函数与按引用 typedef 不匹配，与 BUG-R64-002 同一 ABI 根因；R54 用例禁用，本轮仅静态判读。
- 迭代02依据: [逐条裁定与主代理修订](../../迭代02/缺陷裁定总表.md)。原记录保留作为历史，未声称产品已修复。
## 测试修订建议（仅报告，未改测试）

- 用例 R191MockerFixture.R191UftMocker_CoverTodayPreavailExitCancelBranches 的多头 T+1 / 昨仓平仓 / 撤单还原覆盖可保留。
- 删除 TM_LongT1 下直接注入 short trade 并期待 short 昨仓的段落。若补开空模式测试，TM_LongT1 下调用 stra_enter_short 应验证拒单且订单集不变；TM_Both 下可保留正常 short 的正向开平路径。
- 现有 P08UftOrderPosition 夹具将期货设为 TM_Both，参数守卫只覆盖未知合约与非正数量，没有验证不支持开空模式；因此补充 TM_LongT1 拒绝开空断言不会与已存在的模式夹具冲突。
