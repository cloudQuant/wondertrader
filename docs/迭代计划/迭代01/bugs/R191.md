## BUG-R191-001 插件工厂加载后 Mocker 析构在 `_StraFactInfo::~_StraFactInfo` 崩溃

- 状态: 待审核
- 严重度: 高（进程崩溃，SIGSEGV；公开配置加载本机构建插件即可触发）
- 位置:
  - `src/WtBtCore/UftMocker.h:243-247`（`_StraFactInfo::~_StraFactInfo` 调用 `_remover(_fact)`），
    成员 `_factory` 在 `UftMocker.h:249`；
  - `src/WtBtCore/CtaMocker.h:1011-1015`（同构），成员 `_factory` 在 `CtaMocker.h:1017`；
  - `src/WtBtCore/UftMocker.cpp:59-65`、`src/WtBtCore/CtaMocker.cpp:84-86` 的对象析构入口。
- 现象:
  - `init_uft_factory` / `init_cta_factory` 成功加载 `libWtUftStraFact.dylib` /
    `libWtCtaStraFact.dylib` 并创建工厂后，栈上 Mocker 离开作用域时，
    `_StraFactInfo` 析构无条件调用插件导出的 `deleteStrategyFact`（`_remover(_fact)`），
    进程在析构阶段 SIGSEGV，`[  OK  ]`/`[  PASSED  ]` 都不会打印。
  - Uft 侧即使配置里**没有 `strategy` 段**（`_strategy == NULL`）也会崩，
    说明崩溃点不是 `UftMocker::~UftMocker` 里的 `deleteStrategy`（那段被 `if(_strategy)` 保护），
    而是 `_factory` 成员的析构调用插件的 remover。
- 证据:
  - `build-cov/coverage/CoverageTests_btcore.R121UftMocker_R135ProbeMinimalDtor.log`：
    打印 `PROBE1 factory only, leaving scope` 后无 `PROBE1 survived`，退出码 `CRASH(139,sig=11)`；
    该用例只 `init_uft_factory`，没有创建策略。
  - `...R135ProbeStrategyNoCalls.log`：打印 `PROBE2 strategy created, leaving scope` 后崩溃；
  - `...R121UftMocker_PluginStrategyLifecycle.log`：V1-V12 全部打印完毕后崩溃；
  - `...R121CtaMocker_PluginStrategyEventDispatch.log`：C1-D7 全部打印完毕后崩溃。
  - 对照 `...R135ProbeDirectFactory.log`：直接 `dlopen`/`createStrategyFact`/`deleteStrategyFact`
    并手动删除工厂可以正常 `PASS`，说明插件导出符号本身可用，问题在 Mocker/工厂持有期
    与析构时机的组合。
- 复现步骤:
  1. 用本机构建产物 `build_x64/Debug/bin/WtUftRunner/libWtUftStraFact.dylib` 构造
     `UftMocker`，`init_uft_factory` 传合法 `module`（可不带 `strategy` 段）；
  2. 让 Mocker 作为栈对象离开作用域；
  3. 观察析构阶段 SIGSEGV。
  对应占位用例：`r191_mocker_residual_test.cpp` 的
  `DISABLED_R191Uft_PluginFactoryDestructorCrashes`。
- 期望:
  - `_StraFactInfo` 析构应先判空 `_remover`，并在调用插件 remover 前后保证模块仍加载；
    或者与 `_module_inst` 的释放顺序统一，避免在插件已失效/重复删除时调用 remover。
    无论根因在 Mocker 还是 Demo 插件的 `deleteStrategyFact`，公开 API 的正常作用域退出
    不应崩溃。
- 测试处理:
  - 本轮启用的插件用例（Uft #1/#2、Cta #3）用 `new` 创建 Mocker 后**故意不 delete**，
    让进程正常退出以留下 profraw；断言没有放宽。
  - 新增 `DISABLED_` 占位，启用即崩溃，故不进入门禁用例集。
- 建议:
  - 先确认 `_remover` 是否可能为 NULL、`deleteStrategyFact` 是否重复释放工厂，
    以及 `_module_inst` 是否在 `_factory` 析构前被 `free_library`；
  - 修复后把本轮三个插件用例改回栈对象，并恢复析构删策略行 `UftMocker.cpp:62-64` 的覆盖。
