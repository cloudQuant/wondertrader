## BUG-R55-001

- 状态: 待审核
- 严重级别: Minor
- 模块/文件: `src/Share/charconv.hpp` `UTF8toChar::init`（L85-98）/`~UTF8toChar`（L167-171）；`ChartoUTF8::init`（L257-270）/`~ChartoUTF8`（L341-345）
- 相关测试: `r55_codehelper_charconv_test.cpp: R55_charconv.utf8_helpers_handle_empty_and_null_inputs`
- 输入/前置条件: `UTF8toChar u(static_cast<const char*>(nullptr));`、`ChartoUTF8 c(static_cast<const char*>(nullptr));`
- 期望行为: 空指针分支显式设置 `needFree = false`，析构时的分支判断有确定值
- 实际行为: 空指针分支只把 `t_string` / `utf8_string` 置 0，`needFree` 从未初始化；析构函数读取未初始化的 `bool needFree`，属未定义行为
- 复现步骤: 以空指针构造任一对象并让其离开作用域；在 MemorySanitizer/Valgrind 下会报“conditional jump depends on uninitialised value”
- 影响范围: 所有把 `nullptr` 传给这两个工具类的调用点。当前指针本身是 NULL，`delete[] NULL` 在两条分支上都是 no-op，所以普通构建暂时不会崩溃；但这是可被优化器/消毒器放大的 UB，后续若把指针改成非空默认值就会变成非法释放
- 备注（是否阻塞覆盖率目标 / 建议的修复方向，不实施）: 不阻塞覆盖率。建议在构造函数初始化列表或 `init` 的两个空指针分支里补 `needFree = false`

## BUG-R55-002

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/Share/charconv.hpp` `EncodingHelper::isUtf8`（L635-669，判定条件在 L645）
- 相关测试: `r55_codehelper_charconv_test.cpp: R55_charconv.encoding_helper_two_byte_and_gbk_boundaries`（锁定实际 false）、`R55_charconv.DISABLED_two_byte_utf8_should_be_accepted`（期望行为，未启用）
- 输入/前置条件: `unsigned char data[] = {0xC2, 0xA2}`（U+00A2，合法 2 字节 UTF-8）；同理 `{0xC3, 0xA9}`（é）
- 期望行为: 返回 `true`（或至少继续扫描后续字节）
- 实际行为: `(num = preNUm(data[i])) > 2` 把 `num == 2` 排除在多字节分支之外，直接落到 `else { return false; }`，任何以 2 字节 UTF-8 开头的非 ASCII 文本都被判成非 UTF-8
- 复现步骤: `EncodingHelper::isUtf8(data, 2)`，输入 `C2 A2`，实际返回 `false`
- 影响范围: 编码探测会把仅含拉丁扩展/西里尔等 2 字节字符的 UTF-8 文本误判为 GBK，随后按 GBK 转码会产生乱码；`isGBK` 的成功返回又会强化误判
- 备注（是否阻塞覆盖率目标 / 建议的修复方向，不实施）: 不阻塞覆盖率。建议把条件改为 `num >= 2`（并对 `num > 6` 做非法前导校验）；修复后把启用用例的 `EXPECT_FALSE` 反转、删除 DISABLED 用例

## BUG-R55-003

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/Share/charconv.hpp` `EncodingHelper::isUtf8`（L635-669，续字节循环在 L653-660）
- 相关测试: 未编写可执行用例（触发即越界读，不能作为确定性启用用例）；本 lane 的 `encoding_helper_two_byte_and_gbk_boundaries` 只用完整序列
- 输入/前置条件: `unsigned char data[] = {0xE4, 0xB8}`（截断的 3 字节“中”）、`{0xF0, 0x9F, 0x98}`（截断的 4 字节 emoji）
- 期望行为: 在读取续字节前检查 `i + num - 1 < len`，截断序列返回 `false`
- 实际行为: `i++` 后直接进入 `for (j = 0; j < num - 1; j++)`，循环体只判断 `(data[i] & 0xc0) != 0x80`，没有 `i < len` 边界；`{E4,B8}` 会读取 `data[2]`（越界 1 字节），`{F0,9F,98}` 会读取 `data[3]`（越界 1 字节）
- 复现步骤: 用长度 2 的 vector 调用 `isUtf8`，在 AddressSanitizer 下报 heap-buffer-overflow；普通构建结果依赖越界字节的偶然值
- 影响范围: 任何把不完整/被截断的 UTF-8 片段送进编码探测的路径（网络分包、文件尾部读断、配置截断）都有越界读风险；与 BUG-L01-005 的 `isGBK` 越界读属同类但函数不同
- 备注（是否阻塞覆盖率目标 / 建议的修复方向，不实施）: 不阻塞覆盖率。建议在进入续字节循环前判 `i + (num - 1) <= len`，循环内也保留 `i < len` 保护
