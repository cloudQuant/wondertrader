## BUG-R72-001 UftMocker::stra_enum_position 在未装载策略时解引用空 `_strategy`（撤回）

- 编号: BUG-R72-001
- 状态: 已撤回（测试前提不属于已确认接口用法）
- 模块/文件/行: `src/WtBtCore/UftMocker.cpp:1030-1047`（循环体内的 `_strategy->on_position(...)`，L1041）
- 测试用例: `src/TestUnits/coverage/p03_btcore_mockers2/r72_hft_uft_paths_test.cpp`
  `R72HftUftPaths.DISABLED_UftEnumPositionWithoutStrategyDerefsNull`
- 源码事实: `_strategy` 默认置空，持仓非空时循环无条件调用 `_strategy->on_position(...)`；该空指针条件静态成立。
- 前提裁定: `IUftStraCtx.h:220-224` 将此方法定义为“枚举持仓，会通过 on_position 回调进来”，这是策略上下文向已装载策略回调的接口。仓内正常 UFT 回测装配（`WtBtRunner.cpp:146-148`）先调用 `init_uft_factory` 再注册/运行；未发现产品路径在无策略时调用该策略回调方法。
- 测试问题: `DISABLED_UftEnumPositionWithoutStrategyDerefsNull` 直接构造未装载策略的 `UftMocker`，再由测试代码调用策略上下文方法，不能证明这是受支持的外部用法；该用例本轮未运行。
- 结论: 空指针解引用的静态条件真实，但触发前提未经接口契约确认且与当前调用生命周期不符，因此撤回“合法公开用法下产品必崩”的缺陷主张。若产品需要支持无策略时外部调用，应先补充接口契约，再决定是否增加保护。

## BUG-R72-002 块数据回读忽略 `proc_block_data` 失败，按错误长度继续解析（合并）

- 编号: BUG-R72-002
- 状态: 已合并（重复于 BUG-R161-001）
- 模块/文件/行:
  - `src/WtBtCore/HisDataReplayer.cpp:3494-3503`（`cacheRawTicksFromCSV` 的 dsb 回读）
  - `src/WtBtCore/HisDataReplayer.cpp:3791-3807`（`cacheRawBarsFromCSV` 的 dsb 回读）
- 测试用例: 与本项同调用点的 `src/TestUnits/coverage/p03_btcore_mockers2/r161_btcore_edges_test.cpp` →
  `DISABLED_MalformedTickBlockTailBeyondLastItem`；该用例故意触发越界写，出于内存安全原因本轮未运行。
- 输入: 一个 `BlockHeaderV2`（version=`BLOCK_VERSION_CMP_V2`）中 `_size` 与
  `content.size() - sizeof(BlockHeaderV2)` 不等的 `.dsb` 文件。
- 期望: `proc_block_data` 返回 false 时，`cacheRaw*...` 应拒绝该文件，不继续拷贝或解析未解压内容。
- 实际: 两处调用都忽略返回值：
  - tick：`proc_block_data(filename.c_str(), content, false, false);` 后直接
    `tickcnt = content.size() / sizeof(WTSTickStruct)`；
  - bar：`proc_block_data(filename.c_str(), content, true, false);` 后直接
    `barcnt = content.size() / sizeof(WTSBarStruct)`。
  压缩块尺寸校验失败时 `content` 保持原始「块头 + 压缩字节」。调用点继续按结构体大小向下取整扩容，
  再按完整 `content.size()` 复制；文件长度余数不为零时会越过 vector 尾部写入。R161 已以 tick 和 bar
  两条路径、同一组调用点登记该内存破坏问题；错误内容被当结构体处理也是同一根因，不另计。
- 复现步骤:
- 修复方向: 按 BUG-R161-001 在两处调用点传播 `proc_block_data` 失败，并在 memcpy 前验证内容长度是结构体大小的整数倍。
- 证据边界: 源码可确认忽略 false、取整扩容和按原长 memcpy；具体越界幅度由文件尾余数决定。没有运行 R161 的 `DISABLED_` 用例，也没有 ASan/GuardMalloc 运行证据。
- 备注: 本 lane 的两条老版本块用例（`OldRawBarBlockIsConverted`、`OldRawTickBlockIsConverted`）
  走的是 `bOldVer` 成功分支，不触发本缺陷。

## BUG-R72-003 `proc_block_data` 对未压缩 V2 块只跳过 12 字节块头（撤回）

- 编号: BUG-R72-003
- 状态: 已撤回（RAW_V2 格式头长判断错误）
- 模块/文件/行: `src/WtBtCore/HisDataReplayer.cpp:48-61`（`bKeepHead=false` 的
  `content.erase(0, BLOCK_HEADER_SIZE)`）与 `126-135`（保留块头时的 resize/版本改写）
- 格式裁定: `BLOCK_VERSION_RAW_V2` 的未压缩文件使用 `BlockHeader`（12 字节）+ 原始结构体数组；`BlockHeaderV2` 中新增的 `_size` 注释限定为压缩后数据大小。`WtDataWriter::dump_day_data` 在新建及未压缩写回分支都写入 `BlockHeader`（`WtDataWriter.cpp:1942-1948,1997-2005`），不是 20 字节头。
- 实际: `proc_block_data` 对 RAW_V2 进入非压缩/非旧版分支，按 `BLOCK_HEADER_SIZE` 剥离 12 字节；与生产 RAW_V2 文件格式一致，行为正确。
- 结论: 原报告把压缩格式的 `BlockHeaderV2` 错套到未压缩 RAW_V2。以 `BlockHeaderV2(0x03)` 造输入不符合仓内生产格式，撤回此项；无需按 20 字节修改处理函数。

## BUG-R72-004 `get_tick_slice` 的 etime 晚于末笔时漏掉最后一笔

- 编号: BUG-R72-004
- 状态: 已确认（真实缺陷；源码与当前 binary 隔离复现一致）
- 严重级别: Major
- 模块/文件/行: `src/WtBtCore/HisDataReplayer.cpp:2470-2544`，尾后 `lower_bound` 分支在 L2504-L2507；共同切片端点计算在 L2530-L2539。
- 测试用例: `src/TestUnits/coverage/p03_btcore_mockers2/r72_replayer_tick_loader_test.cpp` → `R72ReplayerTickLoader.TickSliceCursorAndEtimeMatrix`，L89-L95。
- 输入: 内存 loader 提供 2020-01-02 09:30/09:31/09:32 三笔 tick，价格分别为 10.0/10.5/11.0；请求 `count=2, etime=202001021000`，截止时间晚于所有数据。
- 期望: 返回截止时间前最后两笔 `[10.5, 11.0]`。接口注释将 `etime` 定义为结束时间（`HisDataReplayer.h:836-842`），实现注释也说明要取截止时间前最后一笔（L2530-L2531）。
- 实际行为: 当前 binary 返回 `[10.0, 10.5]`，遗漏最后一笔 11.0。
- 源码因果: `lower_bound` 命中 `end()` 时将 `_cursor` 设为 `size()`；后续沿用 `eIdx = _cursor - 2`，三笔数据时端点落在下标 1，因此整段窗口偏早一笔。该分支未把“截止时间晚于末笔”表示为最后一笔之后的切片端点。
- 修复方向: 统一尾后命中与普通命中的端点语义，让 `etime` 晚于末笔时端点指向末项，再按 `count` 向前取；显式覆盖空数据、首项之前、精确边界和尾后边界，避免通过游标约定造成越界。
- 动态证据: 使用 `build-cov/build_x64/Debug/bin/TestUnits/CoverageTests_btcore`，从临时 cwd、独立 `LLVM_PROFILE_FILE` 运行 `--gtest_filter=R72ReplayerTickLoader.TickSliceCursorAndEtimeMatrix`（15 秒 alarm）；测试在 13 ms 内失败，两项断言分别显示期望 10.5、11.0，实际 10.0、10.5。测试源码和 binary 均为 2026-10-29 worker 更新后版本。
- 证据边界: 这是本地当前 binary 的单测复现与静态因果核对；未证明其他数据源/所有 cursor 状态或发布构建，也未运行完整回测验收。
- 区分: 此项属于 `get_tick_slice` 查询路径；p07 BUG-P07-001/005 属于 `getNextTickTime` 的回放游标路径，症状和调用点不同，不合并。
