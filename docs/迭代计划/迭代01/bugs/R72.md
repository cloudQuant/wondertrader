## BUG-R72-001 UftMocker::stra_enum_position 在未装载策略时解引用空 `_strategy`

- 编号: BUG-R72-001
- 状态: 待审核
- 模块/文件/行: `src/WtBtCore/UftMocker.cpp:1030-1047`（循环体内的 `_strategy->on_position(...)`，L1041）
- 测试用例: `src/TestUnits/coverage/p03_btcore_mockers2/r72_hft_uft_paths_test.cpp`
  `R72HftUftPaths.DISABLED_UftEnumPositionWithoutStrategyDerefsNull`
- 输入:
  1. `HisDataReplayer rp;`
  2. `UftMocker uft(&rp, "r72_uft_enum");`（不调用 `init_uft_factory`，因此 `_strategy == NULL`）
  3. `uft.on_trade(1u, "SSE.STK.000001", true, 0, 1.0, 10.0);` 让 `_pos_map` 非空
  4. `uft.stra_enum_position("");`
- 期望: 未装载策略时要么跳过回调，要么返回 0；与 `on_tick`/`on_init`/`on_order` 的 `if (_strategy)` 守卫一致。
- 实际: `stra_enum_position` 只检查 `_pos_map`，循环内无条件执行
  `_strategy->on_position(...)`；`_strategy == NULL` 时 SIGSEGV（必崩）。
- 复现步骤:
  1. 在覆盖率构建中启用上述 `DISABLED_` 用例；
  2. 运行 `CoverageTests_btcore --gtest_filter=R72HftUftPaths.DISABLED_UftEnumPositionWithoutStrategyDerefsNull`；
  3. 进程在 `stra_enum_position` 的 `_strategy->on_position` 处崩溃。
- 严重级别: 中（公开 API 在「不装载策略 DLL」的合法用法下崩溃；同族的
  `on_session_begin`/`on_session_end` 也是无条件解引用 `_strategy`，p08 已归档，未重复立案）
- 备注: 本 lane 的启用用例因此不调用 `stra_enum_position` / `handle_session_begin` / `handle_session_end`。

## BUG-R72-002 块数据回读忽略 `proc_block_data` 失败，按错误长度继续解析

- 编号: BUG-R72-002
- 状态: 待审核
- 模块/文件/行:
  - `src/WtBtCore/HisDataReplayer.cpp:3494-3503`（`cacheRawTicksFromCSV` 的 dsb 回读）
  - `src/WtBtCore/HisDataReplayer.cpp:3791-3807`（`cacheRawBarsFromCSV` 的 dsb 回读）
- 测试用例: 无启用用例（构造夹具时发现）。原因：需要一份通过 `content.size() >= sizeof(HisKlineBlockV2)` /
  `HisTickBlockV2` 前置检查、但 `BlockHeaderV2::_size` 与真实内容长度不一致的压缩块；当前仓库没有
  这种产物，伪造后继续解析会读出未定义字段，不能写成确定性断言。
- 输入: 一个 `BlockHeaderV2`（version=`BLOCK_VERSION_CMP_V2`）中 `_size` 与
  `content.size() - sizeof(BlockHeaderV2)` 不等的 `.dsb` 文件。
- 期望: `proc_block_data` 返回 false 时，`cacheRaw*...` 应返回 false（不装载），而不是把块头当行情。
- 实际: 两处调用都忽略返回值：
  - tick：`proc_block_data(filename.c_str(), content, false, false);` 后直接
    `tickcnt = content.size() / sizeof(WTSTickStruct)`；
  - bar：`proc_block_data(filename.c_str(), content, true, false);` 后直接
    `barcnt = content.size() / sizeof(WTSBarStruct)`。
  压缩块校验失败时 `content` 仍是「块头 + 压缩字节」，会被当成结构体数组 memcpy 进缓存；
  后续 `get_tick_slice`/`get_kline_slice` 读取的是块头字节伪装成的价格/日期。
- 复现步骤:
  1. 在临时 `<base>/his/day/SSE/` 或 `<base>/bin/ticks/` 写一个 `CMP_V2` 块，令
     `_size` 比真实压缩数据长度大 1；
  2. `mode=csv`，`prepare()` 后调用 `get_kline_slice` / `get_tick_slice`；
  3. 观察日志出现 `Size check failed`，但接口仍返回非空切片/缓存。
- 严重级别: 中（损坏文件会被静默装载为垃圾行情；无越界写，但有不可预期的读和错误回测结果）
- 备注: 本 lane 的两条老版本块用例（`OldRawBarBlockIsConverted`、`OldRawTickBlockIsConverted`）
  走的是 `bOldVer` 成功分支，不触发本缺陷。

## BUG-R72-003 `proc_block_data` 对未压缩 V2 块只跳过 12 字节块头

- 编号: BUG-R72-003
- 状态: 待审核
- 模块/文件/行: `src/WtBtCore/HisDataReplayer.cpp:48-61`（`bKeepHead=false` 的
  `content.erase(0, BLOCK_HEADER_SIZE)`）与 `126-135`（保留块头时的 resize/版本改写）
- 测试用例: 无（当前仓库未发现 `BLOCK_VERSION_RAW_V2` 的生产者；伪造该块后解析结果
  依赖块头 `_size` 字段被当作第一根 bar 的前 8 字节，不能写成确定性断言）
- 输入: `BlockHeaderV2`（`_version = BLOCK_VERSION_RAW_V2 = 0x03`，`_blk_flag` 合法）
  后直接跟 `WTSBarStruct[]`，`bKeepHead=false`
- 期望: 跳过完整的 `sizeof(BlockHeaderV2)`（20 字节）后再取 bar 数组
- 实际: `BlockHeader::is_compressed()` 与 `is_old_version()` 对 0x03 都为 false，
  代码走 `content.erase(0, BLOCK_HEADER_SIZE)`，而 `BLOCK_HEADER_SIZE` 是
  `sizeof(BlockHeader)`（12 字节）；`BlockHeaderV2::_size` 的 8 字节残留在数据前，
  整个 bar 数组向前错位 8 字节
- 复现步骤:
  1. 在临时 `<base>/his/day/SSE/000001.dsb` 写 `BlockHeaderV2(0x03) + 3*WTSBarStruct`；
  2. `mode=csv`、`prepare()` 后 `get_kline_slice("SSE.STK.000001","d1",3)`；
  3. 返回的 date/close 与写入值不一致（首根被 `_size` 字节污染）。
- 严重级别: 低（当前无该版本产物；一旦未来写出 RAW_V2 文件即静默错位）
- 备注: 本轮刻意不写该格式的启用用例，老版本块用例只覆盖 `BLOCK_VERSION_RAW`。

## 已知同族缺陷（仅引用，不重复立案）

  本 lane 的 SelMocker 用例因此不调用 `handle_replay_done`。

  的会话族 null 解引用记录；本 lane 的启用用例不进入这两个入口。

  从而让 `replayHftDatas` 走 etime break 成功臂。
