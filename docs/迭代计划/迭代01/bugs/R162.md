# R162 缺陷清单（第二十四波 · 主存储 + AD 读取/收盘边角）

## BUG-R162-003 AD K 线缓存增量更新前提前缩小请求数量

- 状态: 真实缺陷（本机独立测试复现）
- 严重级别: Major
- 位置: `src/WtDataStorageAD/WtDataReaderAD.cpp` 的 `readKlineSlice`：约 425 行在增量更新前将请求 `count` 缩为旧缓存大小，后续约 437 行才执行 `update_cache_from_lmdb`。
- 相关测试: `R162AdReaderTest.R162ReaderADMinuteBarsAppendFromLmdb`。测试直接按生产 LMDB 键和值格式写入数据，避免旧 fixture 中 writer 的未初始化 `_async_task`。
- 前提: 首次请求 count=10 读入 09:31 一根；随后向 LMDB 追加 09:32 一根，再以 count=10 请求截至 09:32 的分钟线。
- 期望: 返回按时间排列的两根已落库 K 线及其原始字段。
- 实际行为: 增量更新完成后返回切片只有一根 09:32，09:31 未返回。重建 `CoverageTests_adstorage` 后本机单例运行 FAIL；tick 重复读取对照在该次运行通过。
- 原因与修复: 依旧缓存长度提前截小 `count`，即使刷新后缓存有更多数据也未恢复原请求值。保留用户请求的数量，在完成 LMDB/实时缓存刷新及截止时间过滤后再按最终可用条数截取。另需同时审查 `lastBar` 引用在追加后被赋值的覆盖/失效问题（见 BUG-R155），两种问题的测试应分别隔离。
- 边界: 本次是独立 LMDB fixture 的本机路径，未验证其他存储后端或线上数据。

- 范围: `src/WtDataStorageAD/WtDataWriterAD.*`、`src/WtDataStorage/WtDataWriter.cpp`
- 只记录、不修改生产代码；会造成行为不确定或双重计数的输入只放在 `DISABLED_` 用例或仅静态登记。
- 关联用例: `src/TestUnits/coverage/p05_datastorage2/r162_ad_reader_lmdb_test.cpp`
- 复核日期: 2026-10-29
- 交叉引用（不重复主张）：BUG-P05-005、R4-BUG-01、R4-BUG-03。本文件两项均与既有登记
  重复，保留原编号供追溯，不作为新增独立缺陷计数。

## 重复复核（原 BUG-R162-001）：WtDataWriterAD::_async_task 未初始化

- 状态: 已合并（主编号 BUG-P05-005；R4-BUG-01 为同源记录）
- 严重级别: Major（未定义行为，执行模型不确定）
- 模块/文件/行:
  - 成员声明 `src/WtDataStorageAD/WtDataWriterAD.h:245`（`bool _async_task;` 无默认初值）
  - 构造列表 `src/WtDataStorageAD/WtDataWriterAD.cpp:55-66`（未列 `_async_task`）
  - `init` `src/WtDataStorageAD/WtDataWriterAD.cpp:73-104`（未赋值）
  - 消费点 `src/WtDataStorageAD/WtDataWriterAD.cpp:375`（`if(_async_task)` 决定 pushTask 同步执行还是入队）
- 分类: 已有同源问题，重复登记；代码位置与 BUG-P05-005 / R4-BUG-01 相同，不另计缺陷。
- 相关测试: `r162_ad_reader_lmdb_test.cpp` 中仍使用 writer 的测试通过公开 `writeTick` 触达
  `pushTask`；`WriterSink` 轮询不能令未初始化读取变得确定。`R162ReaderADMinuteBarsAppendFromLmdb` 已单独改为直接 LMDB 夹具，不再依赖 writer；其 reader 结果见 BUG-R162-003。
- 输入/前置条件: 任意 `WtDataWriterAD` 实例，调用 `writeTick`。
- 期望行为: 构造或 `init` 时把 `_async_task` 显式初始化为 `false`（或按配置赋值），
  保证同一份配置下执行模型稳定。
- 实际行为: 构造与 `init` 均未赋值，`pushTask` 读取未初始化的 `bool`，行为属于未定义行为；
  不应把它描述成可预测的“栈/堆残留随机切换”。队列创建和 `release()` 的 join 路径确实
  受该读取控制，但其具体运行结果不可由源码确定。
- 影响范围: 经 `writeTick` 等进入 `pushTask` 的 AD 写入调用存在未定义行为风险；本轮没有
  动态测量同步/异步比例、空读频率或线程回收结果。
- 修复方向: 在产品构造/初始化处给出明确执行模式，再以确定配置验证同步和异步路径。
  任何 writer 公开调用测试在产品状态初始化前都不能当作稳定的动态验收。此前的
  `DISABLED_`/writer 路径用例若要稳定验收，需待产品修复或提供受控配置入口后调整。
- 关联: BUG-P05-005、R4-BUG-01 已记录相同成员与消费点；本条不新增主张。

## 重复复核（原 BUG-R162-002）：同日 tick 合并日线时 vol/money 重复累加

- 状态: 已合并（主编号 R4-BUG-03）
- 严重级别: Major（日线成交量/成交额系统性偏高）
- 模块/文件/行:
  - `src/WtDataStorageAD/WtDataWriterAD.cpp:649-652`（`updateBarCache` 日线 else 分支）
- 分类: `R4-BUG-03` 已记录同一行的重复累加，不另计缺陷。
- 相关测试: `r162_ad_reader_lmdb_test.cpp::R162AdReaderTest.DISABLED_R162WriterADMergedDayBarVolumeIsDoubleCounted`
  当前为禁用用例；本轮未执行。其断言只覆盖 volume，不能证明 money 结果。
- 输入/前置条件:
  1. 同一合约（本用例 `SSE.600000`）同一交易日连续两笔 tick，`curTick->volume() == 1`；
  2. 第二笔 tick 与第一笔同 `trading_date`（走合并分支，而不是新日线分支）；
  3. 第三笔 tick 的 `trading_date` 进入下一交易日，触发上一日线 `pipeToDayBars`。
- 期望行为: 20240110 日线 `vol == 1 + 1 == 2`，`money == 两笔成交额之和`。
- 实际行为: 源码 `updateBarCache` 的日线合并分支有两组相同的 volume/money 累加语句；
  这是静态确认的重复计算。给定测试输入若确实进入该分支，公式预期为每笔只累计一次；
  但因为公开 `writeTick` 还会触达未初始化的 `_async_task`，本条禁用用例当前不能作为
  稳定动态证明。`R4-BUG-03` 的既有用例断言现有输出，不等于正确业务契约。
- 影响范围: 使用该 AD 写入器并进入同日合并分支时，源码会对后续 tick 重复累计量额；
  本轮未运行端到端数据验证，也未测量生产数据偏差。
- 修复方向: 去掉重复累加语句，并为日线 volume 与 money 分别建立按输入逐笔求和的期望值；
  确保测试 writer 的执行模式已被确定后再启用公开调用验收。
- 关联: R4-BUG-03 已在同一源位置登记，本条保留编号供追踪，不新增计数。
