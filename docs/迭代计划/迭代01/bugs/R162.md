## BUG-R162-001 WtDataWriterAD::_async_task 未初始化，写入是同步还是排队取决于栈/堆残留

- 状态: 待审核
- 严重级别: Major（未定义行为，执行模型不确定）
- 模块/文件/行:
  - 成员声明 `src/WtDataStorageAD/WtDataWriterAD.h:245`（`bool _async_task;` 无默认初值）
  - 构造列表 `src/WtDataStorageAD/WtDataWriterAD.cpp:55-66`（未列 `_async_task`）
  - `init` `src/WtDataStorageAD/WtDataWriterAD.cpp:73-104`（未赋值）
  - 消费点 `src/WtDataStorageAD/WtDataWriterAD.cpp:375`（`if(_async_task)` 决定 pushTask 同步执行还是入队）
- 相关测试: 无（UB 非确定，无法在不访问私有成员的前提下稳定复现）。本 lane 的 AD 用例
  一律用 `WriterSink` 计数轮询等待，因此无论 `_async_task` 为真为假都能继续。
- 输入/前置条件: 任意 `WtDataWriterAD` 实例，调用 `writeTick`。
- 期望行为: 构造或 `init` 时把 `_async_task` 显式初始化为 `false`（或按配置赋值），
  保证同一份配置下执行模型稳定。
- 实际行为: `_async_task` 从未初始化；`new` 出来的对象该字节可能是任意值。若为 true，
  `pushTask` 会把任务入队并惰性创建 `_task_thrd`；若为 false，则在本线程直接执行。
  同一程序在不同内存状态下可能表现不同，`release()` 是否 join 线程也随之不同。
- 复现步骤: 1) 构造 `WtDataWriterAD` 并 `init`；2) 在调试器观察 `_async_task` 字节；
  3) 重复构造/销毁，观察该字节随分配器残留变化（无需崩溃即可证明未初始化）。
- 影响范围: AD 写入链路的所有 `writeTick` 调用；测试侧若按同步假设立即读 LMDB 会偶发空读，
  实盘侧 `release()` 的线程回收行为也不确定。
- 备注: 建议在构造函数初始化列表补 `_async_task(false)`，或在 `init` 中按参数显式赋值；
  修复后本 lane 的轮询等待仍可保留（对两种模型都成立）。

## BUG-R162-002 同日 tick 合并日线时 vol/money 被累加两次

- 状态: 待审核
- 严重级别: Major（日线成交量/成交额系统性偏高）
- 模块/文件/行:
  - `src/WtDataStorageAD/WtDataWriterAD.cpp:649-652`（`updateBarCache` 日线 else 分支）
- 相关测试: `r162_ad_reader_lmdb_test.cpp::R162AdReaderTest.DISABLED_R162WriterADMergedDayBarVolumeIsDoubleCounted`
- 输入/前置条件:
  1. 同一合约（本用例 `SSE.600000`）同一交易日连续两笔 tick，`curTick->volume() == 1`；
  2. 第二笔 tick 与第一笔同 `trading_date`（走合并分支，而不是新日线分支）；
  3. 第三笔 tick 的 `trading_date` 进入下一交易日，触发上一日线 `pipeToDayBars`。
- 期望行为: 20240110 日线 `vol == 1 + 1 == 2`，`money == 两笔成交额之和`。
- 实际行为: 合并分支连续执行两次
  `newBar->vol += curTick->volume(); newBar->money += curTick->turnover();`
  （`WtDataWriterAD.cpp:649-650` 与 `651-652` 重复），日线 `vol == 3`、`money` 同样翻倍累加。
  分钟线分支（同函数 `:754-755`）只有一份累加，未受影响。
- 复现步骤: 1) 按上述三笔 tick 调用公开 `writeTick`；2) 用 `WtDataReaderAD::readKlineSlice`
  以 `KP_DAY` 读取 20240110；3) 断言 `bars[0].vol == 2.0` 会失败，实际为 `3.0`。
- 影响范围: 所有使用 AD 写入器、同一交易日有多笔 tick 的品种；日线成交量/成交额被按
  “同日后每笔 tick 多计一次”累积放大，与分钟线/逐笔数据不一致。
- 备注: 删除 `:651-652` 两行重复累加即可；修复后 `DISABLED_` 用例可改为启用。
