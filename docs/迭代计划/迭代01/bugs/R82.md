## BUG-R82-001 create_sel_context / create_hft_context 未检查所选引擎已初始化（仅跨环境类型调用时）

- 迭代02第二轮前状态（历史）: - 状态: 待环境契约确认（源码风险已核对；未动态复现）
- 状态: 已撤回（迭代02：NOT_BUG，原产品主张不成立）
- 严重级别: 条件性 Major（仅当 API 允许在一个 runner 中混用不同环境 context）
- 模块/文件:
  - `src/WtPorter/WtRtRunner.cpp:338-359`（`createSelContext` 直接使用 `_sel_engine`）
  - `src/WtPorter/WtRtRunner.cpp:321-336`（`createHftContext` 直接使用 `_hft_engine`）
  - `src/WtPorter/WtRtRunner.cpp:838-882`（`initEngine` 只 init 当前 `env.name` 对应的那一个引擎）
  - `src/WtCore/WtEngine.cpp:37-50`（构造函数未初始化 `_base_data_mgr/_hot_mgr/_data_mgr`）
- 源码链与适用前提:
  - `config()` 的 `initEngine()` 是「三选一」：`env.name=cta` 时只调用
    `_cta_engine.init(...)`，`_sel_engine`/`_hft_engine` 仍是默认构造状态；
  - 但 WtPorter 的 `create_sel_context` / `create_hft_context` 不检查当前 env，
    直接把 `&_sel_engine` / `&_hft_engine` 交给 `ExpSelContext` / `ExpHftContext`；
  - `WtEngine` 构造函数没有把 `_base_data_mgr`、`_hot_mgr`、`_data_mgr` 置空，
    因此这些引擎上的第一次取数就解引用未定义值。
  - 因此仅在先配置 `env.name=cta`、随后调用 `create_hft_context(...)` 这类**环境类型不匹配**的调用序列中，才会把未初始化引擎交给 context。若随后调用
    `hft_get_position`：`HftStraBaseCtx::stra_get_position` 先走
    `_engine->get_hot_mgr()`（WtHftEngine 的未初始化成员），随后
    `_trader->getPosition`；`hft_get_bars` 则走 `_base_data_mgr->getCommodity`。
- 相关测试与契约:
  - 本 lane 的 3 条真实上下文用例在创建 SEL/HFT 上下文之前，分别用
    `env=sel`、`env=hft` 重新 `config_porter` 一次，主动绕开本缺陷；
  - 这些用例不是反例测试：它们遵守每种 context 先配置对应 `env` 的前置条件。测试源码明确写出为何要重新配置，但不证明混用属于支持场景。
  - `WtPorter.h` 将三类 context 分成独立创建 API，没有明确说明能否跨环境创建；因此“混用是不支持输入”或“混用应被拒绝”仍需接口契约确认。当前测试没有动态命中过未初始化引擎。
- 输入:
  ```
  config_porter(<env={"name":"cta"}> 的完整配置, false);
  CtxHandler h = create_hft_context("x", "trd", false, 0);   // 返回非 0 句柄
  hft_get_position(h, "SHFE.au.2406", true);                 // 解引用未初始化 _hot_mgr
  ```
- 条件期望: 若跨环境 context 创建受支持，应在创建前确认该引擎已初始化，并安全拒绝；若不支持，应在导出 API/runner 入口明确拒绝不匹配的环境类型。仅把 `WtEngine` 指针设为 NULL 可避免未定义初值，但还需在访问点判空才能安全返回。
- 源码推演（非运行结果）: 不匹配的 context 创建路径目前返回非零句柄；后续部分引擎取数调用会读未初始化管理器指针。具体是否崩溃取决于未定义指针值和路径，本次未执行该输入。
- 候选验证步骤（未执行）:
  1. 以 `env.name="cta"` 配置 `WtRtRunner`（单例或堆实例均可）；
  2. 调用 `create_hft_context("x","trd",false,0)`；
  3. 调用 `hft_get_position(h,"SHFE.au.2406",true)` 或 `hft_get_bars(...)`。
- 影响: 只有宿主在同一 runner 上按不匹配环境类型创建 context 时才可能读未初始化指针；现有测试按环境分开配置。若该调用不在公开接口契约内，属于缺少早期拒绝/防御的健壮性问题，而非已确认的正常使用故障。
- 修复方向: 先明确 runner 是否只支持单一 `env.name`。若支持混用，为引擎初始化状态加明确标记并在对应 `create_*_context` 入口拒绝未初始化引擎；同时将管理器成员初始化为 `nullptr` 并对访问点做判空。若不支持混用，在 API 文档和入口报错中明确该限制。

## BUG-R82-002 initCtaStrategies 未检查策略创建结果，失败配置存在空指针解引用路径

- 状态: 待审核（源码静态确认；负向测试未执行）
- 严重级别: Major（配置中 active CTA 策略创建失败时）
- 模块/文件: `src/WtPorter/WtRtRunner.cpp:726-740`
  - `:735` `CtaStrategyPtr stra = _cta_mgr.createStrategy(name, id);`
  - `:736` `stra->self()->init(cfgItem->get("params"));`
  - 对照：`initHftStrategies` 在 `:812-814` 有 `if (stra == NULL) continue;`
- 现象:
  - `CtaStrategyMgr::createStrategy(name, id)` 在两类情况下返回空
    `std::shared_ptr<CtaStraWrapper>`：`name` 无法拆分为 factory/unit，或工厂名未注册（未加载/目录中没有相应 dylib）。
  - 工厂存在但其 `createStrategy(unitname, id)` 返回 NULL 时，manager 仍构造并返回非空 wrapper；此时 `stra->self()` 为 NULL。
  - `initCtaStrategies` 对空 wrapper 不做判断就调用 `stra->self()`；对非空 wrapper 的空 `self()` 也不检查，随后 `->init(...)` 同样可能空指针解引用。
- 相关测试与交叉引用:
  - 本 lane 的 `R82RunnerEdges.HftStrategyListAndEngineWithoutEnv` 只验证 HFT 分支
    的 `continue`（`stra == NULL` 安全）；
  - CTA 分支没有 R82 启用负向用例；跨 lane 的 `src/TestUnits/coverage/m_WtRunner/r28_runner_main_test.cpp::DISABLED_active_cta_entry_needs_real_factory_dir` 是相似输入，仍为禁用测试，本次未运行。不能据此写成已实际崩溃。
  - `BUG-R104-004` 在独立的 `WtRunner::initCtaStrategies` 有相同缺少判空模式；它与本条调用路径不同，保留本条并互相交叉引用。
- 输入:
  ```
  {"basefiles":{}, "env":{"name":"cta"}, "data":{},
   "bspolicy":"<存在的 actions.json>",
   "strategies":{"cta":[{"active":true,"id":"s1","name":"NoSuchFact.NoSuchStra"}]}}
  ```
- 期望: `createStrategy` 返回空时跳过该策略并记录
  `strategy factory/unit not found`，`config()` 仍可完成或返回 false。
- 源码推演（非运行结果）: `createStrategy` 返回空 `shared_ptr` 时，下一行对 `stra->self()` 解引用空指针；工厂存在但策略工厂返回 NULL 时，wrapper 本身非空而 `self()` 返回 NULL，随后 `->init` 同样没有守卫。本次未运行这些失败输入，也未观察到 SIGSEGV。
- 候选验证步骤（未执行）:
  1. `new WtRtRunner()`（堆上、不 delete）并 `init()`；
  2. 用上面的配置调用 `config(cfg, false)`；
  3. 源码路径推演会在 `initCtaStrategies` 对空对象/空策略指针调用成员函数；本次未运行该输入，不把崩溃作为动态观察结果。
- 影响: 配置包含 active CTA 项但策略名/工厂不可用、或工厂创建函数返回 NULL 时，配置路径存在空指针解引用；若不在外层隔离，通常会终止进程。此为源码风险，未动态验证。它与 HFT 分支 `if (stra == NULL) continue;` 的处理不同。
- 修复方向: 检查 `stra` 和 `stra->self()` 后再调用策略 `init`；失败时记录 factory/unit/id 并跳过或让 `config()` 返回失败，具体策略需统一到 API 的配置失败语义。
