# R82 缺陷清单（第十六波 · WtPorter / WtRtRunner 补测 lane）

> 只读生产代码，本文件只登记不修复；每条状态一律 `待审核`。
> 涉及用例见 [manifests/wave16/R82.md](../manifests/wave16/R82.md)。
> 不重复 R6/R13/R46/R69 已登记的同类项；文末列出交叉引用。

## BUG-R82-001 create_sel_context / create_hft_context 不校验对应引擎是否已初始化，跨 env 使用即解引用未初始化成员

- 状态: 待审核
- 严重级别: Major
- 模块/文件:
  - `src/WtPorter/WtRtRunner.cpp:338-359`（`createSelContext` 直接使用 `_sel_engine`）
  - `src/WtPorter/WtRtRunner.cpp:321-336`（`createHftContext` 直接使用 `_hft_engine`）
  - `src/WtPorter/WtRtRunner.cpp:838-882`（`initEngine` 只 init 当前 `env.name` 对应的那一个引擎）
  - `src/WtCore/WtEngine.cpp:37-50`（构造函数未初始化 `_base_data_mgr/_hot_mgr/_data_mgr`）
- 现象:
  - `config()` 的 `initEngine()` 是「三选一」：`env.name=cta` 时只调用
    `_cta_engine.init(...)`，`_sel_engine`/`_hft_engine` 仍是默认构造状态；
  - 但 WtPorter 的 `create_sel_context` / `create_hft_context` 不检查当前 env，
    直接把 `&_sel_engine` / `&_hft_engine` 交给 `ExpSelContext` / `ExpHftContext`；
  - `WtEngine` 构造函数没有把 `_base_data_mgr`、`_hot_mgr`、`_data_mgr` 置空，
    因此这些引擎上的第一次取数就解引用未定义值。
  - 例如 `env.name=cta` 后调用 `create_hft_context(...)`，再调用
    `hft_get_position`：`HftStraBaseCtx::stra_get_position` 先走
    `_engine->get_hot_mgr()`（WtHftEngine 的未初始化成员），随后
    `_trader->getPosition`；`hft_get_bars` 则走 `_base_data_mgr->getCommodity`。
- 相关测试:
  - 本 lane 的 3 条真实上下文用例在创建 SEL/HFT 上下文之前，分别用
    `env=sel`、`env=hft` 重新 `config_porter` 一次，主动绕开本缺陷；
  - 反向证据：若跳过该重配置，`sel_set_position` / `hft_get_position`
    在覆盖率构建里会命中未初始化成员（与 BUG-R13-001 的 `_trader` 野指针同族）。
- 输入:
  ```
  config_porter(<env={"name":"cta"}> 的完整配置, false);
  CtxHandler h = create_hft_context("x", "trd", false, 0);   // 返回非 0 句柄
  hft_get_position(h, "SHFE.au.2406", true);                 // 解引用未初始化 _hot_mgr
  ```
- 期望: `create_sel_context/create_hft_context` 在对应引擎未 `init()` 时返回 0
  并记录错误；或 `WtEngine` 构造时把三个管理器指针置空，让取数路径安全返回 0。
- 实际: 句柄创建成功；后续任意取数/下单/订阅入口都可能段错误或读到野指针。
- 复现步骤:
  1. 以 `env.name="cta"` 配置 `WtRtRunner`（单例或堆实例均可）；
  2. 调用 `create_hft_context("x","trd",false,0)`；
  3. 调用 `hft_get_position(h,"SHFE.au.2406",true)` 或 `hft_get_bars(...)`。
- 影响: 同一进程内切换/复用 PORTer 环境、或宿主先做 CTA 再创建 HFT/SEL 上下文时，
  轻则取到随机持仓/价格，重则崩溃；测试侧只能靠「每族 env 各 config 一次」规避。

## BUG-R82-002 initCtaStrategies 不检查 createStrategy 返回空，策略名写错或工厂未加载时启动即崩溃

- 状态: 待审核
- 严重级别: Major
- 模块/文件: `src/WtPorter/WtRtRunner.cpp:726-740`
  - `:735` `CtaStrategyPtr stra = _cta_mgr.createStrategy(name, id);`
  - `:736` `stra->self()->init(cfgItem->get("params"));`
  - 对照：`initHftStrategies` 在 `:812-814` 有 `if (stra == NULL) continue;`
- 现象:
  - `CtaStrategyMgr::createStrategy(name, id)` 在以下三种情况返回空
    `std::shared_ptr<CtaStraWrapper>`：
    1) `name` 不含 `.`（无法拆分工厂名/策略名）；
    2) 工厂名未注册（未 `loadFactories` 或目录里没有该 dylib）；
    3) 工厂存在但 `createStrategy(unitname, id)` 返回 NULL（策略名写错）。
  - `initCtaStrategies` 对空指针不做判断，直接 `stra->self()`；
  - 即使 wrapper 非空，`self()` 也可能返回 NULL（情况 3），随后
    `->init(...)` 仍然是空指针解引用。
- 相关测试:
  - 本 lane 的 `R82RunnerEdges.HftStrategyListAndEngineWithoutEnv` 只验证 HFT 分支
    的 `continue`（`stra == NULL` 安全）；
  - CTA 分支因会稳定崩溃，未写启用用例（同 R46/R69 的「崩溃面 DISABLED」口径）。
- 输入:
  ```
  {"basefiles":{}, "env":{"name":"cta"}, "data":{},
   "bspolicy":"<存在的 actions.json>",
   "strategies":{"cta":[{"active":true,"id":"s1","name":"NoSuchFact.NoSuchStra"}]}}
  ```
- 期望: `createStrategy` 返回空时跳过该策略并记录
  `strategy factory/unit not found`，`config()` 仍可完成或返回 false。
- 实际: 在 `stra->self()->init(...)` 处空指针解引用；`-DCOVERAGE` 构建里是
  SIGSEGV（`catch(...)` 抓不到），整个进程退出。
- 复现步骤:
  1. `new WtRtRunner()`（堆上、不 delete）并 `init()`；
  2. 用上面的配置调用 `config(cfg, false)`；
  3. 进程在 `initCtaStrategies` 内崩溃。
- 影响: 策略名拼写错误、工厂 dylib 未部署、或 `active=true` 但工厂加载失败时，
  实盘/回测进程直接崩溃而不是给出可读错误；与 `initHftStrategies` 的防御口径不一致。

## 3. 交叉引用（不重复立案）

- `BUG-R6-001/002`：`WtRtRunner::config` 对 `_config`/`basefiles` 无 NULL 守卫。
  本 lane 的所有 config 用例都提供 `basefiles`，未新增崩溃证据。
- `BUG-R6-003`：`createExtParser` 未 config 即解引用 `_engine`；本 lane 只在
  已配置 engine 后调用（用例 4）。
- `BUG-R6-006`：`WTSLogger::stop` 的进程级静默；本 lane 的 `release_porter`
  用例固定放在文件最后（用例 9）。
- `BUG-R46-001`：两个 runner 构造列表漏初始化；本 lane 的堆实例一律 new 后不 delete。
- `BUG-R46-002` / `BUG-R69-003`：config 忽略 `initEngine()` / `initDataMgr()` 返回值；
  本 lane 用 `R82RunnerEdges.HftStrategyListAndEngineWithoutEnv` 与
  `R82RunnerEdges.ConfigFailureArmsAcrossSections` 取样，不重复立案。
- `BUG-R69-001`：`WTSHotMgr::getHotTags` 的 static 缓存；本 lane 只用它触达
  `WtRtRunner.cpp:572` 的 `continue`，不对 hotCode 回填结果做断言。
- `BUG-R69-002`：`initSelStrategies` 无调用点；本 lane 不写该函数的用例。
- `BUG-R13-001`：HFT 未绑定 `_trader` 时的野指针；本 lane 的 HFT 用例显式绑定
  一个已入表的 `TraderAdapter`，规避该缺陷。
