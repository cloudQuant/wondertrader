## 已排除的候选（初看像产品缺陷，复核后为测试侧）

1. **R66 首笔 tick 不写价格 / 不推进平台时间**（6 条中的 #1、#4、#5）
   - 初看：`on_tick` 收到行情后 `get_cur_price` 仍为 0，疑似丢行情。
   - 复核：三个 ticker 的 `on_tick` 在 `_cur_pos == 0` 时只记录分钟位
     （`WtCtaTicker.cpp:110-114`、`WtHftTicker.cpp:102-106`、`WtSelTicker.cpp:105-109`），
     设计上首笔不分发；实时链路中策略行情由引擎 `handle_push_quote` 另行分发。
     原用例把价格断言放在首笔之后，属期望位置错误，已移到真正走 `trigger_price`
     的后续 tick。
2. **R66 小节末用例 `get_min_time` 停在 900**（#2、#3、#6）
   - 初看：15:00 行情未推进平台时间，疑似 `isLastOfSection` 处理缺陷。
   - 复核：用例的 `actiontime` 写成 8 位 `14590000`/`15000000`，按 HHMMSSmmm 解析为
     01:45/01:50，落在 900-1500 之外；`WTSSessionInfo::timeToMinutes` 返回
     `INVALID_UINT32`（`WTSSessionInfo.hpp:144-189`）后分钟回绕，ticker 走的是
     `_cur_pos==0` 支。改为 9 位后行为完全符合源码。
3. **R67 日线复权 tick 代码未剥离后缀**（#7）
   - 初看：`simTicks` 日线分支未按复权码剥离末位，疑似产品缺陷。
   - 复核：用例把复权后缀写成 `Q`，而 `CodeHelper` 定义的是 `-`/`+`
     （`CodeHelper.hpp:27-37`），`extractStdCode` 只识别这两个字符
     （`CodeHelper.hpp:629-635`）。改用 `SSE.STK.600000-` 后
     `HisDataReplayer.cpp:1341-1342` 的剥离分支按预期执行。
4. **R67 淘汰后重装返回 NULL**（#8）
   - 初看：`cache_clear_days` 淘汰后 `get_kline_slice` 为 NULL，疑似淘汰逻辑破坏了缓存。
   - 复核：`check_cache_days` 确实在首个 `session_begin` 淘汰了非主K线
     （`HisDataReplayer.cpp:4607-4634`）；但原用例在 `run()` 结束后才重装，此时
     `_cur_tdate` 已越过 B 的最后一根日线，`get_kline_slice` 首次定位的
     `lower_bound` 落到 end 后按契约返回 NULL（`HisDataReplayer.cpp:2396-2409`）。
     已改为在第二个 `session_begin`（淘汰之后、当日 `check_cache_days` 之前）重装，
     并断言 loader 调用次数 1 -> 2。产品行为自洽，不是缓存损坏。
5. **R68 两条用例 `cfg==NULL`**（#9、#10）
   - 初看：`WTSCfgLoader::load_from_file` 对合法临时路径返回 NULL，疑似加载器缺陷。
   - 复核：JSON 由 raw literal 拼接，第一段以 `)"` 结束而非 `)JSON"`，整段
     `" + path + "` 文本被吞进一个字面量，实际写入文件的内容不是合法 JSON。
     改为显式转义字符串后解析正常；加载器对非法 JSON 返回 NULL 的行为
     （`WTSCfgLoader.cpp:231-256`）符合契约。
