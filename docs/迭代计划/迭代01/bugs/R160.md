## BUG-R160-001 EventNotifier 的订单通知 retain 后不 release

- 状态: 待审核
- 位置: `src/WtCore/EventNotifier.cpp:214-230`（`notify(const char*, uint32_t, const char*, WTSOrderInfo*)`）
- 证据: 第 221 行 `ordInfo->retain();`，post 的 lambda 在第 222-227 行只做
  `orderToJson` + `_publisher`，没有对应的 `ordInfo->release();`；同一文件第
  197-212 行的成交通知 lambda 末尾有 `trdInfo->release();`。
- 影响: 每推送一笔委托回报泄漏一个 `WTSOrderInfo` 引用；长期运行的通知进程
  内存单调增长。R41/R120 用例每次只发一笔，未暴露为崩溃。
- 建议: 在订单 lambda 末尾补 `ordInfo->release();`，与成交 lambda 对称。
- 用例关系: `r160_event_notifier_test.cpp` 只发一笔订单（覆盖发布体），
  不放大泄漏；未新增 DISABLED_ 用例。

## BUG-R160-002 EventNotifier 以单参函数指针调用双参 create_server

- 状态: 待审核
- 位置: `src/WtCore/EventNotifier.h:18`、`src/WtCore/EventNotifier.cpp:94`
- 证据: 头文件定义
  `typedef unsigned long(*FuncCreateMQServer)(const char*);`
  而 `src/WtMsgQue/WtMsgQue.h:32` 的导出是
  `EXPORT_FLAG WtUInt32 create_server(const char* url, bool confirm);`。
  `EventNotifier::init()` 第 94 行通过该函数指针只传 url 调用。
- 影响: 未定义行为。arm64 上第二个参数寄存器是调用点残留值，`confirm`
  实际为随机 true/false；若为 true，`MQServer::publish` 在无连接时会走确认/
  等待分支，发布行为依赖寄存器垃圾。当前用例能过属偶然。
- 建议: 把 typedef 改为 `(const char*, bool)` 并显式传 `false`（与
  `WtMsgQue` 的默认语义一致），或改调带确认参数的导出。
- 用例关系: 本轮 `r160_event_notifier_test.cpp` 只使用本地 inproc 端点，
  不断言 confirm 语义；未新增 DISABLED_ 用例。

## BUG-R160-003 WtHftRtTicker 自动闭合后把 _time 写成 HHMM，下一轮误判为 0 点

- 状态: 待审核
- 位置: `src/WtCore/WtHftTicker.cpp:175、:189、:202-216`
- 证据: 第 175 行用 `_time / 100000` 取 HHMM（`_time` 约定为 HHMMSSmmm）；
  第 189 行在自动闭合分支把 `_time = thisMin;`，而 `thisMin` 来自
  `minuteToTime()`，只有 HHMM（如 1459，没有秒/毫秒）。下一轮
  `1459 / 100000 == 0`，`isInTradingTime(0, true)` 通常为假，线程进入第
  219-248 行的休市 else 分支并 sleep 10 秒；此后 `_time` 一直是 0/HHMM，
  自动闭合不再按分钟推进。
- 影响: 依赖本地时钟的分钟闭合只生效一次；后续分钟必须等行情 tick 才能闭合，
  收盘强平/会话结束可能延迟。`run()` 的 10 秒 sleep 还会拖慢 `stop()` 的 join。
- 建议: 自动闭合分支保留 `_time` 的 HHMMSSmmm 语义（例如只改
  `_date/_cur_pos`，或写 `thisMin * 100000`），并单独维护给
  `set_date_time` 的分钟值。
- 用例关系: `r160_hft_ticker_test.cpp` 把会话设为 00:00-03:59，使
  `isInTradingTime(0)` 仍为真，从而在覆盖线程体的同时避开 10 秒 sleep；
  未新增 DISABLED_ 用例。

## BUG-R160-004 WtDtMgr 后复权 tick 缓存未检查 readTickSlice 返回 NULL

- 状态: 待审核
- 位置: `src/WtCore/WtDtMgr.cpp:301-314`
- 证据: `WTSTickSlice* slice = _reader->readTickSlice(...);` 之后立即
  `ayTicks.resize(slice->size());` 与 `slice->get_block_counts()`，没有
  `slice == NULL` 检查。`IDataReader::readTickSlice` 在无数据时返回 NULL
  （WtDataStorage/AD 的空库路径即如此，参见 BUG-R73-001）。
- 影响: 对不存在历史 tick 的合约请求后复权切片时，空指针解引用崩溃；该分支
  只有在 `_ticks_adjusted` 尚未建立时才进入，首查最危险。
- 建议: 读取后判空并返回 NULL（或把空切片当作 0 条缓存）。
- 用例关系: `r160_dtmgr_test.cpp` 的替身 reader 在 HFQ 路径始终返回 3 根
  tick，专门覆盖缓存/回退逻辑；不触发空指针，未新增 DISABLED_ 用例。
