## BUG-R64-001 · `WTSHotMgr::isCustomHot` 未知品种分支 `return "";` 在 bool 返回值下恒为 true

- 状态: 待审核
- 严重级别: Major（静默错误结果，未知品种被误判为主力）
- 模块/文件: `src/WTSTools/WTSHotMgr.cpp:358-405`（关键行 `:383-388`）
- 相关测试: `src/TestUnits/coverage/l02_wtstools_mq/r56_hotmgr_test.cpp`
  → `R56HotMgr.DISABLED_UnknownProductIsNotHot`（原红清单第 155 行断言）
- 输入/前置条件: 已 `loadHots` 登记 `SHFE.rb` 的换月规则（tag=`HOT`）；
  查询已知标签 + 未登记品种：`m_mgr.isHot("DCE", "i2405", 20240115)`
- 期望行为: 返回 `false`（`DCE.i` 不在任何换月规则中，不是主力）
- 实际行为: `isCustomHot` 的 `m_mapCustRules->get(tag)` / `prodMap->get(fullPid)` 落空分支
  写的是 `return "";`；函数返回类型是 `bool`，空串字面量的指针非空，
  隐式转换为 `true`。因此未知品种被当成主力，`isHot` 返回 `true`
- 复现: R64 manifest 记载启用该 DISABLED 用例后的结果：
  `Value of: m_mgr.isHot("DCE", "i2405", 20240115) Actual: true Expected: false`；本次复核未重跑。
- 影响: 上层用 `isHot` 判断「某合约是否为主力」时，任何未登记品种都会被误判；
  行情订阅、主力过滤、回放选择都可能把非主力合约纳入。该分支无日志，完全静默
- 备注: 修复方向是把两处 `return "";` 改为 `return false;`（同类函数
  `getCustomRawCode/getPrevCustomRawCode` 返回 `const char*`，那里的 `""` 是正确的）。
  `isHot` 对**未登记 tag** 的 `curHotCodes.empty()` 早退（`:361-363`）本身正常，
  本缺陷只影响「已知 tag + 未知品种」

## BUG-R64-002 · `UftStrategyMgr` 析构用错签名的 `deleteStrategyFact`，释放工厂时 SIGSEGV

- 状态: 待审核
- 严重级别: Blocker（进程崩溃，发生在正常关停路径）
- 模块/文件:
  - `src/Includes/UftStrategyDefs.h:207`：`typedef void(*FuncDeleteUftStraFact)(IUftStrategyFact* &fact);`
  - `src/WtUftStraFact/WtUftStraFact.cpp:43-47`：插件导出
    `void deleteStrategyFact(IUftStrategyFact* fact)`（**按值**）
  - `src/WtUftCore/UftStrategyMgr.cpp:76`：把插件符号强转为上面的函数指针类型
  - `src/WtUftCore/UftStrategyMgr.h:140-144`：`~StraFactInfo()` 执行 `_remover(_fact)`
- 相关测试: `src/TestUnits/coverage/q04_uftcore3/r54_uftcore_guards_test.cpp`
  → `R54StraMgr.DISABLED_manager_destructor_releases_factory_with_mismatched_abi`
- 输入/前置条件: 用真实构建产物 `libWtUftStraFact.dylib` 调用
  `UftStrategyMgr::loadFactories`，随后让 manager 正常析构（无需创建任何策略）
- 期望行为: manager 析构时把 `_fact` 指向的工厂对象交给插件释放，进程正常退出
- 实际行为: `FuncDeleteUftStraFact` 声明参数为 `IUftStrategyFact*&`，调用
  `_remover(_fact)` 时传入的是 `_fact` **成员的地址**；插件按值接收后把该地址
  当作工厂指针执行 `delete fact`，即对 manager 内部的指针成员做 `free`，
  属于未定义行为。R64 manifest 记录该执行路径 rc=139；本次复核未重跑。
- 复现: R64 manifest 记载启用上述 DISABLED 用例，`ASSERT_TRUE(mgr.loadFactories(...))` 之后
  作用域结束即崩溃。另用「只 loadFactories、不 createStrategy」的最小探针
  同样崩溃；这是 manifest 记录的动态证据。源码 typedef 与插件导出签名不匹配，足以确认调用约定错误；测试没有真实交易或生产 runner 生命周期。
- 影响: 任何加载了真实 UFT 策略工厂的进程，在 `UftStrategyMgr` 析构（Runner 退出）
  时会沿该析构路径触发错误调用；manifest 的本地构建产物报告在此处崩溃。此结论限于通过该按值 ABI 的 UFT 插件成功加载且 remover 可调用的配置。
  同型 `*&` 声明还出现在 `CtaStrategyDefs.h:130`、`HftStrategyDefs.h:164`、
  `SelStrategyDefs.h:119`、`ExecuteDefs.h:282`、`RiskMonDefs.h:157` 等。
  当前源码只找到 UFT/CTA/HFT 内置插件的对应 `deleteStrategyFact` 按值实现；Sel、Execute、RiskMon 的插件实现未在本仓库中找到，不能据此断言它们均不匹配。R191-001 记录 UftMocker/同类 CTA Mocker 的析构调用，和本条共享 UFT ABI 根因，但调用持有者不同；建议保留本条 manager 路径证据并在总账合并根因。
- 备注: 修复方向是让 typedef 与真实插件符号签名一致。对当前已检索到的 UFT/CTA/HFT 内置插件，按值
  `void(*)(IUftStrategyFact*)` 与 UFT 实现一致；CTA/HFT 应使用各自接口类型。其他类型应先盘点其导出签名。若保留 `*&`，需同步改
  各插件导出签名，并保证传入/写回规则一致。无论哪种方案，
  `~StraFactInfo` 都应在 `_remover` 非空时才调用
