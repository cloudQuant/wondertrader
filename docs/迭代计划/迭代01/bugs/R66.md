## BUG-R66-001 `EventNotifier::init` 重复调用覆盖 `_mq_sid`，旧 MQ server 句柄丢失

- 状态: 待审核
- 严重级别: 低（长时间运行/重复初始化场景的句柄与内存泄漏）
- 模块/文件: WtCore / `src/WtCore/EventNotifier.cpp:58-112`（第 94 行 `_mq_sid = _creator(...)`）
- 相关测试: `r66_event_notifier_test.cpp` 的 `R66ActiveNotifierRepeatedInitKeepsWorker`
- 输入:
  - 同一个 `EventNotifier notifier` 先后用两份配置 `{"active":true,"url":"inproc://r66_first_<pid>"}`
    与 `{"active":true,"url":"inproc://r66_second_<pid>"}` 调用 `init()`；
  - 两次 `init` 之间不析构 notifier。
- 期望: 第二次 `init` 应拒绝重复初始化，或先 `_remover(_mq_sid)` 销毁旧 server 再创建新 server；
  两次返回 true 时也只能有一个有效 server 句柄被最终回收。
- 实际: 第二次 `init` 直接执行 `_mq_sid = _creator(_url.c_str())`，第一次创建的 server id
  被覆盖；析构函数只在 `_remover && _mq_sid != 0` 时销毁最后一条（第 54-55 行），
  第一个 server 永远不会被 destroy。`_worker` 因已存在而不再新建（第 98 行），
  旧 server 的接收/发布资源与句柄随进程存活泄漏。
- 复现步骤:
  1. 定位到 `libWtMsgQue`（本机 `build-cov/build_x64/Debug/bin/libWtMsgQue.dylib`），
     设置 `WtHelper::setInstDir`；
  2. 构造 notifier，用 URL A 调 `init`，再用 URL B 调 `init`，两次都返回 true；
  3. 析构 notifier，观察只有 URL B 的 server 被 `destroy_server`，URL A 的 server 未回收
     （可用 WtMsgQue 的 server 计数或内存/句柄观察）。
- 影响: 宿主若因配置热重载、重连流程对同一 notifier 重复 `init`，会累积 MQ server
  句柄/线程/共享内存，且旧通道仍在接收消息；属于资源泄漏而非立即崩溃，故定级低。
