- 输入/前置条件: 任意 Hft 策略上下文；先 `stra_get_price(code)`，或 `do_set_position(code, qty, 0.0)`。

- 影响: 确认有一个未使用缓存和不可达命中分支；若业务要求零价代表“使用最新价”，当前零价回退实现才构成功能问题。

## BUG-R81-002 — Cta 条件单恢复/触发的固定名称表未校验枚举范围，非法 JSON 会越界读

- 文件: `src/WtCore/CtaStraBaseCtx.cpp`
- 位置: `load_data` L436-445（`condInfo._alg = (WTSCompareType)cItem["alg"].GetUint();`、`condInfo._action = (char)cItem["action"].GetUint();`，随后 L444-445 以 `ACTION_NAMES[...]`、`CMP_ALG_NAMES[...]` 下标访问）；`on_tick` L860-861 同样以动作/算法值索引名称表。
- 输入/前置条件: 策略数据 `stradata/<name>.json` 的 `conditions.items.<code>[].alg` 或 `.action` 超出 `CMP_ALG_NAMES`（5 项，0-4）/`ACTION_NAMES`（5 项，0-4）的范围，例如 `action=99`。
- 输入契约: 策略状态 JSON 的 `alg/action` 合法值范围没有在本文件能找到的接口说明中明确。以下结论只对可解析且枚举值超界的持久化输入成立，是否属于产品缺陷需确认策略数据是否视为不可信/可损坏输入。
- 源码证据: `load_data` 将 JSON 数值直接转成枚举/`char`，再对 5 项名称表索引；超界值会越界读。`on_tick` 只有比较算法匹配后才取名称：非法 `alg` 会走比较 switch 的 `default`、保持 `isMatched=false`，不会走该日志索引；合法 `alg` 配上非法 `action` 则可能在命中后的日志访问越界 `ACTION_NAMES`。
- 测试边界: R71 `TickConditionsCoverAllAlgorithmsAndActions` 原先在 JSON 中注入 `action=99`，`on_init()` 的恢复日志会越界；现已去除非法动作，补全合法持仓 `details`，并以五种合法动作和算法单例运行 PASS。它不验证非法动作。R81 `ConditionAlgorithmsActionsAndNoMatchCode` 用测试子类注入 `alg=99`，只验证比较 switch 的 default 不产生信号；没有验证 JSON 恢复边界或 `action` 越界。未运行 ASan 或非法动作路径。
- 期望/修复方向: 若格式要求容忍无效/损坏值，在写入 `_condtions` 和所有日志索引前分别校验 `alg/action` 范围，拒绝或跳过记录并给出诊断；若格式契约保证范围，则补充契约并让测试只输入合法值。不要通过将测试输入改为默认枚举来宣称已覆盖非法持久化值。
- 影响: 对超出格式范围但仍可解析的条件单 JSON，当前恢复路径有未定义行为；尚无证据表明合法生成文件会产生该输入。
- 分级: 条件性 S（确认接受超界枚举输入时；否则为输入校验观察项）
- 状态: 待输入契约确认（静态风险已核对；未动态复现）
