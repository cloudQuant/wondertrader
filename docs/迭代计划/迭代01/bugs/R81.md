## BUG-R81-001 — HftStraBaseCtx 的 `_price_map` 从不写入，价格缓存分支为死代码

- 文件: `src/WtCore/HftStraBaseCtx.cpp`
- 位置: `stra_get_price` L687-694（`_price_map.find` 命中分支 L690-691）；`do_set_position` L789-790（`price==0` 时读 `_price_map`）。
- 输入/前置条件: 任意 Hft 策略上下文；先 `stra_get_price(code)`，或 `do_set_position(code, qty, 0.0)`。
- 期望行为: Hft 上下文应在行情回调（`on_tick` 或 Hft 引擎推送）中维护自己的最新价缓存，使 `stra_get_price` 优先返回上下文缓存；`price==0` 的 `do_set_position` 应能取到该合约最新价。
- 实际行为: 全仓库对 `HftStraBaseCtx::_price_map` 只有读（本文件 L689/L790），没有任何写点；`stra_get_price` 的缓存命中分支永远不可达，只能落到 `_engine->get_cur_price(stdCode)`。若以 `price==0` 调 `do_set_position`，成交价会取到 map 默认值 0（`on_trade` 当前总是传真实价，故实盘主路径未暴露）。
- 复现步骤: 构造 `HftStraBaseCtx`，先 `on_tick(code, tick)` 再 `stra_get_price(code)`，返回值来自 `WtEngine::get_cur_price` 而非上下文缓存；对该上下文无法触发 L690-691。
- 影响: 覆盖率上形成 1 行不可达分支；若后续新增 `do_set_position(..., 0.0)` 调用方，会以 0 价记账。
- 分级: B
- 状态: 待审核

## BUG-R81-002 — Cta 条件单恢复/触发的固定名称表未校验枚举范围，非法 JSON 会越界读

- 文件: `src/WtCore/CtaStraBaseCtx.cpp`
- 位置: `load_data` L436-445（`condInfo._alg = (WTSCompareType)cItem["alg"].GetUint();`、`condInfo._action = (char)cItem["action"].GetUint();`，随后 L444-445 以 `ACTION_NAMES[...]`、`CMP_ALG_NAMES[...]` 下标访问）；`on_tick` L860-861 同样以动作/算法值索引名称表。
- 输入/前置条件: 策略数据 `stradata/<name>.json` 的 `conditions.items.<code>[].alg` 或 `.action` 超出 `CMP_ALG_NAMES`（5 项，0-4）/`ACTION_NAMES`（5 项，0-4）的范围，例如 `action=99`。
- 期望行为: 对非法 `alg/action` 做范围校验：忽略该条条件单并记日志，或夹到合法枚举。
- 实际行为: `load_data` 直接按非法值索引两个 5 元素 `const char*[]`，读取数组边界外指针并 `fmt` 输出，属未定义行为；`on_tick` 在条件命中后的日志也有同样问题。既有 R71 用例曾以 `action=99` 触发该路径，本 lane 为避免 UB 改为默认枚举并在测试侧注入非法 `alg` 覆盖 `switch default`。
- 复现步骤: 写入 `{"conditions":{"settime":0,"items":{"SHFE.rb.2510":[{"usertag":"x","field":0,"alg":0,"target":3500,"qty":1,"action":99}]}}}`，调用 `on_init()`；在 ASan 构建下可观察到全局数组越界读。
- 影响: 恶意/损坏的策略状态文件可导致越界读（轻则日志乱码，重则崩溃）；同时使 `switch` 的 `default` 动作分支无法通过正常输入覆盖。
- 分级: B
- 状态: 待审核
