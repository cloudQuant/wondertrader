## BUG-R103-001 TraderMocker 收到零长度 UDP 数据报后不再重新挂起 UDP 接收

- 编号: BUG-R103-001
- 状态: 源码缺陷成立；现有定向测试在空包后的异步回报断言失败，未直接断言后续 tick
- 模块/文件/行: `src/TraderMocker/TraderMocker.cpp:935-962`，
  重点是 `950-951`（`if (_terminated || bytes_transferred <= 0) return;`）
  与 `955-960`（仅在正常路径重新 `async_receive_from`）
- 相关测试: `src/TestUnits/coverage/t_TraderMocker/r103_mocker_udp_packet_test.cpp`
  `R103Mocker_UdpUnknownTickAndEmptyDatagram`
- 输入/前置条件:
  1. `init(cfg)`（`udp_port` 为任意本地端口）+ `connect()`；
  2. 向该端口发送一个长度为 0 的 UDP 数据报（`sendto(fd, "", 0, ...)`）；
  3. 之后再发送任意合法 `UDP_MSG_PUSHTICK` 包。
- 期望行为: 0 字节数据报应跳过 `extract_buffer()`，但仍重新挂起 `async_receive_from`；之后的合法 tick
  应继续进入 `extract_buffer()`。
- 证据/复核: `handle_read` 在 `bytes_transferred <= 0` 时直接 `return`，重挂接收只在后续 `955-960`，
  因此空数据报完成当前 socket receive 后不会再挂起读操作。测试 helper 的 `send_udp(port, "", 0)`
  以 `sendto` 返回 0 与 len 0 相等作为成功（`r103_mocker_common.h:356-370`）。本轮运行
  `LLVM_PROFILE_FILE=/tmp/R103-%p.profraw build-cov/build_x64/Debug/bin/TestUnits/CoverageTests_t_TraderMocker --gtest_filter='*R103Mocker_UdpUnknownTickAndEmptyDatagram'`
  得到 FAIL：空包前的 `queryAccount()` 回报已收到；空包后再次调用 `queryAccount()`，测试在
  `r103_mocker_udp_packet_test.cpp:84` 等待 `onRspAccount` 超时。`queryAccount()` 将任务 post 到 `_io_service`
  （`TraderMocker.cpp:830-858`），该结果支持空包后服务循环不再处理已 post 任务。源码未重挂接收确定；
  现有用例没有在空包后再发送合法 tick，也没有直接读 `_ticks`，故不能把 tick 丢失写成已动态观测。
- 测试边界: 当前用例意图验证“空包不能中断接收”，其失败与代码路径一致，不是前置条件错误；但建议追加
  空包后发送合法 tick 并断言可观察的行情驱动结果，直接锁定数据接收恢复，而不是只依赖账户回报。
- 复现步骤:
  1. `TraderMocker a; a.init(cfg); a.connect();`；
  2. 用一个本机 UDP socket 向 `cfg.udp_port` 发送 0 字节数据报；
  3. 当前启用测试在空包后发起的账户查询未收到回报；若需直接证明行情路径，继续发送合法 tick 并断言其
     对撮合/报价状态的影响。后半项尚未由现有测试执行。
- 影响范围: 任何对端/网络设备发送空 UDP 数据报（心跳、探测、截断包）的场景；
  仿真撮合的 UDP 接收链停止。空包本身没有错误日志；本轮观察到空包后账户查询无回报，不能再描述为
  `io_context` 仍正常处理查询。
- 严重级别: Major
- 备注: 修复方向是把 `951` 的早退改成 `if (bytes_transferred > 0) extract_buffer(...);
  if (isBroad && _b_socket) async_receive_from(...)`，或在 `bytes_transferred == 0` 时
  仅跳过 `extract_buffer`、仍然重新挂起。本 lane 的用例把空数据报放在最后发送，
  避免影响前面 tick 包的覆盖断言；该缺陷不阻塞覆盖率。

## BUG-R103-002 HisDataReplayer::get_last_tick 首次定位晚于尾 tick 时越界读

- 编号: BUG-R103-002
- 状态: 源码边界缺陷成立；无直接相关启用测试，未作动态/ASan 复现
- 模块/文件/行: `src/WtBtCore/HisDataReplayer.cpp:2881-2912`，
  重点是 `2890-2908`（`_cursor == UINT_MAX` 时用 `lower_bound` 直接写
  `_cursor = idx + 1`）与 `2912`（`_items[_cursor - 1]`）
- 相关测试: 无直接相关启用用例。`r103_replayer_minute_slice_test.cpp` 配置 `opts.tick = false`，
  覆盖分钟 K 线切片/模拟 tick 的 day price 路径，不调用 `get_last_tick`，不能作为本条发现或避让的证据。
  现有 `r91_replayer_bin_hft_test.cpp` 与 `r2_replayer_loader_test.cpp` 在 cursor 已定位到有数据的有效范围后
  检查 `get_last_tick`，没有覆盖首次定位落在数据尾部之后。
- 输入/前置条件:
  1. 某合约当日 tick 缓存有 2 笔：09:31、09:33；
  2. 在 `prepare()` 前将回放起始时间设为同日 09:35；`prepare()` 调用 `reset()` 后把该时间写入
     `_cur_date/_cur_time` 并将 tick cursor 重置为 `UINT_MAX`（`HisDataReplayer.cpp:436-490,654-665`）；
  3. 不先调用其他会初始化该 tick cursor 的接口，直接首次调用 `get_last_tick(code)`。
  `run()` 完成后的 cursor 状态不作为本条前置条件，因为主回放路径可能已推进/初始化该 cursor。
- 期望行为: `get_last_tick` 文档定义为“最新 Tick”；当当前时间晚于当日最后一笔时，应安全返回最后一笔或
  明确返回 NULL，不得读取 vector 末尾之外。两笔之间的当前/下一笔语义还应与 BUG-P07-005 一并明确。
- 源码证据: `std::lower_bound` 对 09:35 返回 `end()`，`idx == size`，
  `_cursor = idx + 1 == size + 1`。由于该赋值发生在
  `if (_cursor == UINT_MAX)` 分支内，紧随其后的
  `else if (_cursor > _count) return NULL;` 本次调用不会执行；
  函数直接执行 `_items[_cursor - 1]`，即 `_items[size]`，越界读一个 `WTSTickStruct`
  然后交给 `WTSTickData::create()`。这是源码边界推导；本轮没有在 ASan/libc++ 调试模式下动态复现，
  不断言实际读值、信号或崩溃形式。`cacheRawTicksFromBin` 把读取数量写入 `_count` 并按该数量 resize `_items`
  （`HisDataReplayer.cpp:3345-3351`），使 `idx == size` 确为有效下标之外。
- 复现步骤（未运行）: 用 `mode=bin`/`tick=true` 缓存 09:31、09:33 两笔 tick；将 `set_time_range` 的开始时间
  设为同日 09:35，调用 `prepare()` 后不先查询/回放 tick，立即调用 `get_last_tick`。建议在隔离子进程 + ASan
  下构建直接用例；当前仅源码审阅。
- 影响范围: 直接在回放起始点位于当日尾 tick 之后查询，可能触发 vector 越界未定义行为；实际表现未动态确认。
- 严重级别: Major
- 修复方向: 首次定位用与“最新不晚于当前时间”契约一致的边界算法，并在访问前校验 `idx < _items.size()`、
  `_count == _items.size()`；无满足当前时刻的 tick 时安全返回 NULL，越界守卫须对本次首调生效。
  同时与 BUG-P07-005 的 `get_last_tick` 当前/下一笔选择语义一并设计，避免仅修 `end()` 却仍返回未来 tick。
