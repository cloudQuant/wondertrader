## BUG-R105-001 夜盘纠偏的“行情 0 点/系统 23 点”分支是死代码

- 状态: 待验证（死条件静态可确认；日期影响需确定性时钟用例）
- 严重级别: Major（行为与时序不确定，且一块代码永远不可达）
- 模块/文件:
  - `src/ParserCTP/ParserCTP.cpp:254-275`（内层 `271-274`）
  - `src/ParserCTPMini/ParserCTPMini.cpp:232-257`（内层 `252-256`）
  - `src/ParserFemas/ParserFemas.cpp:228-253`（内层 `248-252`）
- 相关测试: `R105CtpTest.night_session_recomputes_action_date`、
  `R105MiniTest.night_session_recomputes_action_date`、
  `R105FemasTest.night_session_recomputes_action_date`
- 输入/前置条件: `ActionDay == m_uTradingDate` 且 `actHour >= 20` 的夜盘行情；另一个预期纠偏方向要求 `actHour==0 && curHour==23`。
- 期望行为: 跨日修正应同时覆盖“行情 23 点/系统 0 点”和“行情 0 点/系统 23 点”两个方向。
- 实际行为: 三个文件的外层条件都要求 `actHour >= 20`，内层 `actHour == 0 && curHour == 23` 因而恒假；该加一天分支静态不可达。反方向 `actHour == 23 && curHour == 0` 可达，但路径还读取本地墙钟；本地时刻在 [3,9) 时会丢弃行情。不要把“不可达分支”直接等同于某类生产行情必然错日。
- 复现步骤: 静态比较外层/内层条件即可证明分支不可达；现有测试不能执行一条同时满足 `actHour>=20` 和 `actHour==0` 的输入。验证可达纠偏效果需要注入时钟并覆盖 23/0 点边界。
- 影响范围: 外层覆盖的场景下，预期“行情 0 点/系统 23 点”纠偏没有实现；业务是否会以 `ActionDay==交易日` 报送该类行情需用柜台/行情契约确认。该路径有死分支，但不能只凭此宣称策略日期已被错误写出。
- 备注: 建议按交易日/时段规则推导或注入时钟，避免把不相容条件嵌套；不可达行可用静态条件证明，不需用崩溃类测试制造。R105 三个夜盘测试读取当前主机时间，本次没有运行，也不覆盖所有时段。
- 审查裁定: 死条件是源码事实；生产数据可达性和错日影响仍待验证。T4-012 已作为 Mini 子项合并到本条。

  集合大小 > 500。

- 影响范围: 超过 500 项时存在栈越界写；实际配置是否会达到该规模及运行后果本次没有验证，不声称必然随机崩溃或覆盖返回地址。
- 备注: BUG-T4-013 已登记 Mini 一处；Femas/CTPOpt 的同形代码未见单独记录，本条补齐。
- 审查裁定: 容量与循环无上界之间的越界由源码静态确认；现有启用测试只传两个元素，也没有运行 501 项边界。范围应表述为“登录后传入超过 500 项时存在越界”，不推断实际柜台是否会接受该批量规模。T4-013 是 Mini 子项，已并入本跨适配器主项。

- 补充本机观察: Femas 的非零 `OnRspError` 在本地 sink 测试中没有任何 parser 日志；按至少应有错误可观察信息的候选断言运行 FAIL，心跳日志与订阅/退订回调安全对照 PASS。`IParserSpi` 提供日志接口且其他 parser 会记录错误，但没有证明该接口要求每种错误都通过日志报告；真实厂商回调和错误登录路径不由此测试证明。
- CTP 测试侧处理: 旧 `rsp_error_publishes_nothing_at_all` 将零日志/事件当作正确结果；现改为仅验证非零错误响应不会发布行情，本机 PASS。具体错误上报方式仍需接口契约，不把这个 PASS 当作错误登录处理正确的证据。
- 复现步骤: 给测试 stub 设置非零 ErrorID，并在 API 指针有效时调用 `OnRspUserLogin(..., bIsLast=true)`；R105 当前测试源码没有此断言，本次也未运行。
- 影响范围: 有效连接会话遇到登录错误时，可能被错误通知为登录成功；订阅错误回调无论该谓词如何都没有处理逻辑。
- 备注: T3-003 和 T4-010 的错误码判定是本项子重复，已合并。T3-002 的未初始化空 API 回调前提已撤回。R105 正向测试只使用 ErrorID=0；四个 `IsErrorRspInfo` 桩可静态确认，但非零错误回报行为仍需 stub 用例验证。Parser `OnRspError` 目前丢弃判定结果且无日志，属于独立的未处理错误路径。
- 审查裁定: 恒 false 及其有效 API 登录分支影响为源码静态结论；未执行回调用例。不得将 DISABLED 的空 API 人工回调用例视为正常登录生命周期证据。
