## BUG-R105-001 夜盘纠偏的“行情 0 点/系统 23 点”分支是死代码

- 状态: 待审核
- 严重级别: Major（行为与时序不确定，且一块代码永远不可达）
- 模块/文件:
  - `src/ParserCTP/ParserCTP.cpp:254-275`（内层 `271-274`）
  - `src/ParserCTPMini/ParserCTPMini.cpp:232-257`（内层 `252-256`）
  - `src/ParserFemas/ParserFemas.cpp:228-253`（内层 `248-252`）
- 相关测试: `R105CtpTest.night_session_recomputes_action_date`、
  `R105MiniTest.night_session_recomputes_action_date`、
  `R105FemasTest.night_session_recomputes_action_date`
- 输入/前置条件: `ActionDay == m_uTradingDate` 且 `actHour >= 20` 的夜盘行情。
- 期望行为: 跨日修正应同时覆盖“行情 23 点/系统 0 点”和“行情 0 点/系统 23 点”两个方向。
- 实际行为: 外层 `if (actDate == m_uTradingDate && actHour >= 20)` 已保证
  `actHour >= 20`，内层 `else if (actHour == 0 && curHour == 23)` 的条件永远为假，
  其赋值 `actDate = TimeUtils::getNextDate(curDate, 1)` 是死代码。反方向
  `actHour == 23 && curHour == 0` 只有测试恰在本地 0 点运行才会执行；同一笔行情在
  03:00-09:00 之间还会被整笔丢弃（已有 BUG-T4-012）。
- 复现步骤:
  1. 构造 `ParserCTPMini`（或 CTP/Femas），注入 API stub，登录拿到交易日；
  2. 喂 `ActionDay=交易日`、`UpdateTime=21:00:00` 的行情；
  3. 改变进程本地时间到 23 点，行情小时设为 0（此时外层 `actHour>=20` 已不成立）；
  4. 内层“系统 23 点”分支不可达，日期不会被加一天。
- 影响范围: 夜盘跨日行情的 `action_date` 可能错误一天；该块行覆盖在白天永远为 0，
  也是三个文件无法达到 100% 的直接原因之一。
- 备注: 建议改为按交易日/时段表推导，或把“当前时间”注入；至少应把外层条件拆成
  `actHour >= 20 || actHour == 0` 再判断。不实施。

## BUG-R105-002 `subscribe()` 的固定 500 指针数组无边界检查（Femas/CTPOpt 同源）

- 状态: 待审核
- 严重级别: Blocker（栈越界写）
- 模块/文件:
  - `src/ParserCTPMini/ParserCTPMini.cpp:424-433`（`char * subscribe[500] = {NULL};`）
  - `src/ParserFemas/ParserFemas.cpp:419-428`（同形）
  - `src/ParserCTPOpt/ParserCTPOpt.cpp:416-425`（同形）
- 相关测试: `R105MiniTest.login_failure_and_inline_subscribe_branches`、
  `R105FemasTest.login_failure_and_inline_subscribe_branches`、
  `R105OptTest.login_failure_and_inline_subscribe_branches`
  （启用用例只放 2 个代码，走的是同一条循环；边界未在用例里制造 501 个代码，
  避免故意写坏栈）
- 输入/前置条件: 已登录（`m_uTradingDate != 0`）后调用 `subscribe(CodeSet)`，
  集合大小 > 500。
- 期望行为: 按 `vecSymbols.size()` 动态分配，或每 500 个分批下发。
- 实际行为: `nCount` 无上限自增写入栈数组，第 501 个代码开始越界写。
  `SubscribeMarketData()`（Mini 381、Femas 376、Opt 373）用 `new char*[]` 是正确写法，
  两条路径不一致。
- 复现步骤:
  1. 注入 API stub 并走登录成功把 `m_uTradingDate` 置非 0；
  2. 构造 501 个 `CodeSet` 元素调用 `subscribe`；
  3. stub 的 `SubMarketData/SubscribeMarketData` 收到 501，但循环已越过栈数组边界。
- 影响范围: 全市场/多品种订阅（商品期货全部合约、ETF 期权全表）可触发栈破坏；
  生产上表现为随机崩溃或返回地址被覆盖。
- 备注: BUG-T4-013 已登记 Mini 一处；Femas/CTPOpt 的同形代码未见单独记录，本条补齐。

## BUG-R105-003 `init()` 在厂商库缺失时仍调用空 `m_funcCreator`

- 状态: 待审核
- 严重级别: Blocker（加载即崩）
- 模块/文件:
  - `src/ParserCTPMini/ParserCTPMini.cpp:127-132`（`get_symbol` 后直接
    `m_pUserAPI = m_funcCreator(...)`，再 `RegisterSpi/RegisterFront`）
  - `src/ParserFemas/ParserFemas.cpp:126-131`
  - `src/ParserCTPOpt/ParserCTPOpt.cpp:127-132`
- 相关测试: `R105MiniTest.init_flowdir_creation_failure_throws_before_vendor_symbol`、
  `R105FemasTest.init_flowdir_creation_failure_throws_before_vendor_symbol`、
  `R105OptTest.init_flowdir_creation_failure_throws_before_vendor_symbol`
  （启用用例用异常路径停在 creator 之前；真正的尾段仍只能 DISABLED，见 T3-001/T4-009）
- 输入/前置条件: 非 Windows 环境，`ctpmodule` 指向不存在的厂商库（本机默认即如此）。
- 期望行为: `load_library`/`get_symbol` 任一为空时记日志并 `return false`。
- 实际行为: 两个返回值都不判空，空函数指针调用 SIGSEGV；`RegisterSpi/RegisterFront`

- 影响范围: macOS/Linux 缺厂商库的任何环境；同时使 init 的
  `create_directories` 之后、`return true` 之前的行无法被启用用例覆盖。
- 备注: 与 T3-001（Femas）、BUG-T4-009（Mini）同源；Opt 侧的登记散在 T2/T4。
  本条只做跨模块合并，不重复给修复方案。

## BUG-R105-004 `IsErrorRspInfo` 恒 false，登录成功路径无 `m_pUserAPI` 判空

- 状态: 待审核
- 严重级别: Blocker（错误应答被当成功，未初始化/已释放时崩溃）
- 模块/文件:
  - `src/ParserCTP/ParserCTP.cpp:426-429`、`188-190`
  - `src/ParserCTPMini/ParserCTPMini.cpp:410-413`、`182-184`
  - `src/ParserFemas/ParserFemas.cpp:405-408`、`181-183`
  - `src/ParserCTPOpt/ParserCTPOpt.cpp:402-405`、`182-184`
- 相关测试: `R105CtpTest.init_connect_login_and_subscribe_flow` 等四条正向用例
  （stub 下 bIsLast=true、ErrorID=0 走成功分支）；既有 DISABLED 用例
  `DISABLED_login_success_branch_dereferences_null_api`（Mini/Femas/Opt）
- 输入/前置条件: 未 `init` 或已 `release`（`m_pUserAPI == NULL`）时收到
  `bIsLast=true` 的 `OnRspUserLogin`；或收到 `ErrorID != 0` 的错误应答。
- 期望行为: 先判 `m_pUserAPI`；`IsErrorRspInfo` 至少检查 `ErrorID != 0`。
- 实际行为: `IsErrorRspInfo` 的参数被注释掉、恒返回 false，任何错误应答都进入
  “登录成功”分支，紧接着 `m_pUserAPI->GetTradingDay()` 解引用空指针（或把错误当成功
  继续 `SubscribeMarketData`）。同时 `OnRspSubMarketData` 的 else 分支永远不可达。
- 复现步骤:
  1. `ParserCTPMini p; p.registerSpi(&sink);`
  2. 构造 `ErrorID=40` 的 `CThostFtdcRspInfoField` 与 `bIsLast=true`；
  3. 调 `p.OnRspUserLogin(&login, &err, 1, true)` → 崩溃/错误登录事件。
- 影响范围: 登录失败无法识别；释放后迟到的登录回报直接崩进程；订阅失败静默。
- 备注: 与 T3-002/T3-003、BUG-T4-010、T2-OPT 同源；R105 首次在四个适配器的
  “有 API” 正向面同时复现，故合并登记。

## BUG-R105-005 Mini/Femas/CTPOpt 未对空的 `GetTradingDay()` 做回退

- 状态: 待审核
- 严重级别: Major（交易日为 0，后续动态订阅只缓存不下发）
- 模块/文件:
  - `src/ParserCTPMini/ParserCTPMini.cpp:184`
  - `src/ParserFemas/ParserFemas.cpp:183`
  - `src/ParserCTPOpt/ParserCTPOpt.cpp:184`
  - 对照：`src/ParserCTP/ParserCTP.cpp:193-194` 有 `m_uTradingDate == 0` 回退
- 相关测试: `R105CtpTest.login_request_failure_and_empty_trading_day_fallback`
  （CTP 回退分支）；Mini/Femas/Opt 的对应路径只能断言“日期为 0 时 subscribe 只缓存”
- 输入/前置条件: 登录回报 `bIsLast=true`、`GetTradingDay()` 返回空串（部分柜台在
  登录瞬间尚未就绪）。
- 期望行为: 与 CTP 一致，空交易日回退 `TimeUtils::getCurDate()` 或延后重试。
- 实际行为: `convert::to_uint32("")` 得 0；`m_uTradingDate` 保持 0。首次
  `SubscribeMarketData()` 仍会直接下发缓存，但之后每次 `subscribe()` 都走
  `m_uTradingDate == 0` 的“只缓存”分支，动态加品种永远不会下发；tick 的
  `trading_date` 也一直为 0。
- 复现步骤:
  1. 注入 API stub，`trading_day = ""`；
  2. 调 `OnRspUserLogin(..., true)`；
  3. 再调 `subscribe(任意代码)`，stub 的订阅计数不增加。
- 影响范围: 依赖登录后动态订阅的行情进程（夜盘启动、断线重连后补订阅）。
- 备注: 不实施；修复时应同时考虑 `m_filterSubs` 的重放。

## BUG-R105-006 `init()` 对 flowdir 创建失败没有异常处理

- 状态: 待审核
- 严重级别: Major（异常穿出 `bool init()`，加载器可能直接终止）
- 模块/文件:
  - `src/ParserCTP/ParserCTP.cpp:114-118`
  - `src/ParserCTPMini/ParserCTPMini.cpp:114-118`
  - `src/ParserFemas/ParserFemas.cpp:113-117`
  - `src/ParserCTPOpt/ParserCTPOpt.cpp:115-119`
- 相关测试: `R105MiniTest.init_flowdir_creation_failure_throws_before_vendor_symbol`、
  `R105FemasTest.init_flowdir_creation_failure_throws_before_vendor_symbol`、
  `R105OptTest.init_flowdir_creation_failure_throws_before_vendor_symbol`
  （三条启用用例都显式 `EXPECT_THROW(..., std::filesystem::filesystem_error)`）
- 输入/前置条件: `flowdir` 的某个父路径是普通文件（或目录无写权限）。
- 期望行为: `init` 捕获异常/改用 `error_code` 重载，记日志并 `return false`。
- 实际行为: `fs::create_directories` 的抛异常重载未包裹 try/catch，异常直接穿过
  `ParserCTP::init` 等声明的 `bool` 返回；调用方（ParserAdapter/插件加载器）
  未预期异常，可能导致进程终止。
- 复现步骤:
  1. 在系统临时目录建一个普通文件 `blocker`；
  2. 配置 `flowdir: <tmp>/blocker/sub`；
  3. 调 `ParserFemas p; p.init(cfg);` → 抛 `filesystem_error`，不返回 false。
- 影响范围: 配置写错/权限不足时不是“加载失败”，而是异常退出；同时使 init 的正常
  返回路径不可达。
- 备注: 不实施；建议统一改为 `fs::create_directories(path, ec)` 并检查 `ec`。
