## BUG-R164-001 UDPCaster 成员析构顺序错误：只要建过 socket，active 装配后析构必 SIGSEGV

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件/行: `src/WtDtCore/UDPCaster.h:88-96`（`m_sktBroadcast`/`m_sktSubscribe`/`m_list*Group` 声明在 `m_ioservice` 之前）、`src/WtDtCore/UDPCaster.h:96`（`m_ioservice`）、`src/WtDtCore/UDPCaster.cpp:58-60`（析构体本身为空）
- 相关测试: `r164_udp_caster_active_test.cpp::R164UdpCasterActiveTest.DISABLED_ActiveStartThenDestructorCrashes`；既有 `r154_udp_caster_start_test.cpp` 的三条 active 用例
- 输入/前置条件: `UDPCaster caster; WTSVariant* cfg = {"active": true, "sport": <空闲端口>}; caster.init(cfg, nullptr, nullptr); caster.stop();` 然后对象离开作用域
- 期望行为: 析构安全；socket 应在 `io_context` 仍然存活时 close/reset，或 `stop()` 主动 reset 所有 socket，再销毁 `io_context`
- 实际行为: 按成员声明逆序析构，`m_ioservice`（H96）先于 `m_sktBroadcast`（H88）、`m_sktSubscribe`（H89）、`m_listFlat/Json/RawGroup`（H93-95）销毁。随后 `shared_ptr<UDPSocket>` 析构调用
  `reactive_socket_service_base::destroy` -> `kqueue_reactor::deregister_descriptor`，访问已析构的 reactor，SIGSEGV（KERN_INVALID_ADDRESS at 0x30）。
  是否调用 `stop()` 不影响：stop 只停 io_context、join 线程，不 reset socket。`ShmCaster` 没有 `io_context` 成员，不受影响。
- 复现步骤: 1) 用 active=true、sport=空闲端口的配置 init 一个栈上 UDPCaster；2) stop()；3) 作用域结束触发析构；4) 进程崩在 `~UDPCaster` 销毁 `m_sktSubscribe`。
- 证据:
  - 最新一轮 `build-cov/coverage/rc/CoverageTests_dtcore/R154UdpCasterTest_*.rc` 三条均 `CRASH(rc=139,sig=11)`，日志停在 `[ RUN ]`；
  - `~/Library/Logs/DiagnosticReports/CoverageTests_dtcore-2026-10-28-200143.ips` 触发线程栈：
    `UDPCaster::~UDPCaster() -> shared_ptr<basic_datagram_socket>::~shared_ptr -> ... -> kqueue_reactor::deregister_descriptor`，异常 `EXC_BAD_ACCESS / SIGSEGV / KERN_INVALID_ADDRESS at 0x30`；
  - 同一对象若只做 `addBRecver`（无 socket）或 `addMRecver` 在 `make_address_v4` 处失败（无 socket），析构正常；一旦 `new UDPSocket` 成功即崩。
- 影响范围: 所有 active UDP 广播器（dt_srv/wtdtserver 及回测/实盘装配）在正常退出、配置重载、异常释放时都会崩溃；R154 的三条 UDP 用例因此实际未覆盖任何 active 行，UDPCaster.cpp 覆盖率停在 70/476。进程崩溃发生在关停阶段，可能丢失尚未落盘的行情/收盘作业状态。
- 备注: 建议把 `m_ioservice` 移到 socket/组播容器之前声明（使它在最后析构），或在 `stop()` 中依次 `m_sktBroadcast.reset(); m_sktSubscribe.reset(); m_list*Group.clear();` 并再 `m_ioservice.stop()`；同时给析构加 try/catch 兜底。修复后本 lane 的 `DISABLED_` 用例可直接启用，`LeakyCaster` 的绕过也可删除。
