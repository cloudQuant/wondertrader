## BUG-R131-001 `COND_ACTION_SP` 缺少显式 `break`（复核：当前不是行为缺陷）

- 编号: BUG-R131-001
- 状态: 已撤回（当前无可观察行为差异；缺少 break 落入空 default 与直接 break 等价，不应计为功能缺陷）
- 模块/文件/行:
  - `src/WtBtCore/CtaMocker.cpp:883-887`
  - `case COND_ACTION_SP:` 块在 `append_signal(...)` 后直接落入 `default: break;`
- 复核结论:
  - `COND_ACTION_SP` 确实没有显式 `break`，控制流会落到 `default`；但当前 `default`
    只有 `break`，没有额外语句或副作用，因此与在 `append_signal` 后直接 `break` 等价。
  - “未来 default 可能增加处理”是假设，不构成当前行为缺陷。代码可加显式 `break` 改善
    可读性，但不应按功能 bug 计数。
- 输入/前置条件:
  - 公开 `stra_exit_short(stdCode, qty, userTag, limitprice, stopprice)` 在带
    `limitprice/stopprice` 时登记 `COND_ACTION_SP`（`CtaMocker.cpp:1580`）；
  - 喂入可触发该条件单的 tick，进入 `proc_tick` 的 `matchedEntrust` 执行段。
- 可选整理:
  - 与同组 case 一致，在 `append_signal` 后加 `break;`；这只明确意图，不改变当前行为。
- 实际:
  - 缺少 `break;`，落入 `default: break;`（当前无副作用）。
- 验证范围: 当前 R131 用例没有覆盖该分支；原记录步骤只检查源代码落空到 `default`，
  没有能区分现状与显式 `break` 的断言。无需动态复现，因为两条控制流在当前实现中等价。
- 严重级别: 不适用（风格/可读性建议）
- 可选整理方向: 在 `append_signal` 后添加 `break;`，防止将来向 `default` 加入副作用时
  改变该分支语义；不需要以功能缺陷立案或新增行为测试。
