## BUG-R154-001 UDPCaster 的订阅回调不校验 m_bdMgr/m_dtMgr，active=true + NULL 装配收包即崩溃

- 迭代02第二轮前状态（历史）: - 状态: 待审核
- 状态: 已撤回（迭代02：TEST，原产品主张不成立）
- 严重级别: Major（仅当 active caster 以空 manager 初始化且可从网络到达订阅端口时成立；未确认
  生产 runner 会传入空 manager）
- 模块/文件/行: `src/WtDtCore/UDPCaster.cpp:62-65`（init 无条件保存 bdMgr/dtMgr）、`src/WtDtCore/UDPCaster.cpp:176`（`m_bdMgr->getContract`）、`src/WtDtCore/UDPCaster.cpp:180`（`m_dtMgr->getCurTick`）
- 相关测试: `r154_udp_caster_start_test.cpp::R154UdpCasterTest.DISABLED_SubscribePacketWithNullBdMgrCrashes`
- 输入/前置条件: `caster.init(cfg, nullptr, nullptr)`，cfg 为 `{"active": true, "sport": <空闲端口>}`；向该端口发送 1024 字节、`_type=0x100`、`_data="ag2512"` 的订阅包
- 期望行为: `init` 拒绝缺少 bdMgr/dtMgr 的 active 装配并返回 false；或 `do_receive` 在解引用前判空、记录 error 后忽略该请求。广播器本身仍可运行
- 静态风险: `init` 不检查 manager 指针，active=true 时仍会启动订阅 socket；收到订阅包后 L176 会对空
  `m_bdMgr` 解引用，若 bdMgr 非空而 dtMgr 为空，L180 同样有空指针解引用风险。本条测试为禁用用例，
  本轮未运行，尚无动态崩溃证据。
- 复现步骤: 1) 构造 UDPCaster；2) 用 active=true、sport=空闲端口的配置调用 `init(cfg, nullptr, nullptr)`；3) 回环发送 1024 字节订阅包；4) 进程崩在 UDPCaster.cpp:176
- 影响范围: `UDPCaster::init` 在 active=true 时接受 NULL managers 并启动订阅 socket；满足该装配条件时，
  能访问绑定端口的发送方可用订阅包触发空指针风险。现有生产调用 `WtDtRunner::init` 传入的是
  `&_bd_mgr` 和 `&_data_mgr`，当前证据不支持声称常规 dt_srv 启动会以 NULL manager 暴露该面。
- 备注: 建议在 `init` active=true 时校验 `bdMgr/dtMgr != NULL`，或在订阅分支判空后丢弃请求并记录错误。

## BUG-R154-002 ShmCaster 二次 active 初始化失败后 _queue 悬垂、_inited 仍为 true

- 状态: 已合并（迭代02：主编号 BUG-R68-002）
- 严重级别: Major（失败重初始化可能留下失效 queue；本轮 disabled 测试进程退出 139，但未采集堆栈）
- 模块/文件/行: `src/WtDtCore/ShmCaster.cpp:46-51`（`_mapfile.reset(new BoostMappingFile)` 先销毁旧映射，`map` 抛异常后 `_queue`/`_inited` 未回滚）
- 相关测试: `r154_shm_caster_active_test.cpp::R154ShmCasterActiveTest.DISABLED_ReinitWithDirectoryPathLeavesDanglingQueue`
- 输入/前置条件: 同一 `ShmCaster` 第一次 `init({"active":true,"path":"<临时文件>"})` 成功并完成一次 broadcast；第二次 `init({"active":true,"path":"<已存在目录>"})`
- 期望行为: 第二次 `init` 返回 false（或抛出后对象仍保持一致）：`_queue == NULL`、`_inited == false`，后续 broadcast 被守卫拦截
- 静态风险链: 若首次路径能进入 L46、第二次 `map(目录)` 在替换旧映射后抛出，`_queue` 仍指向旧映射的
  地址、`_inited` 仍为 true；随后 `broadcast` 的 `_queue==NULL || !_inited` 守卫不会拦截，写入已解除映射
  地址属于未定义行为。`init` 前置的 `BoostFile` 调用会忽略布尔返回值，实际异常落点需结合栈确认。
- 复现步骤: 1) 用临时文件 init 成功并 broadcast 一次；2) 对目录路径再次 init；3) 捕获异常后再 broadcast。
  本轮运行 `DISABLED_ReinitWithDirectoryPathLeavesDanglingQueue`，进程退出码 139，输出只到
  `[ RUN ]`，没有栈帧，因而本轮动态证据只确认该测试序列导致进程崩溃，不能单独定位到 `broadcast` 写入行。
- 影响范围: 若第二次 map 失败发生在旧映射已替换之后，后续 broadcast 会使用悬垂 `_queue`。失效映射
  状态链有源码依据；具体失败路径与崩溃位置仍需带栈复核。R68-002 覆盖首次 init 失败，不能代替本条
  reinit 状态审计。
- 备注: 建议先在局部映射对象上完成 map，成功后再替换 `_mapfile/_queue`；若失败必须保持旧映射可用或
  将 `_queue` 置 NULL、`_inited` 置 false，并按接口约定捕获异常或返回 false。


- 迭代02复核: DUPLICATE。并入 BUG-R68-002。目录输入在 create/truncate 失败（L39-42），早于 _mapfile.reset（L46），不能证明旧映射已替换或 _queue 悬垂；映射失败未收口已有主记录。
- 迭代02依据: [逐条裁定与主代理修订](../../迭代02/缺陷裁定总表.md)。原记录保留作为历史，未声称产品已修复。
- 迭代02前状态（历史）: - 状态: 待审核
## BUG-R154-003 UDPCaster::stop 在 start 之后不幂等，二次调用抛 std::system_error

- 迭代02第二轮前状态（历史）: - 状态: 待审核
- 状态: 已撤回（迭代02：NOT_BUG，原产品主张不成立）
- 严重级别: 条件性候选（静态上第二次 join 会抛 `std::system_error`；尚无本轮动态结果，幂等性要求需按调用契约确认）
- 模块/文件/行: `src/WtDtCore/UDPCaster.cpp:133-143`（L137-138 对 `m_thrdIO` 无条件 `join`，L141-142 对 `m_thrdCast` 无条件 `join`）
- 相关测试: `r154_udp_caster_start_test.cpp::R154UdpCasterTest.DISABLED_SecondStopAfterStartThrows`
- 输入/前置条件: `init(active=true, sport=0)` 成功；连续调用 `stop()` 两次
- 期望行为: `stop()` 幂等；第二次调用安全返回（或至少不抛异常）
- 实际行为（静态核对）: 第一次 stop 已 join IO 线程；第二次 `join()` 对 non-joinable `m_thrdIO`
  抛 `std::system_error`。若调用方未捕获则可能终止进程。当前 `DISABLED_SecondStopAfterStartThrows`
  未在本轮运行，未记录实际异常类型/退出码。
- 复现步骤（静态推演，未动态运行）: 1) active=true 配置 init 成功；2) `caster.stop();` 3) 再调用
  `caster.stop();`；4) 对已 join 的 `m_thrdIO` 再 `join()`。
- 影响范围: 若调用者在成功 start 后重复调用 `stop()`，第二次可能抛异常。没有证据表明正常 runner
  一定走该调用序列。与 BUG-R145-001 形态相似但对象不同；R5 覆盖的是未 start 时 stop 两次，不能证明
  start 后重复 stop 的表现。
- 备注: 建议 join 前判 `joinable()` 或 join 后 `reset()` 线程指针
