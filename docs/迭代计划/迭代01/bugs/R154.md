## BUG-R154-001 UDPCaster 的订阅回调不校验 m_bdMgr/m_dtMgr，active=true + NULL 装配收包即崩溃

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件/行: `src/WtDtCore/UDPCaster.cpp:62-65`（init 无条件保存 bdMgr/dtMgr）、`src/WtDtCore/UDPCaster.cpp:176`（`m_bdMgr->getContract`）、`src/WtDtCore/UDPCaster.cpp:180`（`m_dtMgr->getCurTick`）
- 相关测试: `r154_udp_caster_start_test.cpp::R154UdpCasterTest.DISABLED_SubscribePacketWithNullBdMgrCrashes`
- 输入/前置条件: `caster.init(cfg, nullptr, nullptr)`，cfg 为 `{"active": true, "sport": <空闲端口>}`；向该端口发送 1024 字节、`_type=0x100`、`_data="ag2512"` 的订阅包
- 期望行为: `init` 拒绝缺少 bdMgr/dtMgr 的 active 装配并返回 false；或 `do_receive` 在解引用前判空、记录 error 后忽略该请求。广播器本身仍可运行
- 实际行为: `init` 返回 true 并启动订阅 socket；收到订阅包后 L176 对空 `m_bdMgr` 解引用，进程 SIGSEGV。若 bdMgr 非空而 dtMgr 为空，L180 同样崩溃
- 复现步骤: 1) 构造 UDPCaster；2) 用 active=true、sport=空闲端口的配置调用 `init(cfg, nullptr, nullptr)`；3) 回环发送 1024 字节订阅包；4) 进程崩在 UDPCaster.cpp:176
- 影响范围: dt_srv/wtdtserver 在基础数据加载失败或未装配时仍可能按配置启动 UDP 广播；任意同网段主机发一个订阅包即可打崩进程（无需登录/鉴权）。该路径在 R5/R68 中因「不建 socket」未被执行，属于新增可达面
- 备注: 建议 `init` 在 active=true 时校验 `bdMgr/dtMgr != NULL`，或在 `do_receive` 的订阅分支入口判空并 return

## BUG-R154-002 ShmCaster 二次 active 初始化失败后 _queue 悬垂、_inited 仍为 true

- 状态: 待审核
- 严重级别: Blocker
- 模块/文件/行: `src/WtDtCore/ShmCaster.cpp:46-51`（`_mapfile.reset(new BoostMappingFile)` 先销毁旧映射，`map` 抛异常后 `_queue`/`_inited` 未回滚）
- 相关测试: `r154_shm_caster_active_test.cpp::R154ShmCasterActiveTest.DISABLED_ReinitWithDirectoryPathLeavesDanglingQueue`
- 输入/前置条件: 同一 `ShmCaster` 第一次 `init({"active":true,"path":"<临时文件>"})` 成功并完成一次 broadcast；第二次 `init({"active":true,"path":"<已存在目录>"})`
- 期望行为: 第二次 `init` 返回 false（或抛出后对象仍保持一致）：`_queue == NULL`、`_inited == false`，后续 broadcast 被守卫拦截
- 实际行为: L46 `_mapfile.reset(...)` 先析构旧 `BoostMappingFile`、unmap 旧区域；L47 `map(目录)` 抛 `interprocess_exception` 穿透 `init`。此时 `_queue` 仍指向已 unmap 的旧地址、`_inited` 仍为 true；下一次 `broadcast` 的 `_queue==NULL || !_inited` 守卫全部放行，L83/L110/L137/L164 写入未映射内存，SIGSEGV/UB
- 复现步骤: 1) 用临时文件 init 成功并 broadcast 一次；2) 用目录路径再次 init，捕获异常；3) 再 broadcast 一个 tick；4) 崩在写入体
- 影响范围: 配置热重载/重复装配时把 shm 路径写错（目录、无权限、父目录不存在）即可让进程在后续行情到达时崩溃；R68-002 只覆盖了「首次 init 失败」，本条是「成功后再次失败」的悬垂状态
- 备注: 建议 `init` 先在新局部对象上完成 map，成功后再替换 `_mapfile/_queue`；失败时把 `_queue` 置 NULL、`_inited` 置 false，并用 try/catch 转 false

## BUG-R154-003 UDPCaster::stop 在 start 之后不幂等，二次调用抛 std::system_error

- 状态: 待审核
- 严重级别: Minor
- 模块/文件/行: `src/WtDtCore/UDPCaster.cpp:133-143`（L137-138 对 `m_thrdIO` 无条件 `join`，L141-142 对 `m_thrdCast` 无条件 `join`）
- 相关测试: `r154_udp_caster_start_test.cpp::R154UdpCasterTest.DISABLED_SecondStopAfterStartThrows`
- 输入/前置条件: `init(active=true, sport=0)` 成功；连续调用 `stop()` 两次
- 期望行为: `stop()` 幂等；第二次调用安全返回（或至少不抛异常）
- 实际行为: 第一次 stop 已 join 两个 `std::thread`；第二次 `join()` 对 non-joinable 线程抛 `std::system_error: Invalid argument`，若调用方未捕获则进程 terminate
- 复现步骤: 1) active=true 配置 init 成功；2) `caster.stop();` 3) 再次 `caster.stop();` 4) 抛 std::system_error
- 影响范围: 上层在异常关停、重复 release、信号处理与正常退出路径各调一次 stop 时，第二次即抛异常；与 BUG-R145-001（StateMonitor）同形但对象不同，R5 只测了“未 start 时 stop 两次”
- 备注: 建议 join 前判 `joinable()` 或 join 后 `reset()` 线程指针
