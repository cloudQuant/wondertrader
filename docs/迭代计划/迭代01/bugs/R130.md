# lane R130 疑似缺陷记录（WtCore 残余公开面）

## BUG-R130-001

- 状态: 待审核
- 严重级别: Major（公开 API 结果错误；当前 WtCore 内调用点被注释，故暂无实盘资金影响）
- 模块/文件: `src/WtCore/WtEngine.cpp` L843-876（`load_fees`）、L879-916（`calc_fee`）、
  `src/WtCore/WtEngine.h` L247-260（`FeeItem` / `_fee_map`）
- 相关测试: `src/TestUnits/coverage/q01_wtcore3/r130_engine_fee_test.cpp`
  - `TEST(R130EngineFee, LoadFeesWritesCommodityRatesButNotFeeMap)`（钉住现状）
  - `TEST(R130EngineFee, DISABLED_LoadFeesShouldPopulateEngineFeeMap)`（契约）
- 输入/前置条件:
  1. `engine.init(cfg, ...)`，`cfg.fees` 指向
     `{"SHFE.ag":{"open":1.5,"close":1.2,"closetoday":1.0,"byvolume":true}}`；
  2. `load_fees` 走完解析（品种存在，`commInfo != NULL`）；
  3. 调用 `calc_fee("SHFE.ag.2512", 3500.0, 2.0, 0)`。
- 期望行为: `load_fees` 应把每条模板写入 `_fee_map`（键为 `交易所.品种`），
  `calc_fee` 命中模板后按 `_by_volume` 分支返回 `1.5*2 = 3.0`。
- 实际行为: `load_fees` 只执行 `commInfo->setFeeRates(...)` / `setMarginRate(...)`，
  全文件没有任何 `_fee_map[...] = ...` 的写入点；`calc_fee` 在 L883-888 恒走
  “template not found → return 0.0”。实测 `_fee_map.size()==0`、`calc_fee==0.0`。
- 复现步骤:
  1. 按上述 cfg 调 `init`（或测试子类公开后直接 `load_fees(path)`）；
  2. 断言 `comm->calcFee(3500,2,0)==3.0`（通过，说明品种费率已写入）；
  3. 断言 `calc_fee(...)==3.0`（失败，实际 0.0）。
- 影响范围: 任何通过 `WtEngine::calc_fee` 计费的公开路径都会得到 0 手续费；
  `WtEngine.cpp` L890-916 的 27 行因此成为事实不可达代码（本 lane 只能用测试子类
  注入 `_fee_map` 才能覆盖算术分支）。
- 备注: `src/WtCore/CtaStraBaseCtx.cpp` L1465/L1512 对 `calc_fee` 的调用已被注释，
  当前 WtCore 实盘链路未使用；但 `WtEngine` 是公开基类，回测/外部组件仍可能调用。
  修复方向：在 `load_fees` 循环内同时填充 `_fee_map[fullPid]`（与
  `HisDataReplayer::calc_fee` 的 `_fee_map` 语义对齐）。本 lane 按纪律不改生产代码。

## BUG-R130-002

- 状态: 待审核
- 严重级别: Minor（资源泄漏 + 对象不可重复初始化）
- 模块/文件: `src/WtCore/ParserAdapter.cpp` L95-99（`if (_cfg != NULL) return false;` /
  `_cfg = cfg; _cfg->retain();`）、L41-43（析构空实现）、L214-226（`release` 不释放 `_cfg`）、
  `src/WtCore/ParserAdapter.h` L103
- 相关测试: `src/TestUnits/coverage/q01_wtcore3/r130_misc_tail_test.cpp`
  `TEST(R130MiscTail, ParserInitFailsWhenModuleCannotBeLoaded)`
- 输入/前置条件:
  1. 栈上 `ParserAdapter adapter`；
  2. `cfg.module = "R130NoSuchParserModule"`，`instDir` 指向不含该插件的临时目录；
  3. 调 `adapter.init(...)`（返回 false），随后 `adapter.release()`。
- 期望行为: `init` 失败路径应释放本次 retain 的 `_cfg`（或把 `_cfg` 置回 NULL），
  使对象可以再次 `init`；`release()` 后不应残留引用。
- 实际行为: L98-99 先 retain，再在 L117-121 模块装载失败处直接 `return false`；
  `_cfg` 保持非空。析构函数为空、`release()` 只处理 `_parser_api`，全文件无
  `_cfg->release()`。因此每次失败的 `init` 泄漏一个 `WTSVariant` 引用，且 L95
  使同一个 adapter 永远无法再次 `init`（返回 false）。
- 复现步骤:
  1. 用不存在的 module 调 `init`，得到 false；
  2. 再用合法 module 调同一对象 `init`，仍在 L95-96 直接返回 false；
  3. 析构/`release` 后 `_cfg` 引用计数不下降（可用 `WTSVariant::retain/release`
     计数或泄漏检测观察）。
- 影响范围: 解析器热重载/重连场景无法复用 adapter；长时间运行反复创建失败 adapter
  会累积配置对象。成功路径同样泄漏 `_cfg`（成功 init 后 release 也不释放）。
- 备注: `WtCore/WtDtCore/WtUftCore` 各有一份 `ParserAdapter`，本记录针对 `src/WtCore`。
  修复方向：析构与 `release` 中 `if(_cfg){_cfg->release();_cfg=NULL;}`，
  并把失败路径改为统一清理。
