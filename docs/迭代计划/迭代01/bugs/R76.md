## R76-04

- 编号：R76-04
- 状态: 待审核
- 严重级别：Major（配置错误从「返回 false」变成 connect 期异常 + 资源泄漏）
- 模块/文件/行：`src/ParserXeleSkt/ParserXeleSkt.cpp:110-116`（`init` 只解析 tcp_host）、
  `124-154`（`reconnect`；`prepare()` 返回值被忽略，L140 `new` socket，L145 `make_address_v4`）
- 相关测试：`R76ParserXeleSktTest.InitDefersMulticastValidationUntilConnect`
  （启用，断言非法 mcast/local 下 `init` 仍返回 true）
- 输入/前置条件：`tcp_host` 合法，`mcast_host="not-an-ip"`（或 `local_host` 非法）
- 期望行为：`init` 返回 false 并指出非法地址；或 `connect` 内部捕获异常、释放已建 socket 后返回 false
- 实际行为：
  1. `init` 只对 `tcp_host` 调 `ip::make_address`，`_mcast_host/_local_host` 原样保存 → 返回 true；
  2. `connect()` → `reconnect()` 先调 `prepare()`，**不检查其返回值**（快照 TCP 连不上也继续）；
  3. L140 `_udp_socket = new ip::udp::socket(_io_service)` 后，
     L145 `ip::make_address_v4(_mcast_host.c_str())` / `_local_host` 对非法串抛
     `boost::system::system_error`；异常穿出 `connect()`，已 new 的 socket 无人 delete；
  4. `reconnect()` 未完成，UDP 接收 never started；上层只看到异常
- 复现步骤：`cfg.mcast_host="not-an-ip"` → `init` 返回 true → `connect()`（需要绑定真实 UDP
  端口，本轮未执行；行为由源码 L140-145 直接确定）
- 影响范围：配置拼写错误、容器 DNS/网卡名写错；异常穿透插件边界（同类问题见 T2-XELE-01，
  但那条针对 tcp_host，本条针对 mcast/local 与 prepare 返回值）
- 备注：修复方向：`init` 里校验 `make_address_v4`、`reconnect` 用 RAII/unique_ptr 管理 socket
  并检查 `prepare()`。

## R76-05

- 编号：R76-05
- 状态: 待审核
- 严重级别：Major（外部输入驱动的越界写 + 不可重入）
- 模块/文件/行：`src/ParserXeleSkt/ParserXeleSkt.cpp:37-54`（`strToTime`），
  调用点 `217-218`（`ActionDay` / `UpdateTime`）
- 相关测试：无（`strToTime` 是 .cpp 内 `inline` 自由函数，只被 private `prepare()` 调用；
  按 lane 约束不跨 TU 声明调用，不绕过公开 API）
- 输入/前置条件：厂商快照里的 `ActionDay`/`UpdateTime` 去掉冒号后超过 9 个数字
  （例如 `"09:30:15.450"` 或带 10 位日期的扩展格式）
- 期望行为：使用有界局部缓冲（`std::string`/`char[16]` + 长度判断），函数可重入
- 实际行为：`static char str[10]`，`idx` 无上界；`str[idx]='\0'` 在 idx>=10 时写到数组外；
  同时 `static` 缓冲被同一进程内多个 parser 实例/多个解析线程共享，互相覆盖
- 复现步骤：直接调用 `strToTime("09:30:15.450")`（10 个数字）即越界写；生产路径需
  `prepare()` 收到该格式快照（真实 TCP，T2 DISABLED 面）
- 影响范围：易盛快照同步；与 T5-10（ParserCTP）、T2-OPT-05（ParserCTPOpt）是同一类缺陷的第三份拷贝
- 备注：修复方向：`std::array<char, 16>` + 循环内 `idx+1 < sizeof(str)`，或直接用
  `std::string` 去掉 `':'` 后 `convert::to_uint32`。

## R76-07

- 编号：R76-07
- 状态: 待审核
- 严重级别：Major（订阅报文内容损坏 + 潜在越界写）
- 模块/文件/行：`src/ParserUDP/ParserUDP.cpp:173-214`（偏移与长度在 `184-196`，
  `strcpy` 在 `190/192`，flush 判断在 `196-205`）
- 相关测试：无（`subscribe()` 是 private，唯一调用方 `reconnect()` 需要真实 UDP socket）
- 输入/前置条件：订阅集合里的代码是标准码 `"交易所.原始代码"`（`subscribe` 公开面正是这样存的），
  且集合非空
- 期望行为：每个代码只写 `.` 后的原始代码，`length` 按实际写入字节递增；写前检查
  `length + n + 1 <= sizeof(req->_data)`；用 `memcpy`/有界拷贝
- 实际行为：
  1. `strcpy` 只复制 `pos+1` 起的后缀，但 `length += code.size()` 加的是**完整标准码长度**；
     以 `"SHFE.ag2512"` 为例实际写 6 字节却把偏移推进 11 字节，后续逗号与下一个代码被写到
     偏移 11、12……，中间 5 个字节保持 `'\0'`。由于报文没有显式长度字段，接收端按 C 串解析时
     会在第一个 NUL 处截断，只有第一个合约生效；
  2. `strcpy` 目标为 `req->_data + length`，`_data` 只有 1020 字节，`data` 总长 1024；
     单个超长代码或 `length` 接近 1000 时无界拷贝可越过 `std::string` 缓冲区；
  3. `if (length > 1000)` 在拷贝之后才判断，越界已经发生
- 复现步骤：`subscribe` 两个标准码（例如 `SHFE.ag2512`、`DCE.m2509`），`connect()` 后抓
  `_send_queue` 首包：`_data` 为 `"ag2512\0\0\0\0\0,m2509..."`（需真实 socket，未执行；
  逻辑由 L188-196 直接确定）
- 影响范围：所有走 ParserUDP 的行情订阅；多合约订阅只生效第一个，长代码可写坏堆
- 备注：与 T6-006（`extract_buffer` 忽略 length、订阅回包当 tick 解析）相邻但不同函数；
  修复方向：`std::string suffix = code.substr(pos+1); if (length + suffix.size() + 2 > 1000) flush;`
  然后 `memcpy`。
