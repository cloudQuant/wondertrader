## BUG-R68-001 UDPCaster::init 未判空（仅直接传 NULL 时触发；调用链影响未证）

- 状态: 已撤回（迭代02：TEST，原产品主张不成立）
- 严重级别: 契约待确认（当前已检查的生产调用点不会因缺段传入 NULL）
- 产品文件:行: `src/WtDtCore/UDPCaster.cpp:62-68`（L67 `cfg->getBoolean("active")` 前无判空）
- 相关测试: `src/TestUnits/coverage/q05_dtsrv/r68_udp_caster_init_test.cpp::R68UdpCasterInitTest.DISABLED_InitCrashesWhenConfigIsNull`
- 输入/前置条件: 直接调用 `UDPCaster caster; caster.init(nullptr, nullptr, nullptr);`。
  `QuoteFactory/main.cpp` 与 `WtDtPorter/WtDtRunner.cpp` 都先检查
  `config->has("broadcaster")` 再取段并调用 `init`；仅仅缺少配置段不会走到该空指针形态。
- 期望行为: 与 `ShmCaster::init` 一致，先判 `cfg == NULL` 返回 false，并记一条 error 日志；广播器保持未启动
- 实际行为: L67 对空 `cfg` 调用 `getBoolean`，存在空指针解引用风险（静态推导；用例未运行）
- 复现步骤: 1) 构造 `UDPCaster`；2) 以 `nullptr` 配置调用 `init`；3) 此调用点存在空指针解引用风险（静态推导）
- 影响范围: 直接违反非空参数前置条件的调用会触发空指针行为；现有生产调用点在段缺失时
  不调用 `init`，因此不能据此声称缺少 caster 配置会导致 dt_srv 崩溃。`IDataCaster`/该
  方法注释未明确说明 NULL 是否为合法输入。
- 备注: `DISABLED_InitCrashesWhenConfigIsNull` 只构造直接 NULL 输入，本次未运行。若接口
  契约允许 NULL，应在入口判空并返回 false；若调用方必须传有效对象，应在接口说明中明确
  非空前置条件并保留调用点守卫。本条暂不计作已确认的生产故障。


- 迭代02复核: TEST。cfg 是必需配置指针，正常先解析后传入；没有 nullable 合同。直接 init(null) 属无效参数。
- 迭代02依据: [逐条裁定与主代理修订](../../迭代02/缺陷裁定总表.md)。原记录保留作为历史，未声称产品已修复。

## BUG-R68-002 ShmCaster::init 忽略文件创建/截断/映射失败（主记录，合并 R18-010）

- 状态: 待审核
- 严重级别: Major（目录路径异常已测；缺父目录路径仅源码推导）
- 产品文件:行: `src/WtDtCore/ShmCaster.cpp:35-64`（L39-43 `create_or_open_file`/`truncate_file` 返回值被丢弃；L47 `BoostMappingFile::map`；L48-51 `addr()` 后直接 `new CastQueue()`）
- 相关测试: `src/TestUnits/coverage/q05_dtsrv/r68_shm_caster_init_test.cpp::R68ShmCasterInitTest.InitWithDirectoryPathThrowsInsteadOfReturningFalse`
- 输入/前置条件: 配置 `{"active": true, "path": "<一个已存在的目录>"}`。父目录不存在是
  另一条静态失败形态，不能与目录输入的实测异常混作同一动态结果；不可写路径的具体行为
  依平台和文件系统而异，本次未测试。
- 期望行为: `init` 返回 false，`_queue` 保持 NULL、`_inited` 保持 false，进程继续以「shm 广播不可用」降级
- 实际行为: 本次运行的目录用例通过 `EXPECT_THROW`，确认该环境下 `init` 的异常会穿透调用方。
  源码显示 `BoostFile::create_or_open_file` 与 `truncate_file` 返回值被忽略；`BoostMappingFile::map`
  在目录上构造 `file_mapping` 可抛异常，`init` 没有 catch，也没有转为 `false`。若父目录不存在，
  `map` 会因路径不存在返回 false，之后 `addr()` 仍为 NULL，placement new 继续对空地址构造对象，
  属静态 UB 路径；本次未运行，不能写成已观察 SIGSEGV。
- 复现步骤: 1) 建一个临时目录 `D`；2) 写 `{"active": true, "path": "D"}` 并加载为 `WTSVariant`；3) `ShmCaster caster; caster.init(cfg);` -> 本次运行到 `interprocess_exception`。父目录不存在的 path 可静态推导到空地址 placement new，但本次未执行。
- 影响范围: 配置为已有目录时，本次验证到异常未按 `bool` 失败返回收口；父目录缺失时有静态空地址 UB 路径。对“只读磁盘”等具体部署故障，本次没有测试证据。
- 备注: 建议检查 create/truncate 返回值；检查 `map` 返回值与映射地址/长度；必要时捕获 Boost interprocess 异常并记录错误后返回 false。成功后再赋 `_queue`/`_inited`。目录路径异常由现有用例动态确认；父目录缺失分支仍需隔离验证。

## BUG-R68-003 IndexWorkerMgr 不释放已加载的工厂模块与工厂对象，重复 loadFactories 直接覆写句柄

- 状态: 待审核
- 严重级别: Minor（资源丢失由源码可确认；测试只验证重复加载后仍可用）
- 产品文件:行: `src/WtDtCore/IndexWorkerMgr.cpp:31-33`（析构为空）、`IndexWorkerMgr.cpp:73-86`（登记 `_module_inst`/`_fact`/`_remover`，L76 `_factories[fact->get_name()]` 覆写旧条目）
- 相关测试: `src/TestUnits/coverage/q05_dtsrv/r68_idxworker_factory_test.cpp::R68IndexWorkerFactoryTest.RepeatedLoadKeepsFactoryUsable`
- 输入/前置条件: 同一 `IndexWorkerMgr` 对同一目录连续调用两次 `loadFactories`（配置热重载/重复初始化），或正常析构
- 期望行为: manager 销毁时应销毁所拥有的工厂并释放对应模块。重名重载时应拒绝覆盖，或在确认没有 worker 继续依赖旧 factory 后安全销毁旧资源。
- 实际行为: `~IndexWorkerMgr()` 为空；`_factories[key] = ...` 后逐字段覆盖旧 `IdxFactInfo`，旧 `DllHandle` 与 `IIndexWorkerFact*` 没有经 `_remover`/`free_library` 释放，失去 manager 的回收入口。若此时已有 `IdxWorkerWrapper`，其保存的 `_fact` 仍被 `delete_worker` 使用，所以不能在覆盖时不经 worker 清理就直接销毁旧 factory。
- 复现步骤: 1) 准备 `libWtIndexFactory.dylib` 的临时目录；2) `mgr.loadFactories(dir)` 两次；3) 本次 `RepeatedLoadKeepsFactoryUsable` 通过，确认第二次装载后仍能创建 worker。测试未统计第一次 factory/模块是否释放；资源遗失由覆盖与空析构的源码控制流确认。
- 影响范围: manager 正常析构时工厂对象/模块缺少显式清理；同名重复装载时旧资源失去句柄。当前无内存增长或插件卸载的动态测量，不把具体增长速率作为已实测结论。
- 备注: 建议为加载资源建立明确所有权：先停止/销毁引用该 factory 的 worker，再调用其 `_remover`，最后 `free_library`；或对重名直接拒绝并保留原条目。manager 析构也需按 worker 先于 factory、factory 先于 module 的顺序清理。
