## BUG-R68-001 UDPCaster::init 不校验 cfg，NULL 直接空指针解引用

- 状态: 待审核
- 严重级别: Blocker
- 产品文件:行: `src/WtDtCore/UDPCaster.cpp:62-68`（L67 `cfg->getBoolean("active")` 前无判空）
- 相关测试: `src/TestUnits/coverage/q05_dtsrv/r68_udp_caster_init_test.cpp::R68UdpCasterInitTest.DISABLED_InitCrashesWhenConfigIsNull`
- 输入/前置条件: `UDPCaster caster; caster.init(nullptr, nullptr, nullptr);`（dt_srv 的 caster 配置段缺失时上层仍调用 init）
- 期望行为: 与 `ShmCaster::init` 一致，先判 `cfg == NULL` 返回 false，并记一条 error 日志；广播器保持未启动
- 实际行为: L67 对空 `cfg` 调用 `getBoolean`，SIGSEGV；进程在启动装配阶段直接崩溃
- 复现步骤: 1) 构造 `UDPCaster`；2) 以 `nullptr` 配置调用 `init`；3) 进程崩在 `UDPCaster.cpp:67`
- 影响范围: 任何「caster 段缺失/解析失败但仍继续装配」的部署都会崩进程，而不是退化为「UDP 广播不可用」；与 DataManager（BUG-R18-001）、IndexWorkerMgr（BUG-R44-006）同族的入口判空缺失
- 备注: 建议在 `init` 首行 `if (cfg == NULL) return false;`。阻塞该错误路径的覆盖率。

## BUG-R68-002 ShmCaster::init 忽略文件创建/截断失败，且不捕获映射异常：目录/不可写路径下抛异常或空指针 placement new

- 状态: 待审核
- 严重级别: Major
- 产品文件:行: `src/WtDtCore/ShmCaster.cpp:35-64`（L39-43 `create_or_open_file`/`truncate_file` 返回值被丢弃；L47 `BoostMappingFile::map`；L48-51 `addr()` 后直接 `new CastQueue()`）
- 相关测试: `src/TestUnits/coverage/q05_dtsrv/r68_shm_caster_init_test.cpp::R68ShmCasterInitTest.InitWithDirectoryPathThrowsInsteadOfReturningFalse`
- 输入/前置条件: 配置 `{"active": true, "path": "<一个已存在的目录>"}`（同理适用于无写权限的路径、父目录不存在的路径）
- 期望行为: `init` 返回 false，`_queue` 保持 NULL、`_inited` 保持 false，进程继续以「shm 广播不可用」降级
- 实际行为: `BoostFile::create_or_open_file` 与 `truncate_file` 失败后无人检查；`BoostMappingFile::map` 在 `file_mapping` 构造处抛 `boost::interprocess::interprocess_exception`，`init` 没有 try/catch，异常直接穿透调用方（未按 bool 契约返回）。若 path 的父目录不存在，`map` 会因 `boost::filesystem::exists==false` 返回 false，随后 `_mapfile->addr()` 为 NULL，L51 的 placement new 在 NULL 上构造 `CastQueue` -> SIGSEGV
- 复现步骤: 1) 建一个临时目录 `D`；2) 写 `{"active": true, "path": "D"}` 并加载为 `WTSVariant`；3) `ShmCaster caster; caster.init(cfg);` -> 抛 `interprocess_exception`；4) 改 path 为 `D/not_exist/queue.bin` 再 init -> 崩在 L51
- 影响范围: dt_srv 启动时 shm 路径写错/磁盘只读/父目录未创建是常见部署故障，表现为异常终止或崩溃，而不是按配置关闭 shm 广播；同时 `_mapfile` 已 reset，部分成员处于半初始化状态
- 备注: 建议：检查 create/truncate 返回值；`map` 返回值判 false 后 return false；对 `addr()` 判空；必要时 try/catch 转 error + false。目录输入的本轮启用用例锁定「抛异常」现状，修复后应改为断言返回 false。

## BUG-R68-003 IndexWorkerMgr 不释放已加载的工厂模块与工厂对象，重复 loadFactories 直接覆写句柄

- 状态: 待审核
- 严重级别: Minor
- 产品文件:行: `src/WtDtCore/IndexWorkerMgr.cpp:31-33`（析构为空）、`IndexWorkerMgr.cpp:73-86`（登记 `_module_inst`/`_fact`/`_remover`，L76 `_factories[fact->get_name()]` 覆写旧条目）
- 相关测试: `src/TestUnits/coverage/q05_dtsrv/r68_idxworker_factory_test.cpp::R68IndexWorkerFactoryTest.RepeatedLoadKeepsFactoryUsable`
- 输入/前置条件: 同一 `IndexWorkerMgr` 对同一目录连续调用两次 `loadFactories`（配置热重载/重复初始化），或正常析构
- 期望行为: 覆写前对旧条目调用 `delete_index_factory(_fact)` + `free_library(_module_inst)`；析构时统一释放所有已加载工厂
- 实际行为: `~IndexWorkerMgr()` 为空；`_factories[key] = ...` 只是覆写 `IdxFactInfo` 的裸指针字段，旧 `DllHandle` 与 `IIndexWorkerFact*` 既不解引用也不 `free_library`/`delete`，永久泄漏；进程退出前插件无法卸载
- 复现步骤: 1) 准备 `libWtIndexFactory.dylib` 的临时目录；2) `mgr.loadFactories(dir)` 两次；3) 第二次返回 true 且新工厂可用（用例已断言），但第一次的句柄/工厂对象已不可达且未释放
- 影响范围: 长驻 dt_srv 每次配置重载泄漏一个 dlopen 句柄与一个工厂对象；插件热升级/卸载不可行。不直接崩溃，故定为 Minor
- 备注: 建议给 `IdxFactInfo` 增加析构或在覆写/Manager 析构时统一 `delete_index_factory` + `free_library`；`_workers` 的 wrapper 已正确归还 worker，不在此条范围。
