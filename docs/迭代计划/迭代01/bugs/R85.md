## BUG-R85-001 — TraderAdapter::init 在插件 init 失败时日志文案错位，且把半初始化的 api 留在成员里

- 文件: `src/WtUftCore/TraderAdapter.cpp`
- 位置: L197-203（`_remover = get_symbol(hInst, "deleteTrader");` 之后 `if (!_trader_api->init(params))` 的失败支）
- 输入/前置条件: 模块可 dlopen、导出 `createTrader`/`deleteTrader`，但 `ITraderApi::init(params)` 返回 false
  （例如插件要求必填项缺失）。
- 期望行为: 日志应说明「交易接口初始化失败」；失败后应把 `_trader_api`/`_remover` 回滚，避免调用方误用。
- 实际行为: L201 打印的是 `"[{}] Entrance function deleteTrader not found"`——与真实原因（init 失败）不符，
  会把人引向符号问题；同时 L190 起已赋值的 `_trader_api`、L197 已赋值的 `_remover` 都保留着，`init` 虽返回 false，
  但对象仍处于「有 api」状态，后续若被 `run()`/`release()` 调用就会驱动一个初始化失败的接口。
- 复现步骤: 用任意 trader 插件，构造一份缺必填项的参数让 `TraderAdapter::init` 走到 L199 的 false 分支，观察 L201 日志。
- 影响: 排障误导 + 失败路径状态不一致；不改变返回码。
- 分级: C
- 状态: 待审核

## BUG-R85-002 — WtUftRtTicker::stop() 在非交易时段最长阻塞 10 秒，启停耗时随墙钟变化

- 文件: `src/WtUftCore/WtUftTicker.cpp`
- 位置: L192-249（工作线程 `while (!_stopped)` 内的 `sleep_for(milliseconds(10))` 与
  `else` 分支的 `sleep_for(seconds(10))`）；L257-264（`stop()` 只置 `_stopped` 后 `join()`）
- 输入/前置条件: `init()` 后 `_time` 被写成当前墙钟（L60）；在当前墙钟不落在交易时段内时调用 `run()`，
  等线程进入 `else` 的 10s 休眠后再 `stop()`。
- 期望行为: `stop()`/析构应在毫秒级返回；长休眠应可被停止标志打断（条件变量或分段休眠）。
- 实际行为: 线程在 `sleep_for(seconds(10))` 内不检查 `_stopped`，`join()` 必须等满这一觉；
  `WtUftEngine` 析构里 `ticker->stop()` 因此最长阻塞 10s。且是否落进该分支由 `init()` 读取的墙钟决定，
  同一份代码在不同时刻启停耗时不同（交易时段内 10ms 级，休息时段 10s 级）。
- 复现步骤: 在非交易时段构造 `WtUftRtTicker`，`init(<日盘时段>)`、`run()`，待线程进入 else 后 `stop()`，
  测量 `stop()` 墙钟耗时（≈10s）。
- 影响: 进程退出/热重启延迟；对交易结果无影响。本波 ticker 用例用全天时段规避该分支。
- 分级: C
- 状态: 待审核
