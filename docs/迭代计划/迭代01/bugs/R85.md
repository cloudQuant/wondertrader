## BUG-R85-001 — TraderAdapter::init 失败日志错位且失败 adapter 仍可进入 run

- 文件: `src/WtUftCore/TraderAdapter.cpp`
- 位置: L197-203（`_remover = get_symbol(hInst, "deleteTrader");` 之后 `if (!_trader_api->init(params))` 的失败支）；调用链还涉及 `src/WtUftRunner/WtUftRunner.cpp:313-335` 和 `TraderAdapterMgr::run`。
- 输入/前置条件: 模块可 dlopen、导出 `createTrader`/`deleteTrader`，但 `ITraderApi::init(params)` 返回 false
  （例如插件要求必填项缺失）。
- 期望行为: 日志应说明插件 `init(params)` 失败；返回 false 的 adapter 不应被当作可运行实例启动。清理/保留失败 API 的策略需与插件 `release`/delete 生命周期契约一致。
- 源码证据: L201 的文案指向缺失 `deleteTrader` 符号，但实际条件是 `_trader_api->init(params)` 返回 false。失败后 `_trader_api` 和 `_remover` 仍非空。`WtUftRunner::initTraders` 未检查返回值便登记 adapter；`WtUftRunner::run()` 随后调用管理器 `run()` 遍历登记项，而 `TraderAdapter::run()` 只以 `_trader_api == NULL` 作为拒绝条件，因此调用方可能继续对 init 失败的 API 执行 `registerSpi/connect`。
- 测试证据边界: `r85_uftcore_trader_paths_test.cpp` 只覆盖 mock 插件 init 成功和错单回复早退；没有插件 init 返回 false 的用例。本次未运行，也没有观察失败插件实际收到 `connect` 后的行为。
- 影响: 错误日志会误导排查；在 runner 配置路径上，失败 adapter 仍可能被启动。插件特定的实际后果尚未验证。
- 修复方向: 修正失败日志；让 `initTraders` 根据返回值跳过登记或显式登记为不可运行状态，`run()` 再按初始化状态守卫。只有在确认插件生命周期契约后再处理 `_trader_api/_remover` 回滚，避免错误销毁。
- 分级: Major（失败初始化仍传播到启动路径；插件侧效果未动态验证）
- 状态: 源码链已核对；失败插件动态行为未验证

## BUG-R85-002 — WtUftRtTicker::stop() 等待休息态轮询，且停止标志缺少线程同步

- 文件: `src/WtUftCore/WtUftTicker.cpp`
- 位置: L192-249（工作线程 `while (!_stopped)` 内的 `sleep_for(milliseconds(10))` 与
  `else` 分支的 `sleep_for(seconds(10))`）；L257-264（`stop()` 只置 `_stopped` 后 `join()`）
- 输入/前置条件: `init()` 后 `_time` 被写成当前墙钟（L60）；在当前墙钟不落在交易时段内时调用 `run()`，
  等线程进入 `else` 的 10s 休眠后再 `stop()`。
- 期望行为: `stop()`/析构应在毫秒级返回；长休眠应可被停止标志打断（条件变量或分段休眠）。
- 源码证据: 线程在 `sleep_for(seconds(10))` 内不检查 `_stopped`，`stop()` 置位后直接 `join()`；若线程已进入该休眠，join 至少要等休眠结束后线程才能检查标志。`_stopped` 是普通 `bool`，写入与循环读取未受同步保护，构成数据竞争；因此不能给出严格的“最长 10 秒”保证。`WtUftEngine` 析构会调用 ticker `stop()`。
- 墙钟边界: `init()` 用当前墙钟初始化 `_time`，所走交易/休息分支随当时会话与时刻变化；10 秒是休眠参数，不等于已测量的停机延迟上界。OS 调度也可能造成额外等待。
- 测试证据边界: `r85_uftcore_parser_ticker_test.cpp` 构造近全天会话并休眠 40ms，覆盖 10ms 活动分支；它只在 init 墙钟恰好处于 `00:00/01:00` 等边界时可能进入休息分支，既不确定也未断言停机耗时。本次未运行计时复现。
- 影响: ticker 停止/引擎析构可能等待当前休眠；普通 bool 的数据竞争还使退出观察没有确定保证。实际停机分布和交易结果影响未测。
- 修复方向: 将停止标志改为原子或受互斥保护，并用可中断等待（条件变量/停止令牌）；提供可控的会话时钟/分支接缝后测试休息态立即停止。
- 分级: C（资源/停机响应；数据竞争是条件性 UB）
- 状态: 静态停机路径已确认；未测动态延迟
