# R121 复核记录（第二十波 · WtBtCore mockers）

本次只读复核 `UftMocker` 与 `ExecMocker` 的两个候选问题；未修改生产代码和测试。静态代码结论与动态测试证据分开记录。

## BUG-R121-001 UftMocker 会话回调未检查 `_strategy`

- 审核结论：源码层行为成立；与 `bugs/p08_btcore_mockers3.md` 的 BUG-P08-001 为同一根因，R121 保留本编号作主记录，不重复计数。
- 代码位置：`src/WtBtCore/UftMocker.cpp:205-213,343-366`。
- 条件与行为：构造时 `_strategy` 初始化为 NULL；`init_uft_factory()` 可在无 `strategy` 节点时成功（`src/TestUnits/coverage/p08_btcore_mockers3/r121_uft_mocker_test.cpp` 的 `FactoryWithoutStrategy`）。公开 `handle_session_begin/end` 直接转发到 `on_session_begin/end`，后两者分别在持仓冻结处理后、会话结束日志处理前无条件调用 `_strategy`。在无策略状态调用时会执行空指针虚调用，属于未定义行为；具体进程结果未在本次动态复现。
- 对照：同一类的 `on_init`、`on_bar`、`on_tick_updated`、`on_order`、`on_trade`、`on_channel_ready` 都判 `_strategy`。无策略用例只调用 `handle_init`、成交等入口，没有调用会话入口，不能证明该分支安全。
- 证据边界：R111 的 per-test 崩溃日志不能定位为本问题；本次未运行故意触发空策略会话调用的测试。单独运行现有预编译 `R121UftMocker.FactoryWithoutStrategy` 到 `U7 end` 后以 139 退出，且没有调用会话入口；退出阶段原因未定位，不能当作会话回调的动态证据。源码路径和“无 strategy 配置可成功初始化”由现有测试源码支持，SIGSEGV 不是本次观察结果。
- 修复方向：对两个策略回调加一致的空值守卫；无策略时仍按上下文约定完成冻结结转及持仓/资金日志。补充无策略下分别调用 session begin/end 的回归检查。

## BUG-R121-002 ExecMocker 未检查 `createExeUnit()` 的空返回

- 审核结论：待审核的产品缺陷候选；与 BUG-N04-001/R20 的“未配置执行单元后仍进入回放回调”相邻但前置条件不同，不合并计数。
- 代码位置：`src/WtBtCore/ExecMocker.cpp:77-82`。
- 条件与行为：配置有 `executer` 且 `executer.name` 为非空的未知名称时，具体工厂 `WtExeFact::createExeUnit()` 按其实现和注释（`src/WtExeFact/WtExeFact.cpp:91-107`）返回 NULL；`ExecMocker::init()` 随即执行 `_exec_unit->init(...)`，没有把失败转换为 `false`。这是空指针虚调用的源码证据；本次没有在运行时重现。
- 接口/契约边界：`IExecuterFact::createExeUnit()` 声明返回裸指针，接口声明本身未写明失败值；`WtExeFact` 的具体实现明确对不支持的名称返回 NULL。因此结论限于该工厂契约，不能推为所有插件都必然用 NULL 表示失败。
- 测试边界：`R121ExecMocker.FactoryWithoutExecuter` 省略整个 `executer` 节点，没有覆盖“节点存在但名称未知”。`n05_exe_fact_test.cpp` 中工厂测试证明具体工厂对未知名称返回 NULL，但没有验证 `ExecMocker::init()` 如何处理。现有预编译 `CoverageTests_btcore` 运行 `FactoryWithoutExecuter` 时在测试体打印 `E8 end` 后以 139 退出，退出阶段原因尚未定位；该结果不作为本条或未知名称路径的动态证据。
- 修复方向：检查工厂实例和 `createExeUnit()` 结果；失败时记录执行器名称并让 `init()` 返回 false，保证 runner 不注册失败的 mocker/继续回放。增加“已加载工厂、未知非空名称”的隔离测试；不要用缺省 `executer` 测试替代该输入。
