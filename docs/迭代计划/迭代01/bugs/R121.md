## BUG-R121-001 UftMocker 会话回调在无策略时解引用空 `_strategy`（状态：待审核）

- 编号: BUG-R121-001
- 状态: 待审核
- 模块/文件/行:
  - `src/WtBtCore/UftMocker.cpp:361`（`on_session_begin` 末尾无条件 `_strategy->on_session_begin(...)`）
  - `src/WtBtCore/UftMocker.cpp:366`（`on_session_end` 开头无条件 `_strategy->on_session_end(...)`）
  - 公开入口：`UftMocker::handle_session_begin`（L205-208）、`handle_session_end`（L210-213）
- 现象:
  - 同文件的 `on_init`/`on_bar`/`on_tick_updated`/`on_order`/`on_trade`/`on_entrust`/
    `on_channel_ready` 都先判 `if (_strategy)`，唯独两个会话回调没有判空。
  - 未调用 `init_uft_factory`（或工厂加载失败）时 `_strategy == NULL`，公开的
    `handle_session_begin/end` 立即对空指针发起虚调用。
- 输入/前置条件:
  - 构造 `UftMocker m(&replayer, "x")`，不调用 `init_uft_factory`；
  - 调用 `m.handle_session_begin(20200102u)` 或 `m.handle_session_end(20200102u)`。
- 期望:
  - 与同文件其它回调一致：`_strategy` 为空时跳过策略回调，会话冻结释放/资金日志仍可执行；
    或记录错误并返回。
- 实际:
  - `_strategy->on_session_begin/on_session_end` 空指针虚调用，进程 SIGSEGV。
- 复现步骤:
  1. 用任意已 `init` 的 `HisDataReplayer` 构造 `UftMocker`（不需要策略插件）；
  2. 调用 `handle_session_begin(20200102u)`；
  3. 观察崩溃栈顶为 `UftStrategy::on_session_begin` 类虚调用。
- 旁证:
  - `build-cov/coverage/CoverageTests_btcore.R111UftMocker_SessionFreezeReleaseEnumAndUnknownCommodity.log`
    停在 `[ RUN ]` 后无 PASS 行；R111 用例在 `handle_session_begin` 之后、枚举持仓之前中断。
  - R111 只把 `stra_enum_position` 的空策略问题归到 BUG-R72-001，未登记本会话回调行。
- 测试处理:
  - 本轮 `R121UftMocker.PluginStrategyLifecycle` 只在真实策略非空时调用会话回调；
    `R121UftMocker.FactoryWithoutStrategy` 不调用会话入口，避免重演崩溃。
- 严重级别: Major（公开 API、无策略即崩；与 BUG-R111-001 同根：缺少 `_strategy` 判空）

## BUG-R121-002 ExecMocker::init 未检查 createExeUnit 返回值（状态：待审核）

- 编号: BUG-R121-002
- 状态: 待审核
- 模块/文件/行:
  - `src/WtBtCore/ExecMocker.cpp:80-81`
  - `_exec_unit = _factory._fact->createExeUnit(cfgExec->getCString("name"));`
  - `_exec_unit->init(this, _code.c_str(), cfgExec->get("params"));`
- 现象:
  - `IExecuterFact::createExeUnit` 对未知名称返回 NULL（`WtExeFact.cpp::createExeUnit` 的末行
    `return NULL`），`ExecMocker::init` 未判空就直接 `_exec_unit->init(...)`。
  - 后续 `handle_entrust/handle_order/handle_trade` 也无条件解引用 `_exec_unit`。
- 输入/前置条件:
  - 配置 `module` 指向真实 `libWtExeFact`，`executer.name` 写成工厂不认识的名称，
    例如 `"NoSuchExecUnit"`；
  - 调用 `ExecMocker::init(cfg)`。
- 期望:
  - `createExeUnit` 返回 NULL 时记录错误并返回 false（与同文件模块加载失败分支一致），
    不应在 init 内崩溃。
- 实际:
  - `_exec_unit->init(...)` 空指针虚调用，进程 SIGSEGV。
- 复现步骤:
  1. 用真实 `libWtExeFact` 和 `executer.name = "NoSuchExecUnit"` 构造 `ExecMocker::init` 配置；
  2. 调用 `init`；
  3. 观察崩溃栈顶为 `ExecuteUnit::init` 类虚调用。
- 旁证:
  - `build-cov/coverage/CoverageTests_btcore.R111ExecMocker_InitWithRealExecuterAndInitSchedule.log`
    与 `...ScheduleNegativeAndPositiveVolumeModes.log` 都停在 `[ RUN ]` 后无 PASS 行；
    R111 的 `executer.name` 为合法 `"WtMinImpactExeUnit"`，故其崩溃点可能另有原因，
    但本条的「未知名称 → NULL → 直接解引用」由源码可直接证明。
- 测试处理:
  - 本轮 `R121ExecMocker.FactoryWithoutExecuter` 只覆盖「插件装载成功、无 executer 配置」，
    不创建执行单元，避开该路径；未新增会 SIGSEGV 的 `DISABLED_` 用例。
- 严重级别: Major（配置写错执行单元名即崩；与 BUG-R111-001 策略工厂同构）
