## BUG-R84b-001 StateMonitor::isInState 对 NULL sid 无守卫，用 nullptr 构造 std::string 属未定义行为

- 状态: 待审核
- 严重级别: Minor
- 模块/文件: `src/WtDtCore/StateMonitor.h:211-222`（`inline bool isInState(const char* sid, SimpleState ss) const`，L214 `_map.find(sid)`）
- 相关测试: `r84b_state_monitor_positive_offset_test.cpp::R84bStateMonitorPositiveOffsetTest.DISABLED_NullSessionIdCrashesIsInState`
- 输入/前置条件: 任意 `StateMonitor` 实例（空表也可以），调用 `mon.isInState(nullptr, SS_ORIGINAL)`
- 期望行为: 与未知 sid / 空串 sid 一致，安全返回 false（不崩溃、不抛异常）
- 实际行为: `_map` 是 `wt_hashmap<std::string, StatePtr>`，`find(const char*)` 会先把 `sid` 转成 `std::string`；`std::string(nullptr)` 在 C++ 标准里是未定义行为，libc++ 通常触发断言/异常，部分实现直接 SIGSEGV。当前代码没有任何 `sid == nullptr` 守卫
- 复现步骤: 1) 构造 `StateMonitor mon;` 2) 调用 `mon.isInState(nullptr, SS_ORIGINAL);` 3) 观察崩溃/异常（本 lane 按约束只保留 `DISABLED_` 占位，未实际执行）
- 影响范围: 公有查询接口的上游若传入空指针（例如配置项缺省、C 字符串拼接失败），进程会崩溃而不是按「未命中」降级；`isInState("")` 已能安全返回 false，NULL 却没有同等保护
- 备注: 建议在 `isInState` 入口加 `if (sid == nullptr) return false;`（或改为 `std::string_view` 接口并显式判空）。修复后把 `DISABLED_` 用例改为启用并断言 false。
