## BUG-R53-001【高】WTSEntrustAction::createCancelAction 裸 new 池对象，release 走空对象池崩溃

- 状态: 待审核
- 严重级别: Blocker（稳定 SIGSEGV）
- 模块/文件: `src/Includes/WTSTradeDef.hpp:237-248`（`createCancelAction`）与 `src/Includes/WTSObject.hpp:92-111`（`WTSPoolObject::release`）
- 相关测试: 既有 `src/TestUnits/coverage/r12_headers/r12_trade_def_test.cpp` → `r12_trade_action.cancel_action_fields`（本轮重跑判决 `CRASH(rc=139,sig=11)`）；本轮新增 `r53_trade_def_more_test.cpp` → `DISABLED_r53_entrust_action.cancel_action_release_uses_allocated_pool`
- 输入: `WTSEntrustAction* a = WTSEntrustAction::createCancelAction("1001", "OID01"); a->release();`
- 期望行为: `release()` 引用计数归零后把对象归还对象池，进程正常退出。
- 实际行为: `WTSEntrustAction` 派生自 `WTSPoolObject<WTSEntrustAction>`，正常路径必须用 `allocate()` 初始化 `_pool/_mutex`；`createCancelAction` 却用 `new WTSEntrustAction`，基类构造只把 `_pool` 置 NULL，`_mutex` 保持未初始化。`release()` 在计数 1→0 时执行 `_mutex->lock(); _pool->destroy(this);`，对未初始化/空指针解引用，进程 SIGSEGV。
- 复现步骤:
  1. 覆盖率构建后单跑 `CoverageTests --gtest_filter='r12_trade_action.cancel_action_fields'`；
  2. 观测退出码 139 / SIGSEGV；`build-cov/coverage/CoverageTests.results:576` 记录 `CRASH(rc=139,sig=11) r12_trade_action.cancel_action_fields`。
- 影响: 所有走撤单/改单动作构造的实盘链路（`TraderAdapter::cancelOrder` 等）在对象释放时崩溃；这是当前轮唯一已实测的 use-after-pool-null 崩溃点。修复方向：改为 `WTSEntrustAction::allocate()`（与 `create()` 一致）或为裸 new 对象补 `_pool/_mutex` 初始化。

## BUG-R53-002【中】WTSMap::erase 三个重载只摘除节点不释放元素，稳定泄漏

- 状态: 待审核
- 严重级别: Major（长期运行内存泄漏；与 `remove/clear` 契约不一致）
- 模块/文件: `src/Includes/WTSCollection.hpp:494-510`（`erase(ConstIterator)`、`erase(Iterator)`、`erase(T key)`）；对照 `remove` `:418-428` 与 `clear` `:546-554` 均会 `release()`
- 相关测试: 本轮 `r53_collection_variant_test.cpp` → `DISABLED_r53_map.erase_by_key_does_not_release_element`
- 输入: `WTSMap<int>* m = WTSMap<int>::create(); WTSObject* o = new R53TagObj(7); m->add(1, o, true); m->erase(1);`
- 期望行为: `erase(key)` 与 `remove(key)` 语义一致，元素引用计数从 2 降为 1（容器持有的那一份被释放）。
- 实际行为: `_map.erase(key)` 直接丢弃 `WTSObject*`，不调用 `release()`；实测 `o->retainCount()` 仍为 2，`size()` 已为 0，元素不可达且永不释放。`erase(Iterator)`/`erase(ConstIterator)` 同形。
- 复现步骤: 运行上述 DISABLED 用例（去掉 DISABLED 前缀）即可看到 `retainCount == 2` 与 `EXPECT_EQ(..., 1u)` 失败；对象本身可正常构造/释放，不会崩溃。
- 影响: 使用 `WTSMap::erase` 做逐条删除的容器（订单/持仓/合约映射）在长生命周期进程中持续泄漏元素及其内部字符串/缓冲区；若元素是池对象，还会耗尽对象池并放大内存占用。

## BUG-R53-003【中】WTSTickStruct::operator= 用 strncpy 复制旧结构体全宽字段，不保证 '\0' 终止

- 状态: 待审核
- 严重级别: Major（后续 strlen/%s 越界读；堆/栈相邻字段信息泄露）
- 模块/文件: `src/Includes/WTSStruct.h:203-205`（`strncpy(exchg, tick.exchg, MAX_EXCHANGE_LENGTH); strncpy(code, tick.code, MAX_INSTRUMENT_LENGTH);`）
- 相关测试: 本轮 `r53_struct_union_test.cpp` → `DISABLED_r53_struct_tick.assignment_terminates_full_width_code`
- 输入: `WTSTickStructOld ot; memset(ot.exchg, 'E', 10); memset(ot.code, 'C', 32); WTSTickStruct nt; nt = ot;`
- 期望行为: 赋值后的 `nt.exchg[0..9]` 与 `nt.code[0..31]` 至少各有一个 '\0'，可安全当 C 字符串使用。
- 实际行为: 源字段没有终止符时 `strncpy` 恰好写满目标数组且不补 '\0'；`nt.exchg`/`nt.code` 全宽无终止符。旧结构体是二进制行情落盘/跨版本兼容格式，字段被写满属合法输入。
- 复现步骤: 运行上述 DISABLED 用例（去掉 DISABLED 前缀），`buffer_has_nul(nt.exchg, 10)`/`buffer_has_nul(nt.code, 32)` 均为 false；用例只读取目标数组范围内存，不会在断言阶段越界。
- 影响: 赋值结果进入 `code()/exchg()` 或日志 `%s` 时越过 32/10 字节读取相邻字段，可能输出脏数据或触发 ASAN；跨版本行情转换（旧 tick → 新 tick）是常规路径。
