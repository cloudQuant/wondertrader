## BUG-R144-001

- 状态: 已合并（迭代02：主编号 BUG-R175-001）
- 严重级别: Minor（已确认范围是 TraderMocker 插件清理；未据此推断真实柜台插件都受影响）
- 模块/文件:
  - `src/TraderMocker/TraderMocker.cpp` L659-664（`registerSpi`）
  - `src/WtUftCore/TraderAdapter.cpp` L223-230（`release`）
- 相关测试: `src/TestUnits/coverage/q04_uftcore3/r85_uftcore_trader_paths_test.cpp`
  `R85UftTraderInit.loads_mock_trader_module_and_returns_true` 明确调用 `adapter.release()`，现存
  记录为 `CRASH(rc=139,sig=11)`（日志未保留故障栈）；`R133TraderAdapterInit` 当前夹具显式跳过
  `release()`，只覆盖 init，不能作为该路径的复现或 PASS 证据。
- 输入/前置条件:
  1. 临时模块根内软链本机构建产物 `libTraderMocker.dylib`；
  2. `TraderAdapter::init("...", {"module":"TraderMocker","mockerid":...}, ...)` 成功；
  3. 调用公开的 `TraderAdapter::release()`。
- 期望行为: `TraderAdapter::release()` 当前会把 `NULL` 传给插件的 `registerSpi`；插件需支持该清理
  调用，或由 API 明确规定并由 adapter 遵守非空契约。当前 `ITraderApi` 头文件未见该参数的空值约定。
- 实际行为（静态核对）: `TraderAdapter::release()` 第一行执行 `_trader_api->registerSpi(NULL)`；
  `TraderMocker::registerSpi(ITraderSpi* listener)` 无条件执行
  `_bd_mgr = listener->getBaseDataMgr();`，`listener == NULL` 时解引用空指针，
  该清理路径有空指针解引用风险。R85 用例的进程退出码 139 与该路径相符，但日志没有栈帧，
  因而动态记录本身不能独立定位到这一行。
- 复现步骤:
  1. 按上述步骤装载并 `init` TraderMocker；
  2. 调用 `adapter.release()`；
  3. 已有 R85 测试进程退出码为 139；需在获取堆栈后确认具体帧。
- 影响范围: 使用 `TraderMocker` 且调用 `TraderAdapter::release()` 时有风险；不将结论外推到
  其它插件。修复方向：让 `TraderMocker::registerSpi(NULL)` 清空 `_bd_mgr` 并安全返回，或统一
  adapter/plugin 的 SPI 空值契约。
- 备注: R133 夹具为 init-only 而跳过资源释放；恢复 `release()` 前应先修插件并用 R85/R133 重新验收。


- 迭代02复核: DUPLICATE。与 BUG-R175-001 完全同根因：TraderAdapter::release 传 NULL 给 TraderMocker::registerSpi，而 mocker 随即解引用。R85 active 用例已在 init 后显式调用 release，因此‘测试绕过释放’不是当前事实；本轮未运行它。

## 既有缺陷复核（不新增编号）

### R4-BUG-02：AD reader 缓存句柄移空

- R144 原 BUG-R144-002 描述的是 `get_k_db` 返回 `std::move(it->second)` 后，RT bar 超前分支
  第二次回源在 `update_cache_from_lmdb` 解引用空句柄。该根因及空句柄读取后果已由
  `R4-BUG-02` 登记，R4 还列出 `DISABLED_AdvancingEtimeAfterTwoHandlesCrashesOnNullDb`。
- R144 所引 `R132ReaderADRtBarAheadRechecksLmdb` 的旧记录为禁用用例；R142/R155 的夹具规则
  明确限制每个 `(交易所, 周期)` 的句柄读取次数以规避同一问题。当前证据支持复核 `R4-BUG-02`，
  不支持另立 BUG-R144-002。
- 纠正旧表述：RT bar 超前判断分支本身可以被执行；失败的是再次回源时取得空句柄后的读取，
  不能称该分支“不可达”。

### BUG-R35-001：WtCtaEngine 未初始化即析构

- R144 原 BUG-R144-003 与 `BUG-R35-001` 同根因：构造函数未初始化 `_cfg`，析构会检查并可能
  释放该未初始化指针。`R35_wtporter.md` 已列源码风险及禁用用例的退出码边界，本文件不重复计数。
- R130 当前引擎测试已补 `init`；R140 两个未 init 引擎用例仍由 R155 记录为 `CRASH(rc=139)`，
  但退出码本身不能单独证明唯一故障点是 `_cfg`。统一沿用 `BUG-R35-001`。

## BUG-R144-004

- 状态: 已撤回（迭代02：TEST，原产品主张不成立）
- 严重级别: 条件性候选（生产 runner 在启动路径显式 `set_adapter_mgr`；是否允许裸引擎不设 manager
  调度，需要由公开 API 契约确认）
- 模块/文件: `src/WtCore/WtCtaEngine.cpp` L407-412（`on_schedule` 的 `push_task` lambda）
- 相关测试: `src/TestUnits/coverage/q01_wtcore3/r130_ticker_on_tick_test.cpp`
  `R130TickerOnTick.CtaTickerDrivesEngineThroughMinuteClose` 当前在运行前显式设置空的
  `TraderAdapterMgr`，因此没有复现 manager 为 NULL 的行为。
- 输入/前置条件:
  1. `WtCtaEngine::init` 后直接创建 `WtCtaRtTicker` 并 `run()`（不经 runner）；
  2. 喂 09:30/09:31/09:31:30 三笔 tick，第二笔触发 `on_schedule`；
  3. 未调用 `set_adapter_mgr`。
- 期望行为: 先明确契约：若 `set_adapter_mgr` 是使用 `WtCtaEngine` 调度的必需前置条件，应在
  初始化/启动阶段检查并报告；若 manager 可选，则资金刷新应在 NULL 时跳过。
- 实际行为（静态核对）: `WtEngine` 构造函数将 `_adapter_mgr` 设为 NULL；`WtCtaEngine::on_schedule`
  任务体无条件执行 `_adapter_mgr->refresh_funds()`。现有引用用例已注入空 manager，没有针对 NULL
  manager 执行跨分钟调度的动态复现或堆栈证据。
- 拟复核步骤（静态推演，尚未运行）:
  1. 裸 `WtCtaEngine` + `WtCtaRtTicker`，不设 adapter mgr；
  2. 喂跨越分钟边界的 tick；
  3. 若任务线程执行到无条件调用，静态上会对 NULL manager 解引用；当前没有该序列的动态崩溃证据。
- 影响范围: 仅在不调用 `set_adapter_mgr` 仍触发 `on_schedule` 且该用法符合公开契约时成立；
  生产 runner 路径设置了 manager。修复方向取决于契约：可选时判空；必需时增加前置条件校验，
  并避免后台任务异步解引用空指针。
- 备注: 本 lane 的夹具补了一个空 `TraderAdapterMgr` 并保证其生命周期长于 engine，
  断言不变；这修的是测试前置条件，不是产品实现，也不能作为 manager-NULL 风险已修复的证据。
