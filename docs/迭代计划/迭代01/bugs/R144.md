## BUG-R144-001

- 状态: 待审核
- 严重级别: Minor（Mock 插件生命周期；不影响真实柜台，但会让任何 release 真实插件的用例崩溃）
- 模块/文件:
  - `src/TraderMocker/TraderMocker.cpp` L659-664（`registerSpi`）
  - `src/WtUftCore/TraderAdapter.cpp` L223-230（`release`）
- 相关测试: `src/TestUnits/coverage/q04_uftcore3/r133_uftcore_remaining_test.cpp`
  `R133TraderAdapterInit.loads_mocker_module_and_initializes`
  （另：`R85UftTraderInit.loads_mock_trader_module_and_returns_true` 在同一路径上也是
  `CRASH(rc=139,sig=11)`）
- 输入/前置条件:
  1. 临时模块根内软链本机构建产物 `libTraderMocker.dylib`；
  2. `TraderAdapter::init("...", {"module":"TraderMocker","mockerid":...}, ...)` 成功；
  3. 调用公开的 `TraderAdapter::release()`。
- 期望行为: `release()` 只清空 SPI 并释放插件，`registerSpi(NULL)` 是合法的“解绑”调用。
- 实际行为: `TraderAdapter::release()` 第一行执行 `_trader_api->registerSpi(NULL)`；
  `TraderMocker::registerSpi(ITraderSpi* listener)` 无条件执行
  `_bd_mgr = listener->getBaseDataMgr();`，`listener == NULL` 时解引用空指针，
  进程 `SIGSEGV`。崩溃发生在用例全部断言之后（id/state/二次 init 均通过），
  属清理阶段崩溃。
- 复现步骤:
  1. 按上述步骤装载并 `init` TraderMocker；
  2. 调用 `adapter.release()`；
  3. 进程在 `TraderMocker.cpp:663` 崩溃。
- 影响范围: 所有使用真实 `libTraderMocker` 且调用 `TraderAdapter::release()` 的测试/工具；
  其它实现了 `ITraderApi` 的插件若同样不判空也会复现。修复方向：`TraderMocker::registerSpi`
  在 `listener == NULL` 时清空 `_bd_mgr` 后返回，或 `TraderAdapter::release` 先判空。
- 备注: 本 lane 的用例只验证 init 成功链，不 run/connect，因此夹具不再调用 `release()`
  （不改变任何断言），待插件修复后恢复资源释放即可。

## BUG-R144-002

- 状态: 待审核
- 严重级别: Major（公开读取 API 空指针崩溃；对应分支在公开 API 下不可达）
- 模块/文件: `src/WtDataStorageAD/WtDataReaderAD.cpp`
  - `update_cache_from_lmdb` L269-274：`WtLMDBPtr db = get_k_db(...); WtLMDBQuery query(*db);`
    没有 `db == NULL` 检查
  - `get_k_db` L576-579：命中缓存时 `return std::move(it->second);` 把
    `_exchg_m1_dbs/_m5/_d1` 的槽位掏空（既有 `R4-BUG-02`）
  - 调用点 L444-456：RT bar 时间超前时的第二次 `update_cache_from_lmdb`
- 相关测试: `src/TestUnits/coverage/p05_datastorage2/r132_reader_ad_cache_test.cpp`
  `DISABLED_R132ReaderADCacheTest.R132ReaderADRtBarAheadRechecksLmdb`（保留原输入与断言）
- 输入/前置条件:
  - LMDB `min1/EXQ` 内 09:31/09:32/09:33 三根 bar；
  - `cache_m1.dmb` 内 RT 缓存最后一根 09:35；
  - 请求 `readKlineSlice("EXQ.rb2301", KP_Minute1, 2, 20230103093400000)`。
- 期望行为: 首次 `update_cache_from_lmdb` 不新增后，发现 RT bar(09:35) 晚于截止(09:34)，
  再次回源 LMDB；`get_k_db` 应返回可用句柄或 `update_cache_from_lmdb` 判空后安全返回，
  最终返回 09:32/09:33 两根 bar。
- 实际行为:
  1. `cacheBarsFromStorage` 首次 `get_k_db` 后缓存槽被 `std::move` 掏空；
  2. 第二次 `update_cache_from_lmdb` 的 `get_k_db` 命中空 shared_ptr，返回空 `WtLMDBPtr`；
  3. `WtLMDBQuery query(*db)`（WtLMDB.hpp:111-112）解引用 `this == NULL`，
     `is_readonly()` 读取 `0x10` 偏移，进程 `SIGSEGV`。
- 复现步骤:
  1. 按上述输入 seed bar 与 RT cache；
  2. `--gtest_also_run_disabled_tests --gtest_filter=*RtBarAheadRechecksLmdb*`；
  3. rc=139，崩溃栈 `WtLMDBQuery -> update_cache_from_lmdb -> readKlineSlice`。
- 影响范围: 同一 reader 实例对同一 (交易所, 周期) 第二次取库起，任何再次进入
  `update_cache_from_lmdb` 的路径都会空指针；`readKlineSlice` 的“RT bar 超前二次回源”
  分支因此成为事实不可达代码（R142 manifest 亦记录同一结论）。
- 备注: 修复方向（二者任一即可，建议都做）：`get_k_db/get_t_db` 返回 `it->second`
  而非 `std::move`；`update_cache_from_lmdb` 在 `db == NULL` 时直接返回并记录日志。

## BUG-R144-003

- 状态: 待审核
- 严重级别: Minor（构造后未 init 即析构会崩溃；正常 runner 都会 init）
- 模块/文件:
  - `src/WtCore/WtCtaEngine.cpp` L31-47（构造函数只初始化 `_tm_ticker`）
  - `src/WtCore/WtCtaEngine.h` L92（`WTSVariant* _cfg;`）
- 相关测试:
  - `src/TestUnits/coverage/q01_wtcore3/r130_engine_fee_test.cpp`（4 个 TEST）
  - `src/TestUnits/coverage/q01_wtcore3/r130_stractx_wrapper_test.cpp`
    `R130CtxWrapper.CtaForwardsEveryCallbackToStrategy`
- 输入/前置条件:
  1. 栈上 `P01CtaEngine engine;`（`WtCtaEngine` 派生，只 `attach` 基础数据，不 `init`）；
  2. 作用域结束，`~WtCtaEngine` 执行。
- 期望行为: 构造函数应把 `_cfg` 初始化为 `NULL`（与 `WtSelEngine`/`WtHftEngine` 一致），
  未 `init` 的对象析构时安全跳过 `_cfg->release()`。
- 实际行为: `WtCtaEngine` 构造函数未初始化 `_cfg`；`WtCtaEngine::init` 才赋值并 retain。
  `~WtCtaEngine` 无条件 `if (_cfg) _cfg->release();`，未 init 的实例读到栈残留值，
  用例结束即 `SIGSEGV`（本波 5 条 wtcore crash 的共同根因）。
- 复现步骤:
  1. `P01CtaEngine engine; engine.attach(&bd, &hot);`（不 init）；
  2. 作用域结束；
  3. 崩溃栈 `WtCtaEngine::~WtCtaEngine -> WTSVariant::release`。
- 影响范围: 任何构造后未成功 `init` 就被销毁的 `WtCtaEngine`（异常退出、配置缺失的
  早退路径、单元测试夹具）。修复方向：构造函数初始化 `_cfg(NULL)`，并在
  `WtEngine::init` 失败/早退时保持可析构。
- 备注: 本 lane 的夹具改为先 `engine.init(...)`（空 fees/filters），断言不变；
  产品代码未改。

## BUG-R144-004

- 状态: 待审核
- 严重级别: Minor（生产 runner 总会 `set_adapter_mgr`；裸引擎/测试夹具会崩）
- 模块/文件: `src/WtCore/WtCtaEngine.cpp` L407-412（`on_schedule` 的 `push_task` lambda）
- 相关测试: `src/TestUnits/coverage/q01_wtcore3/r130_ticker_on_tick_test.cpp`
  `R130TickerOnTick.CtaTickerDrivesEngineThroughMinuteClose`
- 输入/前置条件:
  1. `WtCtaEngine::init` 后直接创建 `WtCtaRtTicker` 并 `run()`（不经 runner）；
  2. 喂 09:30/09:31/09:31:30 三笔 tick，第二笔触发 `on_schedule`；
  3. 未调用 `set_adapter_mgr`。
- 期望行为: `on_schedule` 在 `_adapter_mgr == NULL` 时跳过资金刷新（或由基类提供空实现），
  其余调度/落盘逻辑照常执行。
- 实际行为: `on_schedule` 无条件 `push_task([this]{ ... _adapter_mgr->refresh_funds(); })`；
  任务线程在 `TraderAdapterMgr::refresh_funds` 的 `_adapters.begin()` 处解引用 NULL，
  `SIGSEGV`（栈：`refresh_funds -> on_schedule lambda -> task_loop`）。
- 复现步骤:
  1. 裸 `WtCtaEngine` + `WtCtaRtTicker`，不设 adapter mgr；
  2. 喂跨越分钟边界的 tick；
  3. 进程在任务线程崩溃。
- 影响范围: 未配置交易通道的 CTA 引擎（纯回放/测试/只读行情）无法安全跨分钟调度。
  修复方向：`if (_adapter_mgr) _adapter_mgr->refresh_funds();`
- 备注: 本 lane 的夹具补了一个空 `TraderAdapterMgr` 并保证其生命周期长于 engine，
  断言不变；产品代码未改。
