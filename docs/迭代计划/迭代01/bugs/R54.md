## BUG-R54-001 — `onRspTrades` 只认 `tInfo->getContractInfo()`，缺 ContractInfo 时整条成交被静默丢弃

- 状态: 待审核
- 严重级别: A（静默错误结果，风控统计永不推进）
- 产品文件: `src/WtUftCore/TraderAdapter.cpp:1408-1453`（关键行 1414-1418）
- 相关测试: `src/TestUnits/coverage/q04_uftcore3/r54_trader_callback_gaps_test.cpp` → `DISABLED_R54TraderCallback.onRspTrades_without_contract_info_drops_stats`；同文件 `R54TraderCallback.response_chain_reaches_channel_ready` / `order_limit_exhaustion` 必须显式 `setContractInfo` 才能通过
- 输入/前置条件: 已 `initExt + run + login`；构造 `WTSTradeInfo::create("ag2406","SHFE")`，设置 `WDT_LONG/WOT_OPEN/volume=2`，**不调用** `setContractInfo`，经 `WTSArray` 调 `onRspTrades`；随后对同一合约执行 `buy`（规则组 `limit_l=1`）
- 期望行为: 与 `onRspOrders`（`:1286-1288`）和 `onPushTrade`（`:1739-1740`）一致：`getContractInfo()` 为空时回落 `_bd_mgr->getContract(tInfo->getCode(), tInfo->getExchg())`，把 2 手计入 `l_openvol`，后续 1 手买单被 `limit_l` 拦下
- 实际行为: `:1416` 取 `cInfo = tInfo->getContractInfo()`，`:1417-1418` 为 NULL 直接 `continue`；2 手成交完全不进入 `_stat_map`，`l_openvol` 仍为 0，后续 `buy` 正常发出 1 手委托
- 复现步骤: 启用上述 DISABLED 用例即可稳定失败（`buy` 返回非空、`_entrusts.size()==1`）；或把 q04 的 `feedTrade` 去掉 `setContractInfo` 后跑限额用例
- 影响: 柜台“查成交”回报通常只带代码/交易所而不带进程内 `ContractInfo`；重启/登录后的历史成交统计会全部丢失，`_limit/_limit_l/_limit_s` 三条总量风控在当日剩余时段静默失效。与 `onRspOrders`/`onPushTrade` 的容错行为不一致，属于实现遗漏而非调用方契约
- 备注: `_bd_mgr` 非空时修复成本很低；若产品确认“柜台必须回填 ContractInfo”，则应把该约束写进 `ITraderApi` 契约并在 `onRspTrades` 加日志，而不是静默丢弃

## BUG-R54-002 — `UftStraContext::on_tick` 对有持仓合约无条件解引用 tick 的 `ContractInfo`，实盘首笔行情必崩

- 状态: 待审核
- 严重级别: S（空指针解引用，进程崩溃）
- 产品文件: `src/WtUftCore/UftStraContext.cpp:69-97`（关键行 71-84）；关联 `src/WtUftCore/ParserAdapter.cpp:256-263`
- 相关测试: `src/TestUnits/coverage/p06_uftcore2/r54_uftctx_callback_gaps_test.cpp` → `DISABLED_R54UftCtx.tick_without_contract_info_crashes_with_local_position`
- 输入/前置条件: 策略上下文已有本地持仓（手工持仓导入或成交回报均可）；行情 tick 的 `getContractInfo()==NULL`
- 期望行为: `on_tick` 应使用入参 `stdCode` 通过 `_engine->get_contract_info(stdCode)` 取合约/品种，或 `ParserAdapter::handleQuote` 在解析出 `cInfo` 后调用 `quote->setContractInfo(cInfo)`；两种方式都能避免解引用空指针
- 实际行为: `:74` 直接 `newTick->getContractInfo()->getCommInfo()`。`ParserAdapter::handleQuote`（`:256-263`）虽然查到了 `cInfo`，但只执行 `quote->setCode(cInfo->getFullCode())`，**没有** `setContractInfo`；因此解析侧正常推送的 tick 在策略有持仓时首笔即 SIGSEGV
- 复现步骤: 启用上述 DISABLED 用例：`on_channel_ready(20240315)` → `stra_enter_long` + `on_trade` 建立 4 手多仓 → 构造无 `ContractInfo` 的 `WTSTickData` 调 `on_tick`，在 `:74` 崩溃
- 影响: 任何使用本地持仓/手工持仓的 UFT 策略，在收到第一笔正常行情时崩溃；这是实盘主路径，不是边界输入。`on_tick` 的其余盯市逻辑（明细 `_position_profit`、`_dynprofit`）也因此无法在真实链路生效
- 备注: 与 BUG-R54-001 同属“回报/行情对象不带 ContractInfo”家族；建议统一在适配层（ParserAdapter/TraderAdapter）回填 ContractInfo，或在消费层全部按 `stdCode` 回落 `_bd_mgr/_engine`
