## BUG-R54-001 — `onRspTrades` 只认 `tInfo->getContractInfo()`，缺 ContractInfo 时整条成交被静默丢弃

- 状态: 待审核（静态代码路径确认；真实柜台回报是否缺少 ContractInfo 证据不足）
- 严重级别: 条件性 A（若有效成交回报允许不带 ContractInfo，则统计遗漏；当前生产触发未证）
- 产品文件: `src/WtUftCore/TraderAdapter.cpp:1408-1453`（关键行 1414-1418）
- 相关测试: `src/TestUnits/coverage/q04_uftcore3/r54_trader_callback_gaps_test.cpp` → `DISABLED_R54TraderCallback.onRspTrades_without_contract_info_drops_stats`；同文件 `R54TraderCallback.response_chain_reaches_channel_ready` / `order_limit_exhaustion` 必须显式 `setContractInfo` 才能通过
- 输入/前置条件: 已 `initExt + run + login`；构造 `WTSTradeInfo::create("ag2406","SHFE")`，设置 `WDT_LONG/WOT_OPEN/volume=2`，**不调用** `setContractInfo`，经 `WTSArray` 调 `onRspTrades`；随后对同一合约执行 `buy`（规则组 `limit_l=1`）。`WTSTradeInfo` 提供 code/exchange 与可空 ContractInfo，但 `ITraderSpi::onRspTrades` 未明确规定 ContractInfo 是否必须非空。
- 期望行为: 若接口允许该回报形态，则应与 `onRspOrders`（`:1286-1288`）及 UFT `onPushTrade`（`:1739` 后按 code/exchange 查基础数据）一致，按 `_bd_mgr->getContract(tInfo->getCode(), tInfo->getExchg())` 回落；若契约要求非空，则应在契约和适配器边界明确拒绝并记录，而不静默跳过。
- 实际行为: `:1416` 取 `cInfo = tInfo->getContractInfo()`，`:1417-1418` 为 NULL 直接 `continue`；2 手成交完全不进入 `_stat_map`，`l_openvol` 仍为 0，后续 `buy` 正常发出 1 手委托
- 复现步骤: 若启用上述 DISABLED 用例，按源码预期应观察到 `buy` 非空且 `_entrusts.size()==1`；本次未运行，因此没有动态失败证据。也可构造边界测试去掉 q04 `feedTrade` 的 `setContractInfo`，但这仍不能证明厂商适配器会发出该形态。
- 影响: 对实际传入无 ContractInfo 的成交对象，`:1416-1418` 会直接 `continue`，对应统计不更新；但本次源码核对到 CTP (`TraderCTP::makeTradeInfo`) 与 Femas (`TraderFemas::makeTradeRecord`) 均在构造成功回报时设置 ContractInfo，查不到合约时直接不生成该对象。本次没有证明所有适配器都遵循此模式，也没有证明某个部署柜台会送入缺信息对象，因此不得称其为通常柜台回报或已确认的实盘风控失效。
- 修复方向: 契约若允许缺失，按 code/exchange 回查基础数据，并为回查失败打出可审计日志；若契约禁止缺失，补充 `ITraderSpi`/适配器契约并显式报告违约输入。现有 DISABLED 用例只证明设计了该边界输入，不能替代柜台适配器证据。

## BUG-R54-002 — parser 基础数据回退未回填 ContractInfo，可能触发持仓行情空指针

- 状态: 待审核（源码链路确认的条件性崩溃；DISABLED 用例未运行）
- 严重级别: Major（仅在 parser 使用基础数据回退且持仓合约匹配时触发空指针解引用）
- 产品文件: `src/WtUftCore/UftStraContext.cpp:69-97`（关键行 71-84）；关联 `src/WtUftCore/ParserAdapter.cpp:256-263`
- 相关测试: `src/TestUnits/coverage/p06_uftcore2/r54_uftctx_callback_gaps_test.cpp` → `DISABLED_R54UftCtx.tick_without_contract_info_crashes_with_local_position`（用例直接调用 `UftStraContext::on_tick`，并非 parser→ticker→engine 的端到端运行；本次未运行）
- 输入/前置条件: 策略上下文已有本地持仓（手工持仓导入或成交回报均可）；行情 tick 的 `getContractInfo()==NULL`
- 期望行为: `on_tick` 应使用入参 `stdCode` 通过 `_engine->get_contract_info(stdCode)` 取合约/品种，或 `ParserAdapter::handleQuote` 在解析出 `cInfo` 后调用 `quote->setContractInfo(cInfo)`；两种方式都能避免解引用空指针
- 实际行为: 当 parser 收到 ContractInfo 为空、但 `_bd_mgr->getContract(code, exchg)` 成功的 tick 时，`ParserAdapter::handleQuote` 将其标准化为 `fullCode` 后推送，却没有 `setContractInfo(cInfo)`。同一 tick 会经 `WtUftEngine::handle_push_quote` 和 `WtUftRtTicker::on_tick` 进入 `UftStraContext::on_tick`；若 `_positions` 已有该标准代码，`:74` 直接解引用空 `getContractInfo()`。这是可由源码串联确认的条件路径，不代表所有 parser tick 都缺少 ContractInfo，也未在本轮观察到运行时 SIGSEGV。
- 复现步骤: 若启用上述 DISABLED 用例：`on_channel_ready(20240315)` → `stra_enter_long` + `on_trade` 建立 4 手多仓 → 构造无 `ContractInfo` 的 `WTSTickData` 调 `on_tick`，源码预期在 `:74` 解引用失败；本次未执行该用例。
- 影响: 仅覆盖 parser 使用基础数据回退构造的无 ContractInfo tick，且策略已有同代码本地持仓的组合；空持仓或 tick 本身已携带 ContractInfo 时不触发这条解引用。修复方向：`ParserAdapter::handleQuote` 回查成功后回填 `quote->setContractInfo(cInfo)`，或在 `UftStraContext` 通过 `stdCode` 查询合约/品种并对合约、品种指针判空。修复需新增 parser→ticker→engine 链路用例，当前 DISABLED 直调测试只覆盖消费层解引用。
