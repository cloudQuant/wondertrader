# R62 缺陷记录（第十二波 · WtBtCore 四个 Mocker）

> 只记录、不修复。状态均为 `待审核`。

## 本 lane 未发现新的独立根因

R62 的用例通过公开 API 驱动。本 manifest 记录的是 4/4 文件语法门禁，并无 R62 目标二进制全量运行证据；后续 R65 manifest 记录过修正夹具后的部分运行结果。当前 `TickProcessesOrdersAndDrainsCancelTasks` 已由契约正确的返回值断言替换旧错误 oracle，独立运行期望返回目标 `lid`、实际返回空并 FAIL，复现既有 `BUG-P08-004`。因此本 lane 暴露的是既有缺陷，不新增根因，且不能把当前 20 条统称为运行 PASS。

以下问题在测试设计时被再次观察到，但都属于既有 lane 已登记项（或仓库既有口径），不重复编号：

- `SelMocker::handle_replay_done` 零调度整数除零：`BUG-R43-001`。本 lane 的落盘用例先调度一次规避。
- `UftMocker::on_session_begin/on_session_end/stra_enum_position` 无策略空指针：`BUG-P08-001`。本 lane 不驱动这三条路径。
- `UftMocker::stra_cancel_all` 恒返回空容器：`BUG-P08-004`。原 R62 测试曾断言返回列表为空，属于错误 oracle；当前测试已改为断言返回目标 `lid`。接口 `src/Includes/IUftStraCtx.h:99-103` 把该方法定义为返回 `OrderIDs`，示例调用方 `src/WtUftStraFact/WtUftStraDemo.cpp:392-400` 依赖返回 ID 更新受管集合和撤单计数。当前源码遍历匹配订单并排入撤单任务，但未向返回容器追加 ID；修正后的 R62 单测期望 1 个 ID、实际 0 个，FAIL。撤单任务仍会随后执行，不能用撤单副作用已发生替代返回契约。该问题与 BUG-P08-004 同根，不重复开号；修复方向是在排入每个目标撤单任务时同时记录对应 localid，并保留异步取消语义。
- `UftMocker::update_position` 平仓后 0 量明细残留：`BUG-P08-003`。本 lane 不把它写成正确行为。
- 空头 `stra_get_position_avgpx` 返回有符号负均价：q02 清单已将其作为既有口径固化（如 -61/-10），不属于 R62 新缺陷。
