## 观察 1：历史逐笔 lower_bound 回退在块首下溢（既有 BUG-R100-002）

- 位置:
  - `src/WtDataStorage/WtRdmDtReader.cpp:755-760`（queue）、`:930-935`（order detail）、
    `:1104-1109`（trans）
  - 同型 RT 分支见 BUG-R70-001
- 现象: 搜索区间上界写成 `items + (tcnt - 1)`，若查询截止早于块内首条，
  `lower_bound` 返回 `begin`，随后 `pItem->action_time >= eTick.action_time` 为真，
  执行 `pItem--` 与 `eIdx--`（`size_t` 回绕）。
- 分类: 已登记的静态边界缺陷；本轮 active 用例没有验证块首下溢，也没有复现崩溃。
- 与本 lane 的关系: 当前 `R162ReaderEdgeTest.R162RdmReaderHisTransBlocksWithMixedActionDates`
  PASS，但用例把未压缩块直接放入 reader 私有缓存，绕过 CMP_V2 文件装载路径；断言只检查
  返回切片非空。该 PASS 不能证明文件解压/重排正确，也不能覆盖查询早于首条记录时的
  `pItem--` 下溢。此前文档把该 active 用例写为 `CRASH (rc=139)` 与实际不符；生产格式
  文件路径由独立 DISABLED 用例保留，未在本次复核中运行。
- 交叉引用: `bugs/R100.md` BUG-R100-002、`bugs/R70.md` BUG-R70-001。

## 观察 2：三个 AD 读端 get_t_db 查键/存键不一致（既有 BUG-P05-003 等）

- 位置:
  - `src/WtDataStorageAD/WtDataReaderAD.cpp:599`（查 `"exchg.code"`）vs `:617`（存 `exchg`）
  - `src/WtDataStorageAD/WtRdmDtReaderAD.cpp:438-441` vs `:456`
  - `src/WtDataStorageAD/WtBtDtReaderAD.cpp:171-174` vs `:191`
- 现象: 缓存命中分支永不成立，同一合约每次读取都重新 `new WtLMDB(true)` + `mdb_env_open`。
  因此本轮无法用公开 API 覆盖 `WtDataReaderAD.cpp:602`、`WtRdmDtReaderAD.cpp:441`、
  `WtBtDtReaderAD.cpp:174`；这些行在留白表中按不可达处理，不通过改宏/布局镜像绕过。
- 交叉引用: `bugs/p05_datastorage2.md` BUG-P05-003、`bugs/R4_adstorage.md` R4-BUG-07、
  `bugs/R21_adstorage.md` R21-BUG-03。

## 观察 3：WtDataWriterAD 的 _async_task 未初始化（既有 BUG-R162-001）

- 位置: `src/WtDataStorageAD/WtDataWriterAD.h:245`（无初值）、
  `WtDataWriterAD.cpp:55-66/73-104`（构造与 init 均未赋值）、`:375`（消费点）
- 与本 lane 的关系: 旧 `R162ReaderADMinuteBarsAppendFromLmdb` 夹具通过 `writeTick()` 读取未初始化的 `_async_task`，其旧失败不能归因于 reader。现已改为按 `LMDBKeys` 直接写入确定性数据，重建后 reader 增量读取仍 FAIL，另立 BUG-R162-003；tick 对照通过。其它仍通过 writer 的测试不因此摆脱该前提限制。
- 交叉引用: `bugs/R162.md` BUG-R162-001、`bugs/p05_datastorage2.md` BUG-P05-005。

## 观察 4：WtDataWriter 清理分支的 300s 重试与 proc_loop 丢唤醒（既有 BUG-P10-005）

- 位置: `src/WtDataStorage/WtDataWriter.cpp:2366-2387`（`remove_all` 异常后
  `sleep_for(300s)`，最多 5 次）、`:2216-2224`（`_proc_que.empty()` 在锁外判断，
  无谓词 `wait`）
- 与本 lane 的关系: 本轮清理用例只在系统临时目录、全部 rt 路径可删的正常输入上运行，
  并在 5s 内按「快照 CSV 已落盘 + rt/ticks 已删除」收口；不制造 `remove_all` 失败，
  也不在 `transHisData` 后调用 `release()`（避免丢唤醒导致 HANG）。
- 交叉引用: `bugs/p10_storage_writer.md` BUG-P10-005、`bugs/R23_storage.md`。

## 观察 5：R162 相关用例的当前结果与证据边界

- `CoverageTests.R162ReaderEdgeTest.R162ReaderAdjustedStockNonStdExceptionIsCaught` 当前
  重跑 PASS。该结果只验证该异常路径的当前断言，不外推到其他复权行为。
- `CoverageTests.R162ReaderEdgeTest.R162RdmReaderHisTransBlocksWithMixedActionDates` 当前
  重跑 PASS；它是缓存注入路径，且只断言切片非空，不验证 CMP_V2 文件装载或 BUG-R100-002
  的块首下溢边界。不得沿用旧文档的 `CRASH (rc=139)` 结论。
- `CoverageTests_adstorage.R162AdReaderTest.R162ReaderADMinuteBarsAppendFromLmdb` 的旧结果受 writer 未初始化状态影响。修正为直接 LMDB 夹具后重建并单跑：第二次分钟线读取 1 根而非 2 根，tick 对照通过；该 reader 缺陷见 BUG-R162-003。
- `CoverageTests.R162WriterClosingEdgeTest.R162WriterRawMin1BlockHeaderIsStrippedBeforeAppend`
  的失败原因已确认为夹具没有创建 `his/min1/SHFE` 父目录；父目录创建后在独立临时根目录
  重建并重跑 PASS。此 PASS 只证明该夹具能够创建输入文件并通过目标头部转换断言，不是
  RDM/AD 读端证据，也不应归因于前序用例副作用。
