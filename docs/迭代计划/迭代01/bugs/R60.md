## BUG-R60-001

- 状态: 待审核
- 严重级别: Blocker（宿主进程 abort）
- 模块/文件: `src/TraderMocker/TraderMocker.cpp` L705-716（`disconnect`）、L640-657（`release`）、
  L689-703（`connect` 起 `_thrd_worker`）
- 相关测试: 本轮全部 connect 用例只走「connect → release」；该崩溃序列未启用
- 输入/前置条件: `init(cfg)` → `connect()`（成功 bind 并起 io worker）→ `disconnect()` → 对象析构
- 期望行为: `disconnect()` 关闭 UDP socket、`_io_service.stop()` 并 join `_thrd_worker`；`release()` 同样
- 实际行为: `disconnect()` 只 join `_thrd_match`，并把 `_terminated = true`（L710）；随后 `release()`
  在 L642-643 因 `_terminated` 直接 return，`_io_service.stop()` 与 `_thrd_worker->join()`（L652-656）
  **永不执行**。`_thrd_worker` 是 `std::thread` 的 shared_ptr，析构仍 joinable 的 thread 会调用
  `std::terminate`
- 复现步骤: `TraderMocker a; a.init(cfg); a.connect(); a.disconnect();` 离开作用域
- 影响范围: 任何「先 disconnect 再销毁/重载」的宿主；进程被 SIGABRT，且 UDP socket 同时泄漏
- 备注: 修复方向：`disconnect()` 复用 `release()` 的 stop+join 逻辑，或 `release()` 不因
  `_terminated` 跳过 worker 清理；`_thrd_worker.join()` 后置空。

## BUG-R60-002

- 状态: 待审核
- 严重级别: Major（空指针解引用）
- 模块/文件: `src/TraderMocker/TraderMocker.cpp` L750-756（`orderAction`）、L302-309（`_awaits` 仅在下单成功时创建）
- 相关测试: 无启用用例（执行即崩）；本轮 `cancel_open_order_and_unknown_cancel_reports_error` 先下一单再撤，
  避开了该前置条件
- 输入/前置条件: `init` + `connect` 后，**尚未成功下过任何委托**，直接 `orderAction(action)`
- 期望行为: 与 L764-772 一致，回 `WEC_ORDERCANCEL`「订单不存在或者处于不可撤销状态」
- 实际行为: L756 `_awaits->grab(...)` 中 `_awaits == NULL`（只在 L306-309 首次成功下单时 `create()`），
  在进入 L764 的 NULL 判断之前就解引用空指针
- 复现步骤: 构造 → init → connect（驱动 io）→ `orderAction` 一个任意 orderID
- 影响范围: 策略启动/重启时的「全撤」、先撤后下的补偿逻辑；崩溃点在 io 线程，表现为进程直接退出
- 备注: 修复方向：`orderAction` lambda 开头加 `if (_awaits == NULL) { 回 WEC_ORDERCANCEL; return; }`。

## BUG-R60-003

- 状态: 待审核
- 严重级别: Minor（资源泄漏）
- 模块/文件: `src/TraderMocker/TraderMocker.cpp` L666-687（`reconn_udp` 的 `new udp::socket`）、
  L640-657（`release`）、L98-108（析构）
- 相关测试: `r60_tradermocker_async_test.cpp` 全部 8 条 connect 用例（进程退出前不复用对象，故未断言泄漏）
- 输入/前置条件: `init` + `connect` + `release`（或析构）
- 期望行为: `release`/析构关闭并 `delete _b_socket`，释放 fd 与 asio socket 对象
- 实际行为: `_b_socket` 只在 `reconn_udp()` 被再次调用时 close/delete（L668-673）；`release()` 与
  `~TraderMocker()` 都未处理，每 connect 一次泄漏一个 socket/fd 与堆对象
- 复现步骤: 循环 `init → connect → release` 同一进程 N 次，观察 fd 数单调增长
- 影响范围: 长跑仿真器热重载/反复连接；最终 EMFILE，且 asio io_context 析构时仍有悬挂 socket 对象
- 备注: 修复方向：`release()` 里 `if (_b_socket) { close; delete; _b_socket = NULL; }`。

## BUG-R60-006

- 状态: 待审核
- 严重级别: Minor（连接态语义不一致）
- 模块/文件: `src/TraderMocker/TraderMocker.cpp` L718-721（`isConnected`）、L689-703（`connect`）、
  L723-743（`login` 才给 `_thrd_match` 赋值）
- 相关测试: `r60_tradermocker_async_test.cpp` 的 connect 用例（只断言 `WTE_Connect`，未把该现状写成期望）
- 输入/前置条件: `init` + `connect()` 成功（UDP 已 bind、io worker 已 run、`WTE_Connect` 已回调）
- 期望行为: `isConnected()` 为 true（连接事件已经发出）
- 实际行为: `isConnected()` 返回 `_thrd_match != NULL`；`connect()` 只创建 `_thrd_worker`，
  `_thrd_match` 直到 `login()` 才创建，因此 connect 之后仍为 false
- 复现步骤: connect 后等 `handleEvent(WTE_Connect)`，再调 `isConnected()`
- 影响范围: 以 `isConnected()` 作为下单/查询前置条件的宿主会认为仿真器未连接；
  与 `handleEvent(WTE_Connect)` 的语义自相矛盾
- 备注: 若产品定义就是「撮合线程起来才算连接」，至少应在接口注释/事件语义上统一；否则改为
  `_thrd_worker != NULL` 或单独的 `_connected` 标志。
