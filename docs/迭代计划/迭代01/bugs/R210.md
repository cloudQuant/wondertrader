## BUG-R210-001 `get_kline_slice` 把半小时周期 "f" 映射成小时周期

- 编号: BUG-R210-001
- 状态: 待审核
- 严重级别: 中（半小时回测实际拿到小时线；半小时收盘回调不可达）
- 位置: `src/WtBtCore/HisDataReplayer.cpp:2196-2201`
- 现象: `period == "f"` 分支注释为“半小时线”，但 `realTimes = PERIOD_TIMES_HOUR`
  （`0xffffffff`），与上面的 `"h"` 分支完全相同；`PERIOD_TIMES_HALF`（`0xfffffffe`）
  在 `get_kline_slice` 内没有任何写入点。
- 影响:
  - 调用方按半小时查询时，重采样与 `BarsList::_times` 都按小时处理；
  - `simTickWithUnsubBars` 的 `times == PERIOD_TIMES_HALF` 分支
    （`HisDataReplayer.cpp:2037-2038`，`handle_bar_close(..., "f", 1, ...)`）
    在公开 API 下永远不可达；
  - `run_by_bars` / `Sink` 收到的周期与查询周期不一致，策略侧无法区分 h 与 f。
- 期望: `"f"` 分支赋 `PERIOD_TIMES_HALF`，或把 `"f"` 从公开周期表移除并返回 NULL。
- 证据: 基线 `llvm-cov` 中 2038 恒为 0；源码 2194 与 2200 两处赋值相同。
- 测试处理: 本轮未写断言固定错误映射（无公开 getter 可观察 `_times` 之外的映射），
  仅在 `manifests/wave29/R210.md` 记录该段留白。

## BUG-R210-002 tick 时间步进循环条件反向，非交易时段 tick 不会被跳过

- 编号: BUG-R210-002
- 状态: 待审核
- 严重级别: 中（小节间隙/非交易时段的 tick 可能被当作有效行情回放）
- 位置: `src/WtBtCore/HisDataReplayer.cpp:1610-1614`（`replayHftDatasByDay` 前身
  `getNextTickTime` 的尾部步进）
- 现象:
  ```cpp
  while (!sInfo->isInTradingTime(nextMinTime) && tickList._cursor > tickList._items.size())
  ```
  `_cursor` 的合法范围是 `1.._count`，而 `_items.size() == _count`，因此
  `_cursor > _items.size()` 对所有合法游标恒假，循环体（1611-1614：
  `_cursor++` 并读取下一条 `action_time`）从不执行。
- 影响: 当 tick 落在小节之间或非交易时间时，`nextActionTime` 不会被推进到下一笔
  可交易 tick；上层 `nextTime = min(lastTime, nextTime)` 直接把非交易时段 tick
  交给监听器。注释明确说明该循环用于 “tick 数据处于小节之间，但是不在交易时间，
  则指针一直步进”（Issue#104），当前实现与该意图相反。
- 期望: 条件改为允许在未越界时步进（如 `_cursor <= _items.size()`，并在循环体内
  先判越界再取下标），或使用独立的 `_cursor < _items.size()` 配合安全索引。
- 证据: 基线 `llvm-cov` 中 1611-1614 恒为 0；`_cursor` 初始化/递增语义见
  `HftDataList` 注释（`HisDataReplayer.h:270-284`）。
- 测试处理: 公开 API 无法在不触发该错误路径的前提下观察“是否跳过”；本轮只登记，
  不写会固化错误行为的用例。
