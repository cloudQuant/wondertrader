## BUG-R210-001 `get_kline_slice` 把半小时周期 "f" 映射成小时周期

- 编号: BUG-R210-001
- 状态: 已合并（主编号 BUG-P07-004；BUG-Q02-005 为关联记录）
- 严重级别: 中（源码把 f 与 h 映射到同一聚合值；实际回测结果尚无本 lane 动态验证）
- 位置: `src/WtBtCore/HisDataReplayer.cpp:2196-2201`
- 现象: `period == "f"` 分支注释为“半小时线”，但 `realTimes = PERIOD_TIMES_HOUR`
  （`0xffffffff`），与上面的 `"h"` 分支完全相同；`PERIOD_TIMES_HALF`（`0xfffffffe`）
  在 `get_kline_slice` 内没有任何写入点。
- 影响（由映射源码推导，未由本 lane 回测实测）:
  - f 与 h 查询都落到 PERIOD_TIMES_HOUR；
  - 因而 onMinuteEnd 中要求 PERIOD_TIMES_HALF 的 f 回调分支不会由此映射触发。
- 期望: `"f"` 分支赋 `PERIOD_TIMES_HALF`，或把 `"f"` 从公开周期表移除并返回 NULL。
- 证据: 源码 2194 与 2200 两处赋值相同；onMinuteEnd 另有 HALF 对应 f 的分支。
  覆盖率行数不是行为证据。
- 测试处理: 本轮未写断言固定错误映射（无公开 getter 可观察 `_times` 之外的映射），
  仅在 `manifests/wave29/R210.md` 记录该段留白。

## BUG-R210-002 tick 时间步进循环条件反向，非交易时段 tick 不会被跳过

- 编号: BUG-R210-002
- 状态: 已合并（主编号 BUG-P07-002）
- 严重级别: 中（小节间隙/非交易时段的 tick 可能被当作有效行情回放）
- 位置: `src/WtBtCore/HisDataReplayer.cpp:1610-1614`（`replayHftDatasByDay` 前身
  `getNextTickTime` 的尾部步进）
- 现象:
  ```cpp
  while (!sInfo->isInTradingTime(nextMinTime) && tickList._cursor > tickList._items.size())
  ```
  `_cursor` 的合法范围是 `1.._count`，而 `_items.size() == _count`，因此
  `_cursor > _items.size()` 对所有合法游标恒假，循环体（1611-1614：
  `_cursor++` 并读取下一条 `action_time`）从不执行。
- 影响: 当 tick 落在小节之间或非交易时间时，nextActionTime 不会由该循环推进；后续
  是否交给监听器需按上层回放路径另行动态验证。注释说明该循环用于 “tick 数据处于小节之间，但是不在交易时间，
  则指针一直步进”（Issue#104），当前实现与该意图相反。
- 期望: 按 one-based cursor 语义推进；每次递增后检查耗尽并重新读取日期/时间、重新
  计算 nextMinTime。只改比较符会把末项推进后的越界读取留在循环体中。
- 证据: HftDataList 注释规定初始化 cursor 大于 0；装载时 _count 与 vector 项数相同。
  当前条件对合法 cursor 不成立，且循环体没有更新 nextMinTime。
- 测试处理: 现有 R210 落盘用例未覆盖半小时映射或小节间 tick 跳过；其他用例通过
  不能替代针对这些输入的动态断言。

## 复核裁定（2026-10-29；与上文冲突时以本节为准）

- BUG-R210-001 的源码映射问题成立：`get_kline_slice` 的 h/f 都写入
  `PERIOD_TIMES_HOUR`，而 `onMinuteEnd` 的半小时回调分支只认
  `PERIOD_TIMES_HALF`。这证明源码映射不一致；本 lane 没有运行半小时重采样/
  回调测试，不能把“实际回测拿到小时线”写成动态观察。它与 BUG-P07-004、
  BUG-Q02-005、BUG-R171-002 重复，不应增加独立计数。修复方向：f 映射为 HALF，
  并用分钟底座核对重采样边界和回调 period 字符串。
- BUG-R210-002 的 while 条件对合法 cursor 恒不成立，源码层面与小节间跳过意图
  冲突；R210 现有落盘用例没有命中这一输入。该项与 BUG-P07-002 重复。完整修复
  需在每次推进后检查耗尽并重新计算 nextMinTime，不能只调整比较符；建议用
  小节间 tick 后接可交易 tick 的回放断言验证。
- 同一函数还有 cursor==count 时被 `_cursor >= _count` 提前跳过末项的问题，
  这是 BUG-P07-001 已登记的边界，不另编号。两项 cursor 问题有不同触发点，不应
  混成一个根因。
- 本次只读检查截至 2026-10-29 的已有 build-cov 日志，没有重新运行测试。
  R210 半小时映射和小节间 tick 路径均无针对性运行结果。已有
  R210His_UncompressedV2BarBlockHeaderStripped 日志失败于块数断言（预期 2、实际
  1）；当前证据不足以判定该用例是 oracle 错误还是格式语义冲突，也与上述两项无关。
