## BUG-R133-001

- 编号: BUG-R133-001
- 模块/文件: `src/WtUftCore/ParserAdapter.cpp:38-40`（空析构）、`:228-240`（`release`）、
  `:44-56`（`init` retain）
- 相关测试: `R133ParserAdapterGuards.filter_and_level2_early_returns`
  （`src/TestUnits/coverage/q04_uftcore3/r133_uftcore_remaining_test.cpp`）仅测过滤/Level2
  守卫，不覆盖 ParserAdapter 生命周期。
- 复核结论:
  - 源码在 `init` 中 retain `_cfg`，但析构函数为空，`release()` 也不释放 `_cfg`；成功或
    失败初始化后都没有对应的配置引用释放点。这是源码可确认的资源生命周期缺口，当前没有
    LSan/引用计数的动态证据。
  - `release()` 不置空 `_parser_api`/`_remover`。若成功加载插件后对同一对象再次 `release()`，
    会再次调用旧 API 指针及 remover；可能形成 use-after-free/double delete。当前没有专门用例
    验证该序列，且接口没有明确承诺 `release()` 幂等，因此将其记为条件性生命周期风险，不
    作为已动态复现的故障。
  - 原记录中的 `initExt()` 复用路径不成立：`src/WtUftCore/ParserAdapter` 没有 `initExt()`；
    该方法存在于 `src/WtCore/ParserAdapter`。从本条复现步骤删除，避免把另一实现的接口混入。
- 与 BUG-R130-002 的关系: `src/WtCore/ParserAdapter` 有同型的 `_cfg` 未释放模式；两者位于
  不同模块副本，应分别修复各自实现，但根因模式相同，不应当成两个独立的架构问题统计。
- 修复方向: 失败初始化路径回滚 `_cfg` retain；正常释放/析构保证配置引用恰好释放一次。
  `release()` 若允许重复调用，应在回调删除后清空 API/remover 指针并有生命周期用例覆盖；
  若不承诺幂等，则至少明确调用约束并避免析构/管理器清理重复释放。
- 严重级别: Minor（配置引用泄漏源码确认；重复释放风险条件性且尚无动态证据）
- 状态: 已合并（迭代02：主编号 BUG-R78-001）


- 迭代02复核: DUPLICATE。_cfg retain 未配对 release，以及缺 createParser 符号时未释放已加载句柄，与 BUG-R78-001 是同一 ParserAdapter 资源清理根因。原记录称该类没有 initExt 不正确，头文件和实现都提供 initExt；重复 release 后指针未清零不属于已证明的正常生命周期问题。
