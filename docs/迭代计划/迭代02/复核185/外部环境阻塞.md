- 验收：先核对确切 XTP SDK 的 OnOrderEvent 参数保证和错误/拒单事件范围；之后使用对应 XTP callback fixture 验证 mapped 与 unmapped 行为，同时单独验证正常活单 map 的 doCancel 不接受无 contract 单。

## BUG-R53-003

- **缺少的证据**：一个明确版本的已发布旧版 DSB 历史 tick 文件（记录生产者/发行版本及压缩/结构版本），或该版本的正式 SDK/磁盘格式说明，能够界定旧 WTSTickStruct.exchg[10] 是 NUL 终止字符串还是可满宽原始字段。
- **已检查**：本地 git 历史：5f6fa321^ 的 MAX_EXCHANGE_LENGTH 为 10；12098b5b 将其拆为 WTSTickStructOld[10] 并以 strcpy 迁移字符串；该旧结构构造 memset 全零；5f6fa321^ 的内置 CTP/CTPMini/CTPOpt/Femas/XTP parser 用 strcpy(quote.exchg,getExchg())；007d7bc3 和 9bb6c1f2 增加旧 DSB 读取/结构转换。仓库文件清单未发现旧 .dsb/raw tick 二进制 fixture，也未找到旧版字段格式规范。当前 r53 测试仅有合法 max-1+NUL fixture。
- **本地证据限制**：源码可证明本仓库内置生成路径按 C 字符串写入，但不能证明所有已发布旧版本、外部数据写入器或用户存量 DSB 都遵守同一规则。历史二进制的有效格式不能由人工构造的无 NUL 字节或当前代码偏好推断。
- **取证行动**：由主代理从归档取得一份有生产者版本元数据的旧版 DSB tick 文件，或对应旧发布 SDK/格式文档；核对 exchg[10] 与相邻 code 字节并确认兼容合同，再按结果将本项撤回或转为具体产品边界修复。
- 下一步：在取得证据前不改产品代码。若旧版正式格式保证 NUL，撤回满宽无 NUL 缺陷主张并保留合法字符串回归；若已发布格式允许满宽原始字节，按该格式做有界定长转换，不跨 exchg 字段读取 code。
- 验收：确认具体旧版数据格式/生产者版本；检查该版本真实 DSB 中 exchg[10] 的终止字节。若保证 NUL，状态改为 NOT_BUG/TEST；若满宽为有效值，增加不越界原始字节 fixture 并验证 conversion 安全保留字段边界。现有 max-1+NUL 测试只作为合法字符串对照，不声称验证满宽格式。
