# R100-003 / R32-003：分钟 LMDB 键升级审计

状态：设计与基础验证中，**未修复 / 未验收**。本文件保存只读审计发现和候选方案，不代表迁移、真实生产读写或部署门禁已经实现。

## 已核对的约束

- V1 分钟键是 packed 的交易所 16 字节、代码 32 字节和 32 位时间，共 52 字节；min1、min5、day 按周期和交易所分别位于独立 LMDB 环境。未发现可用于判定该 LMDB 键 schema 的版本标识。
- 多种 reader 依赖现有键长和字节排序；不能在旧默认 DB 混入 56 字节新键。范围查询的 upper 包含端点，`0xffffffff` 是合法边界，不能把它直接当成排除值。
- writer 先异步接收入队，worker 再处理 tick/实时缓存、分钟线及广播；仅在 pipe 的窄化位置报错可能已发生副作用。当前写入时 64 位 bar.time 转 32 位，`mdb_put` 可覆盖同键数据；已覆盖值无法由现有库还原。
- `WtDataReaderAD`、`WtRdmDtReaderAD`、`WtBtDtReaderAD` 共用存储路径；首载、增量、范围、`onMinuteEnd` 和 RT 路径均需协同。旧 32 位 value 若已失去高位不能根据猜测恢复，迁移须核对键与 value 时间、长度和身份，隔离歧义并报告。

## 候选迁移方向

保留 V1 原库，采用独立 V2 环境或经明确版本标识的隔离 DB，键使用固定 16+32+8 字节且 64 位时间显式大端编码；不在 V1 默认 DB 混写。迁移只扫描旧 LMDB 写 staging，不重放 tick、不触发广播或策略回调。逐条校验并分批事务提交，重复键只允许已存在值与待写值完全一致；完成数量、顺序及内容校验后，发布可恢复的持久 manifest。任何进度、校验或切换状态不确定时停止，不能静默回退到陈旧 V1。

迁移前须停止接收并排空已接受写入、取得跨进程独占和稳定快照；部署层须阻止不识别新 schema 的旧二进制并发访问，协作式文件锁本身不能阻止不配合的旧进程。各交易所与周期为不同环境，切换不具跨库原子性，须显式协调部分完成及恢复。V2 已接受新增写入后不能直接回滚到 V1。未来实现需进一步审定独立环境与命名 DB 的兼容性、事务和发布协议；不得把该候选当成已确认的无损迁移。

## 必要定向验证

1. 以独立 64 位计算验证 2032/2033、`0xffffffff` 两侧、M1/M5、日线不变、交易日/自然日和跨午夜 session；各 reader 的首载、增量与包含边界分别核对。
2. 真实隔离 LMDB 覆盖多合约、旧/packed/current value 布局、不合法键值长度、身份及时间不匹配、冲突键、V2 排序和跨年 round-trip。
3. 检查写入前失败与成功的队列、缓存、数据库、dumper、广播实际副作用；同步和异步模式、禁用分钟线及迟到数据分别验证。
4. 注入迁移各事务/切换阶段的崩溃、满盘、只读、sync 和损坏，验证重启可恢复、旧库可审计、未完成数据不暴露、不重复调用下游；多进程锁及旧部署门禁分别验证。

现有直接相关用例可作正控，但不足以证明上述跨年和迁移合同。本轮尚无完整方案、真实 LMDB 迁移或上线兼容证据。
