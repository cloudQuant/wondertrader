# NEW-008 / N05-003 / L01-014：订单身份链审计

状态：**未实现、未验收**。用户已确定同账户同合约可由多个执行器共享，订单、成交、委托失败及自动撤单须归属发单 owner；无法确认身份时 fail-closed。本文是本机只读审计和候选架构，不是生产安全保证。

## 当前链路的缺口

- `TraderAdapter` 的 owner 专用 helper 尚未接入生产 order/trade/entrust 回报；通用 `forEachSink` 未过滤 owner sink，仍按合约广播。helper 的路由预约与调用之间若发生注销，内部可跳过 callback 而外层仍返回 true，不能当作已交付证明。
- 现有 runner 先注册普通 sink；adapter 已 READY 时 `addSink` 可同步触发 READY 和下单，owner 注册可能还未发生。必须先在同一准入门禁内建立 owner 路由，再允许 READY 和交易。
- 多个生产回报在验证 owner 前已修改订单、统计、冻结或账户持仓；订单查询先清统计再遍历，无法仅事后过滤。必须在副作用之前保留原始事件并验证身份，查询失败、部分结果和有效空结果不能混同。
- 某些 provider 在生成 WTS 对象前遇到未知合约即丢弃原 SDK 回报；只在 host 内为 WTS 对象加 WAL 会遗漏这些事件。现有多数 SPI 回调是 void，也没有可靠的查询批次/版本完成状态。
- Local、Diff、Arbi 的 `getUndoneQty` 当前返回账户按合约聚合值，六类执行单元据此判断发单/撤单；只过滤快照和取消仍会受其他 owner 订单影响。账户级实际持仓与全局风控有独立用途，不能盲目替换为 owner 虚拟持仓。
- 当前 localid 为进程内时间种子 uint32，重启或回绕可能重用；现有 tag 解析未证明完整分隔、长度、数值与溢出。CTP、CTPOpt、Femas 的 SDK 字段和本地映射持久性不同，不能由 host 字段长度或 fake 测试推断真实 provider 的可恢复身份。

## 候选实施顺序

1. 统一账户 namespace、稳定 owner、不可复用订单身份/代际和每笔拆单 intent。发送前持久登记映射并完成路由准备；持久化失败不得发单。记录 PREPARED、发送中/不确定、确认及终态，不能持普通锁跨可能同步回调的 SDK 调用。
2. 设计能力可发现且不改变旧 vtable 的版本接口：provider 必须能携带/恢复唯一订单关联、稳定成交身份及可证明完整的查询快照；未知能力或旧插件不能自动进入共享 owner 交易。回报转换前保留版本化原始字段，无法识别时暂停账户并等待人工对账。
3. 将账户级账本与 owner 级订单、方向/gross 未完成量、快照及自动取消分开。路由预约、注销和投递要线性化，真实未调用必须报告失败并进入隔离处理；不得持 registry 锁执行外部 callback 或在回调注销时等待自身。
4. crash/restart/发送中断必须恢复意图、核对 provider 查询并对账，不自动重发。磁盘失败时进程内保留原始事件并持续暂停；void 回调与不可靠存储不能证明硬重启后零丢失。WAL primitive 现有本机结果并不证明生产回报已接入。
5. 两执行器同账户同合约的真实 host/fake provider 红绿，覆盖拆单、同步重入、乱序/重复回报、回报先于订单、无效/截断/冲突 tag、未登记 owner、隔离查询和取消，以及账号级风控不被错误分摊；随后验证跨进程重启、故障注入和精确版本 provider 能力。

现有 helper 与局部单测均不能关闭上述端到端缺口。具体版本化 token、耐回滚的可信世代、provider 能力和人工对账接口仍需设计与实现。

## 增量实施的安全门槛

- 应先建立宿主强制的账户准入门禁，所有自动 buy/sell 和自动 cancel 共用；能力、日志、恢复、对账或 owner 未确认时拒绝，人工/外部账户级操作保留独立显式合同。只要求插件自觉调用新接口不足：旧 `ExecuteContext` 入口也须绑定 owner 并受宿主门禁约束。
- `IExecPluginV2` 现有版本只协商初始化与 quiescence，不提供 owner 身份能力；新能力应带版本、结构长度和可区分不可用/真实零值的状态。owner 视图应含一致版本、方向及 gross 未完成量，账户级持仓和风险控制独立维护。
- 对指定订单撤单时，校验后解锁再调用旧 `cancel(localid)` 仍可能遇到终态和 ID 复用；需 claim/in-flight 或串行命令协议，使最终校验与向 provider 发撤单线性化，且允许 SDK 同步回调，不能持普通锁跨调用。
- 重入注销后应保留可等待的 retired 状态，直到 sink 回调及 provider 两类 drain 均有证据；不能先删除唯一映射再以无法重试的 false 冒充完成。
- 当前 journal 是不透明字节组件，未认证操作者、未接入账户门禁和 provider 原始字段；它与未来订单账本若分文件保存，不能假设跨文件原子，必须建立共同事务或显式崩溃恢复状态。
