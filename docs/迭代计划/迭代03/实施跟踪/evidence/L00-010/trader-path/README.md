# BUG-L00-010 TraderXTP / TraderFemas module-directory subfix

Worktree current sources were compiled as two isolated product TUs with dedicated dladdr/dlopen/dlsym/dlclose spies. The spies inject a slash-free module image for empty directory, record every attempted loader path, and do not contact an SDK. The same current shared ModuleHelper is used in both current and pre-change product builds. `final-input-before.sha256` and `final-input-after.sha256` match for eight selected inputs, not all transitive dependencies. Other libraries and configuration are reused from v8. See each `commands.json` for precise arguments and process exit statuses.

Current (`final3/`) selected modes: TraderXTP empty, nonempty and empty-plus-absolute 3/3; TraderFemas empty, nonempty, empty-plus-absolute and default bare-name 4/4. Empty-relative modes return false with 0 dlopen. In XTP they also call connect and observe 0 creator calls; nonempty and absolute modes reach the fake creator exactly once. Both test destructors observe no fake dlclose. This only documents existing unload behavior, not safe drain/unload. Femas default still invokes the prior `libUSTPtraderapiAF` bare-name branch. Nonempty directory behavior is preserved; tests do not assert all nonempty directories are absolute. XTP's existing lib-prefix transformation of absolute names is recorded literally in the output.

Baseline (`red-final/`): product source copies taken before the subfix, compiled with the same current ModuleHelper and final test fixture; both empty-relative modes fail their test as expected because init succeeds and dlopen is called with a relative name. Other modes are controls. The prior direct baseline (`red/`) independently shows those two relative loads. A previous green-final compile attempt timed out under load after 60 seconds; it is not included in pass counts. The later `final3` uses a 180-second per-command bound.

No production provider, Windows/Linux, sanitizer, clean full dependency build, or full regression was run. The underlying XTP missing-symbol handling and broader lifecycle/unload remain outside this subfix. The real DLLHelper may throw or behave differently than the spy; this result is not a real-loader acceptance.
