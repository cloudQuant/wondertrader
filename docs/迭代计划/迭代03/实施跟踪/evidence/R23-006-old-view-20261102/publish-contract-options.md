# R23-006 跨进程发布与回滚：待决合同

本文根据当前 writer/reader 源码和同目录跨进程探针提出可验证方向，**不是已实现协议或通过结论**。没有重新执行此前被自动审核中止的 RDM 清缓存任务。

## 现有实际入口和局限

- `WtDataWriter::resizeRTBlock` 扩展同一个文件，成功创建新映射后更新共享 header 的 `_capacity`，调用路径随后写入新元素并递增 `_size`。`_capacity`、`_size` 是普通 `uint32_t`，当前格式没有发布版本、跨进程锁或带校验的已提交记录快照。
- `WtDataReader::getRTTickBlock` 及其他 RT 块的同类入口仅比较一次 `_last_cap` 和共享 header `_capacity`，不同则 remap；返回之后下游才读取 `_size` 及记录。`BoostMappingFile::size()` 能提供该次映射长度，但当前检查并不与后续 `_size` 读取形成跨进程原子快照。实际旧映射探针验证两次读取之间扩容的交错可使已发布记录数超过旧映射长度；该探针是独立原始映射观察，没有调用生产 reader。
- 旧格式不提供订阅者注册、已离开旧视图的确认、跨进程互斥、记录写完的发布位或平台级内存顺序保证；单纯交换 writer 内部 `shared_ptr`、顺序写普通字段或加入一个进程内 mutex，均不能建立这些跨进程合同。原映射上的旧记录是否持续可读与文件是否被外部截短或替换同样相关。
- 短写回滚按原文件长度截断，而一个非合作外部进程在目标长度范围内追加的数据也会被截去；测试只展示该可发生的交错，不声称产品支持并发 writer。只比较文件大小不能证明追加字节由本 writer 独占产生；文件名锁不能单独排除硬链接或替换别名。

## 可升级方案 A：版本化不可变快照/分段

1. 新文件命名空间及明确版本头；writer 在独立暂存文件或只追加且已封存的段内形成完整记录，校验长度、内容与序号。构造阶段读者不可把它当作已发布数据。
2. 完成持久化策略后，以适合平台的原子方式发布含 epoch、文件身份、已提交字节/记录范围和完整性校验的 manifest。读者只消费稳定 manifest 对应的文件版本并持有该文件/映射所有权，检查长度与溢出后再取记录；直到所有受支持读者离开旧版本才能回收旧文件。manifest 损坏、缺失、回退、切换过程中崩溃均应拒绝不完整版本并给出明确恢复状态；真实断电安全需独立 fsync/目录持久化证据。
3. 热数据发布粒度、段大小、读取可见性与延迟属于产品合同；不能把 staging 或尚未封存的部分记录报告为完整。该方案避免旧的活跃共享 header 作唯一提交点，但需要实现发布、版本保护、回收和读者升级，当前均未实现。

## 可升级方案 B：版本化受控共享视图

1. 为新格式定义平台支持的跨进程锁与可恢复状态；writer 在锁保护下完成扩展/重映射、记录写入，再发布有界 committed-size、capacity、generation 和文件身份。reader 在同一兼容的跨进程同步协议下读取一致快照，确认 `header_size + count * record_size` 无整数溢出且不超过**当前持有映射的实际长度**；长度不足时先安全重新映射并重新验证，再复制或使用有明确生命周期的视图。
2. 同步须覆盖从选择 generation 到完成所需读取的时间；仅先比较 capacity、随后无锁读取 size，或仅增添原子栅栏，不能消除本次观察的窗口。若采用序列号而非锁，还须以平台可证明的共享内存原子性/对齐和 payload 并发读写模型为依据，验证写者退出、序列号溢出与恢复；普通 C++ 整数跨进程读写不能自动当作可移植同步。
3. 记录读取、异步回调与借用视图的所有权/生存期必须另定，不以短期锁解锁后裸指针仍然有效为假设。真实多进程并发、错误映射长度、重映射失败、写者异常退出和平台差异均需定向验证；当前均未实现。

## 回滚互斥、旧版兼容与部署边界

- **单进程可完成**：同一个 writer 实例的线程准入、块锁持有、旧本地映射保活、受控短写/映射失败、回滚失败记录及重试；本证据第三、四项只覆盖所列交错，不证明跨进程安全。
- **跨进程必须共同执行**：在首次检查文件身份/EOF 前取得所有兼容 writer 均遵守的独占权，并持续覆盖扩展、失败判定、回滚/验证及发布。需要稳定文件身份和别名策略、进程崩溃后的锁释放与未完成状态恢复。POSIX advisory lock 只能约束主动遵守者；单靠它不能防止旧版或非合作进程写入。目录权限/独立文件命名空间和外部控制面可作为 gate 的组成部分，但不能仅凭持锁断言未知进程没有文件描述符或映射。
- **旧版切换**：旧 reader 看不懂新协议，不能在它仍访问的同一 V1 文件上单边宣布协议生效。需要由部署控制面停止接收与排空旧 writer，确认所有旧 reader/旧插件与残留文件描述符退出或隔离；将新版本写入独立目录/文件，校验、原子切换并禁止旧版本再次访问。是否提供静止 V1 只读快照须明确它会过时，不能伪称实时；新 V2 数据已产生后不可盲目回退旧版本。多目录/多流切换与崩溃恢复还需协调。
- **测试门槛**：实际生产 writer 与升级 reader 各类流，以进程屏障覆盖 capacity 检查之后写入、扩容/remap 失败、读映射期间文件被截短/替换、非合作旧进程、两进程争锁、锁持有者异常退出、回滚自身失败和恢复。按平台分别验证同步机制与文件持久化；不得以假 writer、内存栅栏、旧映射尺寸单次检查或本机 sanitizer 通过替代这些证据。
