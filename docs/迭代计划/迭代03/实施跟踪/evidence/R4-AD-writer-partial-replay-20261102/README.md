# AD writer 部分提交、重入和恢复红控

本目录是手动运行的预期失败探针，**不是修复或验收**。生产 writer 和现有工作树改动未修改。独立进程、独立临时目录、真实 writer/LMDB、模拟 dumper；无交易、无新建符号链接。`commands.json` 记录本次完整编译和链接参数；`run_probe.py` 由 Anaconda base Python 执行，每次重新编译当前工作树 writer 和探针，复用既有隔离构建中的其他对象。macOS arm64 / LLVM 22，局部 ASan/UBSan，`detect_leaks=0`；预编依赖不保证全部插桩。各日志的 exit 1 均为下列断言失败，不是测试通过。

* 同步：两个 fake dumper 中第一个成功、第二个抛异常。相同行情再提交后，两个目标合计成功回调 3 次，而只向缺失目标投递应为 2 次。
* 异步：三次入队均返回 true，工作线程第二个 dumper 抛异常；相同行情入队后，两个目标合计成功回调仍为 3 次。队列按顺序排空后再检查计数，不能把入队成功当作落地成功。
* 进程恢复：fork 子进程的假外部目标先追加并 fsync 一字节，回调尚未返回时直接退出；控制进程销毁旧实例、用原缓存目录重新创建 writer 并提交同一行情，外部文件为 2 字节。这验证一种实际崩溃窗口；控制进程仍存活，不能泛化为断电、任意宿主重启或所有文件系统的恢复证据。
* 同步重入：bar dumper 内再次调用 `writeTick`，子进程 2 秒后被 SIGALRM 终止（wait status 14）；该受控输入显示当前持有分钟缓存锁期间调用外部 dumper 的重入死锁。它不证明生产插件确实重入，也不覆盖异步重入。

前一组路径失败、拒收丢送、回调保留局部 bar 指针的反例见 `../R4-AD-init-retry-20261102/README.md`。保留指针是对未记载期限的合同作出的更强假设，不证明生产插件依赖该用法。

## 接口及实现边界

`IDataWriter::writeTick` 只有 bool；`DataManager` 透传，`ParserAdapter` 在 false 时停止后续处理，指数 worker 又忽略该返回值。`IHisDataDumper` 只有返回 bool 的裸指针回调，没有携带幂等键、可查询的持久确认或者释放通知；`ExpDumper` 把该指针转发给外部回调。外部作用已发生后返回 false、抛异常、进程退出，以及目标成功但 writer 检查点未持久化，均不能由现有合同区分。单独给 writer 补持久队列只能让状态保留，不能安全判断上述目标是否已提交；重发可重复，不重发可丢失。对齐后的局部副本也不能在缺少释放通知时安全支持任意期限保留；无限保留不是可接受的所有权协议。

可部署的下一步需要 host 与目标一起约定版本化能力：新宿主显式发现版本、传递稳定事件/目标键和不可变数据，在目标原子地记录键与业务效果，提供已提交/明确拒绝/结果未知及按键查询，并明确数据借用期限或带释放确认的所有权。writer 在推进缓存和发出外部调用前持久记录事件及每目标状态；完成与已知拒绝分别记录，未知项在可查询确认或人工对账前暂停，不能盲目重发。恢复队列、单事件大小和容量需有硬上限，满时在产生新副作用前拒绝接纳；回调必须不持缓存锁调用并定义重入/关闭行为。LMDB 的键冲突、迟到更新、tick/bar 身份和保存顺序仍须单独定义与验证。

兼容部署要先同时升级宿主和具备上述能力的目标，再以配置启用新合同。旧插件可以保留旧通道，但其部分提交与崩溃后状态必须标记为未知并进入对账，不能声称自动恰好一次；旧 ABI 也无法给现有调用者传递这个状态。现有限定只能修改 AD writer 和专属测试，不能替外部目标实现原子去重、扩展 host 调用或确认其对象生命周期，因此本次没有引入看似可恢复但不能兑现语义的 writer 改动。此处是候选合同及阻塞说明，不是已经实现、验证或可直接上线的新接口。
