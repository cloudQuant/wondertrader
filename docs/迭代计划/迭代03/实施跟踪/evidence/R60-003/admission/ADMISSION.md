# BUG-R60-003: bounded stop-admission subfix, not lifecycle completion

`TraderMocker` now uses one private mutex to serialize admission with release. `orderInsert`, `orderAction`, `queryAccount`, `queryPositions`, `queryOrders` and `queryTrades` check the closed flag under that mutex; if closed they return -1 before retain/post. A successful retain plus `boost::asio::post` occurs while holding the same lock, so release cannot close admission between the check and post. This only linearizes those six methods against the beginning of release; it does not guarantee that admitted work executes, is canceled with a response, or is freed at release.

`release()` closes admission under the same mutex before its existing termination/join code. The closure is permanent for this instance: `init()` checks it both before initialization and immediately before returning success, and `connect()` rejects after closure. This deliberately fails closed rather than reopening an already-stopped io_context whose old tasks and callback ownership have not been resolved. **A same-instance restart after release is currently not supported**, so R60-003 is not complete. Init before the first release still permits the existing READY/deferred order/query behavior; pre-init null order behavior is unchanged. Init/release concurrent writes to other fields, duplicate release and self-reentry are not made thread-safe by this patch. `login()` and other nonlisted methods are not protected by the new gate.
