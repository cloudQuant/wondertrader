# ParserCTPMini connect return contract

`src/Includes/IParserApi.h:103-106` specifies that `connect()` returns whether the connection command was sent. `ParserCTPMini::connect()` formerly returned true with `m_pUserAPI == NULL`, without making an API call. Current source returns false in that case; with a non-null API it invokes `Init()` and returns true. This does not establish that a server accepted a connection or that an asynchronous connection succeeded.

`src/TestUnits/coverage/t_ParserCTPMini/ctpmini_parser_test.cpp` and `r105_parserctpmini_api_test.cpp` had asserted the old no-API true result; they now assert false. The existing R105 fake API positive still asserts true and exactly one Init call. Pre-fix source, with the two corrected assertions, produced 2 FAIL / 1 PASS: `red-test/output.log` and XML; the current target produces 4/4 PASS in `green-test/` including flow-directory failure control. Both targets rebuilt by `/opt/homebrew/bin/ninja -C /tmp/ctpm-i03-build -j 2 CoverageTests_t_ParserCTPMini`; test filters and outputs are in the two logs.

The isolated `src/TestUnits/fixtures/ctpmini_api_init/run.py` harness additionally verifies connect=false following missing library, missing symbol, null API, null config and after release; it verifies connect=true and one fake Init with a valid API. `red-spy/commands.json` records four pre-fix failures (exit 16) and two post-release failures (exit 25); `green-spy/commands.json` records 6/6 exit 0. Unload marker controls still pass 2/2 with real dlopen on fake dylibs (`unload-green/commands.json`). The separate unresolved cross-instance check still exits 40 and records same-module `opens=2` (`cross-instance/output.log`); it is not included in pass counts.

Source before and after hashes, current input hash checks, `own.diff` and symlink scan are retained here. No real vendor/server, sanitizer, Windows/Linux, callback drain or full regression was tested. The parser-level return is not propagated through all wrappers: `WtCore/ParserAdapter.cpp:506-507`, `WtDtCore/ParserAdapter.cpp:375-376`, `WtDtServo/ParserAdapter.cpp:408-409` each discard `connect()` and return true; this is static evidence only and needs separate repair and verification. The parser lifecycle and cross-instance failed-module isolation remain open.
