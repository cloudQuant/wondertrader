# S5 date-session 包：需用户/产品 owner 裁定的决策卡草稿

本文件只提出待裁定事项，不改变任何条目状态；已实施部分以 README 为准。

## 草稿 D1（卡 2 补充 2d）：空交易时段会话（`sections: []`）的合同

- **要决定什么**：当前 `loadSessions` 接受空 `sections`；空会话的聚合视图（`getTradingMins()=1440`、`getTradingSeconds()=86400`、`getSecMinList()={1440}`）表现为全天，而映射视图（`timeToMinutes/minuteToTime/timeToSeconds/secondsToTime` 返回 `INVALID_UINT32`、`isInTradingTime=false`、开收盘 0）表现为无交易；`DateMappingV1` 把空会话报告为 `MissingSession`。卡 2 已定“交易时段仅 0–0 表示全天”，但未说明空列表。
- **选项**：
  - A 未配置：配置入口拒绝空 `sections`（整份不发布）；直接创建的空对象聚合 getter 改为 0/空列表，与映射视图、`MissingSession` 一致。
  - B 全天：空列表在所有视图中等同 0–0（含映射与日期映射）。
  - C 维持现状：配置仍接受；在公开头写明“空会话不可用于映射，聚合 1440 仅为兼容值”。
- **建议**：A。理由：卡 2 已规定 0–0 是全天唯一表示；1440 兜底的历史注释（2021-12-25）原本针对 0–0 而非空列表；发行配置 `dist/common/sessions.json` 8 个会话无空列表。
- **影响**：`BUG-L03-010`（空会话子项）、`BUG-L03-009`；需改写旧断言 `l03_session.empty_sections_fallback_branches`（当前期望 1440）及 `i03_date_mapping_20261103` 夹具中故意加载的 `EMPTY` 会话；外部用户若有空会话配置将启动失败（需发布说明）。

## 草稿 D2（卡 2 补充 2e）：偏移后仍跨零点的交易段在 `autoAdjust` 下的空档对齐

- **要决定什么**：`timeToMinutes(t, autoAdjust=true)` 对普通段把段前空档对齐到下一段起点；但对偏移后 `first > second`（仍跨零点）的段不做对齐，段前空档返回 `INVALID_UINT32`。发行配置的夜盘均以 +300 偏移消除跨零点，此情形只出现在 offset=0 的隔夜段、负偏移等配置。
- **选项**：A 按偏移后时间的循环顺序对齐到该段起点（与普通段一致）；B 保持 `INVALID_UINT32` 并写入合同；C 配置入口拒绝偏移后仍跨零点的段。
- **建议**：B（行为不变，最小风险）；若产品需要支持 offset=0 的隔夜品种分钟对齐，则选 A 并补正反控。
- **影响**：`BUG-L03-010`（autoAdjust 子项）；A/C 会改变既有 `l03_session.time_to_minutes_offset_nonmonotonic_sections` 等用例的对照。

## 草稿 D3（卡 2 补充 2f）：普通交易段内部重叠

- **要决定什么**：本包已按卡 2 拒绝 0–0 与其他段混合（全天视图不得超过一天）。普通段内部重叠（如 0900–1500 再加 0900–0915）当前仍被接受，聚合分钟重复计数、映射不唯一；既有用例 `l03_session.set_offset_mins_keeps_registered_sections_consistent` 依赖这种追加来验证缓存失效。
- **选项**：A 在 `tryAddTradingSection`/配置入口拒绝内部重叠（端点相接允许）；B 接受并按登记顺序计数（现状）。
- **建议**：A（与 fail-closed 一致；发行配置无重叠）。需改写上述旧用例的追加段为不重叠的时段。
- **影响**：`BUG-L03-010`（重叠子项）。实现已在本包试做并验证可行（后按合同不明撤回为仅拒绝混合 0–0）。

## 草稿 D4（卡 1 实施细节）：插件侧取得 DateMappingV1 的协商方式

- **要决定什么**：读端（`WtDataStorage`/`WtDataStorageAD` 的 reader）与 `ParserXeleSkt` 只持有宿主传入的 `IBaseDataMgr*`，旧 vtable 只有两个日期 virtual，不能把它强转为 `WTSBaseDataMgr` 推定能力。本包已让这些调用者统一消费 typed 结果，但来源是卡 1 C（`DateMappingClient` 对旧 virtual 前置/后置校验）。C 路径无法发现“节假日日历未加载”（`IBaseDataMgr` 无此查询）。
- **选项**：
  - A 插件可选导出（如 `bindDateMappingV1(object, const DateMappingV1*)`），宿主创建插件对象后若找到该导出则注入 V1 表；无导出或旧宿主保持 C 路径。
  - B 版本化 sink 接口（如 `IRdmDtReaderSinkV2`），经导出能力协商后使用。
  - C 长期只用 C 路径，在接口合同写明缺日历不可检测，由宿主启动前确保日历加载。
- **建议**：A（与 `IExecPluginV2` 的版本化导出先例一致，旧插件/旧宿主双向兼容）。
- **影响**：`BUG-R12-13`、`BUG-L03-009`；需改动宿主 `WtDtServo/WtDataManager`（reader 创建处）、`WtCore/WtDtMgr`、`WtExecMon/WtSimpDataMgr`、各 `ParserAdapter`，以及 reader/parser 头文件（非本包所有）。

## 草稿 D5（I03-NEW-006）：运行中时钟失败时 StateMonitor 的行情接收

- **要决定什么**：本包使监控器在时钟/时区快照失败时“冻结”：不做状态转换、不触发收盘作业或缓存清理，失败与恢复各记一次日志并每秒重试。行情接收是否应同时暂停（转 `SS_PAUSED`），或由 owner 停止整个数据服务，尚无合同。
- **选项**：A 冻结（现实现）；B 强制暂停接收并在恢复后按快照重新判定；C 停止监控线程并向宿主报告失败。
- **建议**：A + 告警；B/C 需 DataManager/宿主生命周期合同。
- **影响**：`I03-NEW-006`、`BUG-R12-13`（StateMonitor 子项）。
