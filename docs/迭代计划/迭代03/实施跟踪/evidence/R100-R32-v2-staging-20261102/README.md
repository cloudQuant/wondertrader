# R100-003 / R32-003：独立 LMDB V2 staging 组件

状态：**仅离线组件与本机定向证据，未接入生产、未发布、两条原任务未关闭**。新增 `src/WtDataStorageAD/LMDBBarMigration.hpp`，调用方提供已打开的 V1 只读环境、独立 V2 staging 环境、已知源端序/值布局及每条记录的外部身份与完整时间证据。组件逐条调用既有 codec 验证身份、长度和时间；V1 键和值本身不是独立时间证据。组件无法验证证据实际来源，调用方如果把值中的时间直接当作独立证据将破坏此前提。

每次 `stageBatch` 在一个 V1 只读快照内验证已经提交前缀，再新增最多 4096 条记录；该批 V2 数据、源文件 dev/inode、源事务号、值布局、记录数、末条 V1 键和 I/C 状态作为目标 LMDB 中两个独立命名 DB，在同一目标写事务内提交。源/目标指向同一数据文件、源非只读、非安全同步/无锁标志、无独立证据、错误记录、前缀缺失/冲突/多余记录、源事务发生改变均拒绝；失败中当前批事务回滚，不修改先前提交批次。每次恢复都逐条核对前缀的 V2 键及逐字节值，并核对记录数。单次批量最多 4096 条，前缀扫描的额外应用内存为常数但总时间随已迁移量增加，LMDB map、事务、系统和磁盘资源仍有限；本测试不证明任意规模性能或资源上界。

状态 `Complete` 只表示检查到当前快照的存活记录都写入 staging，**不是外部可读发布、完整历史恢复或交易许可**。stage 的命名 DB 在 LMDB 层仍可由获得该环境访问权限的程序直接读取；组件没有访问控制，部署方必须把整个 staging 环境与生产 reader 隔离，在完整校验和受控切换之前不得开放。V1 旧键发生覆盖导致的历史丢失无法从幸存记录推断或恢复。组件保留原值字节而不是转换为 V2 值 ABI，现有任何生产 reader/writer 均未接入该新 key/value。Windows 路径明确返回 UnsupportedPlatform，尚未实现文件身份比对。

源事务号末次检查能够发现测试中在扫描期间提交的源写入，但检查与目标事务提交之间存在窗口；读事务、只读源句柄或 LMDB 锁均**不能证明生产写者已排空，也不能阻挡不合作旧程序**。实际应用必须由外部控制面先停收、排空、获得可验证的独占并阻止旧二进制访问，之后再完成一致性检查、原子发布和恢复协调。当前没有实现或认证此协议，未实现跨交易所/周期切换、已启用 V2 后的恢复或回滚策略，不能据此发布。文件身份与事务号不能防止有权限者一致篡改、离线替换或回滚整个环境；manifest 不具备加密签名或历史不可篡改证明。

## 定向验证

macOS arm64，使用 `/opt/homebrew/Cellar/llvm/22.1.8/bin`，实体仓库 LMDB C 源码、组件和测试 TU 均分别构建普通与 ASan/UBSan 版本；ASan `detect_leaks=1`。运行：

```sh
bash src/TestUnits/fixtures/lmdb_bar_migration/run.sh /tmp/wt-i03-lmdb-migration-final3-20261102
```

上述目录需事先不存在。`normal-results.json` 与 `asan-results.json` 分别 23/23 退出 0；逐场景日志、完整编译命令、编译器版本及源码前后哈希归档于本目录。仅 alias 测试在独立临时环境内建立数据文件**硬链接**，验证源/目标同一底层文件被拒绝；未创建符号链接，`symlinks.txt` 为空。覆盖：

- 多合约与同一合约跨 `0xffffffff` 的 V2 顺序、字节一致；aligned/packed 64 位值和模拟小端/大端来源，完整后关闭重开再逐条验证。
- 未知或错误独立证据、身份不匹配、时间不匹配、损坏 key/value、相同对象/同一文件别名、可写源及非法批量大小均拒绝。
- 完成阶段的现存值冲突、缺失或多余键均拒绝，且不覆盖冲突内容；写入中第二条证据失败不改变此前已提交批次。
- 完成第一批后，在下一批写入期间通过子进程 `_exit(77)` 模拟进程突然终止；重开时前批和 I 状态保留、未提交数据不存在，继续完成。测试不是硬掉电或存储介质故障。
- 源另进程在扫描期间提交时捕获到事务号变化并回滚本批；两批间发生源写入时，恢复因源事务号不符拒绝并保留旧 staging。该测试不覆盖最后检查后才发生的写入。
- 缩小目标 map 触发真实 `MDB_MAP_FULL`；覆盖首批尚未提交和第一批已提交的两种情况。前者目标为空，后者第一批 1 条及 I 状态保持不变，扩大 map 后均可重试完成。首次为已提交场景设置 64 KiB 时第一批已因空间不足而失败，`initial-map-full-partial.log` 留档；改为 128 KiB 后才可先提交第一批再令第二批满额。该测试不等价真实磁盘写满、fsync 失败、写损坏或电源故障。

系统 libc++、操作系统和文件系统不受 sanitizer 完整插桩；未跑 TSan、多平台、网络文件系统、生产 reader/writer 或全量回归。普通与 ASan 测试的隔离测试环境和生成的 LMDB 数据留在 `/tmp/wt-i03-lmdb-migration-final3-20261102`，未归档真实市场数据。
