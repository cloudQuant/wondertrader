# 有界恢复与连续会话候选协议（未实现）

目标是消除每批从头扫描而导致的约 O(N²/B) 工作，同时在证据撤销、对象失效、数据篡改或重启后不跳过必要校验。下面是待评审的合同，不是已实施的方案，也不认证证据的来源或交易可用性。

1. **可验证的证据快照**：证据应通过专用所有者构造，并以不可变、可持久重获且内容完整校验的版本标识绑定到源身份、每条原始键和独立证明。单纯复用 `std::function` 的地址、内存指针、名称、调用方自行传入的版本字符串，或只比较源/目标 LMDB 事务号，均不能证明证据没被撤销。快照应同时规定证据颁发方的撤销如何使读者可观察；仅持有旧 MVCC 读快照不能自动发现另一个通道的撤销。
2. **环境所有权和撤销**：快速会话须持有生命周期可管理的源、目标与证据快照所有者；所有者不暴露未协调的 close、DBI close 或 resize，并在活动会话期间推迟关闭。外部进程可写/可替换数据、两个非合作绑定或直接使用底层句柄，不能由现有 `Bindings` 的裸指针防止，必须由可验证的外部独占门禁处理；无法取得时拒绝开始，不得仅返回“调用者应保证”。
3. **首次/重启核验**：从持久 manifest 读取源、目标与证据身份及末条键；按有界块逐项核验 staging 与对应源/证据，checkpoint 与校验状态本身必须原子持久、能检测重启后源/目标/证据变化。需仔细处理部分复核过程再次崩溃、数据改变后事务号回绕或整个文件回滚；不允许凭旧进程内 bool 宣称已复核。每次重启至少一次完整前缀审计可以是初始正确性基线。
4. **同一连续会话的快速批次**：仅在持有强所有权、固定证据快照和已完成的初始核验期间缓存已验证前缀；批次开始时核对绑定、源/证据版本、目标前一提交版本与 manifest，按末条键恢复并验证严格后继、目标键不存在。证据读取、目标写入、状态提交需有明确线性化点；若任何版本发生变化、所有者失效、提交结果不明或回调异常，丢弃快速资格，保持原批次原子回滚并重新进行完整复核。单独检查一次版本而在目标提交前允许非合作写入仍有 TOCTOU，必须依赖实际生效的停写/互斥协议，不可据此宣称零竞争。
5. **发布和恢复仍为独立门禁**：`Complete` 仅指 staging 在上述合同下已扫描完幸存源，不代表可读取发布、历史未被 V1 覆盖或数据可追溯。需独立验证 V2 读写、旧程序阻断、多个市场/周期切换和切换后恢复；I/C 元数据不是访问控制。签名、来源真实性和外部独占权需由可信控制面提供并被真实验证，不能仅通过布尔标志代替。

实施前的必要测试：同一 batch/跨 batch 的撤销和证据替换；快照对象销毁、并发 close/resize、源/目标外部修改和重复调用；前缀篡改与额外数据；每个 checkpoint 及 commit 前后杀进程、重开后恢复；stat 与 cursor 不一致；二次版本回退；不合作进程写入；以及 10 万到真实预期规模的内存上限、回调次数、CPU、磁盘与长事务指标。必须保留本目录的批内撤销红控直到快照接口实际实现，并保留原始未注解 TSan 结果。真实掉电/介质故障和多平台需独立环境验证。

现有回调接口既不能证明证据不可变，也不能防止被借用的环境提前关闭；贸然增加“已验证前缀”缓存会使批内撤销和重启校验进一步失效。因此本轮没有改变产品组件，也没有把候选协议算作功能实现。
