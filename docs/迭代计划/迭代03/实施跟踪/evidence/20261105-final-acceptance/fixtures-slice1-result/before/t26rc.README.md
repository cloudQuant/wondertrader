# T26-011：费用请求终帧与发送完成跟踪候选

本次仅修改 `src/CTPLoader/TraderSpi.cpp/.h` 和本夹具；保留此前 T26-007 费用校验、文件发布和其他工作树改动。此为本机候选，**不是 SDK、完整宿主或迭代验收**；没有真实交易或符号链接。

费用模式下，合约请求在 SDK 调用前登记请求 ID；合约终帧处理完毕、需要的佣金/保证金任务全部入队后才封批。每项任务在调用 SDK 前登记类型、合约/交易所和 deadline，只有对应 ID 的终帧与 SDK 同步返回均已到达，且所有已排队任务发出并封批，才允许最终发布。同步返回非零、已观察错误回调、错误终帧、合约/交易所不匹配、同一原始键跨交易所或不同数值冲突均标为失败，不发布新费用文件。未知 ID、已完成请求的重复成功帧不重复记账；已完成请求后、批次结束前的已观察错误会锁存。单一商品键不同费率不能静默互相覆盖。成功终局关闭队列并 join 非当前 worker/watchdog；处在回调或 worker 内的当前线程不能自 join。

每个已发请求默认使用 **60 秒**单项超时，由独立 watchdog 检查，包括 SDK 调用本身未返回和先收到终帧而 SDK 调用仍阻塞；CTP 断连在活跃批次失败退出。60 秒为本次引入的操作策略，真实供应商延迟/部署适用性尚未验证；测试通过编译宏把该值设为 3.5 秒，**没有实测默认 60 秒**。队列等待发送的任务不计入此单项时间上限。对强制终止之前已提交的副作用不提供回滚。

## 尚未闭合

`src/CTPLoader/CTPLoader.cpp` 的 `Join()` 返回后仍无条件 `return 0`，异步模式也立即 `return 0`；此改动没有修改宿主返回协议，不能保证宿主在批次尚未完成时报告失败。真实供应商是否满足 request ID 唯一、终帧顺序、callback 排空及无已完成请求之后的迟到错误尚未证明；批次已发布或进程已退出之后的回报无法撤销。应用的单实例全局 `iRequestID`、全局费率/保证金表、多实例隔离和 provider 生命周期未解决。watchdog 使用进程退出报告故障，无法保证外部阻塞在进程退出时总能安全排空；正常和异常退出不构成真实存储故障或断电证明。

上一轮 T26-007 的费用文件合约键与引擎按品种键消费仍不匹配，合约/品种文件及费用文件也非跨文件事务；Windows 和 Linux 未实测。源码新增私有字段及一个线程，引用类布局的所有对象须重编。由于上述宿主和 provider 边界，本项不应标记完整关闭。
