## 6. 发布与部署注意事项

- **minfee 行为变化**：K10=A 后实盘开始应用 minfee，会改变已部署策略的费用结果，发布说明里要写明。
- **K12 费率数据**：`dist/common/fees.json` 保留第二套 `DCE.pg`（按额，历史实际生效值）。
- **第三方插件需要重编**：交易插件新增了整手校验（卡8）、K42 带状态的订单查询回调、原始回报上送，执行器插件有 ABI 2.2 的 V2 接口，策略插件有版本化要求，数据写端有 lifecycle V1 minor 1。这些插件都要按新 ABI 和合同重新编译验证；旧 ABI 插件会按设计 fail-closed 或给出诊断。
- **新的配置项**：
  - 解压预算：`uncompress_max_bytes`、`uncompress_max_ratio`，默认 1 GiB、1000:1，非法值 fail-closed。
  - parser 的 `required`：缺省为 true，失败即启动失败。
  - 部署配置要对照检查。
- **Loader 退出码**：配置错误时 `run()` 改为返回非零（K02=B、I03-NEW-091）。依赖“返回 0”的脚本需要调整。
- **sanitizer 构建**：Homebrew LLVM 构建要用 `evidence/20261105-final-acceptance/tools/san-configure.sh`，它修正了 `/usr/local` 下 Boost 1.81 头文件的顺序问题。TSan 下进程退出时的崩溃多半是 atexit/dlclose 工具限制，可以用 `runs/run-tsan-nodlclose/nodlclose.c` 验证。
- **夹具运行器 ninja 版本**：`i03_card3_dayboundary/r202_run.py` 写死了 `/opt/homebrew/bin/ninja`，对新版 ninja 生成的构建目录执行 `-t deps` 时会删除 `.ninja_log`。后续应改为使用构建该树的那个 ninja，或者先复制构建目录再执行。
